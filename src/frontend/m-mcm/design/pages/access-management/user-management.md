# 사용자관리 페이지 UI 설계 (1차)

## 1. 목적

- 사용자관리 화면의 1차 UI 골격을 정의한다.
- 이번 단계는 `신규등록`, `갱신`, `삭제`, `조회`의 실제 동작 구현 없이 화면 구조와 컴포넌트 배치만 확정한다.

## 2. 범위

- 포함:
  - 상단 `조회조건 입력 영역`
  - 상단 `명령 영역(조회/등록/갱신/삭제)`
  - 본문 `그리드 테이블 영역`
  - 등록/갱신용 입력 폼 `UI 스켈레톤(모달/패널)`
- 제외:
  - API 연동
  - 폼 유효성 검증 로직
  - 저장/수정/삭제 처리 로직
  - 권한 체크 로직

## 3. 페이지 레이아웃

페이지는 세로 3단 구조로 배치한다.

1. 조회조건 입력 영역
2. 명령 영역
3. 사용자 목록 그리드 영역

### 3.1 조회조건 입력 영역

- 위치: 페이지 상단
- 목적: 목록 조회를 위한 필터 입력
- 필드(초안):
  - 사용자 ID
  - 사용자명
  - 역할(Role)
  - 사용여부(활성/비활성)
- 버튼:
  - `조회`
  - `초기화`

### 3.2 명령 영역

- 위치: 조회조건 영역 하단(동일 상단 그룹 내)
- 목적: 목록/폼 관련 주요 동작 진입점 제공
- 버튼 구성:
  - `조회`
  - `등록`
  - `갱신`
  - `삭제`
- 배치 원칙:
  - 조회 계열(`조회`)과 변경 계열(`등록/갱신/삭제`)을 시각적으로 구분한다.
  - `삭제`는 위험 동작으로 스타일을 구분한다.

### 3.3 그리드 테이블 영역

- 위치: 페이지 본문
- 목적: 사용자 목록 확인 및 대상 선택
- 컬럼(초안):
  - 사용자 ID
  - 사용자명
  - 역할
  - 사용여부
  - 최종 수정자
  - 최종 수정일시
- 선택 방식:
  - 단일 행 선택(기본)
  - 필요 시 다중 선택으로 확장 가능하도록 여지 유지

## 4. 등록/갱신 폼 UI 스켈레톤

- 호출 방식: `등록` 또는 `갱신` 버튼 클릭 시 오픈되는 모달 또는 우측 패널
- 입력 항목(초안):
  - 사용자 ID(등록 시 입력 / 갱신 시 읽기전용 가능)
  - 사용자명
  - 역할
  - 사용여부
  - 비고
- 하단 버튼:
  - `저장`(비활성 또는 no-op)
  - `취소`
- 주의:
  - 이번 단계에서는 입력값 검증 및 저장 동작을 연결하지 않는다.

## 5. 컴포넌트 가이드

- UI 라이브러리는 `@ui5/webcomponents-react`를 우선 사용한다.
- 추천 매핑:
  - 조회조건/입력: `Input`, `Select`, `DatePicker`(필요 시), `Label`
  - 명령 버튼: `Button`, `Bar`, `Toolbar`
  - 그리드: `AnalyticalTable` 또는 프로젝트 표준 테이블 컴포넌트
  - 팝업: `Dialog` 또는 `ResponsivePopover`

## 6. 상태 정의 (UI 전용)

- `초기 상태`: 빈 검색조건 + 기본 목록(목업 가능)
- `조회결과 없음 상태`: "조회 결과가 없습니다" 안내 문구 표시
- `행 미선택 상태`: `갱신`, `삭제` 버튼 비활성 스타일 표현(동작 없음)

## 7. 구현 메모

- 기능 연결 전제 없이도 화면 리뷰가 가능하도록 목업 데이터 기반으로 구성한다.
- 추후 2차에서 API/검증/권한 로직을 연결한다.
