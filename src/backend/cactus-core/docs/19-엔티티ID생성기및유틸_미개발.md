# 19. 엔티티 ID 생성기 및 유틸 (미개발)

> 통합 원본: 명시적 단일 원본 없음
> 구현 상태: **미구현** (CactusIdGenerator, JsonUtils, FileUtils 등). 단, `TxIdGenerator` 는 구현됨 (정리본 08).

---

## 1. 설계 의도

- 엔티티 PK 자동 생성 표준화 (ULID, KSUID, 또는 도메인 패턴)
- 공통 유틸리티 (JSON 직렬화, 파일 처리, 랜덤 문자열) 통합
- 모듈마다 자체 구현하지 않도록 라이브러리화

---

## 2. 제안 명세

### 2.1 ID 생성기
```
cactus-core/util/id/
├── CactusIdGenerator.java           # interface
├── UlidGenerator.java               # ULID (시간순 정렬 가능)
├── PatternIdGenerator.java          # 도메인 패턴 (예: WO-{plantCd}-{YYYYMMDD}-{seq})
└── HibernateIdentifierGenerator.java # JPA @GenericGenerator 통합
```

### 2.2 JPA 통합 예시
```java
@Entity
public class WorkOrder {
    @Id
    @GeneratedValue(generator = "cactus-pattern")
    @GenericGenerator(name = "cactus-pattern", 
        type = PatternIdGenerator.class,
        parameters = @Parameter(name = "pattern", value = "WO-{plantCd}-{yyyyMMdd}-{seq:3}"))
    private String orderId;
}
```

### 2.3 기타 유틸
```
cactus-core/util/
```

## 3. 부분 구현 흔적

| 항목 | 위치 | 내용 |
|---|---|---|
| TxIdGenerator | `cactus-core/util/TxIdGenerator.java` | `{userId}-{menuId}-{yyyyMMddHHmmss}-{random3}` 생성 |

→ 패턴 기반 ID 생성의 단순 사례는 이미 구현됨. 이를 일반화한 PatternIdGenerator 가 미구현.

## 4. 도메인 모듈에서 임시 구현된 사례

`mpp/.../WorkOrderService.java:115-121`:
```java
String generateOrderId(String plantCd, LocalDate baseDate) {
    String prefix = ORDER_ID_PREFIX + plantCd + "-" + baseDate.format(YYYYMMDD) + "-";
    int nextSeq = workOrderRepository.findFirstByOrderIdStartingWithOrderByOrderIdDesc(prefix)
            .map(w -> parseSeq(w.getOrderId(), prefix) + 1)
            .orElse(1);
    return prefix + String.format("%03d", nextSeq);
}
```

→ 도메인마다 비슷한 패턴이 중복될 가능성. 라이브러리화 시 cactus-core 의 `PatternIdGenerator` 활용 가능.

---

## 5. 미구현 사유

- 도메인 ID 패턴이 모듈마다 달라 표준화 어려움
- 단순 UUID 만으로 대부분 해결 가능
- 라이브러리화 비용 > 개별 구현 비용 (현 단계)

---

## 6. 도입 시 고려사항

| 항목 | 설명 |
|---|---|
| 동시성 | seq 기반 시 중복 방지 (PostgreSQL sequence 또는 비관적 락) |
| 성능 | DB 라운드트립 최소화 — 캐시된 sequence 또는 application 단 incrementer |
| ULID vs UUID | ULID 는 시간순 정렬 → 인덱스 효율 좋음. UUID 는 호환성 좋음 |
| 패턴 표현 | `{prefix}-{plantCd}-{yyyyMMdd}-{seq:3}` 같은 mini DSL 또는 SpEL |
| 마이그레이션 | 기존 도메인의 자체 generator 를 점진 교체 |

---

## 7. 임시 대안 (현재 패턴)

- 도메인별 자체 generate 메서드 작성 (위 WorkOrder 예시)
- `findFirstBy{Field}StartingWithOrderBy{Field}Desc` 로 prefix 기반 채번
- UUID 단순 사용 시 `UUID.randomUUID().toString()`
