## 2. AutoConfiguration 7종

| 클래스 | 위치 | 등록 빈 |
|---|---|---|
| `CactusAutoConfiguration` | `autoconfigure/CactusAutoConfiguration.java` | `@ComponentScan("com.dongkuk.dmes.cactus")` + `CactusProperties` 활성화 (배너 출력) |
| `SecurityAutoConfiguration` | `autoconfigure/SecurityAutoConfiguration.java` | JwtTokenProvider 등 보안 빈 1차 등록 |
| `CactusAuthAutoConfiguration` | `autoconfigure/CactusAuthAutoConfiguration.java` | AuthService, PasswordEncoder, SecUser EntityScan/JpaRepositories (`cactus.auth.enabled: true` 시 활성). **AuthController 는 cactus-core 에 없음** — 사용 모듈이 자체 작성 |
| `CactusWebSecurityAutoConfiguration` | `autoconfigure/CactusWebSecurityAutoConfiguration.java` | SecurityFilterChain default + TxIdFilter / RequestIdFilter / ClientKeyFilter / JwtAuthenticationFilter 체인 등록 (도메인이 자체 SecurityConfig 보유 시 SecurityFilterChain 부분만 비활성) |
| `AuditAutoConfiguration` | `audit/AuditAutoConfiguration.java` | CactusAuditListener (JPA), CactusMybatisAuditInterceptor, SqlLoggingInterceptor 자동 plug-in (MyBatis 조건부) |
| `OasisAutoConfiguration` | `oasis/OasisAutoConfiguration.java` | ServiceStarter, OasisServiceExecutor, CactusRequestConverter, CactusResponseConverter |
| `InboundAutoConfiguration` | `web/inbound/InboundAutoConfiguration.java` | (1) OasisController, ServiceController, QueryController, LovController 4개 inbound 컨트롤러 `@Bean` 명시 등록 (`@ConditionalOnBean(OasisServiceExecutor / SqlSession)` 조건부). (2) `WebMvcRegistrations` 빈으로 default `RequestMappingHandlerMapping` 을 `CactusRequestMappingHandlerMapping` 으로 교체 — Spring 7 의 `isHandler` 가 `@Controller` 만 인식하는 변경에 대한 호환 처리 |

> **inbound 컨트롤러는 `@Controller` 어노테이션 미부착** (컴포넌트 스캔 회피). mybatis/oasis-core 가 없는 사이트에서도 cactus-core 자체는 안전하게 부팅되도록, `@Bean` + `@ConditionalOnBean` 으로만 등록되며, 클래스 레벨 `@RequestMapping` 으로 매핑된다. Spring 6 까지는 클래스 레벨 `@RequestMapping` 도 핸들러로 인식했으나 Spring 7 부터 변경되어 별도 `CactusRequestMappingHandlerMapping` 으로 복원.

`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 에 7개 모두 등록되어 Spring Boot 4 자동설정으로 활성화.

> **portal 예외**: portal 모듈만 자체 `SecurityConfig` (`com.dongkuk.dmes.mcm.config.SecurityConfig`) 를 보유 (`/api/auth/**` permitAll + ClientKeyFilter skip 통합). mpp/mqc/aps 는 cactus default(`CactusWebSecurityAutoConfiguration`) 만 사용.
> **portal 만** `cactus.auth.enabled: true` 로 `CactusAuthAutoConfiguration` 활성화 (AuthService/SecUserRepository 사용). 다른 모듈은 미활성.

## 3. ConfigurationProperties

| Properties 클래스 | prefix | 주요 필드 |
|---|---|---|
| `CactusProperties` | `cactus` | `jwt.secret`, `jwt.issuer` (기본 "dmes"), `jwt.access-token-expiry` (초, 기본 28800=8시간), `jwt.refresh-token-expiry` (초, 기본 86400=24시간), `security.max-login-failures` (기본 5), `security.password-expiry-days` (기본 90, 현재 미사용), `security.client-key` (선택, 정의 시 ClientKeyFilter 활성), `auth.enabled` (기본 false, true 시 CactusAuthAutoConfiguration 활성) |
| `OasisProperties` | `cactus.oasis` | `service-group` (기본 "app", **URL 경로에 들어가지 않음** — BPMN 라우팅·로깅 식별용), `service-path` (기본 "resources/services"), `transactional` (기본 false) |

도메인 모듈의 `application.yml` 예시 (portal):
```yaml
cactus:
  auth:
    enabled: true                                # AuthService 활성화
  jwt:
    secret: ${CACTUS_JWT_SECRET}                  # Base64, 최소 256bit
    issuer: portal
    access-token-expiry: 3600                     # 초 단위
    refresh-token-expiry: 86400
  security:
    max-login-failures: 5
    client-key: dmes-bff-local-client-key-2026   # 정의 시 ClientKeyFilter 활성
  oasis:
    service-group: portal
    service-path: resources/services
    transactional: false
```

## 4. 패키지별 책임

### 4.1 `autoconfigure/`
- `CactusAutoConfiguration`: 공통 빈 일괄 등록
- `SecurityAutoConfiguration`: 보안 필터체인
- `CactusProperties`: jwt, oasis 등 통합 prefix

### 4.2 `oasis/`
- `OasisController`, `OasisServiceExecutor`: BPMN 라우팅 (정리본 03 참고)
- `CactusRequestConverter`, `CactusResponseConverter`: CactusRequest ↔ ServiceContext

### 4.3 `security/`
- `auth/`: AuthService, SecUser, SecUserRepository, PasswordEncoder, LoginRequest, RefreshRequest. **AuthController 는 cactus-core 에 존재하지 않음** — 도메인 모듈이 자체 작성 (예: `portal/core` 의 `PortalAuthController`)
- `context/`: UserContext, UserContextHolder (ThreadLocal), UserInfo (record: userId, userNm, userEmpNo, roles)
- `filter/`: ClientKeyFilter (X-Client-Key 헤더 검증)
- `jwt/`: JwtTokenProvider (HMAC-SHA256), JwtAuthenticationFilter, JwtTokenHolder (ThreadLocal 토큰 보관), TokenPair (record: accessToken, refreshToken)

### 4.4 `audit/`
- `CactusAuditEntity` (`@MappedSuperclass`, 9개 감사 컬럼)
- `CactusAuditListener` (`@PrePersist`/`@PreUpdate`)
- `CactusMybatisAuditInterceptor`, `SqlLoggingInterceptor`
- `AuditHolder` (ThreadLocal `CactusAudit`)

### 4.5 `web/`
- `request/`: CactusRequest, RequestMeta (record), GridData, RowStatus (enum C/U/D/R)
- `response/`: CactusResponse (Builder), ResponseMeta (record + 정적 팩토리), GridResult, ColumnMeta, ErrorDetail (record + 정적 팩토리)
- `converter/`: GridConverter (Map↔DTO + ""→null 정규화)
- `filter/`: TxIdFilter (OASIS MDCTemplate 기반), RequestIdFilter (`@Order` 미부착 — SecurityFilterChain 명시 등록)
- `exception/`: GlobalExceptionHandler (`@RestControllerAdvice`)
- `inbound/`: OasisController(`/oasis/{serviceId}/{action}`), ServiceController(`/service/{serviceId}`), QueryController(`/query/{queryId}`), LovController(`/lov/master|query|service/...`), MasterCodeProvider (인터페이스), Lov, InboundAutoConfiguration

### 4.6 `common/`
- `BusinessException` (ErrorCode + List<ErrorDetail>)
- `ErrorCode` (E/A/S 코드 + HTTP 상태)
- `ApiResponse<T>`

### 4.7 `util/`
- `TxIdGenerator`

## 5. 의존성

도메인 모듈에서의 의존 예 (`portal/core/build.gradle`):

```gradle
dependencies {
  // ── Cactus (oasis-core 포함) ──
  api 'com.dongkuk.dmes:cactus-core:1.0.18-SNAPSHOT'

  // ── Spring Boot ──
  api 'org.springframework.boot:spring-boot-starter-data-jpa'
  api 'org.springframework.boot:spring-boot-starter-security'
  api 'org.springframework.boot:spring-boot-starter-web'

  // ── DB Drivers ──
  api 'com.microsoft.sqlserver:mssql-jdbc:12.8.1.jre11'
  api 'org.xerial:sqlite-jdbc:3.45.3.0'
  api 'org.hibernate.orm:hibernate-community-dialects:7.0.5.Final'
}
```

cactus-core 자체는 oasis-core, spring-web, jjwt 등을 `api` 로 노출하며, MyBatis 는 `compileOnly` 로 선언되어 도메인 모듈이 사용할 때만 활성화된다.
