# 파일 업로드/다운로드 명세

> 일시: 2026-03-23 (원본) / 2026-04-26 (현행 사실 박스)
> 목적: 엑셀 업로드/다운로드, 첨부파일 처리 규격 정의
>
> **현행 사실 (마이그레이션 완료, 2026-04-26)**
> - URL 컨벤션: 본 문서의 `POST /api/file/...`, `POST /api/excel/...` 표기는 BE 매핑 시점 기준의 **개념적 경로**이다. 현행 시스템 컨벤션은 UI→BFF 는 `/api/{module}/nooasis/{path}`, BFF→BE 는 `/api/{module}/nooasis/` segment 만 제거하여 `${module_url}/{path}` 로 호출한다. 즉 BE 의 실제 경로는 모듈/배포 환경에 따라 `/api/file/...` 류로 매핑되며, BFF 가 nooasis 라우트로 프록시한다.
> - 파일 처리는 OASIS 매핑(`/oasis/{serviceId}/{action}`) 의 단일 진입점에 포함되지 않는 **특수 케이스** 이며, 이 점은 본 문서가 다루는 분리 원칙 그대로다.
> - **구현 상태**: 본 문서가 기술하는 `FileController` / `FileService` / `ExcelController` 등은 cactus-core 본체(`com.dongkuk.dmes.cactus.*`)에 **아직 존재하지 않는다.** Phase 7 Inbound 컨트롤러(`OasisController`, `QueryController`, `ServiceController`, `LovController`) 만 등록된 상태이며, 파일 처리는 향후 구현 예정. 본 문서는 설계 초안으로 보고, 실제 패키지 위치·시그니처는 구현 시점의 코드를 정으로 한다.

---

## 1. 개요

파일 처리는 `CactusRequest`/`CactusResponse` (JSON) 구조와 분리하여 별도 엔드포인트로 처리한다.

| 구분 | Content-Type | 엔드포인트 |
|------|-------------|-----------|
| 업로드 | `multipart/form-data` | `POST /api/file/upload` |
| 다운로드 | 바이너리 스트림 | `GET /api/file/download` |
| 엑셀 업로드 | `multipart/form-data` | `POST /api/excel/upload` |
| 엑셀 다운로드 | 바이너리 스트림 | `POST /api/excel/download` |

---

## 2. 엑셀 업로드

MES에서 가장 빈번한 케이스. 엑셀 파일을 읽어서 그리드 데이터로 변환한다.

### 2.1 Request

```
POST /api/excel/upload
Content-Type: multipart/form-data

Parts:
  file: (엑셀 파일 바이너리)
  menuId: "PROD001"
  gridId: "master"
  sheetIndex: 0          (optional, 기본값 0)
  headerRow: 0           (optional, 헤더 행 인덱스, 기본값 0)
```

### 2.2 Response

업로드 결과는 `CactusResponse` 형태로 반환한다. 파싱된 데이터를 `grids`에 담아서 프론트가 그리드에 바로 표시할 수 있게 한다.

```json
{
  "meta": {
    "txId": "...",
    "success": true,
    "code": "0000",
    "message": "15건 업로드 완료"
  },
  "grids": {
    "master": {
      "rows": [
        { "rowStatus": "C", "itemCd": "ITEM-001", "itemNm": "철강코일 A타입", "qty": 100 },
        { "rowStatus": "C", "itemCd": "ITEM-002", "itemNm": "철강코일 B타입", "qty": 200 }
      ]
    }
  }
}
```

- 업로드된 행은 모두 `rowStatus: "C"` (신규)
- 프론트에서 그리드에 표시 후, 사용자가 확인/수정 → 저장 API 호출
- 즉 **업로드 = 파싱만**, 실제 저장은 별도 save 호출

### 2.3 업로드 에러

> 엑셀 업로드는 파일 파싱 단계이므로 프론트에서 rowKey를 부여하지 않는다. 에러 위치는 `rowIndex` (엑셀 행 번호)로 식별한다.

```json
{
  "meta": {
    "txId": "...",
    "success": false,
    "code": "E001",
    "message": "엑셀 파싱 중 오류가 발생했습니다."
  },
  "errors": [
    { "rowIndex": 3, "field": "qty", "code": "E002", "message": "숫자 형식이 아닙니다." },
    { "rowIndex": 7, "field": "itemCd", "code": "E003", "message": "필수 항목이 비어 있습니다." }
  ]
}
```

## 3. 엑셀 다운로드

그리드 데이터를 엑셀 파일로 내려받는다.

### 3.1 Request

다운로드는 조회 조건을 전달해야 하므로 `POST`를 사용한다.

```
POST /api/excel/download
Content-Type: application/json

{
  "meta": {
    "userId": "user01",
    "menuId": "PROD001"
  },
  "params": {
    "plantCd": "P01",
    "fromDate": "2026-03-01",
    "toDate": "2026-03-20",
    "gridId": "master",
    "fileName": "생산실적_20260320"
  }
}
```

- Request body는 `CactusRequest`와 동일한 구조
- `params`에 `gridId`, `fileName` 등 다운로드 관련 파라미터 추가
- 페이징 없이 전체 데이터를 조회하여 엑셀 생성

### 3.2 Response

```
HTTP/1.1 200 OK
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="생산실적_20260320.xlsx"

(바이너리 스트림)
```

### 3.3 다운로드 에러

파일 생성 실패 시 JSON 에러 응답을 반환한다.

```
HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "meta": {
    "txId": "...",
    "success": false,
    "code": "E001",
    "message": "다운로드 대상 데이터가 없습니다."
  }
}
```

## 4. 첨부파일 업로드

일반 파일 첨부 (이미지, PDF 등).

### 4.1 Request

```
POST /api/file/upload
Content-Type: multipart/form-data

Parts:
  file: (파일 바이너리, 다중 파일 가능)
  menuId: "PROD001"
  refId: "ORD-001"        (연관 데이터 ID)
  refType: "ORDER"        (연관 데이터 유형)
```

### 4.2 Response

```json
{
  "meta": {
    "txId": "...",
    "success": true,
    "code": "0000",
    "message": "2건 업로드 완료"
  },
  "params": {
    "uploadCount": 2
  },
  "grids": {
    "files": {
      "rows": [
        { "fileId": "FILE-001", "fileName": "도면_v2.pdf", "fileSize": 1048576, "contentType": "application/pdf" },
        { "fileId": "FILE-002", "fileName": "사진.jpg", "fileSize": 524288, "contentType": "image/jpeg" }
      ]
    }
  }
}
```

## 5. 첨부파일 다운로드

### 5.1 Request

```
GET /api/file/download?fileId=FILE-001
```

### 5.2 Response

```
HTTP/1.1 200 OK
Content-Type: application/pdf
Content-Disposition: attachment; filename="도면_v2.pdf"

(바이너리 스트림)
```

## 6. Java 클래스 구조

```java
// === cactus-core에 위치 ===

/**
 * 엑셀 업로드 컨트롤러
 */
@RestController
@RequestMapping("/api/excel")
public class ExcelController {

    private final ExcelService excelService;

    @PostMapping("/upload")
    public CactusResponse upload(
            @RequestParam("file") MultipartFile file,
            @RequestParam("menuId") String menuId,
            @RequestParam("gridId") String gridId,
            @RequestParam(value = "sheetIndex", defaultValue = "0") int sheetIndex,
            @RequestParam(value = "headerRow", defaultValue = "0") int headerRow) {
        return excelService.parseExcel(file, menuId, gridId, sheetIndex, headerRow);
    }

    @PostMapping("/download")
    public ResponseEntity<byte[]> download(@RequestBody CactusRequest request) {
        return excelService.generateExcel(request);
    }
}

/**
 * 첨부파일 컨트롤러
 */
@RestController
@RequestMapping("/api/file")
public class FileController {

    private final FileService fileService;

    @PostMapping("/upload")
    public CactusResponse upload(
            @RequestParam("file") List<MultipartFile> files,
            @RequestParam("menuId") String menuId,
            @RequestParam("refId") String refId,
            @RequestParam("refType") String refType) {
        return fileService.upload(files, menuId, refId, refType);
    }

    @GetMapping("/download")
    public ResponseEntity<byte[]> download(@RequestParam("fileId") String fileId) {
        return fileService.download(fileId);
    }
}
```
