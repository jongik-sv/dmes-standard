## 1. 목표

**JPA 엔티티** 및 **MyBatis SQL**을 INSERT/UPDATE할 때 **감사 컬럼(누가, 언제, 어떤 서비스에서)을 자동으로 채운다**.
비즈니스 코드에서 감사 컬럼을 직접 세팅하지 않아도 되도록 한다.

- **JPA**: `@PrePersist`/`@PreUpdate` 리스너 → 엔티티 필드에 직접 세팅
- **MyBatis**: `Interceptor` → 파라미터 Map에 감사 값 주입 → SQL에서 `#{cUsrId}` 등으로 바인딩

## 2. dmes-ref 현행 분석

### 2.1 구성 요소

```
OASIS (oasis-core)
├── Audit                    인터페이스 (마커)
└── AuditHolder              ThreadLocal<Audit> 보관/조회

dmes-ref-biz (cmn.audit)
├── FilmAudit                Audit 구현체 (userId, programId, serviceId)
├── VersionAuditEntity       @MappedSuperclass — 감사 컬럼 9개 정의
├── VersionAuditListener     @PrePersist/@PreUpdate — 자동 값 세팅
└── MybatisAudit             MyBatis Interceptor — INSERT/UPDATE 시 감사 주입
```

### 2.2 동작 흐름

```
ServiceController
  ① FilmAudit audit = new FilmAudit(userId, programId, serviceId)
  ② serviceContext.setAudit(audit)
     → OASIS 내부에서 AuditHolder.setAudit(audit) 호출 (ThreadLocal 저장)

OASIS 서비스 실행 중 JPA persist/update 발생
  ③ VersionAuditListener.@PrePersist / @PreUpdate 자동 트리거
  ④ AuditHolder.getAudit() 로 ThreadLocal에서 FilmAudit 꺼냄
  ⑤ 감사 컬럼 자동 세팅
```

### 2.3 감사 컬럼 (VersionAuditEntity)

| 컬럼 | 타입 | INSERT | UPDATE |
|------|------|--------|--------|
| C_USR_ID | String(100) | userId | — |
| C_AT | Instant | now() | — |
| C_SVC_ID | String(100) | serviceId | — |
| C_PGM_ID | String(100) | programId | — |
| U_USR_ID | String(100) | userId | userId |
| U_AT | Instant | now() | now() |
| U_SVC_ID | String(100) | serviceId | serviceId |
| U_PGM_ID | String(100) | programId | programId |
| VER | Long | 0 | +1 |

### 2.4 문제점

- `programId`를 Base64 Authorization 헤더에서 가져옴 → cactus-core는 JWT 방식이라 동일 경로 불가 (CactusRequest.meta.menuId로 대체)
- `MybatisAudit`에 버그가 있음 (`audit.getClass()` → `audit.getUserId()`여야 함)
- 각 모듈(biz, portal, toss)에 `VersionAuditEntity`, `VersionAuditListener`, `FilmAudit`, `AuditHolder`가 **중복 복사**되어 있음

## 3. cactus-core 설계

### 3.1 설계 원칙

1. **OASIS의 `Audit`/`AuditHolder`를 그대로 활용** — 이미 oasis-core 의존 있음
2. **cactus-core에서 공통 감사 엔티티와 리스너를 1회 정의** — 프로젝트에서 중복 구현 방지
3. **UserContextHolder와 연동** — cactus-core의 기존 사용자 컨텍스트 활용
4. **Auto-Configuration으로 선택적 활성화** — `@ConditionalOnClass` 기반

### 3.2 cactus-core에서의 감사 정보

dmes-ref의 `FilmAudit`(userId, programId, serviceId)과 달리,
cactus-core는 JWT에서 추출한 정보 + OASIS 실행 컨텍스트를 활용한다.

| 항목 | dmes-ref (FilmAudit) | cactus-core (CactusAudit) | 소스 |
|------|---------------------|--------------------------|------|
| 사용자 ID | userId (Base64 헤더) | userId | UserContextHolder / JWT |
| 프로그램 ID | programId (Base64 헤더) | menuId | CactusRequest.meta.menuId |
| 서비스 ID | serviceId (URL 파라미터) | serviceId | OasisServiceExecutor 파라미터 |

> dmes-ref의 `programId`는 "사용자가 현재 조작 중인 화면 ID"로, cactus-core의 `menuId`와 동일한 개념이다.
> dmes-ref는 Base64 Authorization 헤더에서, cactus-core는 CactusRequest Body에서 가져온다.

### 3.3 감사 컬럼 설계

dmes-ref 9개 컬럼을 그대로 유지한다. `C/U_PGM_ID`에는 `menuId` 값을 넣는다.

| 컬럼 | 필드명 | 타입 | INSERT | UPDATE | 설명 |
|------|--------|------|--------|--------|------|
| C_USR_ID | createdBy | String(100) | ✅ userId | — | 생성자 |
| C_AT | createdAt | Instant | ✅ now() | — | 생성 일시 |
| C_SVC_ID | createdSvcId | String(100) | ✅ serviceId | — | 생성 서비스 ID |
| C_PGM_ID | createdPgmId | String(100) | ✅ menuId | — | 생성 화면(메뉴) ID |
| U_USR_ID | updatedBy | String(100) | ✅ userId | ✅ userId | 수정자 |
| U_AT | updatedAt | Instant | ✅ now() | ✅ now() | 수정 일시 |
| U_SVC_ID | updatedSvcId | String(100) | ✅ serviceId | ✅ serviceId | 수정 서비스 ID |
| U_PGM_ID | updatedPgmId | String(100) | ✅ menuId | ✅ menuId | 수정 화면(메뉴) ID |
| VER | version | Long | ✅ 0 | ✅ +1 | 레코드 버전 (낙관적 락) |

## 5. 상세 설계

### 5.1 CactusAudit

OASIS의 `Audit` 인터페이스를 구현하는 감사 정보 객체.

```java
package com.dongkuk.cactus.audit;

import com.dongkuk.oasis.audit.Audit;

/**
 * 감사 정보. OasisServiceExecutor가 요청마다 생성하여 AuditHolder에 저장한다.
 * CactusAuditListener가 엔티티 persist/update 시 이 정보를 꺼내 감사 컬럼에 세팅한다.
 */
public record CactusAudit(String userId, String menuId, String serviceId) implements Audit {
}
```

**설계 결정:**
- Record 타입 (불변, 간결)
- `userId` — `UserContextHolder.getUserId()`에서 가져옴
- `menuId` — `CactusRequest.meta.menuId`에서 가져옴 → DB `C/U_PGM_ID` 컬럼에 저장
- `serviceId` — `OasisServiceExecutor.execute()`의 파라미터에서 가져옴

### 5.2 CactusAuditEntity

모든 비즈니스 엔티티가 상속할 감사 기본 클래스.

```java
package com.dongkuk.cactus.audit;

import jakarta.persistence.Column;
import jakarta.persistence.EntityListeners;
import jakarta.persistence.MappedSuperclass;
import java.time.Instant;

/**
 * 감사 컬럼을 제공하는 기본 엔티티.
 * 비즈니스 엔티티는 이 클래스를 상속하면 INSERT/UPDATE 시 감사 컬럼이 자동으로 채워진다.
 *
 * <pre>
 * @Entity
 * public class Product extends CactusAuditEntity {
 *     @Id
 *     private String productId;
 *     private String productName;
 *     // ... 감사 컬럼은 자동 관리
 * }
 * </pre>
 */
@MappedSuperclass
@EntityListeners(CactusAuditListener.class)
public abstract class CactusAuditEntity {

    @Column(name = "C_USR_ID", length = 100)
    private String createdBy;

    @Column(name = "C_AT")
    private Instant createdAt;

    @Column(name = "C_SVC_ID", length = 100)
    private String createdSvcId;

    @Column(name = "C_PGM_ID", length = 100)
    private String createdPgmId;

    @Column(name = "U_USR_ID", length = 100)
    private String updatedBy;

    @Column(name = "U_AT")
    private Instant updatedAt;

    @Column(name = "U_SVC_ID", length = 100)
    private String updatedSvcId;

    @Column(name = "U_PGM_ID", length = 100)
    private String updatedPgmId;

    @Column(name = "VER")
    private Long version;

    // Getter/Setter (패키지 접근 — Listener에서만 사용)
    // public Getter는 조회 필요 시 제공

    protected Long getVersion() {
        return version;
    }

    // setter는 패키지 접근 제한 (Listener 전용)
    void setCreatedBy(String createdBy) { this.createdBy = createdBy; }
    void setCreatedAt(Instant createdAt) { this.createdAt = createdAt; }
    void setCreatedSvcId(String createdSvcId) { this.createdSvcId = createdSvcId; }
    void setCreatedPgmId(String createdPgmId) { this.createdPgmId = createdPgmId; }
    void setUpdatedBy(String updatedBy) { this.updatedBy = updatedBy; }
    void setUpdatedAt(Instant updatedAt) { this.updatedAt = updatedAt; }
    void setUpdatedSvcId(String updatedSvcId) { this.updatedSvcId = updatedSvcId; }
    void setUpdatedPgmId(String updatedPgmId) { this.updatedPgmId = updatedPgmId; }
    void setVersion(Long version) { this.version = version; }
}
```

**설계 결정:**
- `@MappedSuperclass` — 독립 테이블 없이 하위 엔티티에 컬럼 포함
- `@EntityListeners(CactusAuditListener.class)` — 리스너 자동 등록
- Setter를 **패키지 접근**으로 제한 — 비즈니스 코드에서 직접 수정 방지
- DB 컬럼명은 dmes-ref와 호환 유지 (C_USR_ID, C_AT, U_USR_ID, U_AT, VER)
- Java 필드명은 camelCase 가독성 (createdBy, createdAt, updatedBy, updatedAt)

### 5.3 CactusAuditListener

JPA `@PrePersist`/`@PreUpdate`에서 감사 컬럼을 자동 세팅하는 리스너.

```java
package com.dongkuk.cactus.audit;

import com.dongkuk.oasis.audit.AuditHolder;
import jakarta.persistence.PrePersist;
import jakarta.persistence.PreUpdate;
import java.time.Instant;

/**
 * CactusAuditEntity의 감사 컬럼을 자동으로 채우는 JPA EntityListener.
 *
 * <p>동작 원리:
 * <ol>
 *   <li>OasisServiceExecutor가 요청 시작 시 AuditHolder에 CactusAudit 저장</li>
 *   <li>JPA persist/update 시 이 리스너가 자동 호출</li>
 *   <li>AuditHolder에서 CactusAudit를 꺼내 감사 컬럼에 값 세팅</li>
 * </ol>
 */
public class CactusAuditListener {

    /**
     * INSERT 시 생성/수정 감사 컬럼을 모두 채운다.
     */
    @PrePersist
    public void onPrePersist(CactusAuditEntity entity) {
        Instant now = Instant.now();
        entity.setCreatedAt(now);
        entity.setUpdatedAt(now);

        CactusAudit audit = AuditHolder.getAudit();
        if (audit != null) {
            entity.setCreatedBy(audit.userId());
            entity.setUpdatedBy(audit.userId());
            entity.setCreatedSvcId(audit.serviceId());
            entity.setUpdatedSvcId(audit.serviceId());
            entity.setCreatedPgmId(audit.menuId());
            entity.setUpdatedPgmId(audit.menuId());
        }

        entity.setVersion(0L);
    }

    /**
     * UPDATE 시 수정 감사 컬럼만 갱신한다.
     */
    @PreUpdate
    public void onPreUpdate(CactusAuditEntity entity) {
        entity.setUpdatedAt(Instant.now());

        CactusAudit audit = AuditHolder.getAudit();
        if (audit != null) {
            entity.setUpdatedBy(audit.userId());
            entity.setUpdatedSvcId(audit.serviceId());
            entity.setUpdatedPgmId(audit.menuId());
        }

        Long ver = entity.getVersion();
        entity.setVersion(ver == null ? 0L : ver + 1);
    }
}
```

### 5.4 OasisServiceExecutor 수정

기존 코드에 `AuditHolder.setAudit()` 호출을 추가한다.

```java
    } catch (...) {
        // ... 기존 예외 처리 그대로 ...
```

### 5.5 CactusMybatisAuditInterceptor

MyBatis INSERT/UPDATE 실행 시 파라미터 Map에 감사 값을 자동 주입하는 인터셉터.

#### 5.5.1 dmes-ref MybatisAudit 문제점

```java
// dmes-ref — 버그 및 한계점
FilmAudit audit = AuditHolder.getAudit();
if (audit != null) {
    map.put("userId", audit.getClass());  // ❌ 버그: getClass()가 아니라 getUserId()
}
// 감사 컬럼 9개 중 timestamp, userId 2개만 처리
// else 분기 (비-Map 파라미터)에서 아무 동작 안 함
```

**cactus-core에서 개선할 점:**
1. `audit.getClass()` 버그 수정
2. 감사 컬럼 9개 전체를 Map에 주입
3. 비-Map 파라미터도 안전하게 처리 (무시하되 예외 발생시키지 않음)
4. INSERT/UPDATE 구분하여 INSERT 시에만 생성 컬럼(C_*) 주입

#### 5.5.2 MyBatis SQL에서의 감사 컬럼 바인딩 규약

인터셉터가 파라미터 Map에 주입하는 키 이름과 SQL에서 사용할 바인딩 변수:

| Map 키 | 값 | INSERT | UPDATE | SQL 바인딩 |
|--------|---|--------|--------|-----------|
| `cUsrId` | userId | ✅ | — | `#{cUsrId}` |
| `cAt` | Instant.now() | ✅ | — | `#{cAt}` |
| `cSvcId` | serviceId | ✅ | — | `#{cSvcId}` |
| `cPgmId` | menuId | ✅ | — | `#{cPgmId}` |
| `uUsrId` | userId | ✅ | ✅ | `#{uUsrId}` |
| `uAt` | Instant.now() | ✅ | ✅ | `#{uAt}` |
| `uSvcId` | serviceId | ✅ | ✅ | `#{uSvcId}` |
| `uPgmId` | menuId | ✅ | ✅ | `#{uPgmId}` |

> `VER`(버전)은 비즈니스 로직에서 낙관적 락과 함께 관리해야 하므로 인터셉터에서 주입하지 않는다.

#### 5.5.3 구현 코드

```java
package com.dongkuk.cactus.audit;

import com.dongkuk.oasis.audit.AuditHolder;
import org.apache.ibatis.executor.Executor;
import org.apache.ibatis.mapping.MappedStatement;
import org.apache.ibatis.mapping.SqlCommandType;
import org.apache.ibatis.plugin.Interceptor;
import org.apache.ibatis.plugin.Intercepts;
import org.apache.ibatis.plugin.Invocation;
import org.apache.ibatis.plugin.Signature;

import java.time.Instant;
import java.util.Map;

/**
 * MyBatis INSERT/UPDATE 실행 시 파라미터 Map에 감사 값을 자동 주입하는 인터셉터.
 *
 * <p>동작 조건:
 * <ul>
 *   <li>SqlCommandType이 INSERT 또는 UPDATE일 때만 동작</li>
 *   <li>파라미터가 Map 타입일 때만 값을 주입 (비-Map은 무시)</li>
 *   <li>AuditHolder에 CactusAudit가 설정되어 있을 때만 사용자/서비스 정보 주입</li>
 * </ul>
 *
 * <p>Mapper XML 사용 예:
 * <pre>{@code
 * <insert id="insertProduct">
 *   INSERT INTO TB_PRODUCT (PRODUCT_ID, PRODUCT_NAME, C_USR_ID, C_AT, C_SVC_ID, C_PGM_ID,
 *                           U_USR_ID, U_AT, U_SVC_ID, U_PGM_ID)
 *   VALUES (#{productId}, #{productName}, #{cUsrId}, #{cAt}, #{cSvcId}, #{cPgmId},
 *           #{uUsrId}, #{uAt}, #{uSvcId}, #{uPgmId})
 * </insert>
 * }</pre>
 */
@Intercepts({
    @Signature(type = Executor.class, method = "update", args = {MappedStatement.class, Object.class})
})
public class CactusMybatisAuditInterceptor implements Interceptor {

    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        MappedStatement ms = (MappedStatement) invocation.getArgs()[0];
        SqlCommandType commandType = ms.getSqlCommandType();
        Object param = invocation.getArgs()[1];

        if (param instanceof Map && (commandType == SqlCommandType.INSERT || commandType == SqlCommandType.UPDATE)) {
            @SuppressWarnings("unchecked")
            Map<String, Object> map = (Map<String, Object>) param;
            Instant now = Instant.now();

            CactusAudit audit = AuditHolder.getAudit();
            String userId = audit != null ? audit.userId() : null;
            String serviceId = audit != null ? audit.serviceId() : null;
            String menuId = audit != null ? audit.menuId() : null;

            // INSERT: 생성 + 수정 컬럼 모두 주입
            if (commandType == SqlCommandType.INSERT) {
                map.put("cUsrId", userId);
                map.put("cAt", now);
                map.put("cSvcId", serviceId);
                map.put("cPgmId", menuId);
            }

            // INSERT & UPDATE: 수정 컬럼 주입
            map.put("uUsrId", userId);
            map.put("uAt", now);
            map.put("uSvcId", serviceId);
            map.put("uPgmId", menuId);
        }

        return invocation.proceed();
    }
}
```

**dmes-ref 대비 개선사항:**
- `audit.getClass()` 버그 제거 → `audit.userId()` 사용
- 감사 컬럼 8개 전체 주입 (dmes-ref는 2개만)
- INSERT/UPDATE 구분하여 생성 컬럼(C_*) 중복 덮어쓰기 방지
- 비-Map 파라미터 시 예외 없이 통과 (`NoSuchFieldException` 제거)
- `Plugin.wrap()` / `setProperties()` 불필요 오버라이드 제거 (Interceptor 디폴트 메서드 활용)

#### 5.5.4 Auto-Configuration으로 자동 등록

프로젝트에서 MyBatis `SqlSessionFactory`를 구성할 때 인터셉터를 수동 등록해야 하는 dmes-ref와 달리,
cactus-core는 Auto-Configuration으로 자동 등록한다 (5.6절 참조).

### 5.6 Auto-Configuration

감사 기능을 classpath 조건에 따라 선택적으로 활성화한다.

```java
package com.dongkuk.cactus.audit;

import org.apache.ibatis.session.SqlSessionFactory;
import org.springframework.boot.autoconfigure.condition.ConditionalOnBean;
import org.springframework.boot.autoconfigure.condition.ConditionalOnClass;
import org.springframework.context.annotation.Configuration;

/**
 * 감사 기능 Auto-Configuration.
 *
 * <p>JPA: CactusAuditEntity에 @EntityListeners가 직접 선언되어 있으므로 별도 설정 불필요.
 * <p>MyBatis: SqlSessionFactory가 존재하면 CactusMybatisAuditInterceptor를 자동 등록.
 */
@Configuration
public class AuditAutoConfiguration {

    /**
     * MyBatis가 classpath에 있고 SqlSessionFactory 빈이 존재할 때
     * CactusMybatisAuditInterceptor를 자동 등록한다.
     */
    @Configuration
    @ConditionalOnClass(SqlSessionFactory.class)
    @ConditionalOnBean(SqlSessionFactory.class)
    static class MybatisAuditAutoConfiguration {

        MybatisAuditAutoConfiguration(SqlSessionFactory sqlSessionFactory) {
            sqlSessionFactory.getConfiguration()
                    .addInterceptor(new CactusMybatisAuditInterceptor());
        }
    }
}
```

**동작 방식:**
- **JPA만 사용하는 프로젝트**: `CactusAuditEntity` + `CactusAuditListener`만 동작 (MyBatis 관련 빈 없으므로 인터셉터 미등록)
- **MyBatis만 사용하는 프로젝트**: `CactusMybatisAuditInterceptor`만 자동 등록
- **JPA + MyBatis 모두 사용하는 프로젝트**: 둘 다 동작

### 7.1 공통 구간 (JPA/MyBatis 동일)

```

    │ ★ AuditHolder.setAudit(new CactusAudit("user01", "PROD001", "ProductService"))
    ▼
[OASIS BPMN 서비스 실행]
```

## 8. dmes-ref와의 차이점

| 항목 | dmes-ref | cactus-core |
|------|----------|-------------|
| Audit 구현체 | `FilmAudit(userId, programId, serviceId)` | `CactusAudit(userId, menuId, serviceId)` — Record |
| programId / menuId | programId (Base64 헤더) | menuId (CactusRequest.meta) → C/U_PGM_ID에 저장 |
| 감사 컬럼 | 9개 | 9개 (dmes-ref와 동일 — DB 호환) |
| AuditHolder 설정 위치 | ServiceController에서 직접 | OasisServiceExecutor에서 자동 |
| userId 소스 | Authorization 헤더 (Base64 JSON) | UserContextHolder (JWT에서 추출) |
| JPA 네임스페이스 | javax.persistence | jakarta.persistence |
| 필드 접근 제어 | @Setter (Lombok, public) | 패키지 접근 setter (외부 수정 방지) |
| MyBatis 감사 | MybatisAudit (Interceptor, 버그 있음, 2개 컬럼만) | CactusMybatisAuditInterceptor (8개 컬럼, INSERT/UPDATE 구분, Auto-Config) |
| 엔티티 중복 | 3개 모듈에 복사 | cactus-core 1곳에서 제공 |
