# OASIS 표준 데이터 포맷 스펙

> 버전: 1.0.0
> 일시: 2026-03-23
> 상태: Draft

---

## 용어 정의

본 문서에서 사용하는 키워드의 의미는 다음과 같다.

- **MUST** (필수): 반드시 준수해야 한다.
- **SHOULD** (권장): 특별한 사유가 없으면 준수한다.
- **MAY** (선택): 필요에 따라 사용할 수 있다.

---

## 1. 프로토콜 규칙

| 항목 | 규칙 |
|------|------|
| 전송 형식 | JSON (`application/json`) |
| 문자 인코딩 | UTF-8 |
| 날짜 형식 | `yyyy-MM-dd` (예: `"2026-03-15"`) |
| 일시 형식 | `yyyy-MM-ddTHH:mm:ss` ISO 8601 (예: `"2026-03-15T09:30:00"`). Jackson/JavaScript 기본 호환. |
| 타임존 | 서버/DB 표준 타임존은 `Asia/Seoul`로 고정. datetime은 서버 기준 로컬 시간으로 처리한다. |
| NULL 처리 | 문자열: `""` 허용. 숫자/날짜/불린: `null` 허용 (MUST). 상세는 5장 참조 |
| 코드성 값 | 상태, 유형, 구분자 등 코드성 값은 문자열로 전달한다 (MUST). 값 형식(숫자코드 `"10"` 또는 Enum name `"ACTIVE"`)은 업무별로 정의한다. 예: `"status": "10"`, `"status": "ACTIVE"` |
| HTTP Method | 화면 API는 원칙적으로 `POST` 사용. 단순 조회성 API는 `GET` 허용 (SHOULD) |
| GET 요청 | `GET` API에서는 `CactusRequest` body를 사용하지 않고 query parameter를 사용한다. `CactusRequest`/`CactusResponse` 포맷은 `POST` 기반 화면 API에 적용한다. `GET` API의 응답은 `ApiResponse<T>`를 사용한다. |
| 인증 토큰 | HTTP Header `Authorization: Bearer {token}` (JSON body에 포함하지 않음) |

## 자료구조 레퍼런스 (Quick Reference)

### CactusRequest

```jsonc
{
  "meta": {                           // object (MUST)
    "userId":    string,              //   (MAY)
    "menuId":    string               //   (MUST)
  },
  "params": {                         // object (MAY) — flat key-value, 중첩 object 금지
    "<key>":     string | integer | float | boolean | string[]
  },
  "grids": {                          // object (MAY)
    "<gridId>": {
      "rows": [                       //   array<object> (MUST)
        {
          "rowKey":    string,        //     (MUST) — 행 고유 ID
          "rowStatus": string,        //     (MUST) — "C" | "U" | "D" | "R"
          "<field>":   string | integer | float | boolean | null
        }
      ]
    }
  }
}
```

### CactusResponse — 성공

```jsonc
{
  "meta": {                           // object (MUST)
    "txId":    string,                //   (MUST) — 요청 추적 ID
    "success": boolean,               //   (MUST)
    "code":    string,                //   (MUST) — 결과 코드
    "message": string                 //   (MAY)
  },
  "data": {                           // object (MAY)
    "<key>":   string | integer | float | boolean
  },
  "grids": {                          // object (MAY)
    "<gridId>": {
      "columns": [                    //   array<ColumnMeta> (MAY) — 그리드 개인화용
        {
          "name":     string,         //     (MUST) — rows의 key와 일치
          "width":    integer,        //     (MAY) — 컬럼 너비 (px)
          "hidden":   boolean,        //     (MAY) — 숨김 여부
          "align":    string,         //     (MAY) — "left"|"center"|"right"
          "order":    integer         //     (MAY) — 컬럼 표시 순서 (0-based)
        }
      ],
      "rows": [                       //   array<object> (MUST)
        {
          "<field>": string | integer | float | boolean | null
        }
      ]
    }
  }
}
```

### CactusResponse — 에러

```jsonc
{
  "meta": {                           // object (MUST)
    "txId":    string,                //   (MUST)
    "success": boolean,               //   (MUST) — false
    "code":    string,                //   (MUST) — 에러 코드
    "message": string                 //   (MAY)
  },
  "errors": [                         // array<ErrorDetail> (MAY)
    {
      "grid":     string,             //   (MAY) — 에러 그리드. 생략 시 공통 에러
      "rowKey":   string,             //   (MAY) — 에러 행 식별
      "rowIndex": integer,            //   (MAY) — 보조 식별자 (0-based)
      "field":    string,             //   (MAY) — 에러 필드. 생략 시 행 전체 에러
      "code":     string,             //   (MUST)
      "message":  string              //   (MUST)
    }
  ]
}
```

### 타입 요약

| JSON 타입 | 표기 | 빈값 |
|-----------|------|------|
| `string` | 문자열 | `""` |
| `integer` | 정수 | `null` |
| `float` | 실수 | `null` |
| `boolean` | 불린 | `null` |
| `string[]` | 문자열 배열 | `[]` |
| `array<object>` | 객체 배열 | `[]` |
| `object` | 객체 | 키 생략 |

## 2. CactusRequest 스펙

### 2.1 최상위 구조

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `meta` | `RequestMeta` | MUST | 요청 메타 정보 |
| `params` | `object` | MAY | 조회 조건, 단건 파라미터. flat key-value |
| `grids` | `Record<string, GridData>` | MAY | 그리드 데이터. key는 그리드 식별자 |

**생략 vs 빈값 규칙:**

- `params`, `grids`는 해당 데이터가 없으면 **키 자체를 생략**한다 (SHOULD). 빈 객체 `{}`도 허용하지만, 생략을 우선한다.
- `grids` 내 특정 그리드를 포함하는 경우, 해당 그리드의 `rows`는 반드시 배열이며 데이터가 없으면 `[]`을 사용한다 (MUST).
- 프론트는 `undefined`와 빈 객체/빈 배열을 모두 처리할 수 있어야 한다.

```json
{
  "meta": {
    "userId": "user01",
    "menuId": "SC001"
  },
  "params": {
    "plantCd": "P01",
    "fromDate": "2026-03-01"
  },
  "grids": {
    "master": {
      "rows": [
        { "rowKey": "tmp-a1b2", "rowStatus": "C", "itemCd": "ITEM-001", "qty": 100 }
      ]
    }
  }
}
```

### 2.2 RequestMeta

| 필드 | 타입 | 필수 | 제약조건 | 설명 |
|------|------|------|----------|------|
| `userId` | string | MAY | | 요청 사용자 ID. 감사 로그/화면 표시 등 컨텍스트 용도. 인증 및 권한 판정은 반드시 `Authorization` 토큰 기준으로 수행한다. |
| `menuId` | string | MUST | 비어있으면 안 됨 | 메뉴/화면 ID. 권한 체크에 활용한다. |

### 2.3 params

- 조회 조건 또는 단건 파라미터를 flat key-value로 전달한다.
- value 타입은 `string`, `number`, `boolean`, `array` 모두 허용한다.
- **1-depth flat object**가 원칙이다. 배열은 허용하지만, 중첩 object는 사용하지 않는다 (MUST).
- 문자열 필드: 값이 없으면 `""` 또는 키 생략 (MUST).
- 숫자/날짜/불린 필드: 값이 없으면 `null` 허용 (MUST).
- 서비스별 params 스키마가 정의된 경우 DTO로 변환하여 검증할 수 있다 (MAY).

```json
// O — flat key-value + 배열
{ "plantCd": "P01", "statusList": ["10", "20"], "page": 1 }

// X — 중첩 object 금지
{ "filter": { "plantCd": "P01", "status": "10" } }
```

### 2.4 GridData

| 필드 | 타입 | 필수 | 제약조건 | 설명 |
|------|------|------|----------|------|
| `rows` | `array<object>` | MUST | 빈 배열 허용 | 그리드 행 데이터 배열 |

**rows 내 각 행 규칙:**

- 저장 요청 시 각 행은 `rowStatus` 필드를 MUST 포함한다.
- 저장 요청 시 각 행은 `rowKey` 필드를 MUST 포함한다. 프론트에서 UUID 등으로 생성한 행 고유 식별자이며, 에러 응답 및 부분 성공 결과 매핑에 사용한다.
- 조회 응답의 행에는 `rowStatus`가 포함되지 않는다.
- 변경되지 않은 행은 전송하지 않는다 (SHOULD).

### 2.5 rowStatus

저장/삭제 요청 시 각 행의 변경 상태를 나타낸다.

| 값 | 의미 | 백엔드 처리 | 설명 |
|----|------|-------------|------|
| `C` | Create | INSERT | 신규 행. 서버에서 PK 채번 |
| `U` | Update | UPDATE | 수정된 행. PK MUST 포함 |
| `D` | Delete | DELETE | 삭제 대상 행. PK MUST 포함 |
| `R` | Read | 없음 | 일반 저장에서는 사용하지 않는다. 전체행 검증, 부모-자식 동시 저장 시 참조행 전달 등 특수한 경우에만 MAY |

**rowStatus별 필수 필드 요약:**

| rowStatus | rowKey | PK (orderId 등) | 업무 필드 | 설명 |
|-----------|--------|-----------------|----------|------|
| `C` | MUST | 불필요 (서버 채번) | MUST | 신규 행 |
| `U` | MUST | MUST | 변경 필드만 | 수정 행 |
| `D` | MUST | MUST | 불필요 | 삭제 행 |
| `R` | MUST | 상황별 | 상황별 | 특수 용도만 |

## 3. CactusResponse 스펙

### 3.1 최상위 구조

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `meta` | `ResponseMeta` | MUST | 응답 메타 정보 |
| `data` | `object` | MAY | 단건 결과, 처리 건수 등 |
| `grids` | `Record<string, GridResult>` | MAY | 그리드 결과 데이터 |
| `errors` | `array<ErrorDetail>` | MAY | 에러 상세 목록. `meta.success`가 `false`일 때 사용 |

**생략 vs 빈값 규칙:**

- `data`, `grids`, `errors`는 해당 데이터가 없으면 **키 자체를 생략**한다 (SHOULD).
- `grids` 내 특정 그리드를 포함하는 경우, 해당 그리드의 `rows`는 반드시 배열이며 데이터가 없으면 `[]`을 사용한다 (MUST).
- `errors`는 `meta.success`가 `true`이면 생략한다.

### 3.2 ResponseMeta

| 필드 | 타입 | 필수 | 제약조건 | 설명 |
|------|------|------|----------|------|
| `txId` | string | MUST | 백엔드에서 생성 | 요청 추적 ID. 형식: `{userId}-{menuId}-{yyyyMMddHHmmss}-{random3}`. 3자리 랜덤 suffix로 충돌 가능성을 최소화한다. 매 요청마다 백엔드에서 생성하여 응답에 포함한다. 예: `user01-PROD001-20260323153000-a7f` |
| `success` | boolean | MUST | `true` / `false` | 처리 성공 여부 |
| `code` | string | MUST | 코드 체계 참조 | 결과 코드 |
| `message` | string | MAY | | 사용자에게 표시할 메시지. 성공 시 생략하거나 빈문자열 사용. 사용자 안내가 필요한 경우에만 의미 있는 메시지를 포함한다. |

### 3.3 GridResult

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `columns` | `array<ColumnMeta>` | MAY | 컬럼 개인화 정보. 사용자별 그리드 개인화 시에만 사용 |
| `rows` | `array<object>` | MUST | 행 데이터 배열 |

### 3.4 ColumnMeta (optional)

> 컬럼의 데이터 타입(`type`), 편집 가능 여부(`editable`), 포맷(`format`), 필수 여부(`required`), 선택 목록(`options`) 등은 **프론트엔드 화면 정의(정적 설정)**에서 관리한다.
> 서버에서 `columns`를 내려주는 것은 **사용자별 그리드 개인화**(컬럼 너비, 순서, 숨김, 정렬)가 필요한 경우에만 사용한다.

| 필드 | 타입 | 필수 | 제약조건 | 설명 |
|------|------|------|----------|------|
| `name` | string | MUST | rows의 key와 일치 | 필드명 (개인화 대상 컬럼 식별) |
| `width` | number | MAY | 양수 | 컬럼 너비 (px) |
| `hidden` | boolean | MAY | 기본값 `false` | 숨김 여부 |
| `align` | string | MAY | `left` `center` `right` 중 하나 | 정렬 |
| `order` | number | MAY | 0-based | 컬럼 표시 순서 |

### 3.5 ErrorDetail

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `grid` | string | MAY | 에러가 발생한 그리드명. 생략 시 공통 에러 |
| `rowKey` | string | MAY | 프론트에서 부여한 행 고유 키. rowIndex보다 안정적인 행 식별자. 프론트 정렬/필터링 후에도 정확한 행 매핑이 가능하다. |
| `rowIndex` | number | MAY | 에러 행 인덱스 (0-based). 보조 식별자. rowKey가 있으면 rowKey 우선 |
| `field` | string | MAY | 에러 필드명. 생략 시 행 전체 에러 |
| `code` | string | MUST | 에러 코드 |
| `message` | string | MUST | 에러 메시지 |

**rowKey echo-back 규칙:**

- 서버는 에러 응답 시 요청에 포함된 `rowKey`를 그대로 반환한다 (MUST).
- 프론트는 응답의 `rowKey`로 원래 요청 행을 매핑하여 에러를 표시한다.
- 향후 부분 성공/채번 결과 확장 시에도 `rowKey`를 기준으로 행을 식별한다.

## 4. HTTP 상태코드

HTTP 상태코드와 `meta.success`를 병행한다. 프론트는 HTTP 상태코드로 1차 분기하고, 상세 에러는 `meta.code` + `errors[]`로 처리한다.

| 상황 | HTTP | meta.success | meta.code | 설명 |
|------|------|----------------|-------------|------|
| 정상 | 200 | `true` | `"0000"` | 처리 성공 |
| 비즈니스 에러 | 400 | `false` | `"E0xx"` | 유효성 검증 실패, 비즈니스 규칙 위반 |
| 인증 실패 | 401 | `false` | `"A0xx"` | 토큰 만료, 로그인 필요 |
| 권한 없음 | 403 | `false` | `"A0xx"` | 접근 권한 없음 |
| 서버 에러 | 500 | `false` | `"S0xx"` | 시스템 오류 |

### 4.1 결과 코드 체계

| 접두사 | 범위 | 분류 | 예시 |
|--------|------|------|------|
| `0` | `0000` | 성공 | `0000` 정상 처리 |
| `E` | `E001` ~ `E999` | 비즈니스 에러 | `E001` 필수값 누락, `E002` 유효하지 않은 값, `E003` 중복 데이터 |
| `A` | `A001` ~ `A999` | 인증/권한 에러 | `A001` 인증 실패, `A003` 권한 없음, `A008` 토큰 만료 |
| `S` | `S001` ~ `S999` | 시스템 에러 | `S001` 서버 내부 오류, `S002` DB 연결 실패, `S999` 알 수 없는 오류 |

## 5. NULL 처리 규칙

타입별로 빈값 표현 방식을 구분한다 (MUST).

| 타입 | 빈값 표현 | 예시 |
|------|----------|------|
| 문자열 (string) | `""` (빈문자열) | `"itemCd": ""` |
| 숫자 (number/integer) | `null` | `"qty": null` |
| 날짜 (date/datetime) | `null` | `"dueDate": null` |
| 불린 (boolean) | `null` | `"useYn": null` |

```json
// O — 올바른 표현
{ "orderId": "", "itemCd": "ITEM-001", "qty": null, "dueDate": null, "useYn": null }

// X — 숫자에 빈문자열 사용 금지
{ "orderId": "", "itemCd": "ITEM-001", "qty": "", "dueDate": "", "useYn": "" }
```

- 문자열은 `""` 사용. `null` 사용하지 않는다.
- 숫자/날짜/불린은 `null` 사용. `""` 사용하지 않는다.
- DTO 변환 시 프레임워크가 `"" → null` 정규화를 자동 수행한다 (숫자/날짜/불린 필드 대상).

**MUST vs MAY 필드의 null 허용 규칙:**

| 필수 여부 | string | integer / float | date / datetime | boolean |
|-----------|--------|-----------------|-----------------|---------|
| **MUST** | `""` 허용, `null` 금지 | `null` 금지 (값 필수) | `null` 금지 (값 필수) | `true` / `false` 만 허용, `null` 금지 |
| **MAY** | `""` 또는 키 생략 | `null` 또는 키 생략 | `null` 또는 키 생략 | `true` / `false` / `null` 또는 키 생략 |

## 6. 액션별 포맷 규격

> 구조(껍데기)는 동일하되, 액션에 따라 채우는 영역이 달라진다.
> 액션 구분은 URL 패턴으로 하며, 별도 action 필드는 두지 않는다.
> 화면형 API는 기본적으로 `POST`를 사용하되, 단순 조회성 REST API(공통코드 등)는 별도로 `GET`을 사용할 수 있다.
> URL 패턴은 자유롭게 정의할 수 있다. 아래 표준 액션 외에 업무별 커스텀 액션도 허용한다.

### 6.1 표준 액션

| 액션 | URL 패턴 | Request 구성 | Response 구성 | HTTP |
|------|----------|-------------|---------------|------|
| 조회 | `/search` | `meta` + `params` | `meta` + `data` + `grids` | 200 |
| 저장 (CUD) | `/save` | `meta` + `params` + `grids` | `meta` + `data` | 200 / 400 |
| 삭제 전용 | `/delete` | `meta` + `grids` | `meta` + `data` | 200 / 400 |
| 단건 상세 | `/detail` | `meta` + `params` | `meta` + `data` + `grids` (MAY) | 200 |
| 에러 (공통) | - | - | `meta` + `errors[]` | 400 / 401 / 403 / 500 |

### 6.2 커스텀 액션

표준 액션(`search`, `save`, `delete`, `detail`)으로 표현할 수 없는 업무 액션은 자유롭게 정의할 수 있다.

| 예시 | URL 패턴 | Request 구성 | Response 구성 | 설명 |
|------|----------|-------------|---------------|------|
| 실행 | `/execute` | `meta` + `params` | `meta` + `data` | 스케줄링 실행, 계획 실행 등 |
| 확정 | `/confirm` | `meta` + `params` + `grids` (MAY) | `meta` + `data` | 수주 확정 (다건 ID 전달 시 grids 사용) |
| 취소 | `/cancel` | `meta` + `params` | `meta` + `data` | 주문 취소 등 |
| 승인 | `/approve` | `meta` + `params` + `grids` (MAY) | `meta` + `data` | 결재 승인 |
| 반려 | `/reject` | `meta` + `params` | `meta` + `data` | 결재 반려 |

**커스텀 액션 규칙:**

- Request/Response 구조는 `CactusRequest`/`CactusResponse`를 그대로 사용한다 (MUST).
- Request는 `meta` + `params`가 기본이며, 다건 처리가 필요하면 `grids`를 사용할 수 있다 (MAY). Response는 `meta` + `data`가 기본이다.
- 에러 응답은 표준 에러 구조(`meta` + `errors[]`)를 따른다 (MUST).
- 액션 이름은 소문자 영문, 동사형을 권장한다 (SHOULD). 예: `execute`, `confirm`, `cancel`

### 6.3 조회 (Search)

그리드 목록을 조회한다. 페이징이 필요하면 `params`에 포함한다.

```json
// --- Request ---
{
  "meta": { "userId": "user01", "menuId": "PROD001" },
  "params": {
    "plantCd": "P01",
    "fromDate": "2026-03-01",
    "toDate": "2026-03-20",

    "size": 50
  }
}

// --- Response (200) ---
{
  "meta": { "txId": "user01-PROD001-20260323153000-a7f", "success": true, "code": "0000", "message": "" },
  "data": {
    "page": 1,
    "size": 50,
    "totalCount": 1500,
    "totalPages": 30,
    "first": true,
    "last": false
  },
  "grids": {

      "rows": [ { "orderId": "ORD-001", "itemCd": "ITEM-001", "qty": 100 }, ... ]
    }
```

### 6.4 저장 (Save)

변경된 행만 `rowStatus`와 함께 전송한다. 각 행은 `rowKey`를 MUST 포함한다. 응답은 처리 건수만 반환하고, 프론트에서 필요 시 재조회한다. 필요 시 `data`에 `createdKeys[]`, `results[]` 등을 확장하여 행별 처리 결과(채번 PK, 부분 성공/실패 등)를 반환할 수 있다 (MAY).

```json
// --- Request ---
{
  "meta": { "userId": "user01", "menuId": "PROD001" },
  "params": { "plantCd": "P01" },
  "grids": {
    "master": {
      "rows": [
        { "rowKey": "tmp-a1b2", "rowStatus": "C", "orderId": "", "itemCd": "ITEM-004", "qty": 300 },
        { "rowKey": "tmp-c3d4", "rowStatus": "U", "orderId": "ORD-001", "itemCd": "ITEM-001", "qty": 120 },
        { "rowKey": "tmp-e5f6", "rowStatus": "D", "orderId": "ORD-003", "itemCd": "ITEM-003", "qty": 150 }
      ]
    }
  }
}

// --- Response (200) ---
{
  "meta": { "txId": "user01-PROD001-20260323153000-a7f", "success": true, "code": "0000", "message": "정상 처리되었습니다." },
  "data": { "savedCount": 3 }
}

// --- Response (400) ---
{
  "meta": { "txId": "user01-PROD001-20260323153000-a7f", "success": false, "code": "E001", "message": "저장 중 오류가 발생했습니다." },
  "errors": [
    { "grid": "master", "rowKey": "tmp-a1b2", "rowIndex": 0, "field": "itemCd", "code": "E001", "message": "존재하지 않는 품목코드입니다." }
  ]
}
```

### 6.5 단건 폼 저장 (Form Save)

그리드가 아닌 폼 기반 단건 CUD는 `params`로 처리할 수 있다. `grids`를 사용하지 않으며, `params`에 `rowStatus`를 포함한다.

```json
// --- Request (생성) ---
{
  "meta": { "userId": "user01", "menuId": "PLANT001" },
  "params": {
    "rowStatus": "C",
    "plantId": "P01",
    "plantName": "서울공장",
    "siteType": "MANUFACTURING",
    "status": "ACTIVE"
  }
}

// --- Request (수정) ---
{
  "meta": { "userId": "user01", "menuId": "PLANT001" },
  "params": {
    "rowStatus": "U",
    "plantId": "P01",
    "plantName": "서울공장 (이름변경)"
  }
}

// --- Response (200) ---
{
  "meta": { "txId": "user01-PLANT001-20260323153000-b2c", "success": true, "code": "0000", "message": "정상 처리되었습니다." },
  "data": { "plantId": "P01" }
}
```

**에러 응답 예시:**

```json
// --- Response (400) — 단건 폼 저장 에러 ---
{
  "meta": { "txId": "user01-PLANT001-20260323153000-b2c", "success": false, "code": "E001", "message": "저장 중 오류가 발생했습니다." },
  "errors": [
    { "field": "plantId", "code": "E003", "message": "이미 존재하는 공장코드입니다." },
    { "field": "plantName", "code": "E001", "message": "공장명은 필수입니다." }
  ]
}
```

> 단건 폼 에러는 `grid`, `rowKey`, `rowIndex` 없이 `field` + `code` + `message`만으로 표현한다.

**규칙:**

- 단건 폼 저장 시 `grids`는 사용하지 않는다. `params`에 업무 필드와 `rowStatus`를 함께 전달한다.
- `rowKey`는 단건이므로 불필요하다 (생략 가능).
- 응답은 저장된 PK 또는 처리 결과를 `data`로 반환한다.
- 에러 응답의 `ErrorDetail`에서 `grid`, `rowKey`, `rowIndex`는 생략하고 `field`로 에러 위치를 식별한다.

### 6.6 삭제 전용 (Delete)

선택된 행만 삭제할 때 사용한다. 모든 행의 `rowStatus`는 `D`이다 (MUST).

## 7. 타입 변환 (DTO 매핑)

`CactusRequest`의 `params`와 `grids`는 `Map<String, Object>` 기반이다. 타입 안전한 처리가 필요한 경우 업무 DTO로 변환할 수 있다 (MAY).

### 7.1 사용 방식

프레임워크가 `CactusRequest`에 제네릭 헬퍼 메서드를 제공한다.

```java
// Map으로 직접 사용 (기존 방식 — 항상 가능)
Map<String, Object> params = request.getParams();
String plantCd = (String) params.get("plantCd");

// DTO로 변환 (타입 안전 — 업무 DTO가 정의된 경우)
ProdSearchParams params = request.getParams(ProdSearchParams.class);
List<ProdResultRow> masterRows = request.getGrid("master", ProdResultRow.class);
```

### 7.2 CactusRequest 헬퍼 메서드

| 메서드 | 반환 타입 | 설명 |
|--------|----------|------|
| `getParams()` | `Map<String, Object>` | params를 Map으로 반환 |
| `getParams(Class<T>)` | `T` | params를 지정한 DTO 타입으로 변환하여 반환 |
| `getGrid(String gridId)` | `List<Map<String, Object>>` | 그리드 rows를 Map 리스트로 반환 |
| `getGrid(String gridId, Class<T>)` | `List<T>` | 그리드 rows를 지정한 DTO 타입 리스트로 변환하여 반환 |

### 7.3 업무 DTO 정의 예시

```java
// params용 DTO
public class ProdSearchParams {
    private String plantCd;
    private String fromDate;
    private String toDate;
    private String prodType;
    private Integer page;
    private Integer size;
    // getter/setter
}

// 그리드 행 DTO
public class ProdResultRow {
    private String rowKey;
    private String rowStatus;
    private String orderId;
    private String itemCd;
    private String itemNm;
    private Integer qty;
    private String prodDate;
    private String status;
    // getter/setter
}
```

### 7.4 업무 코드에서의 사용

```java
@PostMapping("/save")
public CactusResponse save(@RequestBody CactusRequest request) {
    // params → DTO
    ProdSearchParams params = request.getParams(ProdSearchParams.class);

    // grids → DTO 리스트
    List<ProdResultRow> masterRows = request.getGrid("master", ProdResultRow.class);
    List<ProdDetailRow> detailRows = request.getGrid("detail", ProdDetailRow.class);

    // rowStatus로 분기
    List<ProdResultRow> inserts = masterRows.stream()
        .filter(r -> "C".equals(r.getRowStatus()))
        .toList();
    List<ProdResultRow> updates = masterRows.stream()
        .filter(r -> "U".equals(r.getRowStatus()))
        .toList();
    List<ProdResultRow> deletes = masterRows.stream()
        .filter(r -> "D".equals(r.getRowStatus()))
        .toList();

    // CUD 처리 ...

    // txId는 프레임워크(TxIdFilter/OasisServiceExecutor)가 자동 생성.
    // 업무 코드에서는 CactusResponse.success()로 응답을 조립한다.
    return CactusResponse.success()
            .param("savedCount", inserts.size() + updates.size() + deletes.size())
            .build();
}
```

### 7.5 규칙

- DTO 정의는 선택 사항이다 (MAY). 정의하지 않으면 Map으로 사용한다.
- DTO 변환 시 매핑되지 않는 필드는 무시한다 (SHOULD).
- DTO 변환 실패 시 `400 Bad Request` + `ErrorDetail`을 반환한다 (MUST).
- 프레임워크 내부적으로 Jackson `ObjectMapper`를 사용하여 `Map` → DTO 변환을 수행한다.

## 8. 설계 결정 사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 액션 구분 방식 | URL 패턴으로 구분 | `grids` 유무로 자연스럽게 판별, 별도 action 필드 불필요 |
| 저장 응답 | `savedCount`만 반환 | 프론트에서 필요 시 재조회. 응답 단순화 |
| 페이징 | `params`에 포함 | 별도 `paging` 영역 없이 구조 단순하게 유지 |
| 단건 조회 | Request는 `params`, Response는 `data`로 처리 | 1건에 grids를 쓰면 과도, 직관적으로 처리 |
| grids 구조 | 배열이 아닌 맵(객체) | `response.grids.master.rows`로 바로 접근. 인덱스 의존 없음 |
| rowStatus | 행 단위 포함 | MES는 다중 행 수정 후 일괄 저장이 기본 패턴 |
| columns | optional | 프론트에서 컬럼 정의가 기본. 사용자별 그리드 개인화(너비/순서/숨김/정렬) 시에만 서버에서 제공 |
| 응답 클래스 | 이원화 | `ApiResponse<T>` (인증 등 단순 REST) + `CactusResponse` (화면 데이터) |
| NULL 처리 | 문자열은 `""`, 숫자/날짜/불린은 `null` | 타입 안정성 확보 및 DTO 변환 안정성. 프레임워크가 `"" → null` 정규화 수행 |
| URL 패턴 | 자유 정의 | 기존 RESTful URL(`/api/plants`)과 신규 화면 API가 공존 가능. 본 명세는 Request/Response 데이터 포맷만 규정하며, URL 체계는 프로젝트별로 정의한다. |

## 9. JSON Schema

> JSON Schema는 공통 구조 검증을 위한 기준이며, 액션별 상세 제약(rowStatus, rowKey MUST 등)은 본문 규칙을 따른다.
> 업무 필드는 화면/서비스별로 달라지므로, `params`와 `rows`의 상세 필드는 공통 Schema에서 고정하지 않고 업무 DTO/서비스 검증으로 보완한다.

```java
public class CactusRequest {

    public List<Map<String, Object>> getGrid(String gridId) { ... }
```

```typescript
interface CactusResponse {
  meta: ResponseMeta;
  data?: Record<string, any>;
  grids?: Record<string, GridResult>;
  errors?: ErrorDetail[];
}

interface ResponseMeta {
  txId: string;
  success: boolean;
  code: string;
  message?: string;
}

interface GridResult {
  columns?: ColumnMeta[];
  rows: Record<string, any>[];
}

interface ColumnMeta {
  name: string;
  width?: number;
  hidden?: boolean;
  align?: 'left' | 'center' | 'right';
  order?: number;
}

interface ErrorDetail {
  grid?: string;
  rowKey?: string;
  rowIndex?: number;
  field?: string;
  code: string;
  message: string;
}
```
