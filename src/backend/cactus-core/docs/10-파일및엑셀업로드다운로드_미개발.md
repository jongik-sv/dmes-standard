# 10. 파일 및 엑셀 업로드/다운로드 (미개발)

> 통합 원본: `04-파일-업로드-다운로드.md`, `new/07-file-handling.md` (`Status: not yet implemented as of 2026-04-26`)
> 구현 상태: **미구현**. cactus-core 에 FileController, ExcelController, FileService 등 관련 클래스 전무.

---

## 1. 설계 의도

- 표준화된 파일·엑셀 업로드/다운로드 엔드포인트 제공
- 그리드 데이터 ↔ 엑셀 양방향 변환 (ColumnMeta 기반)
- 첨부파일 메타 관리 (DB) + 실제 파일 스토리지 (로컬/S3) 분리

---

## 2. 제안 명세

### 2.1 패키지
```
cactus-core/file/
├── FileController.java          # /api/file/upload, /api/file/download/{fileId}
├── FileService.java             # 파일 저장/조회/삭제
├── FileEntity.java              # 첨부파일 메타 (FILE_ID, ORIGINAL_NAME, PATH, SIZE, ...)
├── FileStorage.java             # interface (LocalStorage / S3Storage 구현체)
└── excel/
    ├── ExcelController.java     # /api/excel/import, /api/excel/export
    ├── ExcelService.java
    ├── ExcelImporter.java       # MultipartFile → List<Map<String,Object>>
    ├── ExcelExporter.java       # GridResult (rows + columns) → byte[]
    └── ExcelTemplate.java       # 헤더-라인 spec 기반 템플릿
```

### 2.2 API 예시
```
POST /api/file/upload (multipart/form-data)
GET  /api/file/download/{fileId}
DELETE /api/file/{fileId}

POST /api/excel/import   (multipart) → List<Map> JSON 반환
POST /api/excel/export   (json: rows + columns) → xlsx bytes
```

### 2.3 엑셀 변환 규칙
- ColumnMeta 의 `header`, `key`, `width`, `align`, `type` 활용
- type=number → 숫자 셀, type=date → 날짜 셀
- hidden=true 컬럼은 export 시 제외

---

## 3. 미구현 사유

- 현 단계 모듈(portal, mpp, aps)에서 직접 파일 처리 요건 미발생
- 일부 모듈은 `m-aps` 에 자체 엑셀 인프라 존재 (마스터 헤더-라인 spec 기반) → cactus-core 통합 시 그쪽 패턴 참고
- 구현 우선순위 Phase 3 (`new/09-implementation-roadmap.md`)

---

## 4. 도입 시 고려사항

| 항목 | 설명 |
|---|---|
| 스토리지 추상화 | LocalStorage 우선, S3 등은 인터페이스만 |
| 파일 크기 제한 | Spring `spring.servlet.multipart.max-file-size` |
| 보안 | 업로드 시 MIME 검증, 다운로드 시 권한 체크 (UserContextHolder) |
| 트랜잭션 | DB 메타 저장과 파일 저장의 원자성 (보상 트랜잭션 또는 임시 디렉토리 후 commit) |
| 엑셀 라이브러리 | Apache POI vs FastExcel (메모리 효율) |
| 헤더-라인 spec | m-aps 의 기존 패턴(`HeaderLineSpec`) 차용 검토 |
