# 12. 요청 로그 DB 저장 (미개발)

> 통합 원본: `new/05-web-commons.md` §RequestLoggingFilter (향후 구현 표기)
> 구현 상태: **미구현**. RequestLog 엔티티/서비스/필터 전무. 현재 콘솔 로그(MDC + logback)만 존재.

---

## 1. 설계 의도

- 모든 HTTP 요청/응답을 DB 에 영구 저장 (감사 추적용)
- 운영 사고 발생 시 사후 분석
- 응답시간/에러율 모니터링용 raw 데이터

---

## 2. 제안 명세

### 2.1 패키지
```
cactus-core/web/log/
├── RequestLog.java                # 엔티티 (TB_SYS_REQUEST_LOG)
├── RequestLogRepository.java
├── RequestLogService.java         # 비동기 저장
└── RequestLoggingFilter.java      # 요청/응답 캡처 (ContentCachingRequestWrapper)
```

### 2.2 RequestLog 엔티티
| 컬럼 | 의미 |
|---|---|
| `LOG_ID` | PK (UUID) |
| `TX_ID` | 정식 txId |
| `USER_ID` | 사용자 |
| `MENU_ID` | 메뉴 |
| `SERVICE_ID` | 서비스 |
| `ACTION` | search/save/delete |

| `REQUEST_BODY` | 요청 본문 (TEXT, 압축 옵션) |
| `RESPONSE_BODY` | 응답 본문 (옵션) |
| `STATUS_CODE` | HTTP 상태 |
| `ELAPSED_MS` | 처리 시간 |

| `USER_AGENT` | UA |
| `STARTED_AT` | 시작 시각 |

### 2.3 RequestLoggingFilter
```java
@Order(Ordered.LOWEST_PRECEDENCE)
public class RequestLoggingFilter extends OncePerRequestFilter {
    protected void doFilterInternal(req, res, chain) {
        var wrappedReq = new ContentCachingRequestWrapper(req);
        var wrappedRes = new ContentCachingResponseWrapper(res);
        long start = System.currentTimeMillis();
        chain.doFilter(wrappedReq, wrappedRes);
        long elapsed = System.currentTimeMillis() - start;
        // 비동기로 RequestLogService.save(...)
        wrappedRes.copyBodyToResponse();
    }
}
```

비동기 저장 (`@Async` 또는 별도 큐) 으로 응답 시간 영향 최소화.

---

## 3. 미구현 사유

- 현재 콘솔 로그 + logback 파일 출력으로 운영 대응 가능
- DB 저장 시 스토리지 폭증 (요청 본문 크기) 우려
- 보안: 비밀번호 등 민감 정보 마스킹 정책 필요

---

## 4. 도입 시 고려사항

| 항목 | 설명 |
|---|---|
| 비동기 저장 | `@Async` + 큐 (예: ArrayBlockingQueue) |
| 본문 크기 제한 | `body.length > 1MB` 시 truncate |
| 민감정보 마스킹 | password, token, ssn 등 키워드 필터링 |
| 스토리지 | 별도 DB 또는 파티션 테이블 (월별 파티션) |
| 보존 기간 | 30~90일 후 자동 archive 또는 삭제 |
| 권한 | 로그 조회 화면은 ROLE_ADMIN |

---

## 5. 임시 대안

- logback 으로 파일 저장 + 일자별 rolling
- ELK / Loki 등 외부 로그 인프라 활용
- DB 저장은 도입 후에도 외부 인프라와 병행 권장 (DB는 키 분석용, ELK는 전수 검색용)
