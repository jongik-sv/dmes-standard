## 3. 부분 구현 (개발완료에 흡수, 단 일부 미개발)

| 영역 | 구현된 부분 | 미구현 부분 | 정리본 |
|---|---|---|---|
| ServiceTag 추적 | TxIdFilter (OASIS MDCTemplate 사용), RequestIdFilter, TxIdGenerator. OASIS 측 자동 service_tag 4자리 + 체이닝 | cactus 자체 비즈니스 흐름의 명시 체이닝, 병렬 게이트웨이 자식 스레드 MDC 전파 | 08 |
| MyBatis 인프라 | SqlLoggingInterceptor, CactusMybatisAuditInterceptor (audit 패키지 등록) | 멀티 DS, PaginationInterceptor | 06, 13 |
| BFF Role 검증 | NextAuth + 동적 권한 캐시 + 403 | RS256 미들웨어 + 정적 ROUTE_ROLE_MAP | 17 |
| HTTP 클라이언트 | JwtTokenHolder (전파용 ThreadLocal) | ModuleClient 래퍼, Circuit Breaker | 15 |
| 비밀번호 정책 | SecUser 컬럼 (PASS_SET_DD, PASS_INIT_YN, TRY_CNT, LOCK_YN, USE_YN) | 만료 체크, 이력 비교, 잠금 자동화 | 18 |
| ID 생성기 | TxIdGenerator (트랜잭션 ID 한정) | 엔티티 PK 패턴 생성기, ULID, JSON/File 유틸 | 19 |

## 4. 구현 로드맵 (Phase 별)

### Phase 1 — 완료 (정리본 01~08)
- 데이터 포맷, 패키지, OasisController, JWT, 웹공통, 감사, URL 구조, MDC

### Phase 2 — 검토 단계
- 13 멀티 데이터소스 라우팅 (이미 MyBatis 인프라 일부 구현)
- 11 마스터코드 + LoV (FE 헬퍼는 정의됨)
- 18 비밀번호 정책 (SecUser 컬럼 준비됨)

### Phase 3 — 우선순위 도입 후보
- 10 파일/엑셀 업로드/다운로드 (m-aps 의 자체 구현 활용 가능)
- 15 HTTP 클라이언트 (모듈간 동기 호출 늘어날 시)

### Phase 4 — 트리거 기반 도입
- 17 RSA 비대칭 JWT (외부 노출 / 다중 사업장)
- 14 메시지 EAI / 메일 (비동기 요건)
- 12 요청 로그 DB 저장 (보안 감사)

### Phase 5 — 장기 검토
- 16 Naming 전략 (자동 매핑 vs 명시적 트레이드오프)
- 19 엔티티 ID 생성기 (도메인별 패턴 통합)

## 5. 즉시 적용 가능한 보안 강화 (RSA 도입 없이도)

정리본 17 §6.3 의 4개 권장:
1. `cactus.jwt.secret` 환경변수화
2. Access token 만료 단축 + Refresh rotation
3. `X-User-Id` ↔ JWT subject 교차검증
4. 헤더명 통일 (`X-Authenticated-User/Role` ↔ `X-User-Id/Roles`)
