# 01. 데이터포맷 명세 (개발완료)

> 통합 원본: `01-데이터포맷-명세.md`, `new/02-data-format.md`, `CACTUS_ARCHITECTURE.md §2`
> 구현 상태: **개발완료**. cactus-core/web/request/, cactus-core/web/response/, cactus-core/web/converter/, cactus-core/util/ 패키지에 전체 구현됨.

---

## 1. 표준 요청 포맷 — `CactusRequest`

### 1.1 JSON 구조
```json
{
  "meta":   { "userId": "u1", "menuId": "MPP_WORK_ORDER" },
  "params": { "plantCd": "P1", "status": "READY" },
  "grids":  { "master": { "rows": [ { "rowKey":"...", "rowStatus":"C", ... } ] } }
}
```

### 1.2 클래스
| 클래스 | 위치 | 역할 |
|---|---|---|
| `CactusRequest` | `cactus-core/web/request/CactusRequest.java` | 최상위 요청 DTO. meta/params/grids 보유 |
| `RequestMeta` | `cactus-core/web/request/RequestMeta.java` | record (userId, menuId) |
| `GridData` | `cactus-core/web/request/GridData.java` | rows: List<Map<String,Object>> |
| `RowStatus` | `cactus-core/web/request/RowStatus.java` | enum **C**(Create) / **U**(Update) / **D**(Delete) / **R**(Read) |

### 1.3 동작 규약
- `meta` 는 inputs Map에 포함되지 않는다 (필드 충돌 방지). txId 생성·감사 컬럼 주입 용도.
- `params` 는 OASIS ServiceContext에 키별로 flat 전개된다.
- `grids[gridId]` 는 `gridId: List<Map>` 형태로 BPMN ServiceTask 파라미터에 직접 매핑된다.

---

## 2. 표준 응답 포맷 — `CactusResponse`

### 2.1 JSON 구조
```json
{
  "meta":  { "txId":"...", "success":true, "code":"S001", "message":"OK" },
  "data":  { "savedCount": 3 },
  "grids": { "workOrders": { "rows":[...], "columns":[...] } },
  "errors":[ { "grid":"master", "rowKey":"...", "rowIndex":0, "field":"qty", "code":"E001", "message":"..." } ]
}
```

### 2.2 클래스
| 클래스 | 위치 | 역할 |
|---|---|---|
| `CactusResponse` | `cactus-core/web/response/CactusResponse.java` | Builder 패턴, meta/data/grids/errors |
| `ResponseMeta` | `cactus-core/web/response/ResponseMeta.java` | `success(txId)`, `error(txId, code, msg)` 정적 팩토리 |
| `GridResult` | `cactus-core/web/response/GridResult.java` | rows + columns(`ColumnMeta`) |
| `ColumnMeta` | `cactus-core/web/response/ColumnMeta.java` | width/hidden/align/order |
| `ErrorDetail` | `cactus-core/web/response/ErrorDetail.java` | record. 정적 팩토리 3개: `of(code, msg)`, `ofGrid(grid, rowKey, field, code, msg)` (5-arg), `ofGrid(grid, rowKey, rowIndex, field, code, msg)` (6-arg) |

---

## 3. 변환·유틸

| 클래스 | 위치 | 역할 |
|---|---|---|
| `GridConverter` | `cactus-core/web/converter/GridConverter.java` | Map ↔ DTO 양방향, 빈 문자열 → null 정규화 |
| `TxIdGenerator` | `cactus-core/util/TxIdGenerator.java` | `{userId}-{menuId}-{yyyyMMddHHmmss}-{random3}` 생성 |
| `ApiResponse` | `cactus-core/common/ApiResponse.java` | 제네릭 래퍼 (`ok(T)`, `error(code,msg)`) |

---

## 4. 사용 패턴

### 4.1 BPMN 서비스에서 grid 데이터 받기
BPMN ServiceTask 메서드 시그니처가 `(List<Map<String,Object>> master)` 일 때, `grids.master.rows` 가 자동으로 master 파라미터에 바인딩됨. (예: `WorkOrderService.saveWorkOrders(List<Map<String,Object>> master)`)

### 4.2 에러 응답 생성
```java
List<ErrorDetail> errors = new ArrayList<>();
errors.add(ErrorDetail.ofGrid("master", rowKey, idx, "qty", "E001", "수량은 필수입니다."));
throw new BusinessException(ErrorCode.REQUIRED_VALUE, "입력값을 확인해주세요.", errors);
```
GlobalExceptionHandler 가 ErrorDetail 리스트를 CactusResponse.errors 로 변환.

---

## 5. 미구현/제한 사항

- `ColumnOption` (컬럼 옵션 메타) 은 명시적 미구현. 현재 `ColumnMeta` 기본 4필드만 지원.
- `meta` 의 추가 필드(예: `__meta_userId` prefix 메커니즘) 는 향후 확장 시 도입 예정.
