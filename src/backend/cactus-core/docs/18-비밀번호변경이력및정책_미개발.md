# 18. 비밀번호 변경 이력 및 정책 (미개발)

> 통합 원본: `CACTUS_SECURITY.md` §비밀번호 일부, `new/04-security.md` 향후 항목
> 구현 상태: **미구현** (이력/정책). 단, SecUser 엔티티에 비밀번호 기본 정보 컬럼은 이미 존재.

---

## 1. 설계 의도

- 비밀번호 변경 이력 관리 (재사용 방지)
- 비밀번호 만료 정책 (90일 등)
- 비밀번호 복잡도 검증 (길이/문자종류)
- 잠금 정책 (n회 실패 시 계정 잠금)

---

## 2. 부분 구현 흔적 — SecUser 엔티티

| 컬럼 | 의미 | 활용 |
|---|---|---|
| `USER_PASS` | BCrypt 해시 | 검증 시 PasswordEncoder.matches |
| `PASS_SET_DD` | 비밀번호 설정일 | 만료 체크용 (현재 미사용) |
| `PASS_INIT_YN` | 초기화 필요 여부 | 강제 변경 플래그 (현재 미사용) |
| `TRY_CNT` | 로그인 실패 횟수 | 잠금 정책용 (현재 미사용) |
| `LOCK_YN` | 잠금 여부 | 계정 잠금 (현재 미사용) |

→ 컬럼은 있지만, 실제 만료/잠금/이력 관련 비즈니스 로직은 미구현.

---

## 3. 제안 명세

### 3.1 패키지
```
cactus-core/security/auth/password/
├── SecUserPwd.java                  # 현재 비밀번호 분리 엔티티 (옵션)
├── SecUserPwdHistory.java           # 변경 이력 엔티티
├── PasswordPolicy.java              # 정책 (길이, 만료일, 잠금 임계 등)
├── PasswordPolicyValidator.java     # 복잡도 검증
└── PasswordHistoryService.java      # 이력 저장/재사용 검사
```

### 3.2 SecUserPwdHistory 엔티티
| 컬럼 | 의미 |
|---|---|
| `HIST_ID` | PK |
| `USER_ID` | 사용자 |
| `PASS_HASH` | BCrypt 해시 |
| `CHANGED_AT` | 변경 일시 |
| `CHANGED_BY` | 변경자 (사용자 본인 vs 관리자) |
| `REASON` | 변경 사유 (만료/요청/관리자초기화) |

### 3.3 application.yml
```yaml
cactus:
  security:
    password:
      min-length: 8
      require-special-char: true
      expiry-days: 90
      history-count: 5         # 최근 5개 비밀번호 재사용 금지
      max-fail-attempts: 5     # 5회 실패 시 잠금
      lock-duration-minutes: 30
```

### 3.4 비즈니스 로직
- **로그인 시**: TRY_CNT 증가, 임계 초과 시 LOCK_YN='Y'
- **비밀번호 변경 시**: 최근 N개 이력과 비교, 일치하면 거부
- **만료 체크**: PASS_SET_DD 가 expiry-days 초과 시 강제 변경 화면 redirect
- **PASS_INIT_YN='Y'**: 첫 로그인 시 강제 변경

---

## 4. 미구현 사유

- 현 단계에서 보안 감사 요구 미발생
- 사내 시스템으로 외부 공격 표면 제한적
- SecUser 컬럼은 미리 준비되어 있어, 도입 시 마이그레이션 비용 낮음

---

## 5. 도입 시 고려사항

| 항목 | 설명 |
|---|---|
| 이력 저장 시점 | 비밀번호 변경 시 직전 비밀번호를 history 에 저장 |
| 비교 방식 | BCrypt 는 단방향 → 새 비밀번호의 BCrypt 해시와 history 의 해시 비교 (matches) |
| 만료 처리 | 만료된 토큰은 응답 시 `passwordExpired: true` 플래그 → FE 에서 변경 화면 |
| 강제 변경 화면 | NextAuth 세션 + redirect to `/auth/change-password` |
| 관리자 초기화 | PASS_INIT_YN='Y' + 임시 비밀번호 발급 |
| 정책 변경 | application.yml hot reload 또는 DB 정책 테이블 |

---

## 6. 임시 대안

- 운영 환경에서 사용자에게 주기적 변경을 매뉴얼 안내
- 잠금은 DB 직접 업데이트 (LOCK_YN='Y') 로 수동 처리
- 이력 관리는 도입 시점에 한 번에 마이그레이션
