# sample-migration

레거시 시스템(ERP 등) → 신규 시스템 데이터 이관 스크립트의 **표준 형태 예시**다.

원본 프로젝트의 `data-migration/erp-*` 스크립트 약 20 종이 모두 이 모양을 따랐다.
Gradle 프로젝트가 아니라 **순수 Node 스크립트**이며, 백엔드 모듈들과 나란히 놓이되
composite build 에는 포함되지 않는다.

## 실행

```bash
npm start          # == node index.cjs
```

## 스크립트가 지켜야 할 형태

`index.cjs` 가 보여주는 세 단계를 분리해서 작성한다.

| 단계 | 함수 | 원칙 |
| --- | --- | --- |
| 읽기 | `readSource()` | 소스 DB · 엑셀 접근을 여기에만 가둔다. |
| 변환 | `transform()` | 순수 함수로 두어 단위 검증이 가능하게 한다. 이관 불가 행은 예외를 던지지 말고 걸러내고 사유를 남긴다. |
| 쓰기 | `writeTarget()` | **멱등**해야 한다. 자연키 기준 upsert 로 작성하고, 단순 INSERT 는 쓰지 않는다. |

## 새 이관 스크립트를 만들 때

`data-migration/{소스}-{대상}-migration/` 디렉터리를 만들고 아래를 함께 둔다.

- `index.cjs` — 위 3 단계 구조
- `package.json` — `"start": "node index.cjs"`
- `README.md` — **아래 세 가지를 반드시 명시한다.**
  - **소스**: 어느 시스템의 어느 테이블/시트를 읽는가
  - **대상**: 어느 DB 의 어느 테이블에 쓰는가
  - **멱등성 전략**: 무엇을 자연키로 삼아 재실행 안전성을 확보하는가

이관은 대개 한 번 돌고 끝나지 않는다. 컷오버 리허설로 여러 번 재실행되므로
멱등성 전략을 README 에 적어두지 않으면 다음 실행 때 누가 판단해야 할 몫이 된다.
