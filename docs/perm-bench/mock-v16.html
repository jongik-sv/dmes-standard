권한 작업대 시안

권한을 고치는 일(편집), 지금 누가 무엇을 쓰는지 보는 일(확인), 바꾸면 무슨 일이 생기는지 미리 보는 일(시뮬레이션)을 한 화면에서 하는 방법을 한 화면에 모았습니다. 왼쪽에 역할 관리 시안 D안의 칸 흐름(사람 → 역할 그룹 → 역할 → 메뉴)을 두고, 오른쪽에는 고른 사람이 실제로 보는 메뉴와 화면을 그려 그 안에서 퍼미션을 고칩니다. 데이터는 가상 표본입니다.

화면 1,004개역할 12개 · 역할 그룹 11개사람모두 가상 표본
한 화면에서 할 세 가지 일
  • 편집사람을 그룹에, 역할을 그룹에 넣고 빼고, 역할에 메뉴를 등록해 버튼 · 팝업을 고른다. 사람 · 그룹 · 역할 · 메뉴 · 오브젝트의 등록과 수정은 원래 프로그램에서 한다. 이 화면은 칸 머리 링크(↗)로 그 화면을 연다. USER · GROUP · ROLE · MENU · OBJECT · PERMISSION(ROLE_ID, OBJECT_ID)
  • 확인「이 사람이 이 메뉴에서 이 버튼을 쓸 수 있나, 왜 쓰나, 왜 못 쓰나」에 답한다. 답은 사람 → 그룹 → 역할 → 퍼미션으로 이어지는 길이다.
  • 시뮬레이션저장하기 전에 「누가, 어느 화면에서, 어느 버튼을 얻고 잃나」를 사람 수와 화면 수로 센다.
바탕 규칙 — 초안
  • 편집은 초안에 쓴다체크와 칩을 바꿔도 바로 저장하지 않는다. 바꾼 것은 초안에 쌓이고, 맨 위 보라색 막대에 건수가 나온다.
  • 확인은 현재와 초안 둘 다 묻는다같은 질문을 지금 값과 초안 값으로 함께 답한다. 둘이 다르면 그 차이가 곧 이번 변경의 효과다.
  • 시뮬레이션은 초안 − 현재초안을 적용했을 때 바뀌는 사람·화면·버튼만 골라 센다. 「초안 적용」을 누르기 전까지는 아무것도 바뀌지 않는다.
칸 사이 경계를 끌면 폭이 바뀝니다 · 경계를 누르고 ← → 키로도 · 두 번 누르면 처음 폭
만드는 순서

세 단계로 나눠 만듭니다 — 보기, 고치기, 만들기

위 시안을 한 번에 만들지 않고, 위험이 낮고 쓸모가 큰 것부터 세 번에 나눠 내보냅니다. 단계마다 앞 단계의 화면에 기능을 더합니다. 카드 아래 버튼을 누르면 위 시안이 그 단계까지 만든 모습으로 바뀝니다.

  • 1단계만으로도 쓸모가 있다「저장 버튼이 안 눌려요」 문의는 지금도 매일 온다. 보기만 해도 답할 수 있다.
  • 권한 규칙을 먼저 맞춘다1단계에서 서버의 권한 계산을 실제 로그인 결과와 맞춰 두면, 2단계 시뮬레이션은 그 규칙을 그대로 쓴다.
  • 위험한 기능은 뒤로 미룬다칩 하나로 수백 명이 바뀌는 편집은 초안·영향·이력이 갖춰진 뒤에 연다.

기존 관리 화면

기존 화면은 이렇게 바뀝니다 — 역할 관리, 오브젝트 관리, 퍼미션 관리

권한 작업대는 연결과 영향을 맡고, 기존 관리 화면은 한 건의 기준 정보를 정확히 등록하는 일을 맡습니다. 두 쪽은 같은 테이블과 같은 검증 규칙을 씁니다. 퍼미션은 새 정의를 따릅니다. 화면마다 지금 운영 화면과 바뀐 뒤 시안을 나란히 두었고, 파란 숫자는 아래 「바뀌는 점」의 번호입니다.

지금 퍼미션 = 버튼 묶음 마스터

TB_MCM_SEC_ROLEPKROLE_ID
1 : N
TB_MCM_SEC_ROLE_MAPPINGPKROLE_IDPKOBJECT_IDPKPERMISSION_ID
N : 1
TB_MCM_SEC_PERMPKPERMISSION_IDPERMISSION_COMMON · CUSTOMPOPUP_BTN · PERMISSION_ACTION

오브젝트(TB_MCM_SEC_OBJ)에는 쓸 수 있는 버튼 목록이 없습니다. 버튼 묶음을 화면과 따로 만들고, 역할 × 화면에 그 묶음을 겁니다.

새 정의 퍼미션 = 역할 × 오브젝트 한 건

TB_MCM_SEC_ROLEPKROLE_ID
1 : N
TB_MCM_SEC_PERM새 구조PK·FKROLE_IDPK·FKOBJECT_IDBTN_PERM · POPUP_PERM · DATA_PERM
N : 1
TB_MCM_SEC_OBJPKOBJECT_ID+ BTN_PERM · POPUP_PERM · DATA_PERM

오브젝트가 허용 범위를 정하고(예: find,save,order,send — 오브젝트마다 코드를 직접 적는다), 퍼미션은 그 안에서 일부만 고릅니다(예: find,send). 팝업도 같습니다. 역할 안에 오브젝트가 10개면 퍼미션도 10건입니다. 값은 콤마로 잇습니다. 데이터 권한은 지금 고려 사항이 아닙니다(지금은 버튼 · 팝업만). 나중에 볼 가안만 「데이터 권한」 탭에 남겨 두었습니다.

새 퍼미션 테이블 칼럼 이름은 가안

칼럼타입키뜻
ROLE_IDVARCHAR2(30)PK · FKTB_MCM_SEC_ROLE.ROLE_ID
OBJECT_IDVARCHAR2(50)PK · FKTB_MCM_SEC_OBJ.OBJECT_ID
BTN_PERMVARCHAR2(500)버튼 권한 — OBJ.BTN_PERM 안의 값만
POPUP_PERMVARCHAR2(1000)팝업 권한 — OBJ.POPUP_PERM 안의 값만
DATA_PERMVARCHAR2(1000)지금 고려 사항 아님 · 데이터 권한 — 칸만 두고 나중에 정한다
감사 칼럼McmAuditEntity등록자 · 등록일 · 수정자 · 수정일

TB_MCM_SEC_OBJ에도 같은 이름의 칼럼 3개를 더합니다. 오브젝트 쪽 값은 허용 범위, 퍼미션 쪽 값은 부여한 값입니다.

지금 데이터를 옮기는 규칙

  1. TB_MCM_SEC_ROLE_MAPPING 한 줄(ROLE_ID, OBJECT_ID, PERMISSION_ID)은 새 퍼미션 한 건(ROLE_ID, OBJECT_ID)이 됩니다. 같은 역할 · 오브젝트에 PERMISSION_ID가 여럿이면 버튼을 합칩니다.
  2. BTN_PERM = PERMISSION_COMMON + PERMISSION_CUSTOM, POPUP_PERM = POPUP_BTN.
  3. 오브젝트의 BTN_PERM · POPUP_PERM은 그 오브젝트에 걸린 퍼미션 값을 모두 합쳐 처음 채웁니다. 그래서 옮긴 뒤에도 아무도 버튼을 잃지 않습니다.
  4. 옮긴 뒤 옛 계산과 새 계산의 결과를 사람 × 화면으로 비교하고, 같을 때만 옛 테이블을 없앱니다.
  5. (데이터 권한 — 지금 고려 사항 아님) 데이터 권한은 값이 비면 안 보입니다. 그래서 오브젝트에 데이터 항목을 처음 적을 때 그 오브젝트의 기존 퍼미션에는 전체(*)를 채워, 아무도 데이터를 잃지 않게 합니다.

정할 것

  • 버튼이 하나도 없는 퍼미션을 둘지 — 메뉴만 보이고 버튼은 없는 상태. 시안은 버튼을 모두 끄면 퍼미션도 빠진다고 봅니다.
  • 오브젝트에서 버튼을 빼면 퍼미션 값도 지울지, 남기고 계산에서만 뺄지. 시안은 남기고 계산에서 뺍니다.
  • PERMISSION_ACTION 값을 어디로 옮길지(데이터 권한 후보).
  • 테이블 이름 — 옛 TB_MCM_SEC_PERM을 새 구조로 바꿀지, 새 이름을 쓸지.
  • 퍼미션에 사용 여부(USE_TP) · 유효 기간을 둘지.
  • 버튼 · 팝업 코드의 화면 이름(order → 생산지시, send → 전송)을 어디서 관리할지. 공통 코드 하나로 두는 안을 제안합니다.
