# 마루 MDM 설계: 인터페이스 레이아웃 관리

> 분할 문서. 항목 속성의 원천인 컬럼 사전·도메인은 `02-term-domain-column.md` 참조.

## 인터페이스 레이아웃 관리

> AS-IS Gluemaster의 인터페이스 정의 방식(고정 길이 전문 + 항목 레이아웃)을 계승한다. 달라지는 점은 둘이다. 첫째, Format ID를 두지 않는다. 레이아웃 하나가 전문 하나이고, 따로 format 관리나 테이블은 만들지 않는다(결정 2026-09-09). 둘째, 항목의 타입·길이·소수 자리·단위를 레이아웃에 다시 적지 않고 **컬럼 사전 → 도메인에서 파생**한다. 전문 정의와 저장 정의가 같은 원천을 쓰므로 서로 어긋날 수 없다.

### 구조: 전문 = EAI 헤더 + 업무 본문

- **EAI 정의(MD_EAI)를 분리한다.** EAI마다 표준 헤더 레이아웃 한 벌과 직렬화 규칙(인코딩, 숫자·문자 패딩)을 가진다. 전문을 등록할 때 EAI를 선택하면 **그 EAI의 헤더가 전문 앞에 자동으로 붙는다.**
- 헤더 항목의 구성·순서·길이는 개별 전문에서 편집할 수 없고, **상수 항목의 기본값만 전문별로 재정의**할 수 있다(예: 송신공장구분은 전문마다 고정값이 다르다).
- EAI를 추가하거나 교체할 때는 헤더 레이아웃만 새로 등록하면 되고, 업무 본문 정의는 그대로 재사용한다.

### 항목 채움 방식(fill_kind)과 기본값

| fill_kind | 뜻 | 값의 출처 | 타입·길이 |
| --- | --- | --- | --- |
| DATA | 업무 데이터 | 송신 레코드의 컬럼 값 | 컬럼 → 도메인에서 파생 |
| CONST | 고정값 | 레이아웃에 등록한 상수(예: 송신공장구분 = `B1`) | 도메인에서 파생, **상수 값은 등록 시 도메인 유효 식으로 검증** |
| AUTO | 송신 시점 시스템 값 | 열거형: SEND_TIME(송신 시각), MSG_LENGTH(전문 길이 합산), SEQ(전문 순서), LAYOUT_ID(전문 식별자, ← `MD_LAYOUT.layout_id`. 20번 반영으로 format_id 폐지, 2026-09-09) | 컬럼 → 도메인에서 파생 |
| FILLER | 여분·예약 공간 | 공백 채움 | 컬럼 참조 없음. **유일하게 길이를 직접 입력**하는 항목 |

- 기본값은 세 층으로 결정된다: **EAI 헤더 항목의 기본값 → 전문별 재정의 → 송신 시점 AUTO 채움.** 앞 층이 정한 값을 뒤 층이 덮는 것이 아니라, 헤더 템플릿이 기본값을 제안하고 전문이 상수를 확정하며 AUTO만 실행 시점에 채워진다.
- AUTO는 EvalEx 함수가 아니라 직렬화기가 채우는 열거형 값이다. 검증식의 결정성 원칙(현재 시각 함수 금지)과 충돌하지 않는다 — 검증이 아니라 송신 시점의 값 기록이기 때문이다.

### 단위와 표현 형식

- 기본은 단위 절의 원칙 그대로다: **저장·검증·인터페이스 = 도메인 기준 단위 하나.** 아무것도 지정하지 않으면 기준 단위로 직렬화한다.
- 단위가 **레코드마다 다를 수 있는** 상대도 있다. SAP `QUAN` 필드는 단위를 같은 전문의 `UNIT` 타입 항목(`MEINS` 등)에서 읽는다. 이때는 `unit_item`에 그 항목의 `column_phys`(표준 물리명)를 적고, 수신 시 그 값을 읽어 기준 단위로 환산한 뒤 저장한다. 마루 도메인은 단위를 하나로 고정하므로 환산은 경계에서 끝난다(검토서 7번).
- 상대 시스템이 다른 단위를 **고정으로** 요구하면 항목에 **전송 단위**를 지정한다. 같은 차원만 허용하고 환산 계수는 MD_UNIT을 쓴다. 송신은 기준 → 전송 단위로 변환해 기록하고, 수신은 전송 → 기준 단위로 역변환한 뒤 저장한다. 화면 표시 단위와 같은 구조다. 변환은 경계에서 일어나고, 저장과 검증은 항상 기준 단위로 한다.
- 고정 길이 숫자는 표현 형식을 항목에 지정한다: 부호 자리 여부, 왼쪽 0 채움, **암묵 소수점**(소수점 문자 없이 도메인 소수 자리로 해석: 3.5 mm, 소수 1자리 → `0035`). 표현 자리수가 도메인의 길이·부호를 담기에 부족하면 등록을 거부한다.
- 날짜는 DATE 도메인이 이미 문자 8(YYYYMMDD)이므로 변환 없이 그대로 직렬화한다.

### 자동 계산과 등록 검증

- **오프셋과 전문 총 길이는 저장 시 계산한다.** MESSAGE 레이아웃은 `header_layout_id`가 가리키는 레이아웃의 `total_length`(EAI 헤더 길이)부터 더하고, 항목 순서와 도메인 파생 길이(+FILLER 길이)를 그 뒤로 합산한다. 그래서 본문 첫 항목의 오프셋은 헤더 길이에서 시작한다. AUTO(MSG_LENGTH)가 이 계산값을 쓴다. 수작업으로 맞추는 값이 없다.
- 등록 거부 조건: 본문 항목의 컬럼이 컬럼 사전에 없음(컬럼명 자동 생성의 `***`와 같은 등재 강제 장치), CONST 값이 도메인 유효 식 위반, 전송 단위의 차원 불일치, 숫자 표현 자리 부족, FILLER가 아닌 항목에 길이 직접 입력, trans_unit과 unit_item 동시 입력, unit_item이 같은 레이아웃의 항목을 가리키지 않음.

### 수신 처리

파싱(레이아웃 스냅샷) → 단위 역변환 → 저장. 받는 쪽은 도메인 유효 식도 제약도 검사하지 않는다. 검증은 값을 생성·수정한 시스템이 이미 끝냈다(결정 2026-09-09). 유일성은 수신 시스템의 DB `UNIQUE`·`PK`가 판정한다(02 "유일성은 MDM 밖이다"). 전문 단위 검증 진입점(`validateMessage`)은 두지 않는다. 배포 라이브러리의 `validate(table, column, record)`는 값을 만드는 쪽이 부른다.

### 버전과 변경

- **레이아웃도 배포 대상이다**(도메인·컬럼 사전 서브셋·단위 마스터에 추가). 송신·수신 양쪽이 같은 스냅샷 버전으로 직렬화·파싱한다.
- FILLER 여분을 표준 관행으로 둔다. 항목 추가가 여분을 쪼개 쓰는 방식이면 전문 총 길이와 기존 항목 오프셋이 변하지 않으므로, 이전 버전으로 파싱하는 상대 시스템이 깨지지 않고 순차 전환이 가능하다. 항목 길이·순서를 바꾸는 변경은 새 버전을 만들고 양측이 동시 전환한다.
- 도메인 좁히기·컬럼 변경의 영향도 목록에 그 컬럼을 쓰는 레이아웃과 상대 시스템이 포함된다.

### 테이블 설계

**MD_EAI (EAI 정의)**

| 컬럼 | 설명 |
| --- | --- |
| eai_code (PK) | 예: GLUE, SAP_PI |
| eai_name | EAI 이름 |
| encoding | EUC-KR / UTF-8. 항목 길이는 이 인코딩의 바이트 기준 |
| pad_rule | 직렬화 패딩 규칙: 숫자 왼쪽 0, 문자 오른쪽 공백 |
| header_layout_id | 이 EAI의 표준 헤더(MD_LAYOUT, layout_kind = HEADER) |

**MD_LAYOUT (전문·헤더 레이아웃)**

| 컬럼 | 설명 |
| --- | --- |
| layout_id (PK) | 대리키 |
| layout_kind | HEADER / MESSAGE |
| layout_name | 전문 이름. 전문은 `layout_id`로 가리키고 별도 Format ID는 두지 않는다(결정 2026-09-09) |
| eai_code | MESSAGE만. 헤더 자동 부착의 근거 |
| snd_system / rcv_system | MD_SYSTEM 참조 |
| total_length | 계산값: 헤더 + 본문 길이 합 |
| version | 공통 관리. 상태·승인·소유자는 두지 않는다. 권한 관리의 표준 관리자 역할만 등록·수정하고 저장하면 바로 배포한다(결정 2026-09-09) |

**MD_LAYOUT_ITEM (레이아웃 항목)**

| 컬럼 | 설명 |
| --- | --- |
| layout_id + seq (PK) | 항목 순서 |
| fill_kind | DATA / CONST / AUTO / FILLER |
| column_phys | 컬럼 사전 참조(DATA·CONST·AUTO 필수, FILLER 없음). 컬럼 사전의 **표준 물리명**(`MD_COLUMN.phys_name`)을 적는다(사용자 결정 2026-09-10). 상대 시스템의 실제 필드명은 여기 적지 않는다. 필요하면 `MD_COLUMN_SYSTEM.phys_name`에서 찾는다. 항목명 표시는 컬럼 사전의 `label_long`을 쓰고, 없으면 논리명으로 내려간다(02 "화면 표시명 3종") |
| trans_unit | 전송 단위(고정). 도메인 기준 단위와 다를 때만, 같은 차원 검사 |
| unit_item | **단위가 다른 항목에 실려 오는 경우** 같은 레이아웃 안 그 항목의 `column_phys`(표준 물리명)를 적는다. 코일 중량에 단위 항목이 붙으면 `COIL_WGT_UNIT`처럼 적는데, 용어집에 단위 약어가 아직 없어 조합 규칙대로 만든 예다. SAP에서는 이 값이 `QUAN`↔`UNIT` 짝의 `MEINS` 필드로 오고, 통화는 `CURR`↔`CUKY` 짝으로 같은 구조다. `trans_unit`과 함께 쓰지 않는다 |
| num_format | 숫자 표현: 부호·0 채움·암묵 소수점. 도메인 소수 자리와 정합 검사 |
| default_value | CONST의 상수 값, 또는 AUTO의 종류(SEND_TIME 등) |
| filler_length | FILLER만 직접 입력 |
| offset / length | 계산값. 조회·배포용. 본문 첫 항목의 오프셋은 헤더 길이(`header_layout_id`가 가리키는 레이아웃의 `total_length`)만큼 밀린 값이다 |

| 4 여분 | FILLER | 공백 | 25 |

### 화면

등록 흐름: EAI 선택 → 헤더 자동 표시(구성 잠김, 상수 기본값 입력) → 본문 항목을 컬럼 사전 검색으로 추가 → 오프셋·총 길이 자동 표시 → **샘플 전문 미리보기**(예시 값을 고정 길이 문자열 한 줄로 렌더) → 저장. 표준 관리자 역할만 저장할 수 있고 저장하면 바로 배포된다. 승인은 없다(결정 2026-09-09). AS-IS Export(엑셀 내보내기)와 Attr. Check에 해당하는 기능은 각각 레이아웃 스냅샷 출력과 등록 검증(위 거부 조건)으로 대체한다.
