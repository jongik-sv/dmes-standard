# 작업기준 칼럼 정의 방식의 MDM 룰 반영 설계

> 라인스피드·작업전환시간 화면 시안(`product/cgl-linespeed-rule.html`, `ccl-linespeed-rule.html`, `ccl-setup-time-rule.html`)에서 정한 칼럼 정의 방식을 MDM 업무기준(룰) 모델로 옮기는 방법. `docs/design/basic/06-business-rule.md`의 "업무기준(룰) 관리" 절을 전제로 하며, 그 절의 모델을 바꾸지 않고 그 위에 얹는다.

## 1. 원칙

1. **매트릭스는 화면 표현이고, 저장은 의사결정표다.** 2차원 표(사이즈 × 조건 그룹, 교환 개수 × 프린트 도수)는 사용자에게 보여주는 피벗 뷰일 뿐이며, 저장소에는 기존 의사결정표(조건 셀 + 결과 셀 행 나열)로 평탄화해서 넣는다. 회의 #174의 "내부 관리 테이블과 사용자 조회 화면을 분리한다"는 결론과 같은 축이다.
2. **엔진은 그대로 둔다.** 평가 엔진에 매트릭스 조회라는 새 개념을 추가하지 않는다. FIRST/UNIQUE/COLLECT 적중 정책과 룰 세트(ctx 전파)만으로 세 화면의 산출 로직이 전부 표현된다.
3. **표현식 원칙 유지.** 조건 셀은 boolean 식, 결과 셀은 값 식이며 대입은 엔진이 한다. 자유 표현식은 저장 시 서버 EvalEx가 1회 파싱해 텍스트 + AST JSON을 함께 저장하고, `getUsedVariables()`로 참조 변수를 추출해 검증한다.

## 2. 개념 매핑

**기본 표의 행 구조**: 앞부분은 **일반 조건**(두께·폭 등 `[FROM..TO]` 구간 조건, 여러 개를 AND로 결합)이고, 그 뒤는 **열별 값**이다. 각 열은 자기 조건(품명·재질·도금부착량 등)을 갖고, 열 판정(FIRST)에 적중한 열의 값을 그 행에서 선택한다. 즉 평가는 "일반 조건으로 행을 찾고, 열 조건으로 컬럼을 골라, 교차한 셀 값을 취한다"이다. 일반 조건의 개수는 표마다 다르다(2CGL은 두께+폭, 3CCL은 폭이 전 행 동일이라 두께만).

| 화면 시안의 요소 | MDM 룰 모델 요소 |
| --- | --- |
| 기본 표의 **열 정의**(조건 그룹: 우선순위 + 조건 조각 + 기본값 열 `TRUE`) | **열 판정 의사결정표** (FIRST). 행 하나 = 열 하나. 결과 = 열 코드(`SPD_COL`). 마지막 `일반` 열 = 기본 행 |
| 기본 표의 **앞부분 일반 조건**(두께·폭 등 `[FROM..TO]` 구간, 여러 개 AND) | **셀 조회 의사결정표**의 단순 연산자 조건 셀 `[a..b]` 여러 개(06의 op-code 셀과 같다. `[a..b]`는 개념 요약이고 경계 규칙은 06이 정한다) (구조화 저장 → 겹침·빈틈 검사 가능) |
| 기본 표의 **뒷부분 값 컬럼**(열 판정에 적중한 열의 값 선택) | 셀 조회 표의 결과 셀 (UNIQUE). 열 코드는 조건 셀 `SPD_COL = "X"`로 평탄화 |
| **이벤트 산출**(파생 변수: `PAINT_CHG_CNT` 등) | **산출 룰**(조건 없는 결과식 나열, 순서 평가). 마루 `VAR_TYPE = OTHERS`(중간 계산용)에 대응 |
| 작업전환시간 **매트릭스 A·B**(정수 축 × 정수 축) | 축 조합을 행으로 평탄화한 **UNIQUE 의사결정표** (조건 셀 두 개는 `= n` 단순 연산자) |
| **예외 조건 표**(자유 EvalEx 조건 + 적용값) | **COLLECT 의사결정표**. 조건 셀 1개(자유 표현식) + 결과 셀 1개 |
| **결합식**(`MIN(BASE_SPD, EXC_SPD…)`, `MAX(T_PAINT, T_ROLL)` / 가중합) | 룰 세트 마지막 단계의 **산출 룰** 결과식 |
| 열 판정 → 셀 조회 → 예외 → 결합의 **단계 연결** | **룰 세트** (앞 룰의 결과 변수를 뒤 룰 조건에서 참조, 같은 ctx) |

## 3. 룰 세트 구성 예

### 3-1. 3CCL 라인스피드 (룰 세트 `LS_A3`)

| 순서 | 룰 | 종류·정책 | 입력 → 결과 |
| --- | --- | --- | --- |
| 1 | 열 판정 | 의사결정표 · FIRST | `TOP_RESIN_CD`, `COAT_SIDE` → `SPD_COL` (기본 행 = `"GENERAL"`) |
| 2 | 기본 L/S 조회 | 의사결정표 · UNIQUE | 일반 조건 `COIL_THK ∈ [a..b]` (+ 표에 따라 `COIL_WTH ∈ [c..d]` 등) && `SPD_COL = "X"` → `BASE_SPD` |
| 3 | 예외 조건 | 의사결정표 · COLLECT(목록) | 자유식 (`BASE_SPD` 참조 가능) → `EXC_SPD[]` |
| 4 | 결합 | 산출 룰 | `LINE_SPD = MIN(BASE_SPD, EXC_SPD…)` |

- 열 판정 표의 행 순서 = 화면의 우선순위(prio). 상세 조건 열이 먼저, 조건 없는 기본값 열이 기본 행이다.
- 2단계 표의 행 수 = 일반 조건 조합(두께 구간 × 폭 구간 …) 수 × 열 수. 화면에는 (일반 조건 조합 × 열) 피벗으로 보여준다. 3CCL처럼 전 행이 같은 값인 일반 조건(폭 0-1270)은 조건에서 빼고 표 머리말에 고정 조건으로 적는다.
- COLLECT 결과를 4단계에서 집계 함수로 소비한다. COLLECT(합·최대·목록) 중 **목록**으로 두고 결합식이 `MIN`을 고르는 편이, 결합 방식이 바뀌어도(예: 작업전환시간의 MAX/가중합) 표 정의를 바꾸지 않아 낫다.

### 3-2. 4CCL 작업전환시간 (룰 세트 `SETUP_A4`)

| 순서 | 룰 | 종류·정책 | 입력 → 결과 |
| --- | --- | --- | --- |
| 1 | 이벤트 산출 | 산출 룰(6개 식, 순서 평가) | `FR_*`, `TO_*` → `PAINT_CHG_CNT`, `PRINT_CHG_CNT`, `WTH_CHG`, `ROLL_CHG_CNT`, `TRANS_ROLL_CNT`, `CHEMI_CHG` |
| 2 | 매트릭스 A 조회 | 의사결정표 · UNIQUE | `PAINT_CHG_CNT = r` && `PRINT_CHG_CNT = c` → `T_PAINT` |
| 3 | 매트릭스 B 조회 | 의사결정표 · UNIQUE | `ROLL_CHG_CNT = r` && `TRANS_ROLL_CNT = c` → `T_ROLL` |
| 4 | 결합 | 산출 룰 | `SETUP_TIME = ROUND(MAX(COALESCE(T_PAINT, 0), COALESCE(T_ROLL, 0)), 0)` 또는 가중합. 매트릭스에 없는 조합은 `T_PAINT`·`T_ROLL`이 NULL이라 `COALESCE`로 막는다(06 엔진 계약 4, 2026-09-09) |

- 산출 룰은 위에서 아래로 평가하며 앞 식의 결과를 뒤 식이 참조한다(`WTH_CHG` → `ROLL_CHG_CNT`). 룰 세트의 ctx 전파를 룰 내부 행 단위에도 그대로 적용하면 된다.
- 선행·후행 비교는 호출 측이 두 주문의 BOM을 `FR_*`/`TO_*` 접두사 변수로 평탄화해서 넣는다. MDM이 "이전 주문"을 찾아오지 않는다(룰은 순수 함수, 데이터 조회는 호출 시스템 책임).

## 4. 저장 구조에 추가할 것

마루 `TB_MR_RULE_*` 대응표(설계 문서의 "기존 마루 룰엔진과의 대응")에 이미 적중 정책·기본 행·적중 행 반환이 신규로 잡혀 있다. 칼럼 정의 방식을 위해 추가로 필요한 것:

1. **룰 종류(RULE_KIND)**: `DECISION`(의사결정표) / `DERIVE`(산출 룰). 산출 룰은 조건 셀이 없고 결과 셀만 순서대로 갖는 의사결정표의 퇴화형이므로, 별도 테이블 없이 헤더 속성으로 구분한다.
2. **룰 세트(`MD_RULE_SET`)**: 세트 ID와 룰 ID 실행 순서 목록(`rule_ids` JSON 배열). 버전·승인·적용시점은 없고 저장하면 바로 배포된다. 버전·승인·배포·활용처 조회의 단위는 개별 룰이다. 세트는 실행 순서와 시뮬레이션의 단위일 뿐이다(06 「테이블 설계」, 결정 2026-09-07. 검토서 86, 2026-09-09).
3. **피벗 축 배정(`MD_RULE_VAR.axis`)**: 조건 열마다 ROW/COL/NONE 한 칸. 축 안의 순서는 그 열의 `seq`에서, 표기(구간/이산값)는 `disp_type`에서, 열 축의 값 출처(변수 자체 또는 다른 룰 참조)는 `var_name`에서 그대로 얻으므로 새 칸 하나면 된다. 별도 테이블도 화면 전용 JSON도 두지 않는다(검토서 122번 재검토, 2026-09-09). 엔진은 읽지 않는다.
4. **행 메타(선택)**: 화면 시안의 `assume`(추정값)·출처(설계 노트/회의 번호) 배지를 위한 비고·태그 컬럼. 값 정비 단계에서 "현장 확인 필요" 행을 추려내는 데 쓴다.

## 5. 등록·검증 규칙

| 검증 | 대상 | 위치 |
| --- | --- | --- |
| 일반 조건 구간 겹침·빈틈·미완성 | 셀 조회 표의 `[a..b]` 구조화 셀. 일반 조건이 여러 개면 나머지 조건 값이 같은 행끼리 묶어 마지막 축 기준으로 검사(2CGL: 같은 폭 구간 안에서 두께 구간이 연속인지) | 화면 JS 즉시(십진 라이브러리) + 저장 시 서버 재검증 |
| 축 조합 완전성 | UNIQUE 셀 조회 표: `axis`가 ROW·COL인 조건 열의 모든 (행 × 열) 조합에 행이 존재하는지. 빈 셀은 "정의 없음"으로 허용하되 평가 시 NULL + 경고. 빈 조합은 행을 만들지 않는다. 기본 행을 두면 그 값이 대신 나온다(06 「룰 구성 요소」, 2026-09-09) | 서버 (등록 시 리포트) |
| 열 판정 순서 | FIRST 표에서 뒤 행을 가리는 앞 행(도달 불가 열) 탐지 | 화면 JS 즉시 경고 + 저장 시 서버 재검증(조건 셀이 전부 `-`인 행은 거부) |
| 참조 변수 | 자유식·산출식의 `getUsedVariables()` ⊆ (입력 변수 ∪ 앞 단계 결과 변수). 컬럼 사전·도메인에 없는 변수는 등록 거부 | 서버 (저장 시 1회 파싱과 함께) |
| 산출 룰 순서 | 뒤 식이 앞 식 결과만 참조(자기·후방 참조 금지) | 서버 |
| 결과 도메인 | `BASE_SPD`·`SETUP_TIME` 등 결과 변수의 도메인 범위(예: 0 이상) | 기존 도메인 검증 그대로 |

## 6. 화면 동작

- **편집**: 피벗 뷰에서 셀 인라인 편집 → 저장 시 평탄화 행으로 변환해 일괄 저장(엑셀형 에디트 모드, 변경 셀 색상 표시 — 회의 #174 결정). 열 정의 편집은 열 판정 룰 편집과 같은 화면에서 한다.
- **시뮬레이션(값 테스트)**: 룰 세트 단위로 실행한다. 서버가 단계별 적중 행 번호와 중간 결과(ctx 스냅숏)를 반환하고, 화면은 그것으로 피벗 뷰의 적중 열·행·셀과 예외 적중 행을 하이라이트한다. 화면 자체 평가는 미리보기 전용이며 서버가 배포한 AST JSON 해석기로 한다(시안의 JS 파서는 시안 전용, 실제 화면에는 넣지 않는다).
- **AS-IS 대비**: 이관 기간에는 기존 나열형 테이블을 참조 탭으로 나란히 보여주고, 예외 조건으로 옮겨간 행을 표시한다.

## 7. AS-IS 이관 절차 (라인당)

1. 기존 나열형 행에서 조건 컬럼 값 분포를 뽑아 **열 후보**(조건 그룹)를 추출한다.
2. 열 판정 룰을 등록한다(상세 조건 먼저, 기본값 열 마지막). 코드 대응이 불확실한 열은 `assume` 태그를 붙인다.
3. 행 축 구간을 정리해 셀 조회 표를 만들고, 값이 있는 셀부터 채운다.
4. 매트릭스로 안 담기는 나머지 행(소량 주문, 특정 도료명, 보호필름 코드 등)은 **예외 조건 표**로 텍스트 조건화해 옮긴다.
5. 결합식을 세트에 등록하고 값 테스트 프리셋(대표 케이스)을 저장한다.
6. 표준 vs 실적 비교 화면으로 값 최신화를 현업에 요청한다(회의 #174 진행 순서: CGL 먼저 → CCL).

## 8. 미결·확인 사항

- 작업전환시간 결합 방식(MAX vs 가중합)과 가중치 값 — 현업 결정 대기. 세트의 결합 산출 룰만 바꾸면 되도록 위 구조가 격리해 둔다.
- ~~COLLECT의 집계 방식 표준~~ **닫힘(2026-09-07).** 결과 변수의 `collect_agg`(LIST/SUM/MIN/MAX/COUNT, 기본 LIST)로 둔다. 06 「테이블 설계」 MD_RULE_VAR.
- ~~피벗 뷰 메타의 자리~~ **재검토해 닫힘(2026-09-09, 검토서 122번).** 별도 테이블도 화면 전용 JSON도 두지 않는다. `MD_RULE_VAR`에 조건 열 전용 칸 `axis`(ROW/COL/NONE) 하나만 두고, 순서·표기·값 출처는 기존 `seq`·`disp_type`·`var_name`에서 얻는다. 배포본에는 싣지 않는다. 2026-09-07의 "06 MD_RULE_STEP" 표기는 오기였다. 06에 그런 테이블은 없다.
- ~~산출 룰의 행 단위 ctx 전파~~ **닫힘(2026-09-07).** 06 `MD_RULE.rule_kind`가 DERIVE인 룰(`MD_RULE_VER.hit_policy` NULL)은 결과 셀을 `MD_RULE_VAR.seq` 순서로 평가하고 앞 셀 결과를 뒤 셀이 읽는다(06 「테이블 설계」 MD_RULE_VER. 검토서 87, 2026-09-09).
- ~~세트 단위 버전·적용시점·승인~~ **닫힘(2026-09-07).** 버전·승인·배포 단위는 룰이다. 세트는 `MD_RULE_SET.rule_ids` 순서 목록이며 저장하면 바로 배포된다. 06 「테이블 설계」(검토서 86, 2026-09-09).
