# mdm — 도메인 관리 기능설계서

> **인용 정본 예외(팀장 지시 2026-09-24, 선례 [DEC-001](../../../ai-build-log/DEC-001_noticeMgmt-on-mls.md) 결정 2)**: 본 화면은 As-Is 레거시가 없는
> To-Be only 신규 화면이다. 분석리포트와 G1~G7 게이트가 성립하지 않으므로 설계 산출물을 기능설계서 1종으로 줄였다.
> 표의 근거는 분석리포트 대신 **원천 설계** `docs/mdm/design/basic/02-term-domain-column.md`(이하 `02:행`)와
> **시안** `docs/mdm/design/basic/html/02-term-domain-column.html`(이하 `시안:행`)의 행 번호를 인용하며, 이를 위해 표 끝에
> "근거" 칸을 더했다. 한계는 §11.1 에 GAP 으로 등재한다. 구현 설계·테스트는 [TSK-04-03 design.md](../../tasks/TSK-04-03/design.md) 가 정본이다.
>
> **Frontend 개발 연계 값**(§1.2 정본) — mesModule `m-mdm` / moduleGroup `dma` / pageName `domainMng` /
> pageId `domainMng` / 페이지 유형 `B` / tsup entry key `pages/dma/domainMng/page`

### 6.3 검증 실행 순서

```
[도메인검증] 클릭
  → 1단계: 필수·형식(S06)
  → 2단계: 식 칸 검사(R01·R02·R04·R05·S05)
  → 3단계: 상속·구조(R06·R07·R09·R10·S01~S04)
  → 4단계: 테스트 케이스·예시 실행(R03·R08, 값 정의 변경·부모 변경이면 하위 도메인 길이·소수(R06)·케이스 포함)
  → 모든 결과를 한 번에 검사 목록으로 표시(첫 오류에서 멈추지 않음)
  → ERROR 0건 → [저장] 활성
[저장] 클릭 → 서버가 같은 검사를 재실행 → 쓰기 → 하위 도메인 재검사(같은 트랜잭션) → 실패 시 전체 롤백

[부모 연결]·[연결 제거](B-007·B-008, D-132)
  → 저장된 행 + 새 부모(또는 부모 없음)로 초안을 만든다
  → 0단계(서버): 연결 제거면 상속값을 초안에 복사(구체화, W05)
  → 1~4단계 그대로(부모 변경은 S01 이 아니고 S02(종류·타입·유효 단위)·R07 로 본다) + W04 영향 경고
  → 대화상자에 검사 목록·영향도·diff 표시 → ERROR 0건 → [연결]/[교체]/[연결 제거] 활성
  → 클릭 → `save` 가 같은 검사를 재실행 → 쓰기 → 하위 도메인 재검사 → 실패 시 전체 롤백(동시 수정은 MDM001)
```

> 서버는 화면 검증을 신뢰하지 않고 위 규칙을 재검증한다(Mes-Guide §7). 식 판정의 정본은 서버 EvalEx 다(02:355·362).
