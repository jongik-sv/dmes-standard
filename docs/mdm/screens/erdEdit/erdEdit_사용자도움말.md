# ERD 설계 사용자 도움말

- 대상: ERD 설계 화면, Claude(MCP 도구), 명령줄 도구(CLI)를 처음 쓰는 사람입니다.
- 기준: `dev` 브랜치 2차 회차(2026-10-12)까지의 코드입니다. 단계 0-2(가져오기·뷰어·편집·동시 편집), UX 정비 1차(화면 틀·문구·큰 모델 읽기), UX 정비 1.5(여러 표 동시 처리·추정 점선 누르기), 2차(관계선 꺾임점, 표 크기 조절, 캔버스 그 자리 편집, Space 속성 창, 표·컬럼 복사, 목록 관리, 처음 둘러보기, 사전에 없는 단어 표시)를 담았습니다.
- 2차 마감(2026-10-12)에서 둘러보기, 그 자리 편집, Space 속성 창, 표·컬럼 복사, 꺾임점, 새 모델 등록, 모델 관리, 다이어그램 복사를 실제 브라우저로 확인했습니다. 확인 결과는 [미룬 기능 목록](../../../erd-tool/deferred.md) 12절에 있습니다.
- 사람 2명과 Claude 세션 2개의 동시 편집 등 아직 브라우저로 확인하지 못한 곳에는 "(확인 예정)"을 붙였습니다.
- 관련 문서: [기능설계서](./erdEdit_기능설계서.md), [ERD 도구 설계](../../../superpowers/specs/2026-10-10-erd-tool-design.md), [미룬 기능 목록](../../../erd-tool/deferred.md)

## 1. 이 도구로 할 수 있는 것

ERD 설계는 Oracle 스키마 하나를 모델 하나로 읽어 ERD 로 보여 주고, 표준 용어 사전에 맞춰 고치게 하는 도구입니다. 같은 모델을 세 가지 방법으로 다룹니다.

| 할 일 | 화면 | Claude(MCP) | CLI |
|---|---|---|---|
| 모델 읽기(표·컬럼·관계·표준 상태) | 예 | 예 | 예 |
| 추정 관계 [맞음]·[아님] 판정 | 예 | 예 | 예 |
| 표·컬럼 추가와 수정, 관계 만들기 | 예 | 예 | 예 |
| 컬럼 삭제 | 아니요 | 예 | 예 |
| 관계 삭제·식별 전환, 키(UK·IX) 편집, 표 이름 바꾸기 | 예(Space 속성 창, 4.2절) | 예 | 예 |
| 관계선의 꺾임점 정하기 | 예(4.3절) | 예(명령으로) | 예(명령으로) |
| 다이어그램 만들기, 자동 배치, 접기 | 예 | 예(명령으로) | 예(명령으로) |
| 표 크기 조절 | 예(4.4절) | 예(명령으로) | 예(명령으로) |
| 다이어그램 이름 바꾸기·지우기·복사 | 예(4.4절) | 예(명령으로) | 예 |
| 모델 목록 보기(상태·확정본·등록자) | 예(4.10절) | 예 | 예 |
| 새 모델 등록과 첫 가져오기 | 예 | 예 | 예 |
| 모델 완전 삭제 | 예(4.10절) | 아니요 | 예 |
| DB 와 모델의 차이 보기 | 예 | 예 | 예 |
| DB 다시 가져오기(DB 차이를 모델에 반영) | 예 | 아니요 | 아니요 |
| 되돌리기 | 예 | 예 | 예 |
| 버전 확정, 새 버전, 공동 편집자 관리 | 예 | 아니요 | 아니요 |

먼저 알아 둘 말은 네 가지입니다. 자세한 뜻은 11절에 있습니다.

- 모델: 모듈 하나에 모델 하나입니다. 예: 모델 `mcm` 은 스키마 `MCMAPUSER` 를 담습니다.
- 버전: 고칠 수 있는 버전은 DRAFT 입니다. 확정하면 RELEASED 가 되고 모델을 더 고칠 수 없습니다.
- 번호(rev): 모델이 바뀔 때마다 1씩 오르는 번호입니다. 위 막대의 [버전 ▾] 를 열면 `번호 12` 처럼 보입니다.
- 소유자와 공동 편집자: DRAFT 를 고칠 수 있는 사람입니다. 소유자가 공동 편집자를 더합니다.

## 2. 처음 시작하기

### 2.1 준비

- MDM 서버가 떠 있어야 합니다. 기본 주소는 `http://localhost:8096` 입니다.
- 포털에 로그인할 수 있어야 하고, 이 화면(`erdEdit`)의 권한이 있어야 합니다. 권한이 없으면 화면은 읽기 전용입니다.
- 이 PC 의 로컬 서버(L_MAIN)에는 샘플 모델 두 개가 있습니다.

| 모델 ID | 단추 이름 | 스키마 | 규모(약) | 관계 |
|---|---|---|---|---|
| `mcm` | MCM 스키마 | `MCMAPUSER` | 표 57개 | DB FK 가 없습니다. 관계는 모두 추정 관계(노란 파선)입니다 |
| `mdm` | MDM 스키마 | `MDMAPUSER` | 표 46개 | DB FK 59개가 실선으로 보이고, 추정 관계가 조금 더 있습니다 |

표 수와 관계 수는 복제 DB(L_ERD12)에서 잰 값입니다. L_MAIN 에서는 조금 다를 수 있습니다.

### 2.2 화면 열기

1. 포털에 로그인하세요.
2. 메뉴에서 `마루 MDM > 용어·도메인 > ERD 설계` 를 여세요.
3. 처음 여는 사용자는 시작 화면을 봅니다. 모델 카드(모델 이름 · 모듈 · 스키마) 가운데 [MCM 스키마 · mcm · MCMAPUSER] 를 누르세요. 위 막대의 모델 단추를 눌러도 됩니다.

시작 화면은 상황에 따라 다릅니다.

| 상황 | 시작 화면 |
|---|---|
| 등록된 모델이 없음 | "등록된 모델이 없습니다." 와 [새 모델 등록] |
| 모델은 있지만 아직 고르지 않음 | "열 모델을 고르세요." 와 모델 카드, [새 모델 등록] |
| 고른 모델에 표가 없음 | "표가 없습니다. DB 스키마를 가져오면 표·관계를 만듭니다." 와 [DB 에서 가져오기] |

권한이 없으면 해당 단추가 꺼지고, 마우스를 올리면 이유가 보입니다.

화면은 마지막으로 본 상태를 기억합니다. 다시 열면 마지막 모델, 논리·물리 모드, 보기 프리셋, 패널이 열렸는지 접혔는지, 다이어그램마다의 화면 위치와 배율로 열립니다. 이 기억은 이 브라우저에만 있고 사용자마다 따로입니다. 브라우저 저장 공간을 지우면 처음 상태로 돌아갑니다.

열리는 다이어그램은 다음 순서로 정합니다.

1. 이 모델에서 마지막으로 본 다이어그램이 있으면 그것을 엽니다.
2. 없으면 표가 30개 이하인 첫 다이어그램을 엽니다.
3. 그것도 없으면 목록의 첫 다이어그램을 엽니다.

가져오기는 다이어그램 `기본 / 전체` 를 만들고 모든 표를 놓아 둡니다. 표가 많은 모델은 [주제별로 나누기](4.4절)로 작은 다이어그램을 만들면 다음부터 작은 것이 먼저 열립니다.

첫 화면 배율은 이렇게 정합니다. 저장된 위치가 있으면 그대로 엽니다. 없으면 다이어그램 전체가 들어오는 배율을 계산합니다. 그 배율이 35% 이상이면 전체가 보이게 열고, 35% 미만이면 글자를 읽을 수 있도록 배율 100% 로 첫 표부터 보여 줍니다. 전체를 보려면 [화면 맞춤] 이나 `Shift+1` 을 누르세요.

### 2.3 5분 둘러보기 (모델 mcm)

먼저 위 막대의 요약 줄을 읽으세요. 예: `표 57 · 관계 113(추정 113) · 고칠 위반 737`. 관계 수는 아님으로 판정한 관계를 뺀 수이고 괄호 안은 추정 관계 수입니다. 고칠 위반은 6절의 TYPE·DOMAIN·MISS 컬럼 수입니다. 표준 상태를 아직 읽지 못했으면 위반 수 자리에 `…` 가 보입니다.

1. 캔버스 오른쪽 아래의 [화면 맞춤] 단추나 `Shift+1` 을 누르세요. 모든 표가 한 화면에 들어옵니다. 아래 검토 패널은 접혀 있습니다. 탭 줄에서 탭을 누르면 패널이 열립니다(9단계).
2. 마우스 휠로 축소하세요. 확대율이 50% 미만이 되면 표마다 이름 한 줄만 보이고, 35% 미만이 되면 표가 큰 이름판으로 바뀝니다(3.2절).
3. `F3` 을 누르세요. 논리 모드(푸른 바탕)와 물리 모드(회색 바탕)가 바뀝니다.
4. 위 막대의 보기 프리셋에서 [E-R 개요] 를 누르세요. 컬럼 없이 표와 관계만 보입니다. [기본] 을 눌러 돌아오세요.
5. `Ctrl+K`(Mac 은 `⌘K`)를 누르고 `TB_MCM_SEC_MENU` 를 입력한 후 `Enter` 를 누르세요. 캔버스가 그 표로 옮겨 가고 표가 선택됩니다.
6. 오른쪽 컬럼 그리드를 보세요. `MENU_ID` 의 키 칸에 `PK` 가 있습니다. 표준 칸에는 컬럼마다 표준 상태(6절)가 있습니다.
7. `Esc` 를 눌러 표 찾기 칸을 닫으세요. 표 선택은 그대로 남습니다. 찾기 칸에 초점이 있으면 다음 단계의 키를 받지 않습니다.
8. `Alt+O`(Mac 은 `⌥O`)를 누르고 `MENU_NM` 을 입력한 후 `Enter` 를 누르세요. 그리드가 그 컬럼 행으로 갑니다.
9. 아래 탭 줄에서 [추정 관계 검토(n)] 탭을 누르세요. 검토 패널이 열립니다. 행을 누르면 그 자식 표가 선택됩니다. 패널을 다시 접으려면 탭 줄 끝의 접기 단추를 누르세요.
10. [표준 위반(n)] 탭을 누르세요. 고칠 위반 컬럼이 나옵니다. 행을 누르면 그 컬럼이 골라집니다.
11. 위 막대에서 [MDM 스키마] 를 누르세요. DB FK 관계가 실선으로 보입니다. 예: `TB_MDM_CODE_ITEM` 에서 `TB_MDM_CODE` 로 가는 선입니다.

### 2.4 편집하려면

화면을 읽기만 하는 데는 조건이 없습니다. 고치려면 그 DRAFT 의 소유자나 공동 편집자여야 합니다. 확정된 버전을 보고 있어도 새 버전을 만들 수 있는 사람이 처음 편집을 시작하면 화면이 DRAFT 를 저절로 만든 뒤 그 변경을 넣습니다(4.9절). 조건이 맞지 않으면 위 막대에 [읽기 전용] 칩이 보입니다. 칩에 마우스를 올리면 짧은 이유가 보이고, 칩을 누르면 이유와 할 일이 창으로 열립니다. 모델과 이유마다 처음 한 번은 창이 저절로 열립니다. 다시 열면 열리지 않습니다.

| 짧은 이유 | 창에 나오는 글 | 할 일 |
|---|---|---|
| 권한 없음 | 이 화면의 편집 권한이 없어 읽기만 할 수 있습니다. | 시스템 관리자에게 화면 권한을 요청하세요. |
| 공동 편집자 아님 | 공동 편집자가 아니어서 읽기만 할 수 있습니다. 소유자(...)에게 공동 편집자 등록을 요청하세요. | 창에 적힌 소유자에게 공동 편집자로 더해 달라고 하세요. |
| 확정된 버전 | 확정된 버전이라 모델을 고칠 수 없습니다. [버전 ▾] 의 [새 버전] 으로 DRAFT 를 만드세요. | 4.9절을 따라 새 버전을 만드세요. |
| 소유자 없음 | 이 버전에 소유자가 없어 아무도 다이어그램을 고칠 수 없습니다. ... | DRAFT 를 [선점] 하거나 [새 버전] 을 만드세요. |

꺼진 단추에 마우스를 올리면 "할 일 — 짧은 이유" 형식의 툴팁이 보입니다. 예: `표 추가 (2) — 확정된 버전`. 긴 안내는 칩 창에만 나옵니다.

### 2.5 처음 둘러보기

ERD 설계를 처음 열면 모델을 읽은 뒤 4단계 둘러보기가 저절로 열립니다.

| 단계 | 가리키는 곳 | 안내 |
|---|---|---|
| 1. 모델 고르기 | 위 막대의 모델 단추 | 볼 모델을 고릅니다. 모델이 없으면 [+ 모델] 로 스키마를 등록합니다 |
| 2. 표 추가 | 도구 막대의 [표 추가] | 단추를 누르고 캔버스를 눌러 새 표를 놓습니다 |
| 3. 관계 긋기 | 도구 막대의 [관계 ▾] | 관계 도구를 고르고 자식 표에서 부모 표로 끌면 관계가 생깁니다 |
| 4. Space 로 속성 창 | 화면 가운데 | 표를 고르고 Space 를 누르면 속성 창이 열립니다 |

- [다음]·[이전] 으로 단계를 옮깁니다.
- [완료] 를 누르거나 "다시 보지 않기" 를 고르면 그 뒤로는 저절로 열리지 않습니다. 이 선택은 이 브라우저에 사용자별로 저장됩니다.
- [건너뛰기] 나 `Esc` 는 이번에만 닫습니다. 다음에 열면 다시 나옵니다.
- 위 막대의 [둘러보기] 를 누르면 언제든 다시 봅니다.

## 3. 화면 구성

| 영역 | 위치 | 들어 있는 것 |
|---|---|---|
| 위 막대 | 맨 위, 한 줄 | 모델 단추, [모델 관리], [+ 모델], 요약 줄, [버전 ▾] 와 DRAFT 일 때 [기준본으로 저장], [읽기 전용] 칩(읽기 전용일 때만), 접속자 동그라미, [논리]·[물리], 보기 프리셋, [범례], [둘러보기], [DB 에서 가져오기](표가 없을 때만) |
| 끊김 띠 | 위 막대 아래 | 실시간 연결이 끊겼을 때만 보입니다(9.5절) |
| 알림 띠 | 끊김 띠 아래 | 서버가 거절한 변경의 이유(9.2절). 있을 때만 보입니다 |
| 왼쪽 패널 | 왼쪽 | [표 찾기], [새 다이어그램], 업무영역별 다이어그램 목록(표 수, 붉은 숫자는 고칠 위반 수), 다이어그램에 없는 표 수, 범례. 머리의 [‹] 로 접습니다 |
| 캔버스 | 가운데 | 도구 막대, 표 노드, 관계 선, 접속자 이름표, 미니맵, 확대·축소·화면 맞춤·캔버스 최대화 단추 |
| 속성 패널 | 오른쪽 | 고른 표의 컬럼(키, 논리명, 사전 재구성, 물리명, 도메인, 타입, NN, 표준)과 그 아래 입력 칸. 표를 고르면 나타나고 고른 표가 없으면 없습니다 |
| 검토 패널 | 아래 | 평소에는 탭 줄만 보입니다. [표준 위반(n)], [추정 관계 검토(n)], [DB 다시 가져오기], [변경 기록] 탭 |

버전 단추는 위 막대의 [버전 1.000 · 작성 중 ▾] 안에 있습니다. 누르면 번호(rev), [새 버전(major)], [새 버전(minor)], [삭제], [확정], [선점], [해제], [넘기기(준비 중)], [공동 편집자(n)] 가 열립니다. DRAFT 일 때는 그 옆에 [기준본으로 저장] 단추 하나가 따로 있습니다(4.8절). 메시지는 화면 오른쪽 아래에 잠깐 나타나는 알림(toast)으로 보입니다. 알림은 몇 초 뒤 사라집니다. 오류 알림은 더 오래 남습니다.

패널 크기와 접기는 다음처럼 다룹니다.

- 패널 사이의 경계 막대를 끌면 크기가 바뀝니다. 경계 막대에 초점을 둔 채 화살표 키를 눌러도 바뀝니다. 경계 막대를 더블클릭하면 기본 크기로 돌아갑니다. 크기는 사용자별로 저장됩니다.
- 왼쪽 패널과 속성 패널의 [‹]·[›] 단추를 누르면 폭 28px 의 얇은 줄로 접힙니다. 줄을 누르면 다시 펼칩니다. 접은 상태는 기억합니다.
- 속성 패널은 표를 고르면 나타나고 고른 표가 없으면 사라집니다. 입력 칸에 초점이 있는 동안에는 선택이 풀려도 남아 있습니다. 패널이 열려 캔버스 폭이 줄 때 고른 표가 화면 밖이면 그 표로 화면이 옮겨 갑니다.
- 검토 패널은 접힌 탭 줄에서 탭을 누르면 열리고 그 탭을 보여 줍니다. 마지막으로 연 탭과 열림 상태를 기억합니다. 위반이 있어도 저절로 열지 않습니다.
- 캔버스 오른쪽 아래의 [캔버스 최대화 (Alt+M)] 단추나 `Alt+M`(Mac 은 `⌥M`)을 누르면 왼쪽 패널, 속성 패널, 검토 패널이 모두 사라지고 위 막대와 캔버스만 남습니다. 표를 고르면 속성이 떠다니는 창으로 열립니다. 창은 끌어 옮기고 크기를 바꿀 수 있고, 위치는 저장됩니다. 한 번 더 누르면 원래대로 돌아옵니다. 최대화 상태는 기억하지 않습니다.

위 막대의 [범례] 를 누르면 3.1절의 색 견본이 열립니다. 왼쪽 패널을 접었을 때 씁니다.

### 3.1 캔버스에서 보이는 것

왼쪽 패널 아래와 위 막대의 [범례] 에 같은 색 견본 표가 있습니다. 견본 10줄은 실제 화면의 색과 같습니다.

| 보이는 것 | 뜻 |
|---|---|
| 실선 | DB FK 관계나 확정한 관계 |
| 노란 파선 | 추정 관계(검토 대기) |
| 선 위 "다른 후보 n개" | 같은 컬럼의 추정 후보가 더 있습니다. 나머지는 접혀 있고 검토 패널에 모두 나옵니다 |
| 키 칸 `PK`·`FK`·`FK?` | 기본키, DB·확정 관계의 자식 컬럼, 추정 관계뿐인 자식 컬럼. `PK` 는 파란색입니다 |
| 컬럼 줄 맨 위 묶음과 구분선 | PK 컬럼은 표 맨 위에 모여 있고, 그 아래에 구분선이 있습니다. 컬럼 순서 자체는 바뀌지 않고 보이는 순서만 PK 가 먼저입니다 |
| 기울인 회색 단어 | 논리명 중 사전에 없는 단어 자리입니다(아래 "사전에 없는 단어") |
| 관계선의 꺾임점 | 손으로 정한 경유점입니다. 선에 마우스를 올리거나 선을 누르면 손잡이로 보입니다(4.3절) |
| 붉은 행 바탕 | 표준 상태 MISS(사전 없음) |
| 노란 행 바탕 | 표준 상태 TYPE·DOMAIN |
| 표 머리의 붉은 숫자 | 그 표에서 고칠 위반(TYPE·DOMAIN·MISS)인 컬럼 수 |
| `감사 8` | 숨긴 감사 컬럼 수(4.11절) |
| 캔버스 바탕 | 논리 모드는 푸른 바탕, 물리 모드는 회색 바탕입니다. 위반 행의 붉은 바탕과 겹치지 않도록 물리 모드를 회색으로 바꿨습니다 |
| "접힘 · 컬럼 n개 숨김" | 접기로 숨긴 컬럼 수 |
| 「▾ N개 더」 막대 | 표 높이를 줄여 표 안에서 스크롤해야 보이는 컬럼 수입니다. 누르면 높이가 자동 크기로 돌아옵니다(4.4절) |
| 표 위의 이름표 | 다른 사람이나 Claude 세션이 그 표를 고르거나 고치고 있습니다. "· 작업 중" 이 붙으면 작업 중 표시가 있습니다. 사람 이름표는 파란색입니다 |
| 흐린 표·행 | 내 변경을 서버가 아직 받아들이지 않았습니다 |
| 오른쪽 아래 작은 지도 | 미니맵입니다. 지금 보는 영역이 어디인지 보여 줍니다. 위반이 있는 표는 붉은색, 고른 표는 파란색입니다. 끌거나 휠로 움직일 수 있습니다 |

범례 견본 10줄은 다음과 같습니다.

| 견본 | 뜻 |
|---|---|
| 실선 | DB FK·확정 관계 |
| 파선 | 추정 관계(검토 대기) |
| 붉은 바탕 | 사전 없음 |
| 노란 바탕 | 타입 불일치·도메인 다름 |
| 붉은 수 `3` | 고칠 위반 수(표 머리) |
| `감사 8` | 숨긴 감사 컬럼 수 |
| `PK FK FK?` | 기본 키·외래 키·추정 외래 키 |
| `다른 후보 n개` | 같은 자식 컬럼의 다른 부모 후보 |
| 푸른 바탕 | 캔버스 바탕 — 논리 모드 |
| 회색 바탕 | 캔버스 바탕 — 물리 모드 |

사전에 없는 단어: 서버가 물리명에서 논리명을 만들 때 사전에 없는 토막은 `***` 로 둡니다. 예: `EXCEL_TP` 의 논리명은 「*** 구분」 으로 저장됩니다. 화면은 이 `***` 자리에 물리 토막을 넣어 「EXCEL 구분」 처럼 보입니다.

- 컬럼 그리드(속성 패널 안 그리드 포함)의 논리명 칸에는 물리 토막으로 채운 이름이 보입니다. 채운 단어는 기울인 회색이고, 마우스를 올리면 「사전에 없는 단어」 가 보입니다.
- 그 바로 오른쪽 읽기 전용 칸 [사전 재구성] 에는 저장된 논리명이 `***` 그대로 보입니다. 사전으로 만든 이름입니다.
- 표 노드에는 채운 이름만 보입니다.
- 이름을 고칠 때 입력 칸은 저장된 값(`***` 포함)으로 시작합니다. 화면에 보이는 채운 이름이 저장되지는 않습니다. 저장 값과 「사전 없음」 위반은 그대로입니다.
- 논리명의 단어 수와 물리명의 `_` 토막 수가 달라 자리를 맞출 수 없으면 `***` 가 그대로 보이고, 마우스를 올리면 물리명 전체가 나옵니다.

관계선은 표 위치에 따라 붙는 변이 달라집니다. 두 표가 좌우로 8px 넘게 떨어져 있으면 서로 마주 보는 변에 붙습니다. 겹치거나 맞닿아 있으면 둘 다 오른쪽 변에 붙어 ㄷ 모양이 됩니다. 같은 표를 잇는 선(자기 참조)은 오른쪽 변에 붙습니다. 표를 끄는 동안에도 바로 바뀝니다.

미니맵은 도구 막대의 [미니맵] 단추로 켜고 끕니다. 다이어그램에 표가 30개 이상이면 처음부터 켜져 있습니다. 한 번 켜거나 끄면 그 선택을 기억합니다.

### 3.2 보기 프리셋과 모드

| 프리셋 | 표 노드 |
|---|---|
| 기본 | 논리 모드면 논리명과 도메인, 물리 모드면 물리명과 타입 |
| E-R 개요 | 표 이름만. 컬럼 행을 그리지 않습니다 |
| 논리+물리 동시 | 논리명 옆에 물리명, 오른쪽에 타입 |

- `F3` 이나 [논리]·[물리] 단추로 모드를 바꿉니다. 포털의 메뉴 찾기 창은 열리지 않습니다.
- 확대율에 따라 표를 3단계로 그립니다.

| 확대율 | 단계 | 보이는 모양 |
|---|---|---|
| 50% 이상 | 자세히 | 프리셋대로 그립니다 |
| 35% 이상 50% 미만 | 이름만 | 프리셋과 상관없이 표 이름 한 줄만 그립니다. 이름 글자는 화면에서 읽을 수 있는 크기로 키웁니다 |
| 35% 미만 | 개요 | 표가 원래 크기의 상자로 남고 안에 논리명과 물리명 두 줄이 큰 글자로 보입니다. 관계선은 끝 모양(까마귀발·막대·"0")과 후보 표지를 빼고 굵기를 일정하게 그립니다 |

- 단계는 확대율만으로 정해집니다. 모델에 저장된 표 위치는 바뀌지 않습니다.
- 50% 이상 90% 미만에서는 표 이름이 작게 보일 수 있습니다. 이때는 확대하세요.
- 표가 많은 모델은 [미니맵](3.1절)과 [주제별로 나누기](4.4절)를 함께 쓰면 읽기 쉽습니다.

## 4. 자주 하는 일

모든 변경은 서버가 판정한 뒤 반영됩니다. 거절되면 알림 띠에 이유가 나오고 화면은 원래 값으로 돌아갑니다.

### 4.1 추정 관계 검토하기

모델 `mcm` 은 DB FK 가 없어서 관계가 모두 추정 관계입니다. 추정 근거는 세 가지입니다.

- 설계 문서: 설계 문서에 적힌 관계
- SQL 조인: 프로그램 SQL 의 조인 조건
- 이름 규칙: 컬럼 이름 규칙(예: 자식 표의 컬럼 이름이 부모 표의 PK 와 같음)

1. 아래 탭 줄에서 [추정 관계 검토(n)] 탭을 누르세요. 검토 패널이 열립니다.
2. 행을 누르세요. 자식 표가 선택되고 캔버스가 그 표로 옮겨 갑니다.
3. 자식(FK 쪽)·부모·근거·후보 순위 칸을 읽으세요. 근거는 `SQL 조인 V1__baseline.sql:1108` 처럼 근거 종류와 파일:줄만 보입니다. 전체 경로는 칸에 마우스를 올리면 보입니다. 후보 순위의 "1" 은 캔버스에 그린 후보이고, "2" 이하는 접힌 후보입니다.
4. 판정 칸에서 맞으면 [맞음] 을, 틀리면 [아님] 을 누르세요.

캔버스에서 시작할 수도 있습니다. 캔버스의 점선(추정 관계)을 누르면 그 관계 행이 골라집니다. 검토 패널이 접혀 있으면 펼쳐지고, [추정 관계 검토] 탭으로 바뀌고, 그 행이 보이도록 그리드가 움직입니다. 선이 가늘어도 선 둘레를 누르면 됩니다. 실선(확정 관계)은 눌러도 아무 변화가 없습니다.

- 그리드를 굴린 뒤 같은 점선을 다시 누르면 그리드가 그 행으로 다시 움직이지 않습니다. 다른 점선을 한 번 누른 후 다시 누르세요.
- 점선 바로 위에서 끌면 캔버스가 움직이지 않고, 오른쪽 단추를 눌러도 캔버스 메뉴가 열리지 않습니다. 선에서 조금 떨어진 빈 곳에서 하세요.
- 캔버스 최대화(`Alt+M`) 중에는 검토 패널이 없습니다. 점선을 누른 후 최대화를 끄면 그 행이 골라져 있습니다.

[맞음] 을 누르면 "관계를 확정했습니다." 알림이 나오고 관계가 실선이 됩니다. 키 칸은 `FK?` 에서 `FK` 로 바뀝니다. [아님] 을 누른 관계는 캔버스에서 사라집니다. 둘 다 되돌릴 수 있습니다(4.7절). 버전의 [확정] 과는 다른 일입니다. 버전의 [확정] 은 4.8절에서 다룹니다.

방향이 거꾸로 된 추정 관계가 있습니다. SQL 조인에 양쪽 키가 없으면 이름 순서로 방향을 정하기 때문입니다. 예: `TB_MCM_SEC_USER.USER_ID` 가 `TB_MCM_SEC_USER_PWD` 의 자식으로 잡힌 행, `TB_MCM_SEC_ROLE_MAPPING` 과 `TB_MCM_SEC_MENU` 사이의 행입니다. 이런 행은 [아님] 을 누른 후 4.3절의 관계 도구로 바른 방향의 관계를 만드세요.

남은 추정 관계는 버전 확정을 막지 않습니다. 확정 창에 "검토 안 한 추정 관계" 건수로만 나옵니다.

### 4.2 표와 컬럼 고치기

캔버스와 컬럼 그리드에서 칸을 바로 고칩니다. 캔버스에서 그 자리에서 고치는 방법은 아래 "캔버스에서 바로 고치기" 에 있습니다.

1. 캔버스에서 표를 누르세요. 예: `TB_MCM_SEC_USER`.
2. 그리드에서 고칠 칸을 두 번 누르거나 `F2` 를 누르세요. 고칠 수 있는 칸은 논리명, 물리명, 타입, NN 입니다.
3. 값을 넣은 후 `Enter` 나 `Tab` 을 누르세요. 칸을 떠날 때 변경이 한 건 보내집니다.

- 타입은 `VARCHAR2(50)`, `NUMBER(10,2)`, `DATE`, `TIMESTAMP(6)` 처럼 씁니다.
- 물리명은 영문 대문자로 시작하고 영문 대문자·숫자·`_` 만 씁니다. 소문자로 넣으면 대문자로 바뀝니다.
- 컬럼 순서를 바꾸려면 키 칸의 손잡이를 끌어 행을 옮기세요.

새 컬럼은 그리드 아래 입력 칸에서 더합니다. 컬럼을 고르지 않았거나 [추가] 모드일 때 `Enter` 가 새 컬럼을 더합니다. 표를 하나 고른 뒤 도구 막대의 [컬럼 추가] 나 [PK 추가] 를 누르면 속성 패널이 열리고 입력 칸에 초점이 갑니다. 표를 오른쪽 단추로 누른 메뉴의 [컬럼 추가]·[PK 컬럼 추가] 도 같습니다. 입력 칸 안내 글은 "새 컬럼 논리명 — Enter·Ctrl+Enter 로 추가" 이고, PK 이면 "PK 컬럼 논리명 — Enter 로 추가" 입니다. 이 단추들은 입력 칸을 [추가] 모드로 바꿉니다. [PK 추가] 는 표를 하나만 골랐을 때 켜집니다. [컬럼 추가] 는 표를 여러 개 골랐을 때도 켜지고, 그때는 같은 컬럼 창이 열립니다(아래 "같은 컬럼을 여러 표에 더하기"). 표를 고르지 않았으면 둘 다 꺼지고, 마우스를 올리면 이유가 보입니다.

1. 입력 칸에 논리명을 넣으세요. 예: `사용여부`.
2. 0.3초 뒤 미리보기 줄을 읽으세요. 서버가 만든 물리명, 표준 상태, 단어 토막마다의 약어, 추천 도메인이 보입니다.
3. 미리보기 줄에 [토막 고르기] 가 보이면 누른 후 토막마다 약어를 고르세요. 사전에 약어가 없는 토막은 직접 넣습니다.
4. `Enter`(또는 `Ctrl+Enter`)를 누르세요. PK 컬럼으로 더하려면 `Ctrl+Shift+Enter` 를 누르세요.

물리명과 도메인은 서버가 사전에서 채웁니다. 후보가 여럿이면 토막 고르기 창이 뜹니다.

있는 컬럼의 논리명과 도메인도 입력 칸에서 바꿉니다.

[물리명도] 는 기본으로 꺼져 있고, 컬럼을 고를 때마다 꺼진 상태로 돌아옵니다. 켜면 미리보기의 모든 토막이 사전과 맞을 때 물리명도 미리보기 물리명으로 바꿉니다. 가져온 컬럼의 물리명을 바꾸면 모델이 DB 와 달라집니다. 그래서 켰을 때 물리명이 달라지면 미리보기 줄에 `물리명도 MENU_NM → MENU_NAME 으로 바뀝니다(DB 와 달라짐)` 같은 경고가 나옵니다. 경고가 없는데 물리명이 안 바뀌면 토막 중에 아직 확정하지 않은 것이 있는 경우입니다.

입력 칸에는 모드가 두 개 있습니다. 입력 칸 위의 [추가]·[이름 바꾸기] 로 바꿉니다.

| 모드 | 언제 기본인가 | `Enter` 의 동작 |
|---|---|---|
| [이름 바꾸기] | 그리드에서 컬럼을 고르면 기본입니다. 다른 컬럼을 고르면 다시 기본으로 돌아옵니다 | 고른 컬럼의 논리명을 바꿉니다 |
| [추가] | 컬럼을 고르지 않았을 때, 또는 [추가] 를 직접 골랐을 때 | 새 컬럼을 더합니다 |

1. 그리드에서 컬럼 행을 누르세요. 입력 칸 아래에 그 컬럼의 물리명이 보이고 모드는 [이름 바꾸기] 입니다.
2. 논리명만 바꾸려면 [물리명도] 를 끈 채로 두세요. 처음부터 꺼져 있습니다.
3. 입력 칸에 새 논리명을 넣은 후 `Enter` 나 [논리명 바꾸기] 를 누르세요.
4. 같은 칸으로 새 컬럼을 더하려면 [추가] 로 바꾸거나 `Ctrl+Enter`(Mac 은 `⌘Enter`)를 누르세요. 컬럼을 고른 채 `Enter` 만 눌러 새 컬럼이 생기는 일은 없습니다.
5. 도메인을 바꾸려면 [도메인] 칸에서 찾아 고르세요. [추천] 을 누르면 물리명에 맞는 추천 도메인을 넣습니다.

같은 컬럼을 여러 표에 더하기:

1. 표를 2개 이상 고르세요(아래 "여러 표 고르기").
2. 도구 막대의 [컬럼 추가] 를 누르세요. 마우스를 올리면 `컬럼 추가 — 고른 표 3개에 같은 컬럼` 처럼 보입니다. 고른 표 하나를 오른쪽 단추로 누른 후 [표 n개에 같은 컬럼 추가…] 를 골라도 됩니다. "같은 컬럼 추가 — 표 n개" 창이 열립니다.
3. 논리명을 넣으세요. 예: `비고`. 0.3초 뒤 물리명 칸이 채워지고 "물리명 미리보기 RMK — 사전 기준, 고칠 수 있습니다" 줄이 나옵니다. 사전에 없는 단어가 있으면 물리명을 직접 넣으세요.
4. 창의 목록을 읽으세요. "넣을 표 n개: …" 는 컬럼이 들어갈 표입니다. 같은 물리명의 컬럼이 이미 있는 표(대소문자 무시)는 "같은 물리명이 있어 건너뜀 n개: …" 에 나오고 그대로 둡니다.
5. [추가] 를 누르세요. "RMK 컬럼을 표 2개에 더했습니다." 알림이 나옵니다. 건너뛴 표가 있으면 "(이미 있던 1개 건너뜀)" 이 붙습니다.

- 컬럼은 각 표의 끝, 감사 컬럼 앞에 들어갑니다. PK 컬럼은 아닙니다. PK 컬럼은 표를 하나씩 골라 [PK 추가] 로 넣으세요.
- 감사 컬럼 이름(`C_USR_ID` 등)은 쓸 수 없습니다. 감사 컬럼은 표마다 저절로 붙습니다.
- 한 번에 200개 표까지 넣을 수 있습니다. 넣을 표가 없으면 [추가] 가 꺼집니다.
- 모든 표에 한 번에 들어갑니다. 서버가 거절하면 창 안에 이유가 나오고 어느 표에도 들어가지 않습니다. `Ctrl+Z` 한 번에 모든 표에서 빠집니다.

새 표는 캔버스에서 더합니다.

1. 도구 막대의 [표 추가] 를 누르세요. 캔버스 빈 곳을 누른 후 `2` 를 눌러도 됩니다. 캔버스 위에 "표를 놓을 빈 곳을 누르세요 · Esc 취소" 안내가 나옵니다.
2. 표를 놓을 빈 곳을 누르세요. 빈 곳을 오른쪽 단추로 누른 후 [여기에 표 추가] 를 골라도 됩니다.
3. [새 표] 창에서 논리명을 먼저 넣으세요. 입력을 멈추고 0.3초 뒤 물리명 칸에 사전 기준의 물리명이 저절로 채워지고 "물리명 미리보기 TB_MCM_MENU_AUT — 사전 기준, 고칠 수 있습니다" 같은 줄이 나옵니다. 이름 앞 토막(`TB_MCM_`)은 이 모델의 표들이 가장 많이 쓰는 것을 붙입니다.
4. 물리명 칸을 직접 고치면 자동 채움이 멈춥니다. 사전에 없는 단어가 있으면 "사전에 없는 단어가 있어 물리명을 직접 넣으세요." 가 나옵니다. 그러면 물리명을 직접 넣으세요. 물리명을 넣으면 이 줄은 사라집니다.
5. [만들기] 를 누르세요. 물리명 칸에서 `Enter` 를 눌러도 만들어집니다. 미리보기가 오기 전에는 [만들기] 가 꺼져 있습니다.

만든 직후 창이 닫히기 전 2~4초 동안 "같은 물리명의 표가 이미 있습니다: …" 가 보일 수 있습니다. 방금 만든 표와 견준 글이고, 표는 하나만 만들어졌습니다. 다시 누르지 마세요(미룬 기능 목록 참고).

새 표에는 감사 컬럼 8개가 저절로 붙습니다(4.11절).

표를 오른쪽 단추로 누르면 메뉴가 열립니다. 항목은 컬럼 추가, PK 컬럼 추가, "관계 시작" 묶음의 비식별 관계·식별 관계, "접기" 묶음의 컬럼 모두 보이기·키 컬럼만·표 이름만, 표 다이어그램에서 빼기 (Delete), 표 모델에서 삭제 (⌥⌫), 부모 표로, 자식 표로 입니다. 묶음 제목("관계 시작"·"접기")은 누르는 항목이 아니고, 그 아래 항목을 누릅니다. [비식별 관계]·[식별 관계] 를 고르면 그 표가 부모로 정해지고 자식 표를 누르라는 안내가 나옵니다(4.3절).

고른 표가 여러 개일 때 그중 하나를 오른쪽 단추로 누르면 메뉴가 고른 표 모두에 적용됩니다. 이때 항목은 "접기" 묶음, "정렬" 묶음(4.4절), 표 n개 다른 다이어그램에 넣기…, 표 n개에 같은 컬럼 추가…, 표 n개 다이어그램에서 빼기 (Delete), 표 n개 모델에서 삭제 (⌥⌫) 입니다. 고르지 않은 표를 누르면 그 표가 고른 표에 더해집니다.

도구 막대의 글자 단추는 [표 추가], [관계 ▾], [컬럼 추가], [PK 추가], [정렬 ▾] 입니다. 나머지는 아이콘 단추입니다. 마우스를 올리면 이름과 단축키가 보입니다. 단추가 꺼져 있으면 이름 뒤에 꺼진 이유가 보입니다. 예: `컬럼 추가 — 표를 먼저 고르세요`, `PK 추가 — 표를 하나만 고르세요`, `키 컬럼만 — 표를 먼저 고르세요`, `모델에서 삭제 (⌥⌫) — 표를 먼저 고르세요`, `정렬 — 표를 2개 이상 고르세요`. 확정된 버전에서는 `— 확정된 버전` 이 붙습니다. 표를 여러 개 고르면 접기 3개, [다른 다이어그램에 넣기], [다이어그램에서 빼기], [모델에서 삭제] 의 이름 뒤에 `(표 3개)` 처럼 고른 표 수가 붙습니다.

#### 캔버스에서 바로 고치기

표 노드의 이름이나 컬럼 줄을 그 자리에서 고칠 수 있습니다.

1. 표 이름이나 컬럼 줄의 논리명·물리명을 두 번 누르세요. 줄을 고른 뒤 `F2` 를 눌러도 됩니다.
2. 그 자리에 입력 칸이 열립니다. 값을 고치세요.
3. `Enter` 나 밖을 누르면 저장하고, `Esc` 는 그만둡니다.

- 보이는 칸(논리명 또는 물리명)이 고쳐집니다. 입력 칸은 저장된 값(`***` 포함)으로 시작합니다.
- 물리명은 소문자로 넣어도 대문자로 저장합니다.
- 규칙에 맞지 않는 값이면 입력 칸이 그대로 남고 빨간 테두리가 보입니다. 알림 띠에 이유가 나옵니다.
- 논리명이 비어 있으면 물리명이 흐린 힌트로 보입니다.
- 감사 컬럼 이름으로 바꾸면 [감사 컬럼 보기] 가 저절로 켜집니다.
- 개요 단계(배율 35% 미만)에서 `F2` 를 누르면 「확대」 하라는 안내만 나옵니다.

#### Space 속성 창

표를 하나 고르고 `Space` 를 누르면 그 표의 속성 창이 열립니다. 표를 오른쪽 단추로 눌러 [속성 (Space)] 를 골라도 됩니다. 단추·메뉴에 초점이 있으면 `Space` 는 그 단추를 누르는 키이므로 창이 열리지 않습니다.

| 영역 | 고칠 수 있는 것 |
|---|---|
| 표 | 논리명, 물리명, 설명 |
| 컬럼 | 논리명, 물리명, 도메인(사전 찾기), NULL 허용, PK. 타입·길이·기본값은 컬럼 그리드에서 고칩니다 |
| 키 | UK(고유)·IX 의 종류·이름·컬럼을 고치고 [키 추가] 로 더하고 지웁니다. PK 는 컬럼의 PK 칸으로 정합니다. 키 컬럼 고르는 법은 아래 설명을 보세요 |
| 관계 | 식별 여부, 부모·자식 쪽 기수, DB FK, 판정(그대로·확정·기각), 지우기 |

- 창 안에서 고친 값은 [적용] 을 눌러야 한 번에 반영됩니다. 반영은 변경 하나이므로 `Ctrl+Z` 한 번에 모두 되돌아갑니다.
- 창을 연 뒤 다른 사람이 바꾼 칸은 그대로 두고, 내가 고친 칸을 다른 사람도 바꿨으면 「다시 여세요」 라고 안내합니다.
- 키의 컬럼은 표 안의 칸이 아니라 키 영역 아래의 고르기 칸에서 고릅니다. 키 행의 컬럼 칸(고른 컬럼 이름이 보이는 단추, 비었으면 「컬럼 고르기」)을 누르면 그 아래에 「키 … 의 컬럼」 칸이 열립니다. 칸을 누르거나 글자를 쳐 컬럼을 찾아 고르고, 같은 단추를 다시 누르면 접힙니다. [키 추가] 를 누르면 새 키의 고르기 칸이 바로 열립니다.
- 바깥을 눌러도 창이 닫히지 않습니다. [닫기] 로 닫으세요.
- 읽기 전용이어도 창은 열리고 값만 볼 수 있습니다.
- 캔버스에서 `Space` 를 누른 채 끌어 옮기던 동작은 없어졌습니다. 캔버스는 빈 곳을 끌어 옮기세요.

#### 표·컬럼 복사와 붙여넣기

표 복사:

1. 표를 고르고 `Ctrl+C`(Mac 은 `⌘C`)를 누르세요. 표 메뉴의 [표 복사] 도 같습니다.
2. 캔버스에서 `Ctrl+V`(Mac 은 `⌘V`)를 누르세요. 마우스가 캔버스 위에 있으면 그 자리에, 없으면 원래 표 옆에 놓입니다. 빈 곳 메뉴의 [여기에 붙이기] 도 됩니다.

- 같은 모델 안에서만 붙입니다.
- 이름은 물리명 `<원래>_COPY`, 논리명 「<원래> 복사」 로 바뀝니다. 같은 이름이 있으면 번호가 붙습니다.
- 컬럼(감사 컬럼 포함)·키와, 고른 표끼리 이어진 확정·DB 관계가 함께 복사됩니다. 추정·기각 관계는 복사하지 않습니다. 붙이기 한 번은 되돌리기 한 번입니다.

컬럼 복사:

1. 컬럼 그리드에서 행을 하나 고르고 `Ctrl+C`(`⌘C`)를 누르세요. 한 번에 한 행만 됩니다.
2. 다른 표(또는 같은 표)를 고르고 그리드에서 `Ctrl+V`(`⌘V`)를 누르세요.

- 붙일 표에 같은 물리명의 컬럼이 이미 있으면(같은 표에 붙일 때) 이름 뒤에 `_COPY` 가 붙고 논리명은 「… 복사」 가 됩니다. 같은 이름이 없으면 원래 이름 그대로 들어갑니다.
- 고른 컬럼 바로 뒤에 들어갑니다. 키와 관계는 복사하지 않고 컬럼 값만 복사합니다.

#### 여러 표 고르기

⌘+클릭(Windows 는 Ctrl+클릭, 확인 예정)으로 표를 하나씩 더하고, Shift 를 누른 채 빈 곳을 끌면 사각형 안 표를 모두 고릅니다. 캔버스 빈 곳을 누른 후 `⌘A`(Windows `Ctrl+A`)를 누르면 이 다이어그램의 표를 모두 고릅니다. 입력 칸에 초점이 있으면 `⌘A` 는 칸의 글자를 고릅니다. 고른 표를 함께 끌면 한 번에 옮겨지고 ⌘Z 한 번에 되돌아갑니다.

여러 개를 고르면 속성 패널은 한 표만 보이고, 머리 글이 `속성 · 고른 표 5개 중 TB_MCM_WIDGET_DEF` 처럼 바뀝니다. 다른 다이어그램을 열면 고른 표가 풀리고 속성 패널이 닫힙니다.

- [컬럼 추가] 는 같은 컬럼 창을 엽니다(위 "같은 컬럼을 여러 표에 더하기"). [PK 추가] 는 꺼집니다.
- `Delete` 는 고른 표를 모두 다이어그램에서 뺍니다. 한 번에 빼고 ⌘Z 한 번에 되돌아옵니다.
- 모델에서 삭제(`Alt+Delete`)도 고른 표 모두에 적용됩니다(4.4절).
- 정렬, 다른 다이어그램에 넣기, 접기는 4.4절 "여러 표 한 번에 다루기" 를 보세요.

### 4.3 관계 만들기

관계를 그으면 서버가 부모 표의 PK 컬럼을 자식 표에 복사합니다. 식별 관계면 복사한 컬럼을 자식 표의 PK 에도 넣습니다.

1. 도구 막대의 [관계 ▾] 를 누르세요. 메뉴에 "비식별 관계 (4)" 와 "식별 관계 (5)" 가 있습니다. 캔버스 빈 곳을 누른 후 `4` 나 `5` 를 눌러도 됩니다. 아이콘 단추([비식별 관계]·[식별 관계])도 있습니다.
2. 캔버스 위 안내 줄을 읽으세요. 시작 전에는 "부모 표에서 자식 표로 끌거나, 부모 표 → 자식 표 순서로 누르세요 · Esc 취소" 입니다. 식별 관계이면 앞에 "식별 관계:" 가 붙습니다.
3. 부모 표를 누른 후 자식 표를 누르세요. 부모 표에서 자식 표로 끌어도 됩니다. 부모 표를 누르면 안내 줄이 "자식 표를 누르세요 · Esc 취소" 로 바뀝니다.
4. 표를 오른쪽 단추로 눌러 메뉴의 "관계 시작" 아래 [비식별 관계]·[식별 관계] 를 골라도 시작할 수 있습니다. 그 표가 부모가 되고 자식 표를 누르면 됩니다. `Esc` 를 누르면 취소됩니다.
5. "같은 이름의 컬럼" 창이 뜨면 고르세요.
   - [있는 컬럼 쓰기]: 자식 표에 이미 있는 같은 이름의 컬럼을 관계 컬럼으로 씁니다.
   - [새 컬럼 만들기]: 부모 표 접두를 붙인 컬럼을 새로 만듭니다.
   - 고른 방식은 그 관계의 모든 컬럼에 같이 쓰입니다.

관계가 생기면 도구가 선택 도구로 돌아옵니다.

같은 표를 부모와 자식으로 고르면(자기 참조) 관계가 만들어지지 않고 "같은 표 안의 관계(자기 참조)는 아직 화면에서 그릴 수 없습니다. Claude 나 CLI 의 addRelation 으로 만드세요." 알림이 나옵니다.

관계선의 꺾임점(경유점)을 손으로 정할 수 있습니다. 선이 다른 표를 지나가거나 겹칠 때 씁니다. 선은 모서리가 둥근 꺾은선으로 그려집니다. 선분 막대로 옮기면 직각이 유지됩니다. 점을 자유롭게 옮기면 비스듬한 선분이 생길 수 있습니다.

선에 마우스를 올리거나 선을 누르면 손잡이가 나타납니다. 손잡이는 세 가지입니다.

- 저장한 꺾임점: 손으로 정한 점입니다.
- 자동 경로 점: 꺾임점이 없는 선에서 자동 경로가 꺾이는 자리입니다.
- 선분 막대: 가로나 세로 선분 가운데에 있는 막대입니다.

| 하고 싶은 일 | 방법 |
|---|---|
| 선 고르기 | 선을 누르세요. 선이 강조되고 손잡이가 나타납니다 |
| 선분 통째로 옮기기 | 선분 막대를 끄세요. 선분이 수직으로만 움직입니다. 이웃 선분과 6px 안이면 일직선으로 맞춰집니다 |
| 꺾임점 옮기기 | 점 손잡이를 끄세요. 자유롭게 움직이고, 이웃 점과 가로나 세로가 화면에서 6px 안으로 가까우면 안내선이 나타나 맞춰집니다. `Alt` 를 누른 채 끌면 맞추지 않습니다 |
| 꺾임점 만들기 | 선을 두 번 누르세요. 누른 자리에 점이 생깁니다. 꺾임점이 없는 선이면 자동 경로의 꺾임을 이어받고 점이 하나 더해집니다. 자동 경로 점이나 막대를 끌어도 점이 저장됩니다 |
| 꺾임점 지우기 | 점 손잡이를 두 번 누르거나, 점을 고른 채 `Delete` 나 `Backspace` 를 누르세요. 이웃 점이 고른 채로 남아서 계속 누르면 점이 차례로 지워집니다 |
| 자동 경로로 되돌리기 | 선을 오른쪽 단추로 눌러 [자동 경로로 되돌리기] 를 고르세요. 꺾임점이 모두 사라집니다 |

- 한 선에 꺾임점 50개까지 둘 수 있습니다. 넘으면 "꺾임점은 한 선에 50개까지입니다." 알림이 나옵니다.
- 점을 고르지 않은 채 `Delete` 나 `Backspace` 를 누르면 고른 표가 다이어그램에서 빠집니다.
- 꺾임점은 다이어그램마다 따로 저장됩니다. 같은 관계라도 다른 다이어그램에서는 자동 경로입니다.
- 꺾임점은 캔버스의 절대 위치입니다. 표를 손으로 옮기거나 정렬해도 꺾임점은 그 자리에 남습니다.
- [자동 배치] 는 옮겨진 표에 걸린 관계의 꺾임점을 지웁니다. 되돌리기 한 번에 표 위치와 꺾임점이 함께 돌아옵니다.
- 선분 막대를 끌어 앞뒤와 한 줄이 되거나 겹친 꺾임점은 놓을 때 저절로 지워집니다. 모두 지워지면 자동 경로가 됩니다.
- 비스듬하거나 너무 짧은 선분에는 막대가 나타나지 않습니다. 점 손잡이를 끄세요.
- 관계를 지우면 그 관계의 꺾임점도 함께 지워집니다. 되돌리기 한 번에 모두 돌아옵니다.
- 개요 단계(배율 35% 미만)에서는 손잡이가 보이지 않습니다. 확대해서 고치세요.
- 선 위에서 끌면 캔버스가 움직이지 않고 손잡이 끌기가 됩니다. 캔버스를 옮기려면 빈 곳을 끄세요.
- 확정된 버전에서도 다이어그램 편집 권한이 있으면 꺾임점을 고칠 수 있습니다.

예: `TB_MCM_SEC_MENU` 의 `OBJECT_ID` 가 `TB_MCM_SEC_OBJ`(PK `OBJECT_ID`)를 가리키게 하려면 부모 `TB_MCM_SEC_OBJ`, 자식 `TB_MCM_SEC_MENU` 순서로 누르세요. 자식 표에 `OBJECT_ID` 가 이미 있으므로 [있는 컬럼 쓰기] 를 고르세요. 같은 관계가 추정 관계로 이미 있으면 새로 긋지 말고 4.1절에서 [맞음] 을 누르세요. 같은 자식 표·부모 표·컬럼 짝의 관계가 이미 있으면 상태와 상관없이([아님] 으로 판정한 관계 포함) 규칙 위반으로 거절됩니다. [아님] 으로 판정한 관계를 살리려면 변경 기록에서 그 판정을 되돌리세요.

### 4.4 다이어그램 만들기와 배치

새 다이어그램은 마법사로 만듭니다.

1. 왼쪽 패널에서 [새 다이어그램] 을 누르세요.
2. 1단계에서 업무영역과 다이어그램 이름을 넣으세요. 예: 업무영역 `보안`, 이름 `메뉴·권한`.
3. 2단계에서 표를 고르세요. 거르기 칸에 `TB_MCM_SEC_` 를 넣은 후 [보이는 표 모두 고르기] 를 누르면 보안 표를 한 번에 고릅니다.
4. 3단계에서 배치 방식을 고르세요. [자동 배치] 는 관계를 따라 부모 표를 왼쪽에 두고, [격자] 는 물리명 순으로 줄지어 둡니다.
5. [만들기] 를 누르세요. 새 다이어그램이 열립니다.

같은 업무영역에 같은 이름의 다이어그램은 만들 수 없습니다.

왼쪽 패널의 다이어그램 목록에서 다이어그램을 오른쪽 단추로 누르면 메뉴가 열립니다.

| 항목 | 하는 일 |
|---|---|
| 이름 바꾸기 | 업무영역과 이름을 고칩니다 |
| 복사 | 이름 기본값 「<이름> 복사」(겹치면 번호)로 새 다이어그램을 만듭니다. 표 위치·접기와 관계선 꺾임점이 함께 복사되고, 끝나면 새 다이어그램이 열립니다 |
| 지우기 | 다이어그램을 지웁니다. 모델의 표는 남습니다. 지운 뒤 [되돌리기] 를 누르면 꺾임점까지 돌아옵니다 |

다이어그램 편집 권한이 있어야 합니다. 확정된 버전에서도 소유자와 공동 편집자는 쓸 수 있습니다.

배치는 다음처럼 고칩니다.

- 표를 끌어 옮기세요. 놓을 때 위치가 저장됩니다.
- 도구 막대의 [자동 배치] 를 누르거나 빈 곳을 오른쪽 단추로 누른 후 [자동 배치] 를 고르세요. "자동 배치했습니다. ⌘Z 로 되돌릴 수 있습니다." 알림이 나옵니다. Windows 에서는 `Ctrl+Z` 입니다. 이미 그 배치대로 놓여 있으면 "이미 자동 배치대로 놓여 있습니다." 가 나옵니다.
- 자동 배치는 관계로 이어진 표 묶음마다 부모를 왼쪽에 두고, 묶음과 외톨이 표를 캔버스의 가로세로 비에 맞춰 여러 줄로 놓습니다. 묶음이 세로로 쌓이는 경우가 있어 결과 모양이 캔버스 비와 덜 맞을 수 있습니다(미룬 기능 목록 참고). 저장된 배치에 반영하려면 소유자나 공동 편집자가 [자동 배치] 를 한 번 눌러야 합니다.
- 표를 고른 후 도구 막대의 접기 단추([컬럼 모두 보이기], [키 컬럼만], [표 이름만])를 누르세요. 표를 오른쪽 단추로 눌러 [접기] 메뉴를 써도 됩니다. 여러 개를 고르면 고른 표 모두가 접힙니다.

#### 여러 표 한 번에 다루기

표를 여러 개 고르는 방법은 4.2절 "여러 표 고르기" 에 있습니다. 아래 동작은 표 수와 상관없이 한 번에 저장되고 `Ctrl+Z` 한 번에 모두 되돌아갑니다.

줄 맞추기와 간격 맞추기는 [정렬 ▾] 로 합니다.

1. 표를 2개 이상 고르세요.
2. 도구 막대의 [정렬 ▾] 를 누르세요. 고른 표 하나를 오른쪽 단추로 누른 후 "정렬" 묶음을 써도 됩니다.
3. 항목을 고르세요.

| 항목 | 결과 | 고를 표 |
|---|---|---|
| 왼쪽 맞춤, 가운데 맞춤, 오른쪽 맞춤 | 고른 표 전체를 감싼 상자의 왼쪽 끝·가운데·오른쪽 끝에 맞춥니다 | 2개 이상 |
| 위쪽 맞춤, 중간 맞춤, 아래쪽 맞춤 | 감싼 상자의 위 끝·가운데·아래 끝에 맞춥니다 | 2개 이상 |
| 가로 간격 같게, 세로 간격 같게 | 양 끝 표는 두고 사이 표를 옮겨 표 사이 빈 칸을 같게 합니다. 빈 칸이 40 보다 좁아지면 40 으로 펼치고, 이때는 마지막 표도 옮겨집니다 | 3개 이상 |

- 2개만 고르면 간격 항목이 꺼지고, 마우스를 올리면 "표를 3개 이상 고르세요" 가 보입니다.
- 이미 그 모양이면 "이미 맞춰져 있습니다." 알림만 나오고 아무것도 바뀌지 않습니다.
- 정렬은 실제 표 크기로 계산합니다. 배율이 낮아 표 이름만 보일 때(배율 약 50% 미만)는 화면의 이름 상자끼리 줄이 안 맞아 보일 수 있습니다. 확대하면 맞습니다.

고른 표를 다른 다이어그램에도 놓으려면 [다른 다이어그램에 넣기] 를 씁니다.

1. 표를 1개 이상 고르세요.
2. 도구 막대의 [다른 다이어그램에 넣기] 아이콘 단추를 누르세요. 고른 표 하나를 오른쪽 단추로 누른 후 [표 n개 다른 다이어그램에 넣기…] 를 골라도 됩니다.
3. 창의 [넣을 다이어그램] 에서 대상을 고르세요. 안내 줄이 "표 2개를 넣습니다. 이미 있는 1개는 그대로 둡니다." 처럼 바뀝니다. 고른 표가 모두 대상에 있으면 "고른 표가 모두 그 다이어그램에 이미 있습니다." 가 나오고 [넣기] 가 꺼집니다.
4. [넣기] 를 누르세요. "표 2개를 「주제별 / UX15 대상」에 넣었습니다(이미 있던 1개 뺌)." 알림이 나옵니다.

- 대상에 이미 있는 표는 자리를 바꾸지 않습니다.
- 새로 넣은 표는 고른 표끼리의 배치를 그대로 두고, 대상 다이어그램 표들의 오른쪽에 놓입니다.
- 지금 다이어그램에서는 빠지지 않고, 화면도 지금 다이어그램에 머뭅니다.
- 다른 다이어그램이 없으면 단추가 꺼집니다.

표를 지우는 방법은 둘입니다.

| 동작 | 키 | 결과 |
|---|---|---|
| 다이어그램에서 빼기 | `Delete` 또는 `Backspace` | 고른 표를 모두 이 다이어그램에서만 숨깁니다. 모델과 다른 다이어그램에는 남습니다. 한 번에 빼고 `Ctrl+Z` 한 번에 되살아납니다 |
| 모델에서 삭제 | `Alt+Delete`(Mac 은 `⌥⌫`) | 고른 표 모두가 대상입니다. 확인 창에 "표 3개를 모델에서 지웁니다." 와 물리명 목록이 나옵니다. [삭제] 를 누르면 컬럼·키·딸린 관계까지 모델에서 지웁니다 |

모델에서 삭제는 한 번에 200개까지입니다. `Ctrl+Z` 나 변경 기록의 [되돌리기] 로 한 번에 되살릴 수 있습니다.

표가 많은 모델은 [주제별로 나누기] 로 작은 다이어그램 여러 개를 만들 수 있습니다.

1. 도구 막대의 [주제별 나누기] 를 누르세요. 빈 곳을 오른쪽 단추로 누른 후 [주제별로 나누기…] 를 골라도 됩니다.
2. 창에서 묶음 미리보기를 읽으세요. 묶음마다 이름, 표 수, 앞 표 3개가 보입니다. 만들 묶음만 체크하세요.
3. 업무영역 이름을 확인하세요. 기본값은 `주제별` 이고 고칠 수 있습니다.
4. [만들기] 를 누르세요. 만든 다이어그램 중 첫 번째가 열립니다.

묶는 규칙은 다음과 같습니다.

- 표 물리명에서 모델 접두(`TB_MCM_` 처럼 `TB_<모듈>_`)를 뺀 첫 토막이 같은 표끼리 묶습니다. 예: `TB_MCM_SEC_MENU` 는 `SEC` 묶음입니다.
- 20개를 넘는 묶음은 관계로 이어진 덩어리끼리 나눕니다. 그래도 20개를 넘으면 물리명 순으로 20개씩 잘라 `SEC 1`·`SEC 2` 처럼 이름을 붙입니다.
- 5개 미만인 묶음은 관계가 가장 많이 걸린 다른 묶음에 붙입니다. 합쳐서 20개 이하일 때만 붙입니다. 붙일 곳이 없으면 `기타` 로 모아 20개씩 만듭니다.
- 같은 입력이면 늘 같은 묶음이 나옵니다.
- 같은 업무영역에 같은 이름의 다이어그램이 이미 있으면 그 묶음은 꺼지고 "이미 있음" 이 보입니다.
- 일부만 만들어지면 "n개 만들었습니다. 나머지는 만들지 못했습니다." 가 보입니다.

나눈 뒤에는 보통 다이어그램처럼 고칩니다. 묶음 이름 바꾸기와 표 옮기기는 아직 없습니다. 다음에 그 모델을 열면 마지막으로 본 다이어그램이 먼저 열리고, 없으면 표가 30개 이하인 첫 다이어그램이 열립니다. 권한은 다이어그램 편집 권한입니다.

다이어그램 편집(배치·접기·빼기)은 확정된 버전에서도 소유자와 공동 편집자가 할 수 있습니다. 모델 편집(표·컬럼·관계)은 DRAFT 에서만 됩니다.

#### 표 크기 조절
편집할 수 있을 때 표를 하나 고르면 표의 오른쪽 가장자리, 아래 가장자리, 오른쪽 아래 모서리에 크기 손잡이가 보입니다. 손잡이를 끌어 너비와 높이를 바꾸세요.

- 끄는 동안에는 화면만 바뀝니다. 놓을 때 한 번 저장됩니다. [되돌리기] 나 `Ctrl+Z` 로 이전 크기로 돌아갑니다.
- 크기는 다이어그램마다 따로 저장됩니다. 같은 표도 다이어그램마다 크기가 다를 수 있습니다.
- 너비를 넓히면 기본 너비에서 잘리던 긴 표 이름이 모두 보입니다.
- 크기 범위는 너비 160~1600, 높이 52~4000 입니다(캔버스 단위 px).
- 높이가 필요한 높이보다 작으면 PK 컬럼은 머리 아래에 고정되고, 나머지 컬럼은 표 안에서 스크롤됩니다. 이때 마우스 휠은 캔버스가 아니라 컬럼 목록을 스크롤합니다.
- 표마다 줄일 수 있는 최소 높이가 있습니다. 머리, PK 컬럼, 일반 컬럼 한 줄, 「▾ N개 더」 막대가 들어갈 높이보다 작게는 줄지 않습니다. 일반 컬럼이 1개 이하인 표는 자동 높이보다 작게 줄지 않습니다.
- 높이를 줄여 「▾ N개 더」 막대가 보이는 표에서는 일반 컬럼에 걸린 관계선이 표 머리에 붙습니다. PK 컬럼의 관계선은 그대로 그 컬럼에 붙습니다.
- 숨은 컬럼이 있으면 표 아래에 「▾ N개 더」 막대가 보입니다. 막대를 누르면 높이가 자동 크기로 돌아옵니다(되돌릴 수 있음). 모두 보이면 막대가 없습니다.
- 접힌 표는 접기 동작이 먼저입니다. 저장된 높이는 쓰지 않고 너비만 적용합니다.
- 표를 옮기거나 접거나 자동 배치해도 크기는 그대로입니다. 다이어그램을 복사하면 크기도 복사됩니다. 표를 다이어그램에서 뺀 후 되돌리면 크기도 돌아옵니다.
- 여러 표를 한꺼번에 키우는 기능은 없습니다. 표를 하나씩 조절하세요.
- Claude(MCP)·CLI 에서는 `resizeNodes` 명령(`diagram`, `nodes:[{table, w, h}]`)으로 바꿉니다. `w`·`h` 를 null 로 두면 그 방향은 자동 크기입니다.

### 4.5 표준 상태 보고 고치기

1. 아래 탭 줄에서 [표준 위반(n)] 탭을 누르세요. 검토 패널이 열립니다.
2. 행을 누르세요. 그 표가 선택되고 속성 패널에서 그 컬럼의 행이 골라집니다. 입력 칸의 대상도 그 컬럼이 됩니다. (다른 표의 속성 패널이 열려 있을 때 첫 클릭에서 입력 칸 대상이 비는 일이 있습니다. 같은 행을 한 번 더 누르세요.)
3. 상태에 맞게 고치세요.

이 탭의 건수 `n` 은 "고칠 위반" 수입니다. 규칙은 하나입니다. 상태가 TYPE·DOMAIN·MISS 인 컬럼만 셉니다. NEW·ALIAS 는 이 탭에 나오지 않고 그리드 배지로만 보입니다. 감사 컬럼은 도구 막대의 [감사 컬럼 보기] 를 켰을 때만 셉니다. 위 막대의 요약 줄, 왼쪽 목록의 붉은 수, 표 머리의 붉은 수, 이 탭의 건수가 모두 이 규칙을 씁니다.

| 상태 | 고치는 방법 |
|---|---|
| MISS(사전 없음) | 논리명을 사전 단어로 바꾼 후 [논리명 바꾸기] 를 [물리명도] 와 함께 누르세요. 표준 용어 등록이 필요하면 표준 담당에게 요청하세요 |
| DOMAIN(도메인 다름) | [추천] 으로 맞는 도메인을 넣거나, 타입 칸을 도메인 타입에 맞게 고치세요. 위반 행에는 도메인 이름만 보여 같아 보일 수 있습니다. 다른 것은 타입과 길이입니다. 6절의 대응 표로 확인하세요 |
| TYPE(타입 불일치) | 같은 물리명을 쓰는 다른 표의 컬럼과 타입을 같게 맞추세요. 새 컬럼의 타입을 도메인에서 가져올 때 길이 없는 STRING 도메인은 CLOB 이 되어 기존 컬럼과 어긋날 수 있습니다 |
| NEW(새 이름) | 단어는 사전에 있지만 컬럼 사전에 없는 이름입니다. 컬럼 사전에 등록하면 OK 가 됩니다. 이 화면에서는 등록하지 않고 위반 탭에도 나오지 않습니다 |

표준 상태는 표나 컬럼이 바뀌고 0.5초 뒤 다시 읽습니다.

### 4.6 DB 다시 가져오기 반영

모델을 가져온 뒤 DB 가 바뀌었으면 차이를 골라 모델에 넣습니다.

1. 아래 탭 줄에서 [DB 다시 가져오기] 탭을 누르세요. 탭 이름에 차이 수가 붙습니다.
2. DB 를 바꾼 직후면 [새로 읽기] 를 누르세요.
3. 반영할 행의 체크박스를 고르세요. 고르기 전에는 [고른 항목 가져오기] 가 꺼져 있고, 마우스를 올리면 "항목을 먼저 고르세요." 가 보입니다.
4. [고른 항목 가져오기] 를 누르세요.
5. 표나 컬럼을 지우는 항목이 있으면 확인 창이 뜹니다. 내용을 읽은 후 확인하세요.

| 종류 | 뜻 |
|---|---|
| DB 에 생긴 표 / DB 에서 사라진 표 | 표 추가·삭제. 모델에서 새로 만든 표(DB 에 없던 표)도 "DB 에서 사라진 표" 로 보입니다. 이 경우 삭제 항목은 고르지 마세요 |
| DB 에 생긴 컬럼 / DB 에서 사라진 컬럼 | 컬럼 추가·삭제 |
| 컬럼 다름 | 모델과 DB 의 타입·NN 이 다름 |
| DB 에 생긴 FK / DB 에서 사라진 FK | DB FK 추가·해제 |

- "DB 에 생긴 FK" 를 고르면 그 FK 에 필요한 표·컬럼 추가 항목도 함께 보냅니다. 안내 줄에 "(FK 에 딸린 n건 포함)" 이 보입니다.
- 한 번에 500건까지 반영합니다.
- [맞음]·[아님] 으로 판정한 관계 상태는 그대로 둡니다.
- 반영은 번호(rev) 하나로 들어갑니다. `Ctrl+Z` 로는 되돌리지 못합니다. 변경 기록에서 그 번호의 [되돌리기] 를 누르세요.
- 고르는 동안 DB 차이가 바뀌어 "넣을 수 없습니다" 가 나오면 화면이 차이를 다시 읽습니다. 다시 고르세요.

### 4.7 되돌리기

| 방법 | 대상 |
|---|---|
| `Ctrl+Z`(Mac 은 `⌘Z`) | 이 브라우저 탭에서 내가 반영한 마지막 변경. 누를 때마다 하나씩 앞으로 갑니다 |
| 변경 기록 탭의 [되돌리기] | 최근 100개 변경 가운데 고른 변경 하나. 남의 변경과 DB 차이 반영도 됩니다 |

여러 표를 한 번에 바꾼 변경(함께 끌기, 정렬, 다른 다이어그램에 넣기, 같은 컬럼 추가, 접기, 빼기, 모델에서 삭제)은 변경 하나입니다. 표 수와 상관없이 `Ctrl+Z` 한 번에 모두 되돌아갑니다.

관계선 꺾임점을 바꾼 것, 표 복사·붙여넣기, Space 속성 창의 [적용] 도 변경 하나입니다.

`Ctrl+Z` 를 여러 번 누를 때는 "변경을 되돌렸습니다." 알림을 본 후 다음 번을 누르세요. 다시 하기가 없어서, 너무 많이 되돌렸으면 변경 기록 탭에서 되돌린 행의 [되돌리기] 를 눌러 살려야 합니다.

1. 아래 탭 줄에서 [변경 기록] 탭을 누르세요. 최근 변경이 위에 있습니다.
2. 행의 칸을 읽으세요. 시각(오늘이면 `14:03`, 다른 날이면 `10-11 14:03`), 번호, 사람(내 세션은 "나", 다른 사람은 사용자 ID), 출처(화면·Claude·CLI·시스템), 내용입니다. 내용에는 바뀐 요소 이름이 최대 2개 나오고 더 있으면 "외 n" 이 붙습니다. 감사 컬럼은 "감사 컬럼 8" 처럼, 표 자리 이동은 "표 자리 1" 처럼 따로 셉니다. 사람 칸에 마우스를 올리면 세션과 출처가 보입니다.
3. 되돌릴 행의 [되돌리기] 를 누르세요. 꺼져 있으면 마우스를 올려 이유를 읽으세요.

되돌리면 "변경을 되돌렸습니다." 알림이 나옵니다. 되돌리기는 역명령을 새 번호로 넣습니다. 그래서 되돌린 기록도 변경 기록에 남고, 되돌린 행의 내용 글이 원래 행과 같게 보입니다. 되돌리지 못하는 경우는 9.3절에 있습니다. 다시 하기(redo)는 없습니다. 되돌릴 내 변경이 없으면 `Ctrl+Z` 는 "되돌릴 내 변경이 없습니다." 알림을 냅니다.

[새 버전] 으로 만든 DRAFT 는 다시 읽기 지점(새 DRAFT 를 만든 번호)부터 기록이 보입니다. 이때 탭 위에 "번호 n 에 다시 읽기 지점이 있어 그 앞의 기록은 보이지 않습니다." 가 나옵니다. 보이는 행은 [되돌리기] 를 쓸 수 있습니다.

입력 칸에 초점이 있으면 `Ctrl+Z` 는 입력 칸의 글자를 되돌립니다. 모델을 되돌리려면 캔버스를 누른 후 누르세요.

### 4.8 확정하기

확정은 DRAFT 소유자만 합니다.

1. 위 막대의 [버전 ▾] 를 열고 [확정] 을 누르세요. 팝오버가 닫히고 확정 창이 열려 확정 전 검사를 합니다.
2. 요약 줄 "확정을 막는 문제 n건 · 확인할 경고 n건 · 검토 안 한 추정 관계 n건(확정을 막지 않음)" 을 읽으세요.
3. 막는 문제가 있으면 창을 닫고 고친 후 다시 [확정] 을 누르세요. 창에는 "이번 버전에서 넣거나 바꾼 컬럼이 표준에 맞지 않아 확정할 수 없습니다. 고친 뒤 다시 확정하세요." 가 나옵니다.
4. 경고만 있으면 [경고 n건을 확인했습니다] 를 고르세요. 경고 목록에는 "기존 위반과 감사 컬럼 위반입니다. 확정을 막지 않습니다. 확인했으면 아래를 고르세요." 가 나옵니다.
5. [적용 시작] 칸을 확인하세요. 기본값은 창을 연 시각이고 형식은 `yyyy-MM-dd HH:mm:ss` 입니다.
6. [확정] 을 누르세요. 성공하면 "버전 1.001 를 확정했습니다." 알림이 나옵니다.

- 확정 창의 묶음 이름은 한국어입니다. "사전 없음 · n건", "도메인 다름 · n건", "타입 불일치 · n건" 입니다. 행은 `표.컬럼 (논리명)` 모양이고 감사 컬럼 행에는 "· 감사 컬럼" 이 붙습니다. 검토 안 한 추정 관계는 묶음 없이 요약 줄의 건수로만 나옵니다.
- 첫 확정(이전 RELEASED 가 없는 버전)은 표준 위반을 모두 경고로만 알립니다. 가져온 모델은 경고가 수백 건 나옵니다(MCM 약 737건, MDM 약 657건).
- 두 번째 확정부터는 이번 버전에서 더하거나 바꾼 컬럼이 TYPE·DOMAIN·MISS 이면 오류로 막습니다. 바꾸지 않은 컬럼의 위반은 경고입니다.
- 감사 컬럼 8개의 표준 위반은 첫 확정이든 두 번째 확정이든 늘 경고입니다. 새 표를 만들면 감사 컬럼이 저절로 붙고 그 컬럼에 DOMAIN 위반이 나올 수 있어서, 막지 않고 경고로만 알립니다.
- "바꾼 컬럼" 은 속성 하나라도 바뀐 컬럼입니다. 논리명이나 주석만 바꿔도 바꾼 컬럼입니다. 그래서 기존 위반 컬럼의 논리명만 고쳐도 그 컬럼의 경고가 오류가 됩니다. 기존 위반 컬럼을 건드렸으면 위반까지 함께 고치세요. 감사 컬럼은 예외입니다.
- 창은 코드별로 묶어 코드마다 처음 50건만 보입니다. 그 뒤는 "… n건 더 있습니다." 로 줄입니다.
- 적용 시작을 미래 시각으로 넣으면 그 시각 전까지 이 모델의 새 버전을 만들 수 없습니다(MDM006).

### 4.9 새 버전, 선점, 공동 편집자

아래 단추는 모두 위 막대의 [버전 1.000 · 작성 중 ▾] 를 눌러 열리는 팝오버 안에 있습니다. 팝오버 맨 위에 `번호 n` 이 보입니다. [확정] 이나 [공동 편집자(n)] 를 누르면 팝오버가 닫히고 그 창이 열립니다. 확정할 수 없는 상태의 [확정] 은 회색으로 꺼져 있고, 마우스를 올리면 이유가 보입니다.

| 단추 | 하는 일 | 할 수 있는 사람 |
|---|---|---|
| [새 버전(major)] / [새 버전(minor)] | 마지막 RELEASED 를 복사해 새 DRAFT 를 만듭니다. 만든 사람이 소유자가 됩니다 | DRAFT 가 없을 때, 권한이 있는 사람 |
| [삭제] | DRAFT 를 지웁니다 | DRAFT 소유자 |
| [선점] / [해제] | 소유자가 없는 DRAFT 를 가져오거나 내놓습니다 | 선점은 권한이 있는 사람, 해제는 소유자 |
| [넘기기(준비 중)] | 쓸 수 없습니다(담당자 조회가 아직 없습니다) | - |
| [공동 편집자(n)] | 목록을 보고, 사용자 ID 를 더하거나 뺍니다 | 목록은 누구나, 변경은 DRAFT 소유자 |

DRAFT 가 없어 확정된 버전을 보고 있을 때 표·컬럼·관계를 처음 고치면 화면이 [새 버전(minor)] 과 같은 DRAFT 를 저절로 만들고 그 변경을 넣습니다. 새 버전을 만들 권한이 없으면 읽기 전용 그대로이고, 서버가 만들기를 거절하면 그 문구가 그대로 보입니다. DRAFT 가 있으면 늘 DRAFT 를 보여 줍니다. 위 막대에는 [기준본으로 저장] 단추 하나만 있고, 이력·새 버전·선점·공동 편집자는 [버전 ▾] 안에 있습니다. [기준본으로 저장] 은 [확정] 과 같은 일입니다.

> 경고: DRAFT 를 [삭제] 하면 그 버전에서 고친 모델과 다이어그램이 모두 사라집니다. 되돌릴 수 없습니다. 지우기 전에 확인 창의 버전 번호를 확인하세요.

공동 편집자는 버전마다 따로 둡니다. 새 버전을 만들면 공동 편집자 목록이 비어 있으므로 다시 더하세요. Claude 세션을 공동 편집자로 더할 때는 그 세션의 `ERD_USER` 값(기본 `erd-mcp`)을 넣으세요.

### 4.10 새 모델 등록과 첫 가져오기

샘플이 아닌 다른 스키마를 가져올 때만 합니다.

1. 위 막대에서 [+ 모델] 을 누르세요. 시작 화면의 [새 모델 등록] 을 눌러도 됩니다.
2. [새 모델 등록] 창의 칸 4개를 채운 후 [등록] 을 누르세요. 칸마다 라벨이 있고 흐린 예시(`mcm`·`mcm`·`MCMAPUSER`·`MCM 스키마`)가 보입니다. 예: 모델 ID `mls`, 모듈 `mls`, 스키마 `MLSAPUSER`, 모델 이름 `MLS 스키마`. 모델 ID 와 모듈은 보통 같고, 모듈은 모델 ID 를 따라 바뀝니다(직접 고치면 멈춥니다). 스키마 칸은 DB 사용자 목록에서 고릅니다. 목록을 읽지 못하거나 비어 있으면 직접 입력합니다.
3. 등록하면 "모델 mls 를 등록했습니다. [DB 에서 가져오기] 로 스키마를 가져오세요." 알림이 나옵니다. 새 모델 단추가 선택되면 [DB 에서 가져오기] 를 누르세요. 등록에 실패하면 창이 열린 채 입력이 남습니다.

등록한 사람이 첫 DRAFT(1.000)의 소유자가 됩니다. 가져오기가 끝나면 알림에 표·컬럼·키·관계 수가 나옵니다. 모듈 하나에는 모델 하나만 둘 수 있습니다.

모델 목록 관리와 삭제는 위 막대의 [모델 관리] 로 합니다.

1. 위 막대에서 [모델 관리] 를 누르세요. 모델 목록 창이 열립니다.
2. 목록에서 모델을 고르세요. 상태(생성·사용 중·사용 중지), 최신 확정본 버전, 등록자가 보입니다.
3. [열기] 를 누르면 그 모델이 열립니다.
4. 지우려면 [삭제] 를 누르세요. 확인 창에서 모델 ID 를 그대로 입력해야 [삭제] 가 켜집니다.

> 경고: 모델 삭제는 되돌릴 수 없습니다. 모든 버전, 다이어그램, 꺾임점, 변경 기록이 지워집니다. 모델 ID 를 확인한 뒤 지우세요.

- 관리자(역할 `MDM_STD_ADMIN` 또는 `SYSADMIN`)는 확정본이 있어도 지울 수 있습니다.
- 관리자가 아니면 내가 DRAFT 소유자이고 확정(RELEASED·REQUESTED·APPROVED)된 버전이 하나도 없을 때만 지울 수 있습니다. 그 밖은 서버의 거절 문구가 그대로 보입니다.
- 다른 사람이 열고 있는 모델을 지우면, 그 사람 화면에는 알림이 나온 뒤 시작 화면으로 돌아갑니다.
- 모델 삭제는 Claude(MCP)에서는 할 수 없고 화면과 CLI(`delete-model --yes`)에서만 됩니다.

### 4.11 감사 컬럼

감사 컬럼은 누가 언제 어느 서비스와 프로그램으로 행을 만들고 고쳤는지 남기는 컬럼입니다. 이름은 다음 8개이고, 대소문자를 가리지 않습니다.

| 만든 쪽 | 고친 쪽 | 뜻 |
|---|---|---|
| `C_USR_ID` | `U_USR_ID` | 사용자 ID |
| `C_AT` | `U_AT` | 일시 |
| `C_SVC_ID` | `U_SVC_ID` | 서비스 ID |
| `C_PGM_ID` | `U_PGM_ID` | 프로그램 ID |

`VER` 는 감사 컬럼이 아닙니다.

- 캔버스의 표 노드와 컬럼 그리드는 감사 컬럼을 처음에 숨깁니다.
- 숨긴 표 노드에는 `감사 n` 배지가 보입니다. n 은 그 표에서 숨긴 감사 컬럼 수입니다. 컬럼 그리드 제목 옆에는 `감사 n 숨김` 이 보입니다.
- 도구 막대의 [감사 컬럼 보기] 를 켜면 감사 컬럼이 일반 컬럼처럼 보입니다. 이 설정은 이 브라우저에 저장됩니다.
- 컬럼 점프(Alt+O)는 숨긴 감사 컬럼도 찾습니다. 찾은 컬럼이 감사 컬럼이면 [감사 컬럼 보기] 가 저절로 켜집니다. 그리드에서 감사 컬럼 이름으로 컬럼을 더하거나 이름을 바꿀 때도 저절로 켜집니다.
- 새 표를 만들면 감사 컬럼 8개가 표 끝에 저절로 붙습니다. `*_ID` 컬럼은 `VARCHAR2(100)`, `C_AT`·`U_AT` 는 `TIMESTAMP(6)` 이고, 모두 NULL 을 허용합니다.
- 컬럼을 더하면 표 끝이 감사 컬럼 묶음일 때 그 묶음 바로 앞에 들어갑니다. 더하는 컬럼이 감사 컬럼이면 맨 끝에 들어갑니다. 컬럼을 끝으로 옮길 때도 같습니다. 위치를 직접 정하면 그 위치를 따릅니다.
- Claude(MCP)나 CLI 로 감사 컬럼 없는 표를 만들려면 `addTable` 명령에 `"audit": false` 를 넣으세요.
- DB 가져오기와 다시 가져오기 반영은 DB 모양 그대로 둡니다. 감사 컬럼을 덧붙이지 않습니다.
- 표준 판정은 그대로입니다. 감사 컬럼도 다른 컬럼처럼 판정하므로 `C_AT` 에 DOMAIN 경고가 보일 수 있습니다. 이 경고는 버전 확정을 막지 않습니다. 확정 검사에서 감사 컬럼의 표준 위반은 첫 확정이든 두 번째 확정이든 경고로만 나오고 오류가 되지 않습니다(4.8절). 확정 창에는 그 행에 "감사 컬럼" 이 붙습니다.
- 감사 컬럼은 보기를 켰을 때만 "고칠 위반" 수에 들어갑니다(4.5절).
- Claude 가 `getModelText` 로 읽으면 감사 컬럼은 표마다 한 줄(`감사 컬럼 8개: C_USR_ID C_AT …`)로 접혀 있습니다. PK·NN·FK 표시는 이름 뒤 괄호에, 표준 상태는 `!상태` 로 남습니다(예: `C_AT!DOMAIN`, `U_USR_ID(PK,NN)`). 펼치려면 `audit=true` 를 줍니다. CLI 는 `text --audit` 입니다.

## 6. 표준 상태

서버가 컬럼마다 표준 용어 사전과 비교해 상태를 정합니다. 여러 조건에 걸리면 가장 나쁜 상태 하나를 보입니다. 좋은 순서는 OK, ALIAS, NEW, TYPE, DOMAIN, MISS 입니다.

| 상태 | 화면 글 | 색 | 뜻 | 확정 검사 |
|---|---|---|---|---|
| OK | 표준 | 초록 | 물리명이 컬럼 사전에 있습니다 | 나오지 않음 |
| ALIAS | 별칭 | 초록 | 물리명이 사전의 별칭입니다 | 나오지 않음 |
| NEW | 새 이름 | 파랑 | 컬럼 사전에는 없지만 단어 토막은 모두 사전에 있습니다 | 나오지 않음 |
| TYPE | 타입 불일치 | 노랑 | 같은 물리명이 모델 안에서 다른 타입으로 쓰입니다 | 경고 또는 오류 |
| DOMAIN | 도메인 다름 | 노랑 | 컬럼 타입이 지정한 도메인의 타입과 맞지 않습니다 | 경고 또는 오류 |
| MISS | 사전 없음 | 빨강 | 물리명의 토막 가운데 용어 사전에 없는 것이 있습니다. 논리명에 `***` 로 보입니다 | 경고 또는 오류 |

- 확정 검사의 "경고 또는 오류" 는 4.8절의 규칙을 따릅니다.
- "고칠 위반" 은 TYPE·DOMAIN·MISS 컬럼입니다. 위 막대 요약 줄, 왼쪽 목록의 붉은 수, 표 머리의 붉은 수, [표준 위반] 탭의 건수와 행이 모두 이 규칙을 씁니다. NEW·ALIAS 는 탭에 나오지 않고 그리드 배지로만 보입니다. 감사 컬럼은 [감사 컬럼 보기] 를 켰을 때만 셉니다.
도메인 타입과 컬럼 타입은 다음 규칙으로 맞춰 봅니다.

| 도메인 타입 | 맞는 컬럼 타입 |
|---|---|
| STRING(n) | VARCHAR2·NVARCHAR2·VARCHAR·CHAR·NCHAR 이고 길이 n. 도메인에 길이가 없으면 길이를 보지 않습니다 |
| 길이 없는 STRING | CLOB 도 맞습니다 |
| NUMBER(p,s) | NUMBER 이고 정밀도·소수가 같음. 정밀도와 소수가 둘 다 없는 도메인은 모든 NUMBER 와 맞습니다 |
| DATE(소수 없음) | DATE |
| DATE(소수 n) | TIMESTAMP(n) |
| BOOLEAN | 길이 1 문자 타입(예: `_YN` 컬럼의 `VARCHAR2(1 CHAR)`) |

## 7. Claude 와 함께 쓰기 (MCP)

Claude Code 에 `erd` MCP 서버가 붙으면 Claude 가 모델을 읽고 고칠 수 있습니다. Claude 의 변경도 화면과 똑같이 서버 판정을 거치고, 화면에 실시간으로 보입니다.

### 7.1 연결하기

1. 저장소 루트에서 의존성을 한 번 설치하세요. 루트에 `node_modules` 가 없으면 `erd` 서버가 뜨지 않습니다.
   ```bash
   cd /Users/jji/project/dmes-standard && pnpm install
   ```
2. MDM 서버(포트 8096)를 띄우세요.
3. 저장소 루트에서 Claude Code 를 시작하세요. 고칠 계획이면 `ERD_USER` 에 내 사용자 ID 를 넣으세요.
   ```bash
   cd /Users/jji/project/dmes-standard && ERD_USER=<내 사용자 ID> claude
   ```
4. Claude Code 가 프로젝트 MCP 서버(`.mcp.json` 의 `erd`)를 쓸지 물으면 승인하세요.
5. Claude Code 에서 `/mcp` 를 입력하세요. `erd` 가 연결됨으로 보이면 준비가 끝났습니다.

`.mcp.json` 은 다음 환경변수를 넘깁니다. 비워 두면 기본값을 씁니다.

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `ERD_BASE` | `http://localhost:8096` | MDM 서버 주소 |
| `ERD_USER` | `erd-mcp` | 권한을 판정하고 변경 기록에 남는 사용자 |
| `ERD_ROLE` | `MDM_STEWARD` | 역할 |
| `BACKEND_CLIENT_KEY` | `dmes-bff-local-client-key-2026` | 로컬 서버 인증 키 |
| `ERD_SESSION` | `auto` | 세션 이름. `auto` 면 `claude-` 와 Claude Code 세션 ID 앞 8글자로 정합니다 |

- 권한은 `ERD_USER` 로, 충돌은 세션 이름으로 가립니다. Claude 창 두 개가 같은 사용자를 써도 세션 이름이 달라 서로의 변경을 충돌로 알아봅니다.
- 쓰기에는 `ERD_USER` 가 그 DRAFT 의 소유자나 공동 편집자여야 합니다. 기본값 `erd-mcp` 로 쓰면 `NOT_EDITOR` 로 거절됩니다. 이때는 소유자가 [공동 편집자(n)] 에 `erd-mcp` 를 더하거나, 내 사용자 ID 로 Claude Code 를 다시 시작하세요.

### 7.4 baseRev 와 충돌

Claude 는 `apply` 에 baseRev(마지막으로 읽은 rev)를 함께 보냅니다. 서버는 baseRev 뒤에 다른 세션이 같은 속성을 바꿨으면 묶음 전체를 `CONFLICT` 로 거절합니다.

`getModelText` 머리줄은 다음 모양입니다.

```
# MCM 모델 (MCMAPUSER) ver 1.000 DRAFT rev 12
```

반영 결과와 충돌 결과는 다음과 같은 글입니다(값은 예입니다).

```
반영 rev 216 (baseRev 212) · 변경 3 · 경고 1 · 세션 claude-1a2b3c4d
...
다음 baseRev: 216
```
```
거절 CONFLICT · 명령 #3 updateColumn TB_MCM_SEC_MENU.MENU_NM.logical · 저장한 것 없음
바꾼 사람: 41000207 (세션 ui-ab12cd34) rev 215 · 지금 값: "메뉴명"
다음: getChangesSince(212) 로 바뀐 값을 읽고, 묶음 전체를 baseRev 215 이상으로 다시 보내세요.
```

충돌을 받으면 Claude 가 `getChangesSince` 로 바뀐 값을 읽고 다시 보냅니다. 같은 값을 사람이 고치고 있었다면 Claude 에게 어느 값을 남길지 알려 주세요. 결과에 `CLAIMED` 경고가 있으면 다른 세션이 그 표에 작업 중 표시를 걸어 둔 것입니다. 반영은 되었으니 그 세션의 작업과 겹치지 않는지 확인하세요.

## 8. CLI

`scripts/erd/erd-cli.mjs` 는 MCP 와 같은 일을 셸에서 합니다. `pnpm install` 없이 돌아갑니다. 저장소 루트에서 실행하세요.

| 명령 | 하는 일 |
|---|---|
| `models` | 모델 목록(상태, 최신 확정본 버전, 만든 사람 포함) |
| `diagrams --model M` | 다이어그램 목록(id, 업무영역/이름, 표 수, 꺾임점 수) |
| `text [--tables A,B*] [--diagram D] [--audit]` | `getModelText` 와 같은 글. `--audit` 는 감사 컬럼을 펼칩니다 |
| `changes --since R [--session S]` | `getChangesSince` 와 같은 글. `--session` 은 그 세션의 변경만 거릅니다 |
| `violations [--status NEW\|TYPE\|DOMAIN\|MISS]` | 표준 위반 |
| `inferred [--include-folded]` | 추정 관계 |
| `db-diff` | DB 차이 |
| `apply --file batch.json\|- [--base-rev R] [--apply]` | 명령 묶음 |
| `confirm\|reject <관계> --base-rev R [--apply]` | 추정 관계 확정·기각 |
| `undo [--rev R] [--apply]` | 되돌리기 |
| `claim\|release <표>...` | 작업 중 표시 걸기·풀기 |
| `diagram-rename <다이어그램> --base-rev R [--name 새이름] [--area 새업무영역] [--apply]` | 다이어그램 이름 바꾸기 |
| `diagram-delete <다이어그램> --base-rev R [--apply]` | 다이어그램 지우기 |
| `diagram-copy <다이어그램> --base-rev R [--name 새이름] [--area 업무영역] [--id d-새id] [--apply]` | 다이어그램 복사(노드와 꺾임점 포함) |
| `register --module M --schema S --name N [--model ID] [--apply]` | 새 모델 등록. `--model` 을 빼면 모듈 이름 |
| `import --model M [--base-rev R] [--apply]` | DB 스키마에서 표·관계 첫 가져오기. 표가 없는 모델에만 됩니다 |
| `delete-model --model M --yes` | 모델 완전 삭제. 되돌릴 수 없습니다 |

공통 옵션은 `--model`, `--base`, `--user`, `--role`, `--client-key`, `--session`, `--json` 입니다. 전체 안내는 `node scripts/erd/erd-cli.mjs --help` 로 봅니다.

- 쓰기(`apply`·`confirm`·`reject`·`undo`)의 기본은 시험 실행입니다. 서버가 모든 검사를 하고 저장하지 않습니다. 저장하려면 `--apply` 를 붙이세요.
- `register`·`import` 는 서버에 시험 실행이 없습니다. `--apply` 를 빼면 서버에 보내지 않고, 읽기로 겹침·표 유무만 확인해 "시험 실행: 서버에 보내지 않음, --apply 로 실행" 이라고 알려 줍니다. 이때 종료 코드 0 은 "겹침이 없다" 는 뜻일 뿐 서버 검사를 통과했다는 뜻이 아닙니다.
- `delete-model` 은 `--yes` 와 `--user`(또는 `ERD_USER`)가 둘 다 있어야 보냅니다. 먼저 `models` 로 지울 모델을 확인하세요. 권한은 서버가 가립니다(관리자는 항상, 그 밖은 확정류 버전이 없고 DRAFT 소유자일 때만).
- 시험 실행도 편집자 검사를 합니다. 쓰기 명령에는 늘 `--user <내 사용자 ID>` 를 주세요. `--apply` 는 `--user` 나 `ERD_USER` 가 없으면 실행하지 않습니다.
- 세션 이름은 `--session`, 그다음 `ERD_SESSION`, 그다음 `cli-<사용자>` 순서로 정합니다.
- 종료 코드는 0(반영·시험 통과·읽기 성공), 1(거절·실패), 2(사용 오류)입니다.
- `undo` 에서 `--rev` 를 빼면 이 세션이 최근 500 rev 안에서 마지막으로 반영한 변경을 되돌립니다. 그 구간에 다시 읽기 지점이 있으면 그 지점 뒤에서 찾습니다. Claude 의 `undo` 도 같습니다.

### 8.1 묶음 파일로 고치기

1. 고칠 표를 읽고 머리줄의 rev 를 적어 두세요.
   ```bash
   node scripts/erd/erd-cli.mjs text --model mcm --tables TB_MCM_SEC_MENU,TB_MCM_SEC_USER
   ```
2. 묶음 파일을 만드세요. `baseRev` 에는 1번에서 적은 rev 를 넣으세요. 요소는 id 대신 이름으로 써도 됩니다.
   ```json
   {
     "modelId": "mcm",
     "baseRev": 12,
     "commands": [
       { "op": "updateColumn", "id": "TB_MCM_SEC_MENU.MENU_NM", "set": { "logical": "메뉴명" } },
       { "op": "addColumn", "table": "TB_MCM_SEC_USER", "logical": "사용여부" }
     ]
   }
   ```
3. 시험 실행하세요. 결과(표준 출력)의 첫 줄이 `시험 실행(저장 안 함) · 통과` 면 저장할 수 있습니다. 그 위의 `erd-cli apply: ...` 줄은 표준 오류로 나오는 모드 안내입니다.
   ```bash
   node scripts/erd/erd-cli.mjs apply --file batch.json --user <내 사용자 ID>
   ```
4. 저장하세요. `baseRev` 는 바꾸지 않습니다.
   ```bash
   node scripts/erd/erd-cli.mjs apply --file batch.json --user <내 사용자 ID> --apply
   ```
5. 결과 끝의 "다음 baseRev" 를 다음 묶음에 쓰세요.

- 논리명만 준 `addColumn` 은 서버가 사전에서 물리명과 도메인을 채웁니다. 후보가 여럿이면 `NEEDS_CHOICE` 로 거절하고 후보를 보입니다. 이때 `"phys": "<고른 물리명>"` 을 넣어 다시 보내세요.
- 이름으로 쓰는 법: 표는 물리명, 컬럼은 `"표.컬럼"`, 관계는 `"자식표.컬럼 > 부모표.컬럼"`, 키는 키 이름이나 `"표:PK"`, 다이어그램은 `"업무영역/이름"` 입니다.
- 명령 배열만 담은 파일도 됩니다. 이때는 `--model` 과 `--base-rev` 를 주세요.
- 화면에 없는 작업(컬럼 삭제 `deleteColumn`)도 같은 방법으로 보냅니다. 관계 삭제 `deleteRelation`, 관계 수정 `updateRelation`, 키 `addKey`·`updateKey`·`deleteKey`, 표 이름 변경 `updateTable` 도 같은 방법으로 보낼 수 있습니다.

예를 더 들면 다음과 같습니다.

```bash
node scripts/erd/erd-cli.mjs inferred --model mcm
node scripts/erd/erd-cli.mjs confirm "TB_MCM_SEC_MENU.OBJECT_ID > TB_MCM_SEC_OBJ.OBJECT_ID" --model mcm --base-rev 12 --user <내 사용자 ID> --apply
node scripts/erd/erd-cli.mjs changes --model mcm --since 12
node scripts/erd/erd-cli.mjs undo --model mcm --rev 13 --user <내 사용자 ID> --apply
```

위 `confirm` 은 그 추정 관계가 목록에 있을 때만 통과합니다. 먼저 `inferred` 결과에서 관계 글을 확인하세요.

### 8.2 꺾임점·다이어그램·모델 관리 명령

꺾임점 명령은 묶음 파일의 `commands` 에 넣습니다. 좌표는 캔버스 절대 좌표 정수입니다.

```json
{ "op": "setRoute", "diagram": "업무영역/이름", "relation": "자식표.컬럼 > 부모표.컬럼",
  "points": [{ "x": 120, "y": 40 }, { "x": 120, "y": 200 }] }
{ "op": "clearRoutes", "diagram": "업무영역/이름", "relations": ["자식표.컬럼 > 부모표.컬럼"] }
```

- `setRoute` 의 `points` 는 1-50개입니다. 빈 목록은 거절됩니다. 그 다이어그램의 현재 버전에 없는 관계도 거절됩니다.
- `clearRoutes` 의 빈 목록은 아무 일도 하지 않습니다(번호만 오릅니다).
- 같은 묶음에서 `addRelation` 으로 만든 관계도 글로 가리킬 수 있습니다.
- 꺾임점은 `text --diagram "업무영역/이름"` 결과의 Ref 줄 아래 `via (x,y) → (x,y)` 로 읽습니다.

다이어그램 목록 관리 예:

```bash
node scripts/erd/erd-cli.mjs diagrams --model mcm
node scripts/erd/erd-cli.mjs diagram-copy "보안/메뉴·권한" --model mcm --base-rev 12 --user <내 사용자 ID> --apply
```

새 모델 등록과 가져오기 예(MLS 스키마):

```bash
node scripts/erd/erd-cli.mjs register --module mls --schema MLSAPUSER --name "MLS 스키마" --user <내 사용자 ID> --apply
node scripts/erd/erd-cli.mjs import --model mls --user <내 사용자 ID> --apply
```

잘못 등록한 모델은 `delete-model` 로 지웁니다. 되돌릴 수 없습니다.

```bash
node scripts/erd/erd-cli.mjs models
node scripts/erd/erd-cli.mjs delete-model --model mls --user <내 사용자 ID> --yes
```

## 9. 동시 편집 규칙

여러 사람과 Claude 세션이 한 DRAFT 를 함께 고칠 수 있습니다. 서버가 변경마다 판정하고, 판정 결과를 모든 화면에 실시간으로 보냅니다. 사람 2명과 Claude 세션 2개의 동시 편집은 단계 2 마감에서 브라우저로 확인할 예정입니다(확인 예정).

### 9.1 판정

- 묶음은 모두 반영되거나 모두 거절됩니다.
- 내가 마지막으로 본 번호(rev) 뒤에 다른 세션이 같은 속성을 바꿨으면 `CONFLICT` 입니다.
- 같은 요소라도 다른 속성을 고치면 둘 다 반영합니다. 예: 내가 `MENU_NM` 의 논리명을, 다른 사람이 같은 컬럼의 타입을 고치면 둘 다 들어갑니다.
- 고치려는 요소를 누가 이미 지웠으면 `NOT_FOUND` 입니다.
- 화면은 묶음을 한 번에 하나씩 보냅니다. 응답 전인 표와 행은 흐리게 보이고 고칠 수 없습니다.

### 9.2 알림 띠

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 충돌 | 다른 사람이 먼저 바꿨습니다. 예: "41000207 님이 먼저 바꿨습니다. 지금 값: "역할설명"". 글에 번호(rev)는 나오지 않고, 번호는 알림에 마우스를 올리면 보입니다 | 지금 값을 읽으세요. 내 값이 맞으면 [내 값 복사] 로 복사해 다시 넣으세요 |
| 이미 지워짐 | 고치려던 요소를 누가 지웠습니다 | 변경 기록에서 그 변경을 보세요 |
| 규칙 위반 | 이름 중복, 이름 규칙 위반처럼 서버 규칙에 맞지 않습니다 | 강조된 칸의 문구대로 고치세요 |
| 선택 필요 | 서버가 후보를 골라 달라고 합니다 | 뜬 선택 창에서 고르세요 |
| 편집 권한 없음 | 소유자·공동 편집자가 아니거나 DRAFT 가 아닙니다 | [읽기 전용] 칩을 눌러 이유와 할 일을 읽으세요 |
| 연결 문제 | 실시간 연결이 끊겼습니다 | 다시 연결될 때까지 기다리세요 |

### 9.3 되돌리기의 한계

- 되돌리려는 변경 뒤에 같은 속성을 다른 변경(내 변경 포함)이 바꿨으면 `CONFLICT` 입니다. 화면 알림은 "그 뒤에 바뀐 값이 있어 되돌릴 수 없습니다. 변경 기록에서 다른 변경을 고르거나 직접 고치세요." 처럼 사람 글로 나옵니다.
- 같은 표에 다른 사람이 컬럼을 더한 뒤 내 컬럼 추가를 되돌리면 컬럼 순서 때문에 `CONFLICT` 입니다.
- 이미 되돌린 변경을 다시 되돌리면 `INVALID` 입니다.
- `Ctrl+Z` 목록은 이 브라우저 탭에만 있습니다. 페이지를 새로 읽거나 서버가 모델을 다시 읽게 하면 목록이 비고, 그 앞 변경은 변경 기록에서 되돌려야 합니다.
- 모델 전체를 어떤 번호 시점으로 돌리는 기능은 없습니다.

### 9.4 작업 중 표시

- 작업 중 표시는 Claude 나 CLI 가 "이 표를 고치는 중" 이라고 알리는 표시입니다. 화면 사용자는 걸지 않습니다.
- 권고용입니다. 표시가 있어도 다른 사람이 고칠 수 있고, 그 결과에 `CLAIMED` 경고가 붙습니다.
- 600초가 지나면 저절로 풀립니다. Claude Code 를 끄면 MCP 서버가 잡은 표를 놓아 봅니다. 놓지 못한 표시도 600초 뒤 풀립니다.

### 9.5 연결 끊김

- 실시간 연결이 끊기면 위 막대에 "실시간 연결이 끊겨 편집을 멈췄습니다. 다시 연결되면 이어서 고칠 수 있습니다." 띠가 뜹니다.
- 끊긴 동안은 고칠 수 없습니다. 다시 연결되면 화면이 빠진 변경을 받습니다. 빠진 변경이 500건을 넘으면 모델 전체를 다시 읽습니다.

| 모델을 열었더니 시작 화면으로 돌아갑니다 | 다른 사람이 그 모델을 지웠습니다(알림이 먼저 나옵니다) | [모델 관리] 에서 다른 모델을 여세요 |
| [모델 관리] 의 [삭제] 가 꺼져 있거나 거절됩니다 | 모델 ID 를 입력하지 않았거나 권한이 없습니다. 비관리자는 확정류 버전이 있으면 지울 수 없습니다 | 확인 창에 모델 ID 를 그대로 넣으세요. 권한은 거절 문구를 읽고 관리자에게 요청하세요 |
| Space 를 눌러도 속성 창이 열리지 않습니다 | 표를 하나도 고르지 않았거나, 단추·메뉴에 초점이 있습니다 | 캔버스에서 표 하나를 누른 뒤 다시 누르세요 |
| 선을 눌러도 손잡이가 안 보입니다 | 개요 단계(배율 35% 미만)이거나 선을 고르지 못했습니다 | 확대한 뒤 선을 누르세요 |
| 로컬에서 `http://127.0.0.1:5100` 으로 열면 로그인 칸이 눌리지 않습니다 | Next 개발 서버가 `127.0.0.1` 의 개발 리소스 요청을 막습니다(`allowedDevOrigins` 미설정) | `http://localhost:5100` 으로 여세요 |

## 11. 용어

| 용어 | 뜻 |
|---|---|
| 모델 | 스키마 하나를 담은 ERD 데이터입니다. 모듈마다 하나입니다(예: `mcm`, `mdm`) |
| 다이어그램 | 모델의 표 일부를 놓은 그림입니다. 업무영역 아래에 이름으로 둡니다. 다이어그램에서 빼도 모델의 표는 남습니다 |
| 업무영역 | 다이어그램을 묶는 이름입니다(예: `기본`) |
| DRAFT / RELEASED | 고치는 중인 버전 / 확정한 버전 |
| 번호(rev) | 모델이 바뀔 때마다 오르는 번호입니다. 화면에서는 "번호" 라고 하고, 위 막대의 [버전 ▾] 안과 알림에 마우스를 올릴 때 보입니다. Claude·CLI 글에서는 `rev` 입니다 |
| baseRev | 변경을 보낼 때 함께 보내는, 내가 마지막으로 읽은 번호(rev)입니다. 충돌 판정의 기준입니다 |
| 묶음 | 함께 보내는 명령들입니다. 모두 반영되거나 모두 거절됩니다 |
| 세션 | 변경을 보낸 창 하나입니다. 화면은 `ui-`, Claude 는 `claude-`, CLI 는 `cli-` 로 시작합니다 |
| 소유자 | DRAFT 를 만들거나 선점한 사람입니다. 확정과 공동 편집자 관리를 합니다 |
| 공동 편집자 | 소유자가 더한, 그 버전을 함께 고칠 수 있는 사람입니다 |
| DB 관계 | DB 에 FK 제약으로 있는 관계입니다. 실선으로 그립니다 |
| 추정 관계 | DB FK 는 없지만 문서·SQL·이름 규칙으로 찾은 관계 후보입니다. 노란 파선으로 그립니다 |
| 맞음 / 아님 | 추정 관계를 사람이 맞다고 판정한 것 / 틀리다고 판정한 것입니다. 이전에는 확정 관계·기각 관계라고 했습니다. "확정" 은 이제 버전에만 씁니다 |
| 식별 관계 | 부모 PK 를 자식 PK 에 넣는 관계입니다 |
| 비식별 관계 | 부모 PK 를 자식의 일반 컬럼으로 두는 관계입니다 |
| 표준 상태 | 컬럼 이름과 타입을 표준 사전과 비교한 결과입니다(6절) |
| 도메인 | 컬럼 타입의 표준 묶음입니다(예: 일시, 코드) |
| 작업 중 표시 | Claude·CLI 가 표에 거는 권고용 표시입니다. 600초 뒤 풀립니다 |
| 시험 실행(dryRun) | 서버가 모든 검사를 하고 저장하지 않는 실행입니다 |
| DB 다시 가져오기 | 지금 DB 딕셔너리와 모델의 차이(DB 차이)를 골라 모델에 넣는 일입니다. 처음 가져오기는 "DB 에서 가져오기" 입니다. 검토 패널의 탭 이름도 같습니다 |
| 새로 읽기 | [DB 다시 가져오기] 탭에서 DB 차이를 다시 읽는 단추입니다. 이전에는 [다시 읽기] 였습니다 |
| 고칠 위반 | 상태가 TYPE·DOMAIN·MISS 인 컬럼입니다. 감사 컬럼은 보기를 켰을 때만 셉니다(4.5절) |
| 읽기 전용 칩 | 위 막대의 [읽기 전용] 표시입니다. 누르면 이유와 할 일이 나옵니다 |
| MCP | Claude Code 가 외부 도구를 부르는 방식입니다. 이 도구의 서버 이름은 `erd` 입니다 |
| 꺾임점(경유점) | 관계선이 지나가도록 손으로 정한 점입니다. 다이어그램마다 따로 저장합니다 |
| 사전 재구성 | 저장된 논리명(사전에 없는 단어는 `***`)입니다. 컬럼 그리드에 읽기 전용 칸으로 보입니다 |
| 속성 창 | `Space` 로 여는 표 속성 편집 창입니다. [적용] 한 번이 변경 하나입니다 |
| 기준본 | 확정한 버전(RELEASED)입니다. DRAFT 일 때 위 막대의 [기준본으로 저장] 이 확정 단추입니다 |
