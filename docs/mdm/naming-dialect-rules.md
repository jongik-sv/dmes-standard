## 2. 공통 관리 속성(감사 칼럼)

- **공통 관리 속성 = 감사 9칼럼**: `C_USR_ID VARCHAR(100)`, `C_AT`, `C_SVC_ID VARCHAR(100)`, `C_PGM_ID VARCHAR(100)`, `U_USR_ID VARCHAR(100)`, `U_AT`, `U_SVC_ID VARCHAR(100)`, `U_PGM_ID VARCHAR(100)`, `VER BIGINT`. 원천 04:967·05:601·06:905 가 "관리 속성(등록·수정자·일시)은 공통 모듈에서 정의"로 미룬 항목이 이것이다. 타입은 mls V2 를 따른다(SQLite `C_AT`/`U_AT` 는 `TIMESTAMP`, MSSQL 은 `DATETIME2`). 모두 NULL 을 허용한다(mls V2 와 같다).
- **적용 대상**: 모든 `TB_MDM_*` 테이블. 예외는 1건이다 — `TB_MDM_DICT_SEQ`(순번 카운터 한 행, 보류 테이블). 보류 테이블도 DDL 에 9칼럼을 둔다. 나중에 코드를 붙일 때 마이그레이션을 다시 만들지 않기 위해서이며, PRD §2 규칙 7 의 스키마 원칙과 같은 이유다.
- **채우는 주체**: 엔티티가 `com.dongkuk.dmes.cactus.audit.CactusAuditEntity` 를 상속한다(mls `Notice` 선례). `McmAuditEntity` 는 cactus 비의존이 필요한 mcm-core 전용이라 쓰지 않는다. 엔티티를 거치지 않는 쓰기(네이티브 UPDATE·일괄 DELETE+INSERT·발급 UPDATE)는 SQL 에 감사 칼럼을 **명시적으로** 넣는다. 그 헬퍼는 TSK-01-02 가 만든다.
- **`McmAuditStatementInspector` 는 `TB_MDM_*` 에 적용하지 않는다.** 근거는 세 가지다.
  1. 인스펙터의 대상 정규식은 `MCMAPUSER.TB_MCM_` 접두가 붙은 SQL 만 잡는다. mdm 은 스키마 접두를 쓰지 않으므로, 넓히려면 정규식과 svc 하드코딩(`'mcm'`)을 모두 고쳐야 한다.
  2. mdm 앱은 인스펙터를 등록하지 않고, mdm 테이블은 mcm 앱의 DB 에 없다.
  3. `CactusAuditListener` 가 svc/pgm 을 요청 문맥에서 채우므로 더 정확하다.

  → **코드 변경은 없다.** mdm 설정에 인스펙터를 등록하지 않는 상태를 유지한다.
- **`ROW_VERSION` 과 `VER` 의 역할 분리**: `row_version` 은 원천이 정한 낙관적 잠금 칼럼이다(원천에 있는 테이블에만 원천 그대로 둔다 — CODE_VER·RULE_VER·RULE_TEST_CASE·RULE_SET·DATA_ITEM). 서버가 요청의 값과 저장값을 비교해 다르면 409 로 거부하고, 같으면 저장·상태 전이 때 1 올린다(04:305). 초깃값은 0 이다(04:1008. 06 은 명시가 없어 0 으로 통일한다). `VER` 는 감사용 변경 횟수이며 잠금 판정에 쓰지 않는다(`@Version` 이 아니라 수정마다 1 올리는 카운터). 원천에 `row_version` 이 없는 테이블에는 새로 넣지 않는다(원천 DDL 불변).
- **02 의 "관리 속성(버전·유효기간·소유 부서·담당자·등록 출처)"**(02:36-39·82·762)은 감사 칼럼과 다른 업무 속성이다. 공통 규칙으로 정하지 않고 TSK-02-03(02 DB 설계)이 02 원문대로 정한다.

## 4. 영속성·SQL 작성

- **영속성 수단**: JPA(엔티티·Repository)가 1순위이고, 방언별 SQL 은 JPA native 쿼리(`@Query(nativeQuery=true)` 또는 `EntityManager.createNativeQuery`)로 쓴다. MyBatis(`@MapperScan`/`SqlSession`)는 쓰지 않는다. mdm 은 MES 모듈로 등재되며 backend-standard 04 의 MES 규칙(사용자 동의 없는 MyBatis 도입 금지)과 mcm-reference 의 "JPA 1순위" 를 따른다.
- **방언 분기**: 방언 판정은 한 곳(TSK-01-02 가 만드는 방언 판정 빈)에서 하고, 방언별 문안은 같은 리포지토리 안에 짝으로 둔다. 파일·클래스 이름에 방언을 흩지 않는다.
- **업무 API**: OASIS BPMN 으로만 노출한다(TRD §3). 서비스 ID = screenId([screens/README.md](screens/README.md)).

## 5. Flyway

- 위치: `mdm/api/src/main/resources/db/migration/mdm/{sqlite,mssql}`.
- **두 방언의 V 번호 집합은 항상 같다**(TSK-01-01 불변 규칙 4). 새 번호는 두 방언 합집합의 최댓값 + 1 이다.
- `flyway-migration-add` 스킬이 mdm 경로를 지원하지 않으면 같은 규칙을 손으로 적용한다. 판정(TSK-01-02): 지원하지 않는다(--module 선택지가 aps-core·mcm-core 뿐). 손으로 적용한다.
