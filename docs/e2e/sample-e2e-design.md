# 샘플 E2E 테스트 설계 — 기준정보 송신 → 수신 반영 (예시)

> 템플릿용 뼈대다. 실제 설계는 대상 토픽·메시지 스키마·검증 지점을 구체적으로 채운다.

## 1. 시나리오 목적

한 모듈에서 등록한 기준정보가 메시지 연동을 거쳐 다른 모듈의 조회 화면에
누락·중복 없이 반영되는지 확인한다.

## 2. 참여 구성요소

| 구분 | 대상 |
|---|---|
| 송신 | 샘플 기준정보 모듈 |
| 연동 | 메시지 허브 (토픽: `sample.item.changed`) |
| 수신 | 샘플 실행 모듈 |

## 3. 시나리오 흐름

1. 송신 측에서 `SAMPLE_ITEM` 1건을 신규 등록한다.
2. 등록 트랜잭션 커밋 후 변경 메시지가 발행된다.
3. 수신 측 컨슈머가 메시지를 처리해 로컬 사본을 적재한다.
4. 수신 측 조회 화면에서 해당 품목이 조회된다.

## 4. 검증 항목

| ID | 검증 내용 | 기대 결과 |
|---|---|---|
| E2E-01 | 발행된 메시지 건수 | 등록 1건당 정확히 1건 |
| E2E-02 | 수신 측 적재 결과 | 키·주요 속성 일치 |
| E2E-03 | 동일 메시지 재수신 | 중복 적재 없음 (멱등) |
| E2E-04 | 수신 측 장애 후 복구 | 미처리 메시지 재처리로 최종 일치 |

## 5. 전제 및 정리(teardown)

- 테스트 전용 코드 접두어(`SAMPLE-E2E-`)를 써서 실 데이터와 섞이지 않게 한다.
- 시나리오 종료 후 생성 데이터와 소비 오프셋을 원복한다.
