# DB 설계 도구(ERD) 미룬 기능 목록

- 작성일: 2026-10-10
- 관련 문서: [구상](../superpowers/specs/2026-10-09-erd-tool-concept.md), [연구 보고서](2026-10-09-erd-tool-research.md)
- 첫 스펙 범위는 **기반 + P1(가져오기·뷰어) + P2(exERD 방식 편집)** 이다. 이 범위에 넣지 않은 기능을 모두 여기에 적는다.
- 항목을 다시 꺼낼 때는 "근거" 칸의 문서 절부터 읽는다. 항목을 구현하면 이 문서에서 지우지 말고 "처리" 칸에 커밋을 적는다.

## 1. 다음 단계 (P3: Flyway V 초안 생성)

| # | 기능 | 미룬 이유 | 근거 | 처리 |
|---|---|---|---|---|
| 1 | 모델과 DB 의 차이를 새 V 파일 초안으로 만든다(고정 ID 기반 diff, 이름 변경을 RENAME 으로 인식) | P2 편집이 먼저 있어야 diff 할 변경이 생긴다 | 구상 7절, 연구 10.3절 | |
| 2 | DDL 서식 규칙을 정한다(CREATE TABLE·ALTER·COMMENT·제약 이름) | oracle-sql-rules 에는 쿼리 서식만 있다. V 초안 생성기를 만들기 전에 정한다. ADR 0001(이름 규칙)도 PROPOSED 다 | 연구 1절·10.2절 8번 | |
| 3 | Oracle 함정 경고(컬럼 축소, NOT NULL 추가 시 기존 행 등) | V 초안 생성과 함께 만든다 | 연구 10.3절 | |
| 4 | 템플릿 PDB 에 V 초안을 적용해 검증한다(`pdb.mjs template-schema`) | V 초안 생성과 함께 만든다 | 연구 3.6절 | |
| 5 | V 초안을 만들 때 모델의 객체별 텍스트 스냅샷을 함께 커밋한다 | 저장 위치는 "DB + 텍스트 스냅샷" 으로 정했고, 스냅샷은 V 초안 시점에 만든다 | 결정 4(2026-10-10) | |

## 3. 미룬 exERD 동작

첫 스펙의 P2 에는 다음 네 묶음만 넣었다: 논리·물리 전환과 보기 프리셋, 관계 긋기로 FK 자동 생성, 키보드 편집과 찾기, 큰 모델 처리와 삭제 구분(결정 3, 2026-10-10). 아래는 넣지 않은 동작이다.

| # | 동작 | 근거 | 처리 |
|---|---|---|---|
| 11 | `` ` `` 키로 논리명·물리명·주석을 한 번에 편집 | 연구 2.3절 4번 | |
| 12 | 일괄 적용 마법사(계획 → 검토 → 모호한 항목 선택 → 실행) | 연구 2.3절 6번 | |
| 13 | 모델 검사 후 Ctrl+1 로 문제 자동 수정 | 연구 2.3절 10번 | |
| 14 | 3-way 협업 병합(SAM Edition 방식). 동시 편집은 MDM 버전 객체의 DRAFT 선점으로 대신한다 | 연구 2.3절 12번, 결정 2 | |

| 17 | 운영 DB 의 FK·코멘트 현황 확인, 다른 스키마 읽기 권한 확인 | 수치는 모두 로컬 L_MAIN 기준이다 | 연구 3.3절·11절 | |
| 18 | Oracle SQL Developer(Data Modeler) 도입 계획의 존폐 | 이 도구가 쓸 만해진 뒤에 정한다. Data Modeler 로는 MDM 용어 연동과 Claude 편집이 안 된다 | 연구 10.1절 1번 | |
