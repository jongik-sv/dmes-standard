## 진단: 불편의 뿌리 세 가지

1. **캔버스가 좁다.**
   - 기본 상태에서 캔버스는 화면의 16%(1440×900)~28%(1920×1080)다. 배율 1에서 표가 1~6개만 보인다.
   - 나머지 공간: 아래 검토 패널 260px, 오른쪽 속성 패널 400px, ERD 상단 막대 115px, 포털 메뉴 280px.
   - ERD 화면 안의 패널은 접거나 크기를 바꿀 수 없다. 포털 메뉴 접힘도 새로고침하면 풀린다.
   - 첫 화면이 배율 10%로 열린다. 자동 배치가 세로 한 줄(약 1700×6000px)이라 표 57개가 점처럼 보인다.
2. **기본 편집 상당수가 화면에 없다.** 컬럼 삭제, 관계 삭제, 표 이름 변경, 키 수정, 식별/비식별 전환, 자기 참조는 Claude 나 CLI 로만 된다. exERD 는 이 모두를 속성 창 하나에서 처리한다.
3. **알아야 할 개념이 너무 많다.**
   - 화면에 나오는 개념이 31개다. 그중 9개는 내부 구현 용어다(rev, 세션, 선점, 재적재 표시 등).
   - 알림에 Claude 용 문장이 그대로 나온다. 예: "getChangesSince(212) 로 최신 값을 읽고…"
   - 버전 단추가 8개다.

### 2. 화면에서 다 고칠 수 있게 하기 (exERD 방식)

- Space 키 속성 창 하나로 표·컬럼·키·관계를 고친다. CLI 로만 되던 편집을 없앤다.
- 캔버스에서 이름을 바로 고친다. exERD 의 백틱(`) 키처럼 논리명·물리명·주석을 한 번에 고친다.
- 표·컬럼 복사/붙여넣기. 관계와 도메인까지 함께 복사한다.
- 다시 하기(redo). 같은 속성을 두 번 고친 뒤 두 번째 되돌리기가 CONFLICT 로 실패하는 문제도 고친다.

### 3. 개념과 용어 줄이기

- **버전 숨기기.** 편집을 시작하면 DRAFT 를 자동으로 만들고, 사용자는 [기준본으로 저장] 하나만 본다. 공동 편집자는 모델 단위로 한 번만 등록한다. (아래 「버전 관리」 절)
- 화면 문구를 쉬운 한국어로 바꾼다. `ERD_STD_DOMAIN`, `NAME_RULE`, rev, `ui-` 세션 등.
- 변경 기록에 시각과 사람 이름을 보이고, "배치 57" 같은 모호한 요약을 고친다. 비활성 단추에는 이유를 보인다.
- 빨강·노랑이 각각 4~5가지 뜻을 가진다. 뜻을 줄이고 범례에 색 견본을 넣는다.

### 4. 표준 위반 정리 도구

- 위반 행을 누르면 그 컬럼을 선택한다(`nav.selectColumn` 이 이미 있음).
- exERD 의 Ctrl+1 빠른 수정과 일괄 용어 정책 마법사. 첫 확정에서 위반 약 737건(MCM)이 나오는 문제를 줄인다.
- 조건 검색 뒤 일괄 변경(예: 도메인이 X 인 컬럼 전부).
- **먼저 확인할 것:** MCP 로 L_MAIN `TB_MCM_SEC_MENU` 를 읽으면 감사 컬럼 8개 중 7개가 `!DOMAIN` 이다. 새 표에 자동으로 붙는 감사 컬럼이 다음 확정을 막을 수 있다. 감사 컬럼 도메인 지정 또는 확정 규칙 예외가 필요하다.

### 5. 작은 것들

- [물리명도] 기본 끄기. 지금은 물리명이 경고 없이 바뀐다.
- 입력 칸 Enter 가 항상 새 컬럼을 더해 이름 변경과 헷갈린다.
- Shift+1/2 는 도움말에 있으나 동작하지 않는다. F2 가 셀 편집을 열지 않는다.
- exERD 와 키가 다르다(exERD 는 3 이 표 추가, 우리는 2).
- 비활성 [확정] 단추가 파란색이라 눌리는 것처럼 보인다.

## 사용법 직관성

사용자 의견("사용법도 직관적이지 않다")을 받아 B 의 과제별 단계(§2)와 화면 코드(`canvas/useCanvasEditing.ts`)를 다시 봤다.

### 직관적이지 않은 이유 여섯 가지

1. **보는 곳과 고치는 곳이 다르다.** 표는 캔버스에서 보고, 고치기는 오른쪽 그리드에서, 위반 확인은 아래 패널에서 한다. 캔버스의 표를 두 번 눌러도 아무 일이 없다. exERD 는 캔버스 위에서 바로 고친다(두 번 누르기·F2·Space).
2. **할 수 있는 일이 보이지 않는다.**
   - 표 추가는 `2`, 관계는 `4`·`5` 키다. PK 추가는 단추가 없고 `Ctrl+Shift+Enter` 를 알아야 한다.
   - 오른쪽 클릭 메뉴는 있지만, 표 메뉴는 접기·빼기·삭제·부모/자식 이동뿐이다. 컬럼 추가·이름 바꾸기·관계 긋기·속성이 없다. 빈 곳 메뉴는 표 추가·자동 배치 둘뿐이다.
   - 관계선은 누를 수 없다.
3. **같은 일의 방식이 서로 반대다.**
   - 새 표는 물리명을 먼저 넣고, 새 컬럼은 논리명을 먼저 넣는다.
   - 입력 칸 하나가 컬럼 추가와 이름 변경을 같이 맡는다. `Enter` 는 늘 추가라서, 이름을 바꾸려다 컬럼이 생긴다.
   - "확정" 이 버전 확정과 추정 관계 확정 두 뜻이다. 다시 가져오기는 [DB 가져오기]·[DB 차이]·"다시 가져오기 반영" 세 이름이다.
4. **다음에 할 일을 알려 주지 않는다.**
   - 관계를 그릴 때 부모를 먼저 누르라는 안내가 없다.
   - 같은 표를 두 번 누르는 자기 참조는 아무 메시지 없이 무시된다.
   - 비활성 단추에 이유가 없다.
   - 첫 화면은 "위 막대에서 모델을 고르거나 등록하세요" 한 줄뿐이다. "5분 둘러보기" 는 도움말 문서에만 있다.
5. **결과가 조용히 달라진다.**
   - [물리명도] 가 기본으로 켜져 있어 논리명을 고치면 물리명도 경고 없이 바뀐다(DB 와 달라진다).
   - 숨은 감사 컬럼 8개 때문에 변경 기록에 "컬럼 8" 이 찍힌다.
   - 기존 위반 컬럼의 논리명만 고쳐도 그 경고가 확정을 막는 오류가 된다.
6. **고치기 전에 알아야 할 것이 많다.** 편집하려면 DRAFT 가 있어야 하고, 소유자이거나 공동 편집자여야 한다. 확정본이면 새 버전부터 만든다. Claude 에게 맡기려면 화면 밖에서 6단계를 거친다.

## 버전 관리

버전 관리는 남기되 사용자에게서 숨긴다.

남기는 이유(이전 ERD 를 두는 이유):
1. 단계 3 의 V 파일(ALTER) 초안은 "직전 확정본과 지금 모델의 차이" 로 만든다. 기준이 없으면 계산할 수 없다.
2. "기존 위반은 경고, 이번에 새로 만든 위반만 막기"(D19)는 기준본이 있어야 된다. 검토자도 바뀐 부분만 본다.
3. 여럿이 고치는 중간본(DRAFT)과 믿을 수 있는 확정본(RELEASED)을 나눈다.
4. 되돌리기는 최근 100개 변경까지다. 크게 망가지면 기준본으로 돌아간다.

꼭 필요한 것은 마지막 기준본 하나와 그 뒤 변경 기록이다. 더 오래된 버전은 이력 조회용이다. DB 를 기준으로 쓰는 방법은 개발·운영 DB 차이와 논리명·추정 관계·도메인 부재 때문에 대체가 못 된다. exERD 도 저장소에 "변경 제출"(커밋 메시지)을 하고 과거 이력과 모델을 비교한다(A-exerd.md 6.1·7.2·7.5).

보강할 것: 버전끼리 비교하는 화면이 없다(deferred 10). 기준본의 가치는 이 화면에서 드러난다.

### 1차 결과(10-11)

1차는 2026-10-11 에 구현하고 같은 날 마감했다. 마감 확인은 복제 DB L_UX1C(TPL_DATA 복제, L_MAIN 아님)의 모델 `mcm`(58표)에서 했다. 결정과 구현 중 판단은 [1차 구현 계획 README](../../superpowers/plans/2026-10-11-erd-ux1/README.md) 의 "1차 구현 결정" 에 있다. 남은 일은 [deferred 8절](../deferred.md)(81번부터)에 있다.

#### 캔버스 면적

`measure.js` 로 잰 값이다. 캔버스 크기 뒤의 숫자는 가로×세로(px)다. 기준선은 조사 C 의 「Space / layout」 값(1440×900 에서 16.4%, 1920×1080 에서 28.2%)이다.

| 상태 | 1440×900 | 1920×1080 | 목표(1440 / 1920) | 판정 |
|---|---|---|---|---|
| 기본(고른 표 없음, 검토 패널 접힘) | 51.7% (906×739) | 61.4% (1386×919) | 40% 이상 / 50% 이상 | 통과 |
| 최대화 | 67.4% (1136×769) | 73.9% (1616×949) | 60% 이상 / 70% 이상 | 통과 |
| 표를 고름(속성 패널 398px) | 28.3% (496×739) | 43.3% (976×919) | 목표 없음 | 참고 |
| 포털 메뉴를 접음 | 67.6% (1186×739) | 73.8% (1666×919) | 목표 없음 | 참고 |

- 기본 상태는 기준선보다 1440 에서 35.3%p, 1920 에서 33.2%p 넓다.
- 위 막대 높이(`erdBar`)는 모든 상태에서 35px 다. 목표 44px 이하를 지켰다.
- 화면 제목 줄은 0px(숨김)이고 아래 꼬리가 24px, 검토 접힘 줄이 30px, 왼쪽 목록이 218px, 포털 메뉴가 280px 다.
- 표를 고르면 속성 패널(약 400px)이 열려 캔버스가 좁아진다. 표를 고른 상태의 목표는 정하지 않았다.

#### 직관성 5과제

도움말을 보지 않고 Claude(ego-browser)가 해 본 값이다. 동작은 클릭과 키 입력을 합친 수다. 사용자 직접 5분 확인은 하지 않았고 사람 확인 항목으로 남겼다.

| 과제 | 1차 전(B §2) | 1차 뒤(센 값) | 목표 | 판정 | 메모 |
|---|---|---|---|---|---|
| 표 하나 + 컬럼 3개 + PK | 11-19 | 19(클릭 6, 키 13) | 도움말 없이 성공, 절반 이하 | 성공, 절반 이하는 못 이룸 | 사전에 없는 표 이름이라 물리명을 직접 넣었고, '여부' 후보가 여럿이라 토막 창을 2번 썼다. 사전에 있는 이름이면 약 13회로 본다. 물리명 칸의 `Enter` 는 효과가 없었다(deferred 105) |
| 관계 긋기 | 3-5(안내 없음) | 4(클릭) | 안내만 보고 성공 | 성공 | 안내 줄이 단계마다 바뀌었다 |
| 컬럼 이름 고치기 | 이름 칸 + [논리명 바꾸기] | 4(표 클릭, 셀 더블클릭, 입력, `Enter`) | 그 자리 편집 1번(2차) | 성공 | 그리드 칸에서 그 자리 편집이 이미 된다. 캔버스 위 그 자리 편집은 2차다 |
| 위반 하나 고치기 | 4-8 | 약 7 | 2-3 | 부분 성공, 목표 못 이룸 | 도메인 다름이 풀렸으나 같은 물리명 컬럼과 타입이 달라 '타입 불일치' 로 바뀌었다. '도메인 다름' 행에 도메인 이름만 보여 무엇을 고칠지 몰랐다(deferred 109). 위반 행 첫 클릭에서 입력 칸 대상이 비었다(deferred 106) |
| 실수 되돌리기 | 1 또는 3-5 + 추측 | 1 | 1, 기록에 이름 | 성공 | `Cmd+Z` 한 번으로 돌아오고 알림 "변경을 되돌렸습니다." 가 나왔다. 변경 기록에는 요소 이름이 보이나 되돌림 행이 원래 행과 글이 같다(deferred 111) |

#### 마감 시험과 남은 일

- 전체 시험은 통과했다. 화면 단위 시험 4201/4202(실패 1은 기존 `ui-meta-lock` 의 m-mcm `userQuery`, deferred 50), 노드 시험 99/99, mdm lib 2271건(실패 0), mdm api 4개 클래스 46건(실패 0)이다.
- 확정 검사: 새 표의 감사 컬럼 8개 위반(DOMAIN 7·ALIAS 1)은 확정을 막지 않고 경고로만 나왔다. 같은 묶음의 일반 컬럼 위반(MISS)은 막는 문제로 나왔고, 그 컬럼을 되돌리자 확정이 성공했다.
- 렌더 하네스(erdEdit `formInput`)는 통과했다. 입력 칸에 한 글자를 칠 때마다 커밋이 1회 일어나고 렌더 시간은 0.9ms(가장 긴 것 1.6ms, 기준 16ms 이하)였다. 화면 루트(`ErdViewer`) 렌더와 그리드 셀 다시 그리기는 0회였다(deferred 95 처리 칸).
- 남은 결함 후보와 관찰은 deferred 96-111 에 있다. 중간 등급은 속성 패널 초점 유지(99), 다이어그램을 바꿀 때 선택이 남는 것(102), 새 컬럼 타입 위반(104), 위반 행 첫 클릭(106), 도메인 다름 안내(109)다.
- 1차가 미룬 일은 deferred 81-95 에 있다. 이 가운데 2차로 넘긴 행은 87(큰 모델 읽기 2차분)·91(관계선 경유점)이다. 92 는 UX 정비 1.5 가, 95 는 1차 마감이 처리했다. 위 순서 표의 2차 화면 일 6개(속성 창·그 자리 편집·복사/붙여넣기·버전 숨기기·둘러보기·추가/이름 바꾸기 분리)는 deferred 124 에 따로 적었다. 사용자 승인이 필요한 일은 52-55·83 이다.
