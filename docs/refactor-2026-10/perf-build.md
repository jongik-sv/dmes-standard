## P3. be-run 종료가 다른 워크트리 gradle 빌드에 주는 영향
- 관련 구조 변경: S4
- 지표(건): be-run 종료 정리 중 다른 워크트리에서 돌던 gradle 빌드·시험의 실패 건수(`Gradle build daemon has been stopped`).
- 측정 절차(결정적, 1회):
  1. 다른 워크트리에서 오래 걸리는 gradle 시험(예: engine test)을 시작해 실행 중으로 둔다.
  2. 측정 대상 체크아웃에서 be-run 으로 모듈 1개 이상을 띄웠다가 종료한다(종료 정리 경로 호출). 서버를 띄우는 것이 부담이면 조정 세션과 조건을 정해 정리 경로만 호출한다.
  3. 다른 워크트리 빌드의 결과(BUILD SUCCESSFUL 여부, 실패 메시지)와 `gradle` 데몬 개수 변화를 기록한다.
  4. 기준(`refactor-2026-10-base`: 종료 시 전역 `gradlew --stop`)과 변경(be51ac2e 이후) 각 1회.
- 기준 커밋: refactor-2026-10-base(b557ccbd) / 변경 커밋: dev 114f909e(be51ac2e 이후)
- 측정 환경: 단독, 2026-10-04 16:33~16:36(A 16:33:25 시작, B 16:34:23 시작), 대상별 1회, 희생 빌드와 be-run 이 같은 측정 전용 Gradle 홈 사용, 희생 빌드 `cd src/backend/mdm && ../gradlew :lib:test :api:test --rerun-tasks --max-workers=2`(반대편 체크아웃에서 실행). 희생 빌드가 돌고 있는 중에 be-run 을 띄웠다가 TERM 으로 종료했다. 빌드 종료 시각은 A 16:34:03(be-run 종료 약 5초 뒤), B 16:36:13.

| 항목 | 기준 | 변경 |
|---|---|---|
| 다른 워크트리 빌드 실패 건수 | 1(rc 1) | 0(rc 0, 시험 성공) |
| `Gradle build daemon has been stopped` 메시지 | 1건 | 0건 |
| 정리 전후 gradle 데몬 수 | 1 → 0 | 1 → 1 |

- 참고(구현 때 관찰, 정식 측정 아님): 변경 쪽에서 다른 워크트리 engine test 실행 중 정리 경로를 호출해 BUILD SUCCESSFUL, 데몬 감소 없음 — S4 의 로그 참조.
- 판정: 기준 실패 1건 → 변경 0건. 기준에서는 be-run 종료의 전역 `gradlew --stop` 이 다른 체크아웃에서 돌던 시험 빌드를 죽였고(데몬 1에서 0), 변경에서는 같은 조건에서 빌드가 끝까지 성공하고 데몬이 유지됐다. 결정적 지표라 1회로 판단했으며 S4 의 구현 중 관찰과 같은 방향이다.
- 해석 주의: 측정 전용 Gradle 홈 안에서 한 결과이며 전역 `~/.gradle` 의 다른 데몬은 건드리지 않았다. 대상별 1회라 우연히 어긋날 여지는 남는다. 기준의 희생 빌드는 도중에 죽었으므로 소요 시간은 비교 지표가 아니다. 이전 무효 시도 2건의 파일은 위 「측정 실행 기록」 에 적었다.
