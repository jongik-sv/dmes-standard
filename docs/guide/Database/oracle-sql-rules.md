# Oracle SQL 작성 규칙

이 저장소의 로컬 개발·자동 테스트·운영 DB 는 모두 **Oracle**(26ai Free 컨테이너, 레인·시험별 PDB)이다(oracle-1007, 2026-10-07 결정). SQL 은 Oracle 하나만 가정하고 쓴다. `NVL`·`DECODE`·`CONNECT BY`·`ROWNUM`·`MERGE` 같은 Oracle 고유 구문을 제한 없이 써도 된다. 이 문서는 Oracle 에서 실수하기 쉬운 점과 권장 구문을 모은다. 접속·PDB 사용법은 [`oracle-26ai-test-guide.md`](oracle-26ai-test-guide.md), 스키마 소유·연결 규약은 [`../../oracle-1007/schema-owners.md`](../../oracle-1007/schema-owners.md) 를 본다.

옛 SQLite·MSSQL·PostgreSQL 방언 대조 자료(`DBMS-용어-비교.md`, `oracle-to-mssql-*.md`)는 보관만 한다.

## 1. 원칙

- **Oracle 고유 구문 허용**: 방언 중립을 맞추려고 `COALESCE`·표준 페이징만 고집하지 않는다. 읽기 쉽고 빠른 Oracle 구문을 쓴다. 방언 판정 코드(`MdmDialect` 류)를 새로 만들지 않는다.
- **단순한 CRUD 는 JPQL·Spring Data**: 엔티티 저장·조회·페이징은 Hibernate 가 `OracleDialect` 로 만들게 두고, 계층 조회·`MERGE`·대량 갱신처럼 Oracle 기능이 필요한 곳만 네이티브 SQL 로 쓴다.
- **운영 Oracle 버전은 23 미만일 수 있다**: 23ai 에서만 되는 기능(`BOOLEAN` 열, `CREATE TABLE IF NOT EXISTS` 같은 `IF [NOT] EXISTS`, `FROM` 없는 `SELECT`)은 쓰지 않는다. 19c·21c 에서 도는 구문으로 쓴다.
- **로컬에서 먼저 확인**: 로컬·시험이 운영과 같은 Oracle 이므로 SQL 오류(`ORA-00904`·`ORA-12899` 등)는 로컬 시험에서 드러난다. 시험을 돌리지 않고 운영 반영을 기다리지 않는다.
- **마이그레이션은 Flyway V 파일**: 스키마 변경은 `db/migration/**` 의 새 `V<n>` 파일로만 한다. 이미 머지된 V 파일(특히 V1 baseline)은 고치지 않는다 — 머리 주석 한 줄도 체크섬을 바꾼다. 절차는 [`flyway-migration-add` 스킬](../../../.claude/skills/flyway-migration-add/SKILL.md).

## 2. Oracle 에서 실수하기 쉬운 점

| 항목 | 규칙 | 안 지키면 |
|---|---|---|
| 빈 문자열 | `''` 는 NULL 이다. `''` 를 저장하거나 `col = ''` 로 찾지 않고, `NOT NULL DEFAULT ''` 를 쓰지 않는다. 빈 값은 NULL 로 통일하고 필수 문자열은 애플리케이션이 공백 검증을 한다 | 조건이 항상 거짓, 저장 시 `ORA-01400` |
| 식별자 | 따옴표·백틱 없이 쓰면 대문자로 저장된다. 엔티티 `@Column(name = "`OFFSET`")` 처럼 **백틱을 쓰면 Hibernate 가 소문자 따옴표 `"offset"` 로 내보내** `ORA-00904` 가 난다(`ddl-auto=validate` 로는 잡히지 않는다). 예약어(`USER`·`ORDER`·`DATE`·`LEVEL`·`COMMENT`·`OFFSET` 등)는 식별자로 쓰지 않고, 아니라면 백틱을 뺀다. 물리명은 [`표준단어사전`](../Common/표준단어사전.md) 을 따른다 | `ORA-00904`(실제 쿼리를 한 번 돌려야 드러난다) |
| 문자열 길이 | `VARCHAR2(n CHAR)` 로 만든다(BYTE 단위면 한글이 길이를 넘는다) | `ORA-12899` |
| 자동 번호 | `GENERATED BY DEFAULT ON NULL AS IDENTITY` 는 **명시한 ID 를 따라가지 않는다.** 시험·골든에서 명시 ID 와 자동 ID 를 섞지 않는다(섞으면 번호가 어긋나거나 PK 중복). 섞어야 하면 넣은 뒤 `alter table <표> modify <칼럼> generated by default on null as identity (start with limit value)` 로 맞춘다 | `ORA-00001` |
| boolean | 열은 `NUMBER(1,0)` + `CHECK (… IN (0,1))`, 앱 설정은 `hibernate.type.preferred_boolean_jdbc_type: TINYINT`. 23 의 `BOOLEAN` 열을 쓰지 않는다 | 운영 Oracle 23 미만에서 매핑 오류 |
| 시각 | 감사 칸(`C_AT`·`U_AT`)과 `Instant` 는 `TIMESTAMP(6)` 로 두고 `preferred_instant_jdbc_type: TIMESTAMP`, `hibernate.jdbc.time_zone` 은 넣지 않는다. JVM 은 `-Duser.timezone=Asia/Seoul` 이라 값은 KST 로 저장된다. `DATE` 는 시각까지 든다(날짜 비교는 `TRUNC`). 현재 시각은 DB 함수보다 앱이 만든 값을 바인딩하고 바인딩 전에 초 단위로 절삭한다(MDM 관례) | 시각이 9시간 어긋남, 비교 불일치 |
| CLOB | `@Lob`(CLOB) 칸에 JPQL `UPPER`·`LOWER`·`LIKE` 를 쓰면 `FunctionArgumentException` 이 난다. 네이티브 SQL(`DBMS_LOB`·`TO_CHAR`)로 바꾸거나 4000바이트 이하면 `VARCHAR2(4000 CHAR)` 로 둔다 | 기동은 되고 그 조회에서 예외 |
| 정렬 NULL | `ASC` 는 NULL 이 뒤, `DESC` 는 NULL 이 앞이다. 순서가 중요하면 `NULLS FIRST/LAST` 를 쓴다 | 화면 순서가 흔들림 |
| IN 목록 | 한 `IN` 목록은 1000개까지다. 넘으면 나누거나 임시 키 표·서브쿼리로 바꾼다 | `ORA-01795` |
| DDL 자동 커밋 | DDL 은 문장마다 커밋된다. V 파일 하나가 중간에 실패하면 앞부분만 적용된 채 남으므로 파일을 작게 나누고 재실행에 안전하게 쓴다 | 반쯤 적용된 스키마 |
| DDL 직후 읽기 | `READ ONLY`·`SERIALIZABLE` 트랜잭션이 열려 있는 동안 다른 곳에서 표 정의를 바꾸면 그 트랜잭션의 읽기가 `ORA-01466`(표 정의가 바뀜)이 난다. DDL 뒤에는 새 트랜잭션·새 연결로 읽는다(시험에서 표를 만든 직후 같은 연결로 읽을 때 주의) | `ORA-01466` |
| 숫자 정렬 | 숫자를 문자 칸에 넣으면 문자 순서로 정렬된다. 정렬 키는 숫자 칸으로 둔다 | 1, 10, 2 순서 |

## 3. 권장 구문

### 페이징

- 목록 조회는 Spring Data `Pageable`·JPQL 로 둔다. 네이티브가 필요하면 `ORDER BY <유일한 키> OFFSET :n ROWS FETCH NEXT :m ROWS ONLY`(12c 이상)로 쓴다. 페이징 쿼리는 항상 유일한 정렬 키까지 `ORDER BY` 에 넣는다.
- 상위 몇 건만 필요하면 `FETCH FIRST n ROWS ONLY` 가 간단하다. 옛 `ROWNUM` 도 허용한다(정렬 뒤에 자르려면 서브쿼리로 감싼다).

### NULL 처리·문자열

- `NVL(a, b)`·`NVL2`·`DECODE` 를 써도 된다. 연결 `a || b` 는 NULL 을 빈 문자열처럼 잇는다(`CONCAT` 도 같다).
- 표시용 문자열 조합은 SQL 보다 애플리케이션에서 하는 편이 쉽다.

### upsert·건수 제한 DML

- 멱등 적재·이관·seed 는 `MERGE INTO t USING (SELECT … FROM DUAL) s ON (…) WHEN MATCHED THEN UPDATE … WHEN NOT MATCHED THEN INSERT …` 를 쓴다. 업무 로직은 조회 후 INSERT/UPDATE 로 나누는 편이 읽기 쉽다.
- 건수를 제한한 `UPDATE`·`DELETE` 는 `WHERE ROWNUM <= n` 으로 쓸 수 있다. 대량 처리는 키 범위 `WHERE` 로 나누어 반복해도 된다.

### 계층·재귀

- 계층 조회는 `START WITH … CONNECT BY [NOCYCLE] PRIOR …` 를 쓰고 `LEVEL`·`SYS_CONNECT_BY_PATH` 로 깊이·경로를 얻는다. 표준 재귀 CTE 는 `RECURSIVE` 낱말 없이 칼럼 목록을 붙인 `WITH t(col, …) AS (앵커 UNION ALL 재귀부)` 로 쓴다(Oracle 은 `RECURSIVE` 를 받지 않는다. MDM 의 기본형이 이 모양이다).

### 채번·시퀀스

- 자동 증가 키는 `GENERATED … AS IDENTITY` 와 JPA `@GeneratedValue` 로 둔다. 업무 채번(문서 번호 등)은 채번 테이블·서비스 또는 시퀀스 `seq.NEXTVAL` 로 한다.

### LIKE

- 사용자 입력으로 `LIKE` 를 만들 때는 `ESCAPE` 를 명시하고 `%`·`_` 를 이스케이프한다.

### 조인

- 외부 조인은 ANSI `LEFT JOIN` 으로 쓴다. 옛 `(+)` 문법은 쓰지 않는다.
