# 한국어 기술 문서 작성 규칙

작성일: 2026-10-09

## 1. 머리말

### 1.1 목적

- 한국어 기술 문서의 작성 기준과 점검 기준을 한 곳에 모읍니다.

### 1.2 적용 범위

- 적용: 기술 문서, 매뉴얼, 스킬 문서, 에이전트 답변입니다.
- 제외: 마케팅, 문학, 설득이 목적인 글입니다.
- 제외: 법령, 계약처럼 문구가 정해진 글입니다. 원문을 바꾸지 않습니다.
- 코드, 명령, 경로, 식별자, 로그 인용은 검사하지 않고 원문 그대로 둡니다.

### 1.3 읽는 법

- 규칙 번호 `U01` 등은 이 문서의 번호입니다.
- 등급은 필수·권장·참고 세 가지입니다.

## 3. 본문 규칙

### 3.1 문장 길이와 구조

**U01 문장은 짧게 씁니다.** `권장`
- 이유: 한 번 읽고 이해하게 하려는 것입니다. 길이만으로 좋은 글과 나쁜 글이 갈리지는 않아서 오류로 두지 않습니다.
- 기준: 절차문 16어절 권장, 20어절 상한. 설명문 20어절 권장, 25어절 상한.
- 어절 셈: 공백으로 나눕니다. 괄호 안 글, 숫자+단위, 약어, 식별자, URL은 각각 한 어절입니다.
- 예: `LG ThinQ 앱을 실행하고 메뉴에서 스마트 진단을 선택하고 안내에 따라 제품을 연결하세요.` → 항목을 나눕니다

**U02 지시 한 문장에 동작 하나를 씁니다.** `권장`
- 이유: 동작이 많으면 독자가 순서를 놓칩니다. 잘 쓴 문서에서 항목당 동작 1개가 74%, 2개가 24%입니다.
- 기준: 한 문장에 동작 1개입니다. 같은 대상의 연속 동작만 `-ㄴ 후`로 한 번 이을 수 있습니다.
- 예: `앱을 실행하고 메뉴에서 스마트 진단을 선택하고 제품을 연결하세요.` → 세 줄로 나눕니다
- 예: `앱을 실행하고 …을 선택하고 …` → `앱을 실행한 후 메뉴의 스마트 진단을 선택하세요.`

**U03 조건을 동작 앞에 씁니다.** `권장`
- 이유: 독자가 동작하기 전에 상황을 확인합니다. 잘 쓴 문서에서 조건 있는 지시문의 94.7%가 조건을 먼저 씁니다.
- 한 문장에 조건은 하나입니다.
- 연결어미(참고): 상황 `-ㄹ 때는`, 상태 `-ㄴ 경우`, 사건 `-면`, 목적 `-려면`.
- 예: `전원 플러그를 콘센트에 단단히 꽂으세요, 물기가 묻어 있으면.` → `전원 플러그에 물기가 묻어 있으면 완전히 제거한 후 콘센트에 단단히 꽂으세요.`
- 예: `연결이 실패하면 로그를 읽는다.`

**U04 한 단락에 한 주제만 쓰고 6문장을 넘기지 않습니다.** `참고`
- 이유: 단락 단위로 찾아 읽기 쉽습니다.
- 제목은 3문장 이상인 단락에만 답니다.
- 예: `설치, 설정, 문제 해결을 한 단락에 씁니다.` → 주제별로 단락을 나눕니다

**U05 세미콜론과 줄표를 쓰지 않습니다.** `권장`
- 이유: 문장을 둘로 나누거나 관계를 말로 쓰면 더 분명합니다. 잘 쓴 매뉴얼과 개발자 문서에는 0건입니다.
- 코드와 정규식 안의 세미콜론은 제외합니다. 기술 보고서에서는 `참고`로 낮춥니다.
- 예: `서버를 재시작합니다; 설정이 적용됩니다.` → `서버를 재시작합니다. 그러면 설정이 적용됩니다.`

### 3.2 태와 서술어

**U06 이중피동을 쓰지 않습니다.** `필수`
- 이유: 국립국어원이 부적절하다고 밝힌 표현이고, 기계로 정확히 잡을 수 있습니다.
- 예: `저장되어집니다` → `저장됩니다`
- 예: `보여짐` → `보임`

**U07 행위자가 있으면 능동으로 씁니다.** `권장`
- 이유: 누가 하는 일인지 독자가 추론하지 않게 합니다.
- 적용: 행위자가 분명하고 중요할 때 능동으로 씁니다. 피동 비율 자체를 목표로 삼지 않습니다.
- 행위자가 없거나 불명이면 피동을 씁니다. 이중피동은 U06에 따라 금지합니다.
- 예: `조선은 태조 이성계에 의해 건국되었다.` → `조선은 태조 이성계가 건국했다.`
- 예: `저장됩니다` → `시스템이 저장합니다`(행위자가 중요할 때)

**U08 불필요한 `-시키다`를 쓰지 않습니다.** `참고`
- 이유: 정당한 사동도 있어서(`발전시키다`) 탐지만 합니다.
- 예: `통계 서비스를 개선시킬` → `통계 서비스를 개선할`

**U09 목적어와 서술어의 호응을 맞춥니다.** `권장`
- 이유: `을/를` 뒤에 피동 서술어가 오는 호응 오류가 있습니다.
- 예: `잡상 행위를 근절될 수 있습니다.` → `잡상 행위를 없앨 수 있습니다.`

**U10 명사화 표현을 동사로 풉니다.** `권장`
- 이유: 동작은 동사로 써야 분명하고 문장이 짧아집니다.
- 적용: 새로 쓰는 기술 문서에만 권장합니다. 기존 문서와 규정문은 일괄로 고치지 않습니다. 필수로 올리지 않습니다.
- 예: `분석을 수행한다` → `분석한다`, `점검을 실시한다` → `점검한다`, `확인을 진행한다` → `확인한다`

**U11 명사를 조사 없이 길게 잇지 않습니다.** `권장`
- 이유: 명사 사이의 관계를 독자가 추측하게 됩니다.
- 기준: 절차문과 개발자 문서는 3어절까지입니다. 기술 보고서는 4어절까지입니다. 6어절 이상은 `필수`입니다.
- 고정 명칭, 제목, 표, 목차는 제외합니다.
- 예: `터미널 세션 실패 피드백 화면 상태` → `터미널 세션이 실패할 때의 화면 상태`
- 예: `MongoDB 연결 정보 설정` → `MongoDB에 연결하는 정보를 설정하세요`

**U12 서술어를 풀어 씁니다.** `권장`
- 이유: `-중에 있다`, `N 시`가 서술어를 대신하면 어떤 동작인지 흐려집니다.
- `N 시`는 실무 문서에도 흔해서 점검 때 우선순위를 낮춥니다.
- 예: `진행 중에 있습니다` → `진행하고 있습니다`, `비교 시` → `비교할 때`

**U13 본문 문장은 서술어로 끝냅니다.** `필수`
- 이유: 전문 교정에서 서술어 복원이 수정의 18%를 차지합니다.
- 제외: 제목, 목록 항목, 표 셀입니다. `genre: 개조식`을 선언한 문서는 `권장`으로 낮춥니다.
- 예: `방문 및 우편 접수 불가하며` → `방문 및 우편 접수는 불가능하며`

**U14 조사를 생략하지 않습니다.** `권장`
- 이유: 조사가 빠지면 주어와 목적어를 독자가 추측합니다.
- 예: `공동 실시하는` → `공동으로 실시하는`
- 예: `저장후 다음이동 클릭` → `저장한 후 '다음 이동'을 눌러`

**U15 지시문은 주어를 생략하고, 설명문은 행위자를 씁니다.** `참고`
- 이유: 지시문의 주어는 언제나 독자라서 생략이 표준입니다. 설명문은 누가 하는 일인지 밝혀야 합니다.
- 지시문이라도 행위자가 둘 이상이면 주어를 씁니다.
- 예: `저장 버튼을 누르세요.`(지시문, 주어 생략) / `시스템이 매일 07시에 백업합니다.`(설명문, 행위자 명시)
- 예: `선정평가 방법은 … 별도 통보` → `… 평가 결과는 별도로 통보함`

### 3.3 종결과 문체

**U16 한 문서에서 종결체 하나만 씁니다.** `권장`
- 이유: 체계가 섞이면 독자가 문서의 격을 의심합니다. 잘 쓴 절차문에서 두 체계를 섞은 문서는 없었습니다.
- 프로젝트의 기존 문서가 정한 어미를 따릅니다. 정하지 않은 채팅 답변은 합니다체입니다.
- 장르별 종결 체계(참고):

| 장르 | 지시 | 설명 | 의무 |
|---|---|---|---|
| 절차문·개발자 문서 | `-세요`, `-지 마세요` | `-ㅂ니다` | `-어야 합니다` |
| 기술 보고서 | 쓰지 않음 | `-ㄴ다` | `-어야 한다` |

- 예: `꼼꼼히 확인 신청 부탁드려요!` → `꼼꼼히 확인한 후 신청해 주세요!`

**U17 지시문은 `-세요`로 끝내고 `-할 것`, `-바람`, `-요망`을 쓰지 않습니다.** 지시형 개조식 금지는 절차문에서 `필수`, `-세요` 표준은 `권장`입니다.
- 이유: 절차문에서 `-기 바랍니다`는 0.2%, `-세요`는 20%입니다. `-십시오`는 구형 문서체입니다.
- 적용: 독자에게 말하는 문서(매뉴얼·절차서·답변)는 `-세요`/`-ㅂ니다`를 씁니다. 규정·명세 문서는 `-ㄴ다`/`-어야 한다`를 씁니다.
- 한 문서에는 한 체계만 씁니다. 프로젝트가 이미 정한 어미가 있으면 그것이 우선합니다.
- 서술문에는 명령형을 섞지 않습니다(`참고`). 지시 구간만 절차문 규칙을 따릅니다.
- 예: `급수 밸브를 열 것` → `급수 밸브를 여세요.`
- 예: `의사, 약사의 지시대로 복용할 것` → `의사나 약사의 지시에 따라 복용하세요.`

### 3.4 어휘

**U18 같은 뜻을 겹쳐 쓰지 않습니다.** `필수`
- 이유: 불필요한 반복입니다. 전문 교정에서 중복 제거가 수정의 18%를 차지합니다.
- 예: `매 1년마다` → `1년마다`, `과반수 이상 참석` → `과반수 참석`

**U19 한 대상에 한 단어만 씁니다.** `필수`
- 이유: 동의어를 돌려 쓰면 독자가 다른 대상으로 읽습니다.
- 영문과 한글을 섞어 같은 대상을 부르지 않습니다. 핵심어를 대명사로 바꾸지 않습니다.
- `필수`는 용어 통일표에 등록한 변이형에 한합니다.
- 예: `설정`을 앞에서 `세팅`, 뒤에서 `설정`으로 씁니다. → `설정`만 씁니다

**U20 번역투를 쓰지 않습니다.** 확정형은 `필수`, 의심형은 `권장`입니다.
- 이유: 확정형(`에 있어서`, `필요로 하다`, `득하다`, `갈음하다`)은 전문가가 예외 없이 고쳤습니다.
- 의심형(`에 의해`, `을 통해`, `에 대하여`, `에 위치하다`)은 정당하게 남는 경우가 있습니다. 행위자가 있으면 능동으로 고칩니다.
- 예: `품질에 있어서 세계 최고` → `품질 면에서 세계 최고`
- 예: `현장에서 필요로 하는` → `현장에서 필요한`

**U21 어려운 한자어를 쉬운 말로 바꿉니다.** `권장`
- 이유: 독자가 아는 말을 씁니다. `본 제품`처럼 장르와 독자에 따라 정당한 표현도 있습니다.
- 예: `허가를 득하지 않고` → `허가를 받지 않고`, `향후 감사 시` → `앞으로 감사할 때`

**U22 외래어는 한글 표기법에 맞게 씁니다. 기술 용어는 우리말로 바꾸지 않습니다.** `권장`
- 이유: 개발자 독자는 기술 용어를 원어나 통용 음차로 더 빨리 알아봅니다(`패스워드`, `업데이트`, `카테고리`, `리스크`).
- 맞추는 것은 표기뿐입니다. 다듬은 말(`누리집`, `내려받다`)로 바꾸지 않습니다.
- 예: `포털싸이트` → `포털사이트`, `메뉴얼` → `매뉴얼`

**U23 낯선 약어는 처음 한 번만 풉니다.** `참고`
- 이유: 통용 약어(URL, API)는 병기 없이 씁니다. 제품 이름과 표준 이름은 설명하지 않습니다.
- 형식: 처음 한 번 `전체 이름(약어)`으로 쓰고, 이후에는 약어만 씁니다.
- 기술 용어는 한국어로 옮겨 병기하지 않습니다. `query`, `cache`처럼 원어나 통용 음차를 그대로 씁니다.
- 예: `정부기능분류체계(BRM)`

**U24 코드, 명령, 파일명, 식별자는 원문 그대로 씁니다.** `참고`
- 이유: 바꾸면 틀린 명령이 됩니다. 검사에서도 뺍니다.
- 예: `빌드 명령을 실행하세요.` → `` `pnpm build`를 실행하세요. ``

**U25 지시어와 대명사는 대상이 바로 앞에 있을 때만 씁니다.** `참고`
- 이유: `해당`, `상기`, `이것`, `그 부분`은 대상이 멀면 독자가 찾아야 합니다.
- 예: `해당 설정을 끄세요.` → `자동 저장 설정을 끄세요.`

**U26 효과를 주장하는 말 대신 사실이나 측정값을 씁니다.** `권장`
- 이유: 근거 없는 수식어는 정보가 없습니다.
- 예: `원활하게 처리한다` → `재시작 없이 적용된다`

**U27 모호한 표현을 구체적으로 씁니다.** `권장`
- 이유: `어느 정도`, `다소`, `등`, `기타`, 의존명사 `것`은 범위를 독자가 짐작하게 합니다.
- 예: `어느 정도 느립니다` → `응답이 2초 걸립니다`

**U28 동사는 통제 동사 목록에서 먼저 고릅니다.** `참고`
- 절차문: 사용하다, 설치하다, 연결하다, 확인하다, 누르다, 넣다, 열다, 켜다, 끄다, 설정하다, 선택하다 등입니다.
- 서술문: 작성하다, 설명하다, 제공하다, 적용하다, 정의하다 등입니다.

### 3.5 표기

**U29 숫자는 아라비아 숫자로 쓰고 단위를 띄어 씁니다.** `참고`
- 이유: 붙여 쓴 사례(`3MB`)도 있어서 오류로 올리지 않습니다.
- 예: `50만명` → `50만 명`, `10 cm`, `220 V`

**U30 날짜와 시간은 한 형식으로 씁니다.** `참고`
- 예: `2015.5.1` → `2015. 5. 1.`, `오후 3시 20분` → `13:20`

**U31 띄어쓰기와 맞춤법을 지킵니다.** `권장`
- 이유: 맞춤법 검사기로 점검합니다.
- 예: `고용현황` → `고용 현황`, `갯수` → `개수`

### 3.6 절차문

**U32 순서가 있는 동작은 번호 목록에 한 줄 한 동작으로 씁니다.** `참고`
- 이유: 독자가 지금 단계를 표시하며 따라 합니다. 결과는 다음 문장에 씁니다.
- 예: `전원을 켜고 설정에서 언어를 고른 뒤 저장하세요.` → `1. 전원을 켜세요.` `2. 설정에서 언어를 고르세요.` `3. 저장하세요.`

**U33 문장 골격을 씁니다.** `참고`
- 골격: `[조건절]? [대상]을/를 [방법]어 [동작]세요.` 필요하면 결과 한 문장을 붙입니다.
- 예: `최소 10 cm의 간격을 유지하여 설치하세요.`, `거리는 10 m 이내로 설치하세요.`

**U34 참고(Note)에는 정보만 쓰고 지시를 넣지 않습니다.** `참고`
- 예: `참고: 이 단계를 건너뛰세요.` → 지시는 번호 항목으로 옮깁니다

### 3.7 설명문과 답변

**U35 첫 문장에 결론이나 결과를 씁니다.** `권장`
- 이유: 독자가 결론을 찾느라 읽지 않게 합니다. 질문을 다시 쓰지 않습니다.
- 예: `좋은 질문입니다. 먼저 …를 살펴보겠습니다.` → `원인은 …입니다.`

**U36 인사말과 맺음말을 쓰지 않습니다.** `권장`
- 이유: 정보가 없습니다. 결정이 필요한 질문만 마지막에 씁니다.
- 예: `도움이 되길 바랍니다.` → 삭제

**U37 근거를 씁니다.** `권장`
- 코드는 `경로:줄`, 커밋은 해시, 명령은 전체 명령으로 씁니다.

**U38 글 유형별 패턴을 따릅니다.** `참고`

| 유형 | 패턴 |
|---|---|
| 오류 메시지 | 무엇이 실패했는지 → 원인(아는 경우만) → 사용자가 할 일 한 문장 |
| 런북·절차서 | 번호 목록, 한 단계 한 동작, 조건 먼저, 되돌릴 수 없는 단계 앞에 경고 |
| 사고 보고서 | 영향과 현재 상태 → 시간순(번호나 표) → 모르는 원인은 「원인을 확인하지 못함」 |
| 릴리스 노트 | 사용자에게 보이는 변화 먼저, 한 항목에 변화 하나 |
| 에이전트 지시문 | 목적, 범위, 완료 조건을 각각 한 문장. 하지 말 일을 명시 |
| 결정 요청 | 번호 선택지, 추천을 첫째에 두고 「(권장)」 표시 |

### 3.8 목록, 표, 강조

**U39 항목이 셋 이상이면 세로 목록으로 씁니다.** `참고`
- 이유: 한 문장에 쉼표로 이은 항목은 경계가 흐립니다.
- 예: `A, B, C, D를 설치합니다.` → 항목마다 한 줄로 씁니다

**U40 같은 속성으로 여러 대상을 비교할 때는 표를 씁니다.** `권장`

**U41 굵은 글씨와 제목을 아낍니다.** `권장`
- 굵은 글씨는 결론 한 곳이나 경고에만 씁니다.

### 3.9 경고와 주의

**U42 위험 수준 식별어는 문장 안이 아니라 블록 머리에 둡니다.** `권장`
- 이유: 잘 쓴 문서에서 `경고`, `주의`는 아이콘이나 라벨로 머리에만 있습니다.
- 경고는 부상·사망 위험, 주의는 장비·데이터 손상 위험입니다.

**U43 경고는 [조건] → 지시 → 결과 순서로 씁니다.** `권장`
- 이유: 독자가 해야 할 일을 먼저 읽습니다. 위험은 다음 문장에 씁니다.
- 예: `전원 플러그를 젖은 손으로 만지지 마세요. 감전의 원인이 됩니다.`

**U44 위험이나 결과를 한두 문장으로 설명합니다.** `권장`
- 결과가 자명하지 않으면 이유절이나 별도 문장으로 씁니다.
- 예: `감전의 위험이 있으니, 전원 플러그를 젖은 손으로 만지지 마세요.`

**U45 되돌릴 수 없는 작업 앞에 경고를 둡니다.** `권장`
- 예: `삭제하세요. 복구할 수 없습니다.` → `복구할 수 없습니다. 삭제하기 전에 백업하세요.`

### 3.10 정보 보존과 사실

**U46 숫자, 단위, 식별자, 고유명사를 모두 보존합니다.** `필수`
- 이유: 고쳐 쓰다 값이 사라지면 문서가 틀립니다. 표기만 바뀐 경우(`308천명` → `30만 8천 명`)는 정상입니다.
- 예: `30분 이내에 처리하세요.` → `빨리 처리하세요.`는 숫자가 사라진 나쁜 재작성입니다. `30분 이내`를 그대로 둡니다

**U47 부정, 핵심 명사, 문장 수를 보존합니다.** `권장`
- 이유: 문장 단순화 지시를 엄격히 따르게 한 외부 실험에서 핵심 사실의 46.8%가 사라졌습니다.
- 문장이 줄었거나 부정(`않`, `못`, `없`, `아니`, `마세요`)이 홀수 번 바뀌면 점검합니다.

**U48 확신 수준을 바꾸지 않고, 확인한 것과 못 한 것을 구분합니다.** `권장`
- 이유: `일 수 있다`를 `이다`로 바꾸면 거짓이 됩니다. 원문의 `약`, `대략`도 둡니다.
- 예: `~라고 할 수 있다` → 근거가 있으면 단정합니다. 없으면 `확인하지 못함`이라고 씁니다

**U49 원문에 없는 수치, 원인, 담당자, 날짜를 만들지 않습니다.** `권장`
- 예: `중요하다` → `더 빠르게 처리한다`로 바꾸지 않습니다. 뜻을 바꿔야만 짧아지면 짧게 하지 않습니다

**U50 오류 메시지와 로그는 원문 그대로 인용합니다.** `권장`
- 줄이거나 바꾸지 않고 코드로 인용합니다. 파괴적 작업 전의 확인 문구도 줄이지 않습니다.
