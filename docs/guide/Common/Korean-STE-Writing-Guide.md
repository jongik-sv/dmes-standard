# 한국어 기술 문서 작성 규칙

## 1. 머리말

### 1.1 목적

- 한국어 기술 문서의 작성 기준을 한 곳에 모읍니다.
- ASD-STE100(Simplified Technical English)의 원칙을 한국어에 맞게 옮긴 규칙입니다.
- 제1원칙: 독자가 추론할 것을 남기지 않습니다. 생략된 조사와 서술어를 채우고, 어려운 말을 풀고, 여러 뜻으로 읽히는 표현을 하나로 정합니다.

### 1.2 적용 범위

- 적용: 기술 문서, 매뉴얼, 화면 안내 문구, 에이전트 답변입니다.
- 제외: 마케팅, 문학, 설득이 목적인 글입니다.
- 제외: 법령, 계약처럼 문구가 정해진 글입니다. 원문을 바꾸지 않습니다.
- 제외: 스킬 문서입니다. 스킬 문서는 별도 문체 규칙(명사형 종결, 짧은 불릿)을 따릅니다.
- 코드, 명령, 경로, 식별자, 로그 인용은 원문 그대로 둡니다.

### 1.3 등급

- 필수: 반드시 지킵니다.
- 권장: 특별한 이유가 없으면 지킵니다.
- 참고: 상황에 맞게 판단합니다.

## 2. 본문 규칙

### 2.1 문장 길이와 구조

**U01 문장은 짧게 씁니다.** `권장`
- 이유: 한 번 읽고 이해하게 하려는 것입니다. 길이만으로 좋은 글이 정해지지는 않아서 `권장`으로 둡니다.
- 기준: 절차문 16어절 권장, 20어절 상한. 설명문 20어절 권장, 25어절 상한.
- 어절 셈: 공백으로 나눕니다. 괄호 안 글, 숫자+단위, 약어, 식별자, URL은 각각 한 어절입니다.
- 예: `Docker Desktop의 기업 유료 라이선스 제약을 피하고, Mac(Apple Silicon)과 Windows(WSL2) 양쪽 환경에서 동일한 설정과 podman compose(또는 Docker 호환 모드) 명령어로 테스트할 수 있도록 구성되었습니다.` → `Docker Desktop의 기업 유료 라이선스 제약을 피했습니다. Mac(Apple Silicon)과 Windows(WSL2)에서 같은 설정과 podman compose 명령으로 테스트할 수 있습니다.`

**U02 지시 한 문장에 동작 하나를 씁니다.** `권장`
- 이유: 동작이 많으면 독자가 순서를 놓칩니다. 동작을 하나씩 끊으면 독자가 단계를 건너뛰지 않습니다.
- 기준: 한 문장에 동작 1개입니다. 같은 대상의 연속 동작만 `-ㄴ 후`로 한 번 이을 수 있습니다.
- 예: `서버를 내리고 Flyway를 적용하고 서버를 올리세요.` → 세 줄로 나눕니다
- 예: `예약 작업을 열고 실행 주기를 고치세요.` → `예약 작업을 연 후 실행 주기를 고치세요.`

**U03 조건을 동작 앞에 씁니다.** `권장`
- 이유: 독자가 동작하기 전에 상황을 확인합니다. 조건이 뒤에 오면 독자는 동작한 뒤에야 조건을 읽습니다.
- 한 문장에 조건은 하나입니다.
- 연결어미(참고): 상황 `-ㄹ 때는`, 상태 `-ㄴ 경우`, 사건 `-면`, 목적 `-려면`.
- 예: `저장 버튼을 누르세요, 필수 칸을 모두 채웠으면.` → `필수 칸을 모두 채웠으면 저장 버튼을 누르세요.`
- 예: `게시 대상을 역할로 정했으면 역할을 하나 이상 고르세요.`(조건이 앞에 있는 좋은 문장)

**U04 한 단락에 한 주제만 쓰고 6문장을 넘기지 않습니다.** `참고`
- 이유: 단락 단위로 찾아 읽기 쉽습니다.
- 제목은 3문장 이상인 단락에만 답니다.
- 예: `예약 작업 등록, 실행 이력 조회, 장애 대응을 한 단락에 씁니다.` → 주제별로 단락을 나눕니다

**U05 세미콜론과 줄표를 쓰지 않습니다.** `권장`
- 이유: 문장을 둘로 나누거나 관계를 말로 쓰면 더 분명합니다. 세미콜론과 줄표는 앞뒤 문장의 관계를 알려 주지 않습니다.
- 코드와 정규식 안의 세미콜론은 제외합니다. 기술 보고서에서는 `참고`로 낮춥니다.
- 예: `WildFly 40 통합 인스턴스부터 시작 가능; 자원·장애영역 문제 시 MPN/Caravan 분리` → `WildFly 40 통합 인스턴스부터 시작할 수 있습니다. 자원이나 장애 영역에 문제가 생기면 MPN과 Caravan으로 나눕니다.`
- 예: `MCM을 내립니다; 모듈의 예약 작업이 멈춥니다.` → `MCM을 내리면 모듈의 예약 작업이 멈춥니다.`

### 2.2 태와 서술어

**U06 이중피동을 쓰지 않습니다.** `필수`
- 이유: 한 동사에 피동을 두 번 붙인 군더더기 표현입니다.
- 예: `신입사원 입사에서 퇴직에 이르기까지 관리되어지는 인사행정` → `신입사원 입사에서 퇴직에 이르기까지 관리하는 인사행정`
- 예: `조회되어집니다` → `조회됩니다`, `숨겨져 보여지지 않습니다` → `숨겨져 보이지 않습니다`

**U07 행위자가 있으면 능동으로 씁니다.** `권장`
- 이유: 누가 하는 일인지 독자가 추론하지 않게 합니다.
- 적용: 행위자가 분명하고 중요할 때 능동으로 씁니다. 피동 비율 자체를 목표로 삼지 않습니다.
- 행위자가 없거나 불명이면 피동을 씁니다. 이중피동은 U06에 따라 금지합니다.
- 예: `요청이 거부되었습니다.` → `서버가 요청을 거부했습니다.`
- 예: `머지 허가는 조정자에 의해 내려진다.` → `조정자가 머지를 허가한다.`

**U08 불필요한 `-시키다`를 쓰지 않습니다.** `참고`
- 이유: 주어가 스스로 하는 일에 `-시키다`를 붙이면 뜻이 흐려집니다. 필요한 사동(`발전시키다`)은 그대로 둡니다.
- 예: `조회 속도를 향상시킨다` → `조회 속도를 높인다`

**U09 목적어와 서술어의 호응을 맞춥니다.** `권장`
- 이유: `을/를` 뒤에 피동 서술어가 오는 호응 오류가 있습니다.
- 예: `만료된 세션을 삭제될 수 있습니다.` → `만료된 세션을 삭제할 수 있습니다.`

**U10 명사화 표현을 동사로 풉니다.** `권장`
- 이유: 동작은 동사로 써야 분명하고 문장이 짧아집니다.
- 적용: 새로 쓰는 기술 문서에만 권장합니다. 기존 문서와 규정문은 일괄로 고치지 않습니다. 필수로 올리지 않습니다.
- 예: `Oracle은 DDL 문 전후에 암묵적 COMMIT을 수행한다.` → `Oracle은 DDL 문 전후에 암묵적으로 COMMIT한다.`
- 예: `메뉴·권한 실측을 수행한다.` → `메뉴·권한을 실측한다.`

**U11 명사를 조사 없이 길게 잇지 않습니다.** `권장`
- 이유: 명사 사이의 관계를 독자가 추측하게 됩니다.
- 기준: 절차문과 개발자 문서는 3어절까지입니다. 기술 보고서는 4어절까지입니다. 6어절 이상은 `필수`입니다.
- 고정 명칭, 제목, 표, 목차는 제외합니다.
- 예: `예약 작업 실행 결과 갱신 실패 처리 방식` → `예약 작업의 실행 결과를 갱신하지 못했을 때의 처리 방식`
- 예: `MDM 컬럼 사전 버전 대상 조회 규칙` → `MDM 컬럼 사전에서 버전이 있는 대상을 조회하는 규칙`

**U12 서술어를 풀어 씁니다.** `권장`
- 이유: `-중에 있다`, `N 시`가 서술어를 대신하면 어떤 동작인지 흐려집니다.
- 예: `가림 함수 실패 시 그 대상은 올리지 않는다` → `가림 함수가 실패하면 그 대상은 올리지 않는다`
- 예: `재시도 중에 있습니다` → `재시도하고 있습니다`

**U13 본문 문장은 서술어로 끝냅니다.** `필수`
- 이유: 서술어가 없으면 문장이 끝나지 않아서 독자가 빠진 동작을 짐작해야 합니다.
- 제외: 제목, 목록 항목, 표 셀입니다.
- 예: `Flyway 마이그레이션을 통해 스키마 변경 사항을 코드로 버전 관리.` → `Flyway 마이그레이션으로 스키마 변경을 코드로 버전 관리합니다.`
- 예: `수동 실행과 재실행 요청은 화면에서 불가하며` → `수동 실행과 재실행 요청은 화면에서 할 수 없으며`

**U14 조사를 생략하지 않습니다.** `권장`
- 이유: 조사가 빠지면 주어와 목적어를 독자가 추측합니다.
- 예: `모듈 서버 재기동하면` → `모듈 서버를 재기동하면`
- 예: `조회후 저장버튼 클릭` → `조회한 후 '저장' 버튼을 눌러`

**U15 지시문은 주어를 생략하고, 설명문은 행위자를 씁니다.** `참고`
- 이유: 지시문의 주어는 언제나 독자라서 생략이 표준입니다. 설명문은 누가 하는 일인지 밝혀야 합니다.
- 지시문이라도 행위자가 둘 이상이면 주어를 씁니다.
- 예: `[저장]을 누르세요.`(지시문, 주어 생략) / `실행은 작업에 지정한 모듈 서버가 합니다.`(설명문, 행위자 명시)
- 예: `실행 결과는 이력에 기록` → `MCM이 실행 결과를 이력에 기록합니다.`

### 2.3 종결과 문체

**U16 한 문서에서 종결체 하나만 씁니다.** `권장`
- 이유: 체계가 섞이면 독자가 문서의 격을 의심합니다. 한 문서는 한 체계로 끝까지 씁니다.
- 프로젝트의 기존 문서가 정한 어미를 따릅니다. 정하지 않은 채팅 답변은 합니다체입니다.
- 장르별 종결 체계(참고):

| 장르 | 지시 | 설명 | 의무 |
|---|---|---|---|
| 독자에게 말하는 문서(매뉴얼·절차서·개발자 문서·답변) | `-세요`, `-지 마세요` | `-ㅂ니다` | `-어야 합니다` |
| 규정·명세·보고서 | 쓰지 않음 | `-ㄴ다` | `-어야 한다` |

- 예: `저장 전 입력값 확인 부탁드려요!` → `저장하기 전에 입력값을 확인해 주세요.`

**U17 지시문에 `-할 것`, `-바람`, `-요망`을 쓰지 않습니다.** `필수`
- 이유: `-할 것`, `-바람`, `-요망`은 독자에게 말하는 문장으로 읽히지 않습니다. `-세요`는 독자에게 바로 말하는 형태입니다. `-십시오`는 구형 문서체입니다.
- 지시는 U16 체계표의 지시 어미로 씁니다.
- 서술문에는 명령형을 섞지 않습니다(`참고`). 지시 구간만 절차문 규칙을 따릅니다.
- 예: `반드시 V{nxt} 를 쓸 것.` → `반드시 V{nxt} 를 쓰세요.`
- 예: `재기동 전에 실행 중인 작업을 확인할 것` → `재기동하기 전에 실행 중인 작업을 확인하세요.`

### 2.4 어휘

**U18 같은 뜻을 겹쳐 쓰지 않습니다.** `필수`
- 이유: 불필요한 반복입니다. 같은 뜻을 한 번만 써도 문장이 짧아지고 뜻은 그대로입니다.
- 예: `모두 다 워크플로우를 다 넣을 필요없이` → `모두 워크플로우를 넣을 필요 없이`
- 예: `기존에 있던 컬럼정보들은 모두 삭제됩니다.` → `기존 컬럼 정보는 모두 삭제됩니다.`

**U19 한 대상에 한 단어만 씁니다.** `필수`
- 이유: 동의어를 돌려 쓰면 독자가 다른 대상으로 읽습니다.
- 영문과 한글을 섞어 같은 대상을 부르지 않습니다. 핵심어를 대명사로 바꾸지 않습니다.
- 용어집에 정한 표기가 있으면 그 표기를 씁니다.
- 예: `컬럼`을 앞에서, `칼럼`을 뒤에서 씁니다. → `컬럼`만 씁니다
- 예: `예약 작업`을 앞에서, `스케줄 작업`을 뒤에서 씁니다. → `예약 작업`만 씁니다

**U20 번역투를 쓰지 않습니다.** `필수`·`권장`
- 이유: 번역투는 한국어 어법에 맞지 않거나 문장을 길게 만듭니다.
- 확정형 `필수`: `에 있어서`, `필요로 하다`, `득하다`, `갈음하다`는 예외 없이 고칩니다.
- 의심형 `권장`: `에 의해`, `을 통해`, `에 대하여`, `에 위치하다`는 정당하게 남는 경우가 있습니다. 행위자가 있으면 능동으로 고칩니다.
- 예: `그 갈래가 필요로 하는 키를 한꺼번에 검사한다.` → `그 갈래가 필요한 키를 한꺼번에 검사한다.`
- 예: `깨진 값이 팝업을 통해 계속 재주입됐다.` → `깨진 값이 팝업으로 계속 재주입됐다.`

**U21 어려운 한자어를 쉬운 말로 바꿉니다.** `권장`
- 이유: 독자가 아는 말을 씁니다. `본 시스템`처럼 장르와 독자에 따라 정당한 표현도 있습니다.
- 예: `가장 긴 시그니처가 먼저 시도된다는 점을 감안한다.` → `…점을 고려한다.`
- 예: `향후 cmn/if DS query 도 지원하려면` → `앞으로 cmn/if DS query 도 지원하려면`

**U22 외래어는 한글 표기법에 맞게 씁니다. 기술 용어는 우리말로 바꾸지 않습니다.** `권장`
- 이유: 개발자 독자는 기술 용어를 원어나 통용 음차로 더 빨리 알아봅니다(`패스워드`, `업데이트`, `카테고리`, `리스크`).
- 맞추는 것은 표기뿐입니다. 다듬은 말(`누리집`, `내려받다`)로 바꾸지 않습니다.
- 예: `컨텐츠 영역` → `콘텐츠 영역`, `스케쥴러` → `스케줄러`

**U23 낯선 약어는 처음 한 번만 풉니다.** `참고`
- 이유: 통용 약어(URL, API)는 병기 없이 씁니다. 제품 이름과 표준 이름은 설명하지 않습니다.
- 형식: 처음 한 번 `전체 이름(약어)`으로 쓰고, 이후에는 약어만 씁니다.
- 기술 용어는 한국어로 옮겨 병기하지 않습니다. `query`, `cache`처럼 원어나 통용 음차를 그대로 씁니다.
- 예: `마스터 데이터 관리(MDM)`

**U24 코드, 명령, 파일명, 식별자는 원문 그대로 씁니다.** `참고`
- 이유: 바꾸면 틀린 명령이 됩니다.
- 예: `MDM 서버를 띄우는 스크립트를 실행하세요.` → `` `local-run.sh --mdm -q`를 실행하세요. ``

**U25 지시어와 대명사는 대상이 바로 앞에 있을 때만 씁니다.** `참고`
- 이유: `해당`, `상기`, `이것`, `그 부분`은 대상이 멀면 독자가 찾아야 합니다.
- 예: `재작성 후에도 불일치하면 해당 항목은 확정하지 않고 …` → `재작성 후에도 불일치하면 불일치한 항목은 확정하지 않고 …`

**U26 효과를 주장하는 말 대신 사실이나 측정값을 씁니다.** `권장`
- 이유: 근거 없는 수식어는 정보가 없습니다.
- 예: `예약 작업을 안정적으로 실행한다` → `실행에 실패하면 3번까지 다시 시도한다`

**U27 모호한 표현을 구체적으로 씁니다.** `권장`
- 이유: `어느 정도`, `다소`, `등`, `기타`, 의존명사 `것`은 범위를 독자가 짐작하게 합니다.
- 예: `다소 오래 걸립니다` → `조회에 30초 걸립니다`
- 예: `권한 등을 확인합니다` → `메뉴 권한과 버튼 권한을 확인합니다`

**U28 동사는 통제 동사 목록에서 먼저 고릅니다.** `참고`
- 절차문: 열다, 누르다, 입력하다, 고르다, 선택하다, 저장하다, 실행하다, 확인하다, 조회하다, 지정하다, 등록하다, 지우다, 바꾸다입니다.
- 서술문: 실행하다, 호출하다, 기록하다, 표시하다, 적용하다, 반환하다, 생성하다, 검사하다, 읽다, 막다, 맞추다, 보내다입니다.

### 2.5 표기

**U29 숫자는 아라비아 숫자로 쓰고 단위를 띄어 씁니다.** `참고`
- 단위를 붙여 쓴 관용 표기(`3MB`)도 허용합니다.
- 예: `3만건` → `3만 건`, `512 MB`, `8 GB`

**U30 날짜와 시간은 한 형식으로 씁니다.** `참고`
- 형식: 날짜는 `YYYY-MM-DD`, 시각은 24시간제 `HH:MM`입니다.
- 예: `2026.10.9` → `2026-10-09`, `오후 7시 30분` → `19:30`

**U31 띄어쓰기와 맞춤법을 지킵니다.** `권장`
- 이유: 띄어쓰기가 틀리면 단어 경계가 흐려지고 검색에도 걸리지 않습니다.
- 예: `입력값을 확인해주세요.` → `입력값을 확인해 주세요.`
- 예: `N건 조회 되었습니다.` → `N건 조회되었습니다.`
- 예: `게시상태를 선택하세요.` → `게시 상태를 선택하세요.`
- 예: `본문 [확인필요] 갯수` → `본문 [확인필요] 개수`

### 2.6 절차문

**U32 순서가 있는 동작은 번호 목록에 한 줄 한 동작으로 씁니다.** `참고`
- 이유: 독자가 지금 단계를 표시하며 따라 합니다. 결과는 다음 문장에 씁니다.
- 예: `MDM을 먼저 띄우고 포털에 로그인한 뒤 화면을 여세요.` → `1. MDM을 띄우세요.` `2. 포털에 로그인하세요.` `3. 화면을 여세요.`

**U33 문장 골격을 씁니다.** `참고`
- 골격: `[조건절]? [대상]을/를 [방법]어 [동작]세요.` 필요하면 결과 한 문장을 붙입니다.
- 예: `저장하기 전에 필수 칸을 모두 입력하세요.`, `실행 주기는 5분 이상으로 지정하세요.`

**U34 참고(Note)에는 정보만 쓰고 지시를 넣지 않습니다.** `참고`
- 예: `참고: 서버를 재기동하세요.` → 지시는 번호 항목으로 옮깁니다

### 2.7 설명문과 답변

**U35 첫 문장에 결론이나 결과를 씁니다.** `권장`
- 이유: 독자가 결론을 찾느라 읽지 않게 합니다. 질문을 다시 쓰지 않습니다.
- 예: `예약 작업이 멈춘 이유를 설명드리겠습니다. 먼저 MCM 상태를 보겠습니다.` → `MCM이 꺼져 있어서 멈췄습니다.`

**U36 인사말과 맺음말을 쓰지 않습니다.** `권장`
- 이유: 정보가 없습니다. 결정이 필요한 질문만 마지막에 씁니다.
- 예: `더 궁금한 점이 있으면 말씀해 주세요.` → 삭제

**U37 근거를 씁니다.** `권장`
- 코드는 `경로:줄`, 커밋은 해시, 명령은 전체 명령으로 씁니다.

**U38 글 유형별 패턴을 따릅니다.** `참고`

| 유형 | 패턴 |
|---|---|
| 오류 메시지 | 무엇이 실패했는지 → 원인(아는 경우만) → 사용자가 할 일 한 문장 |
| 런북·절차서 | 번호 목록, 한 단계 한 동작, 조건 먼저, 되돌릴 수 없는 단계 앞에 경고 |
| 사고 보고서 | 영향과 현재 상태 → 시간순(번호나 표) → 모르는 원인은 「원인을 확인하지 못함」 |
| 릴리스 노트 | 사용자에게 보이는 변화 먼저, 한 항목에 변화 하나 |
| 에이전트 지시문 | 목적, 범위, 완료 조건을 각각 한 문장. 하지 말 일을 명시 |
| 결정 요청 | 번호 선택지, 추천을 첫째에 두고 「(권장)」 표시 |

- 예: `서버와 연결할 수 없습니다. 네트워크 또는 서버 상태를 확인한 뒤 다시 시도해 주세요.`(오류 메시지: 실패한 일, 사용자가 할 일 한 문장)

### 2.8 목록, 표, 강조

**U39 항목이 셋 이상이면 세로 목록으로 씁니다.** `참고`
- 이유: 한 문장에 쉼표로 이은 항목은 경계가 흐립니다.
- 예: `MCM, MDM, MLS, MQC를 차례로 띄웁니다.` → 항목마다 한 줄로 씁니다

**U40 같은 속성으로 여러 대상을 비교할 때는 표를 씁니다.** `권장`

**U41 굵은 글씨와 제목을 아낍니다.** `권장`
- 굵은 글씨는 결론 한 곳이나 경고에만 씁니다.

### 2.9 경고와 주의

**U42 위험 수준 식별어는 문장 안이 아니라 블록 머리에 둡니다.** `권장`
- 이유: `경고`, `주의`는 아이콘이나 라벨로 블록 머리에만 둡니다. 문장 안에 섞으면 위험 수준이 눈에 띄지 않습니다.
- 경고는 데이터 손실, 되돌릴 수 없는 작업, 서비스 중단 위험입니다. 주의는 성능 저하, 설정 오류 위험입니다.

**U43 경고는 [조건] → 지시 → 결과 순서로 씁니다.** `권장`
- 이유: 독자가 해야 할 일을 먼저 읽습니다. 위험은 다음 문장에 씁니다.
- 예: `운영 DB에서는 DROP을 실행하지 마세요. 테이블과 데이터가 모두 사라집니다.`

**U44 위험이나 결과를 한두 문장으로 설명합니다.** `권장`
- 결과가 자명하지 않으면 이유절이나 별도 문장으로 씁니다.
- 예: `데이터 유실의 위험이 있으니, 사용 중인 PDB를 지우지 마세요.` → `사용 중인 PDB를 지우지 마세요. 그 PDB를 쓰는 시험이 모두 실패합니다.`

**U45 되돌릴 수 없는 작업 앞에 경고를 둡니다.** `권장`
- 예: `이력을 지우세요. 되돌릴 수 없습니다.` → `되돌릴 수 없습니다. 이력을 지우기 전에 백업하세요.`
- 예: `이 마루 코드를 삭제하면 되돌릴 수 없습니다. 삭제할까요?`(경고가 확인 질문 앞에 있는 좋은 문구)

### 2.10 정보 보존과 사실

**U46 숫자, 단위, 식별자, 고유명사를 모두 보존합니다.** `필수`
- 이유: 고쳐 쓰다 값이 사라지면 문서가 틀립니다. 표기만 바뀐 경우(`1200건` → `1,200건`)는 정상입니다.
- 예: `5분마다 실행하세요.` → `자주 실행하세요.`는 숫자가 사라진 나쁜 재작성입니다. `5분마다`를 그대로 둡니다

**U47 부정, 핵심 명사, 문장 수를 보존합니다.** `권장`
- 이유: 문장을 줄이다 보면 핵심 사실이 함께 사라지는 일이 잦습니다.
- 고친 뒤 부정 표현(`않`, `못`, `없`, `아니`, `마세요`)이 그대로인지 확인합니다.

**U48 확신 수준을 바꾸지 않고, 확인한 것과 못 한 것을 구분합니다.** `권장`
- 이유: `일 수 있다`를 `이다`로 바꾸면 거짓이 됩니다. 원문의 `약`, `대략`도 둡니다.
- 예: `원인은 락 경합일 수 있습니다` → 스레드 덤프 같은 근거가 있으면 `원인은 락 경합입니다`로 단정합니다. 없으면 `원인을 확인하지 못했습니다`라고 씁니다

**U49 원문에 없는 수치, 원인, 담당자, 날짜를 만들지 않습니다.** `권장`
- 예: `실행 이력을 확인한다` → `실행 이력을 확인해 30분 안에 원인을 찾는다`로 바꾸지 않습니다. 뜻을 바꿔야만 짧아지면 짧게 하지 않습니다

**U50 오류 메시지와 로그는 원문 그대로 인용합니다.** `권장`
- 줄이거나 바꾸지 않고 코드로 인용합니다. 파괴적 작업 전의 확인 문구도 줄이지 않습니다.
