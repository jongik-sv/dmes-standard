## 개요

- 본 문서의 [표준단어 목록](#표준단어-목록)은 bpgoat derd 표준사전의 **표준단어(word)** 만 추출한 것이다. (도메인 0건 · 용어 6건은 범위 외)
- 각 단어는 **논리명(한글) / 물리명(약어) / 영문명(풀네임)** 으로 구성된다. 물리명은 컬럼·식별자 명명 시 조합 토큰으로 사용된다.
- 전 단어 `중복예외(dupExempt)=false`, `설명`은 논리명과 동일하여 별도 열로 표기하지 않는다.
- 물리명 중복 없음(보강 단어 포함).
- 정렬: 물리명 알파벳순.
- 표준사전에 없는 개념 중 프로젝트 설계가 이미 쓰는 토큰은 [프로젝트 보강 단어](#프로젝트-보강-단어)에 따로 모은다 — **표준단어 목록(미러)과 섞지 않는다**. 표준사전 등재가 확정되면 목록으로 옮긴다.
- 표준단어 목록의 번호(`#`)는 다른 설계 문서가 토큰 근거로 인용하므로 **행 삽입으로 다시 매기지 않는다**.

## 프로젝트 보강 단어

표준사전 미러에 없어 등재 협의가 필요한 토큰이다. 행 형식과 정렬(물리명 알파벳순)은 표준단어 목록과 같고, 번호는 목록에 이어 붙인 로컬 채번이라 등재가 확정되면 표준사전이 부여하는 번호로 대체된다.

| # | 논리명 | 물리명 | 영문명 |
|---:|--------|--------|--------|
| 453 | 직전 | BEF | BEFORE |
| 454 | 생산지시 | PD | PRODUCTION INSTRUCTION |

- `BEF` 는 보류 직전 오더상태를 담는 `BEF_PD_ORDER_STATUS`·`BEF_WO_ORDER_STATUS` 의 접두다. 표준단어 목록에는 **직전 시점**을 가리키는 토큰이 없다(`ORIGIN`(#268 원본)은 최초 값을 가리켜 의미가 다르다).
- `PD` 는 생산지시 업무번호 `PD_NO` 와 생산지시 오더상태 `PD_ORDER_STATUS` 의 레벨 접두다. 같은 자리에 오는 작업지시 접두 `WO` 는 목록 #447 에 등재돼 있다.

> 🔶 **확인필요 (보강 단어 등재)**: 본 문서는 bpgoat derd 표준사전 미러라 단어 신규 등재를 이 문서만으로 확정할 수 없다.
> 항목 = `BEF`(직전)·`PD`(생산지시) 표준사전 등재.
> 영향 = 명명 표준. 등재 전까지 두 토큰을 쓰는 컬럼은 현재 표기를 그대로 쓴다.
> 확인 주체 = 표준사전 관리자·mpp 개발팀.

### 논리명 보강 대상

물리명은 표준단어 목록에 있으나 논리명이 실제 사용 의미와 갈리는 토큰이다. 물리명이 중복되므로 새 행을 만들지 않고 **논리명 보강**으로 처리한다.

| 물리명 | 목록 논리명 | 사용 의미 |
|---|---|---|
| `ORDER` (#265) | 주문 | 오더(제조오더) — 오더상태 `PD_ORDER_STATUS`·`WO_ORDER_STATUS` 의 축 이름 |
| `WO` (#447) | 작업오더 | 작업지시 — `TB_MPP_WORK_ORDER` |
| `RELEASE` (#332) | 출시 | 릴리즈 — `RELEASE_DTTM`·`RELEASE_USER_REF` |
| `ISSUE` (#202) | 이슈 | 발행 — `ISSUE_DTTM` |

`STATUS`(#383 상태)는 오더상태 컬럼의 사용 의미와 일치해 보강 대상이 아니다.

> 🔶 **확인필요 (논리명 보강)**: 위 네 토큰은 물리명이 이미 등재돼 있어 행을 추가할 수 없고, 논리명만 사용 의미를 담도록 넓혀야 한다.
> 항목 = `ORDER`(주문 → 주문·오더)·`WO`(작업오더 → 작업오더·작업지시)·`RELEASE`(출시 → 출시·릴리즈)·`ISSUE`(이슈 → 이슈·발행) 논리명 보강.
> 영향 = 논리명만 바뀌고 물리명 토큰은 그대로라 컬럼명은 영향이 없다. 보강 전에는 목록 논리명과 설계 문서 용어가 갈려 보인다.
> 확인 주체 = 표준사전 관리자·mpp 개발팀.
