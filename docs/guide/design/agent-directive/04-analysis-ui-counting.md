# Agent 화면 설계서 생성 지시서 V2

> 상위 문서: [Agent 화면 설계서 생성 지시서 V2](../00_Agent지시_가이드.md)

### 6.4 As-Is 화면 요소 전수 분석

> **(MUST)** 본 §6.4 의 알고리즘은 **자동 적용**한다. Agent 가 사용자에게 묻지 않는다. 알고리즘 결과가 As-Is 자료 부족으로 도출 불가능한 경우만 `[확인필요: Q-NNN]` 등재 + 가능 범위로 진행. 자동 판정 결과를 자체 추론으로 뒤집을 수 없다 (MUST NOT). 같은 As-Is 자료에 대해 N 차 반복 적용해도 동일 결과를 도출해야 한다.

### 6.4-R10 반복 결정성 보강 규칙

본 절은 동일 As-Is 자료를 N차 반복 분석해도 동일한 screenId, S-NNN, G-NNN, GE-NNN, B-NNN, GB-NNN, P-NNN, ST-NNN, LV-NNN 결과가 나오도록 하기 위한 결정성 보강 규칙이다.

> **(MUST)** Claude는 본 절의 포함 / 제외 / 별도 분류 기준을 임의 해석할 수 없다. 본 절과 개별 §6.4.x 알고리즘이 충돌하면 **본 R10 보강 규칙을 우선 적용**한다.

#### R10-1. screenId 결정 우선순위

screenId는 다음 우선순위로 결정한다.

| 우선순위 | 조건 | 처리 |
|---:|---|---|
| 1 | `01_Agent부속_가이드.md` A.3 화면 ↔ As-Is 매핑에 As-Is 코드가 등재됨 | **등재된 `화면식별자`를 그대로 사용** (자체 도출 금지) |
| 2 | 사용자 입력에 화면식별자가 명시됨 | 사용자 입력값 사용. 단, A.3 등재값과 충돌 시 **A.3 우선** |
| 3 | A.3 미등재 + 사용자 입력 없음 | 화면명 기반 후보를 제안하지 말고 `[확인필요: Q-NNN]` 등록 |
| 4 | A.3 미등재 + 후보 산출 가능 | 후보는 분석리포트 §12 결정 후보에만 기록하고 확정값으로 사용하지 않음 |

**MUST NOT**

- As-Is 코드가 A.3에 등재되어 있는데 별도 screenId를 자체 도출하지 않는다.
- `workReport`가 등재되어 있으면 `workReportStatus`, `workReportList`, `workResult` 등으로 변경하지 않는다.
- serviceId는 screenId와 동일하게 사용한다.
- **MES 룰 (사용자 결정 사항 — `mls` / `mqc` / `mpp` / `mas` / `mcm`)**: `pageId` / `pageName` 모두 `screenId` 와 동일 camelCase 단일값을 사용한다 (예: `plateSlittingMgmt`). kebab-case (`mls-plate-slitting-mgmt`) ✗ / `portal:{moduleGroup}/{pageName}` path 구조 ✗ / 별도 토큰 분리 ✗. APS 예외 (`mpn`) 만 기존 kebab-case + `-page.tsx` 컨벤션 유지 (§3.1.1 별표 / 01 §A.4.2 / §A.4.3 / §A.4.6 정본).

#### R10-2. S-NNN 조회조건 카운트 결정표

조회조건은 `검색 영역 컨테이너` 내부의 사용자 입력 가능 컨트롤만 카운트한다.

| 원천 | S-NNN 처리 |
|---|---|
| 검색 영역 내부 TextBox | 포함 |
| 검색 영역 내부 ComboBox | 포함 |
| 검색 영역 내부 CheckBox | 포함 |
| 검색 영역 내부 DatePicker | 포함 |
| `txt{X}Cd + btn{X} + txt{X}Nm` Lookup 묶음 | **1행 포함** |
| `txt{X} + btn{X}` Lookup 묶음 | **1행 포함** |
| `btn{X}` 단독 + 조회조건 보조 팝업 역할 | S-NNN에 포함하지 않고 B-NNN 또는 P-NNN 트리거로 분류 |
| Label 단독 | 제외 |
| Hidden / Visible=false | **제외** (`this.X.Visible = false` 라인 명시 검색) |
| 주석 처리 컨트롤 | 제외 |
| 검색영역 밖 Form/Toolbar/Grid 내부 컨트롤 | 제외 |
| 소스에는 있으나 designer 검색영역에서 위치 확인 불가 | `[확인필요: Q-NNN]` 등록, S-NNN 확정 카운트 제외 |

정렬은 `Y좌표 → X좌표 → 컨트롤명 → designer 선언 순서`로 고정한다.

#### R10-3. G-NNN / GE-NNN alias 카운트 결정표

그리드 컬럼은 SQL SELECT alias 기준으로만 카운트한다.

| 원천 | 처리 |
|---|---|
| 대표 조회 분기 `sList` SELECT alias | G-NNN |
| `sList2`, `sSubList`, `sDasSearch`, `sJobInfo`, `sHoldInfo` 등 별도 SELECT 분기 | §6.4.3-1 분기 매트릭스 적용 후 GE/D/L 중 하나로 분류 |
| SELECT 컬럼에 alias가 명시됨 | **alias 1개 = 1행** |
| alias 없음 | 원본 컬럼명을 alias로 간주하되 비고에 `alias 없음` 기록 |
| UI aRow key | 카운트 기준 아님 |
| GridColumn 표시 컬럼 | 카운트 기준 아님. 화면 표시명 근거로만 사용 |
| 의미상 같은 컬럼 | **병합 금지** |
| 숨김 컬럼 | SELECT alias에 있으면 포함. 단, 화면 비표시 여부는 비고에 기록 |
| 주석 처리 SELECT 컬럼 | 제외 |
| 임시테이블 (`#prod` 등) 컬럼 정의 | SELECT alias 1:1 카운트 (실제 그리드 표시 컬럼 = aRow key 와 무관) |

GE-NNN 카운트는 반드시 **`분기명 + SELECT alias 수`를 표로 먼저 산출** 한 후 ID를 부여한다. 분기별 alias 수 표 없이 GE-NNN을 작성하면 정합체크서 §D를 ✗ 처리한다.

#### R10-4. B-NNN 버튼 카운트 결정표

버튼은 다음 분류표를 적용한다.

| 원천 | 처리 |
|---|---|
| PageLayout 상단 표준 버튼 (조회/신규/저장/삭제/닫기 등) | **실제 화면 소스 또는 기능 호출이 확인되면 B-NNN 포함** |
| ToolStrip / ToolbarButton | Click 핸들러가 있으면 B-NNN 포함 |
| 일반 Button 컨트롤 | Click 핸들러가 있으면 B-NNN 포함 |
| Lookup 구성의 보조 버튼 (`btn{X}` of `txt+btn+txtNm`) | **S-NNN Lookup에 묶인 경우 B-NNN 제외** |
| Lookup 버튼이 별도 업무 액션도 수행 (T1-F) | Lookup S-NNN 1행 + 별도 업무 액션 B-NNN 1행 |
| 그리드 셀 ButtonField / IconField | **B-NNN 제외, GB-NNN으로만 분류** |
| CellClick 분기 버튼 | GB-NNN으로만 분류 |
| Visible=false / 주석 버튼 | 제외 |
| 이벤트 핸들러 미연결 버튼 | B-NNN 확정 제외 + `[확인필요: Q-NNN]` |
| 소스 호출은 있으나 화면 컨트롤 미확인 | B-NNN 확정 제외 + `[확인필요: Q-NNN]` |

**B + GB 검증**

- B-NNN = 화면/툴바 레벨 액션 버튼
- GB-NNN = 그리드 셀 내부 액션 버튼
- Lookup 보조 버튼은 원칙적으로 S-NNN에 흡수
- `B + GB + S-Lookup보조버튼` 합이 designer의 버튼성 컨트롤 수와 맞아야 한다.

#### R10-5. P-NNN 팝업 카운트 결정표

팝업은 실제 화면에서 호출되는 것만 P-NNN에 포함한다.

| 원천 | 처리 |
|---|---|
| Button/Toolbar/GridCell 이벤트에서 직접 호출되는 팝업 | P-NNN 포함 |
| 조회조건 Lookup이 호출하는 공통 코드/검색 팝업 | S-NNN의 Lookup으로 기록하고, **별도 업무 팝업이면 P-NNN 포함** |
| NewCodeQuery / GeneralDialog | 사용자에게 창이 열리는 경우 P-NNN 포함 |
| 내부 코드 조회만 수행하고 UI 팝업 없음 | P-NNN 제외, LV-NNN 후보 |
| 호출 코드가 주석 처리됨 | 제외 |
| 호출 함수는 있으나 실제 트리거 미발견 | **P-NNN 확정 제외 + `[확인필요: Q-NNN]`** |
| 외부 화면에서만 호출되는 팝업 | 본 화면 P-NNN 제외 + 자연 제외 표 기록 |
| 자연 제외 팝업 | P-NNN 제외, 분석리포트 §11.3 자연 제외 표에 기록 |

팝업 카운트 전에 반드시 **`후보 팝업 목록 → 포함/제외/Q-NNN` 판정표를 작성**한다. 판정표 없이 P-NNN을 작성하면 정합체크서 §D를 ✗ 처리한다.

#### R10-6. ST-NNN statusCodes 결정표

statusCodes는 아래 기준으로만 카운트한다.

| 원천 | 처리 | 카운트 |
|---|---|---|
| 업무 상태 코드 (진행/승인/마감/취소 등) | 포함 | **값별 1행** |
| `WORK_TYPE`처럼 화면 동작/표시를 바꾸는 업무 enum | 포함 | **값별 1행** |
| `INSP_FLG`, `INSIDE_FLG`, `YYNN`, `idx_YN`, `rowStatus` 등 표시/제어 플래그 | 포함 | **컬럼별 1행** |
| 검색조건용 enum (DateType, 조회구분 등) | 포함 가능 | **컬럼별 1행, 값별 분리 금지** |
| 검색조건 CheckBox 자체 | ST 제외 | S-NNN으로만 카운트 |
| LoV 코드 마스터 값 | ST 제외 | LV-NNN으로만 카운트 |
| 단순 코드명 표시용 코드 | ST 제외 | LV-NNN으로만 카운트 |
| 서버 내부 분기지만 화면 표시/동작 영향 없음 | ST 제외 | 업무 규칙 또는 비고 처리 |

**(MUST)** `WORK_TYPE` 값이 `W/S/SH/WH/R` 5개이면 ST-NNN **5행으로 분리**한다. `WORK_TYPE enum 1행 통합`은 **금지**한다.

#### R10-7. LV-NNN LoV 범위 결정표

LV-NNN은 본 화면에서 직접 사용하는 코드 그룹만 카운트한다.

| 원천 | 처리 |
|---|---|
| 조회조건 ComboBox/Lookup에서 직접 사용하는 코드 그룹 | LV-NNN 포함 |
| 그리드 표시 변환에 직접 사용하는 코드 그룹 | LV-NNN 포함 |
| 팝업 입력/선택값으로 직접 사용하는 코드 그룹 | LV-NNN 포함 |
| 본 화면 API 응답 필드 변환에 필요한 코드 그룹 | LV-NNN 포함 |
| 의존 SP 내부에서만 사용하는 코드 그룹 | **기본 제외**, 업무 규칙 비고에 기록 |
| 외부 SP / 외부 팝업 내부 LoV | 본 화면 LV-NNN 제외 |
| 코드 그룹 ID가 같은 중복 호출 | 1행만 포함 |
| enum 값 개별 항목 | **LV-NNN 값별 분리 금지, 코드 그룹별 1행** |

의존 SP 내부 LoV를 포함해야 한다고 판단되는 경우 확정하지 말고 `[확인필요: Q-NNN]`으로 등록한다.

#### 6.4.0 페이지 유형 A~E 자동 결정 알고리즘 (T2-C)

> **(MUST)** 페이지 유형은 영역 수 / 그리드 분기 기반으로 **자동 분류**. 사용자에게 묻지 않음. 자유 분류 / 자체 추론 금지.

| 유형 | 조건 (자동 enum 매칭) | 예시 |
|---|---|---|
| **A. 단순 조회** | A-FILTER + A-GRID, 메인 그리드 1 + 상세 / 라인 / 확장 모두 0 | 코드 마스터 조회 |
| **B. 조회 + 상세** | A-FILTER + A-GRID + A-DETAIL, 상세(D) ≥ 1, GE = 0, L = 0 | 단순 마스터 조회 |
| **C. 조회 + 라인** (마스터-디테일) | A-FILTER + A-GRID + A-DETAIL + L ≥ 1 (parent FK 라인) | 주문등록 (헤더 + 라인) |
| **D. 다중 그리드** | GE ≥ 1 또는 G2 ≥ 1 (확장 그리드 존재) | workReport (메인 + 지그조회 토글) |
| **E. 등록 폼** | A-FILTER 없음 + A-DETAIL 위주 | 사용자 등록 |

**결정 알고리즘**: 위 조건을 **위에서 아래로 평가**, 먼저 매칭되는 유형을 채택. 다중 매칭 시 D > C > B > A > E 우선순위.

**검증** (정합 §D `D-T2C`): 디자인설계서 §1 페이지 유형 ↔ 본 알고리즘 결과 == 일치.

#### 6.4.1 조회조건 S-NNN 추출 알고리즘

| 단계 | 알고리즘 |
|---|---|
| 1. 입력 | `designer.cs` 의 `grpsearch` 또는 검색 영역 컨테이너 |
| 2. 필터 1 | `Visible=false` 요소 자동 제외 |
| 3. 필터 2 | 주석 처리된 요소 자동 제외 |

##### 6.4.3-1 분기 분류 매트릭스 (T1-C 정밀화 — MUST)

##### 6.4.6-1 T1-E 산식 (R-11 명확화 — MUST)

ST-NNN 카운트 계산식:

```
ST-NNN 수 = (workType enum 값 수)
          + (화면 표시 영향 플래그 컬럼 수)        ← INSP_FLG / INSIDE_FLG / YYNN / idx_YN / BYPASS_YN 등
          + (진행·승인·마감·취소 enum 값 수)        ← ORDER_STATUS / APPROVAL_STATUS 등 값별 1행
          + (sList where 분기 enum 컬럼 수, 컬럼별 1 행)  ← DateType / SearchType 등 컬럼 = 1행
```

**제외 항목** (산식 계산에 포함하지 않음):
- 검색조건 CheckBox / ComboBox 자체 (S-NNN 으로만 카운트)
- LoV 코드 마스터 enum 값 (LV-NNN 으로만 카운트)
- 서버 내부 분기 / 화면 표시·동작 영향 없음
- 단순 코드명 표시용 코드 (LV-NNN 후보)

**(MUST)** 동일 As-Is 자료 N차 회귀 시 위 산식 결과가 동일해야 한다. workType enum 5값을 1행으로 통합하면 ✗ (R10-6 위반). 화면 표시 플래그를 enum 값별로 분리해도 ✗ (컬럼별 1행 강제).
