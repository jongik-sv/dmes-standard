# Agent 화면 설계서 생성 지시서 V2

> 상위 문서: [Agent 화면 설계서 생성 지시서 V2](../00_Agent지시_가이드.md)

## 6. 분석 강화 프로토콜

이 장은 V2의 핵심이다.

Claude는 설계서 작성 전에 반드시 분석리포트를 작성하고, 아래 항목을 모두 채운다. 같은 화면을 N차 반복 설계해도 §6.4 알고리즘이 동일 결과를 도출하므로 분석리포트는 매번 새로 작성하면 된다 (정본 / 차수 / 잠금 개념 사용 안 함).

### 6.1 분석 방식

분석은 3회 통과 방식으로 수행한다.

| Pass | 목적 | 수행 내용 | 산출 |
|---|---|---|---|
| Pass 1 | 인벤토리 확보 | 화면, 소스, SQL, 테이블, 프로시저, 함수, 트리거, Entity 후보를 모두 찾는다 | 자료 수집 현황표 |
| Pass 2 | 구조화 분석 | 조회조건, 그리드 컬럼, 버튼, 팝업, 상태, 검증, API 후보, DB 컬럼을 전수 목록화한다 | 분석 상세표 |
| Pass 3 | 교차 검증 | As-Is 요소가 To-Be 컬럼/API/설계 항목으로 빠짐없이 매핑됐는지 확인한다 | 누락 점검표 |

Pass 1~3 중 하나라도 생략하면 분석 완료로 보지 않는다.

### 6.2 검색 키워드 기록

Claude는 분석리포트에 실제로 사용한 검색 키워드 또는 탐색 기준을 남긴다.

| 구분 | 필수 검색 기준 |
|---|---|
| 화면 식별 | As-Is 식별자, 화면명, 메뉴명, 기존 프로그램명 |
| 소스 탐색 | 화면번호, form/class명, button text, event handler명 |
| DB 탐색 | 주요 테이블명, 컬럼명, 코드값, 상태값 |
| 프로시저 탐색 | 화면번호, 업무명, 저장/조회/상태변경 관련 키워드 |
| 트리거/함수 탐색 | 관련 테이블명, 채번, 계산식, 상태 컬럼 |
| To-Be 탐색 | moduleId, 업무 도메인명, 동일 의미 컬럼명, Entity `@Column` |

검색 키워드를 기록하지 않으면 같은 화면을 다시 생성할 때 분석 재현성이 떨어지므로 금지한다.

### 6.3 자료 수집 인벤토리

분석리포트에는 아래 표를 반드시 포함한다.

| # | 자료 구분 | 경로/파일 | 확인 여부 | 분석에 사용한 내용 | 미확인 시 영향 |
|---:|---|---|---|---|---|
| 1 | As-Is 화면 캡처 |  | 확인/미확인/없음 | 조회조건, 버튼, 그리드 배치 |  |
| 2 | As-Is 원본 소스 |  | 확인/미확인/없음 | 이벤트 핸들러, 화면 동작 |  |
| 3 | As-Is 테이블 |  | 확인/미확인/없음 | 컬럼, 키, 관계 |  |
| 4 | As-Is 뷰 |  | 확인/미확인/없음 | 조회 조인, 집계 |  |
| 5 | As-Is 프로시저 |  | 확인/미확인/없음 | 저장, 상태변경, 배치 |  |
| 6 | As-Is 함수 |  | 확인/미확인/없음 | 계산, 변환, 검증 |  |
| 7 | As-Is 트리거 |  | 확인/미확인/없음 | 자동 갱신, 이력 |  |
| 8 | To-Be 테이블 정의서 |  | 확인/미확인/없음 | 신규 컬럼, 타입 |  |
| 9 | 타 모듈 Entity |  | 확인/미확인/없음 | 컬럼명 재사용 |  |
| 10 | 기존 매핑 문서 |  | 확인/미확인/없음 | 매핑 정본 |  |

미확인 자료가 있으면 설계서에서 해당 영역을 확정 표현으로 쓰지 않는다.
