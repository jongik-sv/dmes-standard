## B.0. 표 작성 룰 — X축 / Y축 (MUST)

> 본 템플릿의 모든 식별자 표는 다음 X/Y축 룰을 따른다. 검증된 표준은 `docs/mqc/design/nonconformityJudgment/nonconformityJudgment_기능설계서.md` §3.1 (line 69 ~) 참조.

### B.0-1. Y축 — 행 식별자 prefix (영역별 고정)

| Prefix | 영역 | 위치 | 예시 |
|---|---|---|---|
| `S-NNN` | 조회조건 | §3.1 | `S-001`, `S-002`, `S-003`, ... |
| `G-NNN` | 조회 결과 그리드 컬럼 | §3.2 | `G-001`, `G-002`, ..., `G-022` |
| `D-NNN` | 상세 영역 필드 (마스터 / 수량 폼 / 모달 등) | §4.1, §4.2 | `D-001`, ..., `D-033` |
| `L-NNN` | 라인 그리드 (서브 그리드) | §4.3 | `L-001`, ..., `L-018` |
| `B-NNN` | 버튼 | §5.1 | `B-001`, ..., `B-016` |
| `V-NNN` | 입력값 검증 규칙 | §6 | `V-001`, `V-002`, ... |
| `P-NNN` | 연동 화면 / 팝업 | §9 | `P-101` (검색), `P-201` (라인용), `P-301` (첨부 등) |

- Y축 식별자는 한 설계서 내에서 **unique** (MUST). 영역 내에서 001 부터 시작하는 zero-padded 3자리.
- `P-NNN` 은 의미상 그룹별로 1-prefix(P-1xx 검색팝업) / 2-prefix(P-2xx 라인용) / 3-prefix(P-3xx 첨부·문서·재작업 등)로 묶어 가독성 확보(SHOULD).
- 영역 추가 시 prefix 충돌 금지. 신규 prefix 가 필요하면 §11 특이사항에 정의 + 명시(MUST).

### B.0-2. X축 — 표 헤더 컬럼 (영역별 표준)

| 영역 | X축 컬럼 순서 (좌→우) |
|---|---|
| 조회조건 (S-NNN) | **필드ID** / DB 컬럼명 / 화면 표시명 / 입력 방식 / 필수 / 기본값 / 설명 |
| 조회 결과 (G-NNN) | **컬럼ID** / DB 컬럼명 / 화면 표시명 / 데이터 설명 / 정렬 / 비고 |
| 상세 필드 (D-NNN) | **필드ID** / DB 컬럼명 / 화면 표시명 / 입력 방식 / 필수 / 기본값 / 설명 |
| 라인 그리드 (L-NNN) | **필드ID** / DB 컬럼명 / 화면 표시명 / 입력 방식 / 필수 / 설명 |
| 버튼 (B-NNN) | **버튼ID** / 버튼명 / 위치 / 트리거 / 설명 |
| 검증 (V-NNN) | **규칙ID** / 대상 필드 / 검증 내용 / 에러 메시지 |
| 팝업 (P-NNN) | **대상** / 호출 방식 / 트리거 / 주고받는 데이터 |

- X축 좌측 첫 컬럼은 항상 **Y축 식별자 (S-001, G-001, ...)**. 컬럼 순서는 위 표 그대로 유지(MUST). 정합성 유지를 위한 컬럼 추가는 가능하지만 순서 재배치 금지.
- DB 컬럼이 없는 행(예: 자동 순번 `No`)은 DB 컬럼명 칸을 `-` 로 표기. 빈 칸 금지(MUST).
- DB 컬럼명은 대문자 SNAKE_CASE (`PLANT_CD`), 화면 표시명은 한글, 입력 방식 / 필수 / 기본값은 §A.5 명명 규칙 준수.
- 다른 모듈과 공통 컬럼 재사용 시 `※` 각주로 출처 명시 (예: `PLANT_CD (※ APS TB_APS_PLANT.PLANT_CD 와 동일)`) — §A.2-4-1.

### B.0-4. 기본값 채택 명시 (MUST — Agent 작성 시)

§A.1-2-1-1 의 카탈로그에 따라 Agent 가 사용자에게 묻지 않고 기본값으로 채택한 항목은 본 표를 §1 화면 개요 끝 또는 §11 특이사항 첫 절에 **반드시 1개 두고 기록**한다 (MUST). 사용자가 사후 검증·뒤집기·예외 사유 추가가 가능하도록 가시화한다.

#### B.0-4-1. 표 형식 (복사 사용)

```markdown
### 1.X 기본값 채택 항목 (Agent — §A.1-2-1 정본 카탈로그 기준)

| 항목 | 채택값 | 가이드 근거 | 변경 사유 |
|---|---|---|---|
| 화면 식별자 명명 | (예: `workReport`) | §A.2-1 + 모듈 예시 표 | - |
| As-Is 조회조건 / 그리드 / 버튼 전수 반영 | 전수 1:1 | §A.1-3 Phase 0 + §A.6 | - |
| As-Is ↔ To-Be 매핑 문서 분리 | `docs/{moduleId}/reference/mapping/{화면식별자}_mapping.md` 별도 작성 | §A.2-4 SHOULD | - |
| body 최상위 키 | (예: `master` 단일 또는 `master`+`detail`) | §A.5-4-3 | - |
| `rowStatus` 약속 | C / U / D / 미변경 행 제외 | §A.5-4-3 + FE v2 §9-3 | - |
| 에러 응답 shape | Level A `meta` + (저장형) Level B `errors` | §A.5-4-4 + FE v2 §8-2 | - |
| 권한 표 축 | 행=기능 / 열=역할 (권한 큰 순) | §A.8-8 | - |
| API URL 형식 | (예: `POST /api/{moduleId}/oasis/{serviceId}/{action}`) | §A.5-4-1 | - |
```

#### B.0-4-2. 작성 규칙

- "변경 사유" 열은 **가이드 기본값에서 의도적으로 벗어난 경우에만** 비공란. 1~2 문장으로 사유와 운영 합의 근거 명시. 그 외에는 `-`.
- 변경 사유가 있는 항목은 §11 특이사항에 별도 절(§11.X "기본값에서 벗어난 결정") 로 상세 기록 (MUST).
- 본 표가 비어 있거나 "해당 없음" 으로 두는 것은 **위반** (MUST NOT). 최소 위 8행은 항상 기록한다.
- 본 표가 §A.6 MUST NOT 항목과 충돌하는 값(예: 조회조건을 일부만 발췌)을 담고 있으면 즉시 가이드 정본을 따르도록 수정 (MUST).
