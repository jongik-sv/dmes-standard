# 화면 설계 사용자 시작 가이드

> 본 가이드는 {CLIENT} MES 화면 설계를 *Agent 에게 요청하고 결과를 검토 / 보완 / 완료* 하는 사용자(설계 작성자)가 따르는 1 페이지 절차서이다.
>
> 3 영역만 다룬다: **(1) 설계 요청** → **(2) 보완 정보 제공** → **(3) 설계 완료 요청**.

---

## Part 1. 설계 요청 — Agent 호출

### 1.1 사전 준비 (한 번만)

- As-Is 자료 위치를 확인한다 (예: `docs/external/KsmErpK/...`).
- `docs/guide/runners/source-roots.config.json` 의 `path` 가 자기 환경과 맞지 않으면 한 줄 수정한다. (같은 git을 공유중이라면 X)

### 1.2 Agent 호출 prompt (복사 → 붙여넣기)

```
화면 설계 요청

- moduleId   : mpp                      (소속 모듈 — 부속서 A.1 참조)
- targetKey  : {CLIENT} 레거시 ERP PJA005K    (As-Is 화면 코드)
- screenId   : equipmentInfo            (사용자가 정함 — 미정 시 Q-001 등재됨)

5종 설계 산출물 작성하고 Phase를 나눠서 자동 진행하고 각 Phase별로 검증 진행 후 다음 Phase를 진행하라.
```

→ Agent 가 자동으로 다음을 수행한다:
1. **Auto Manifest Runner 실행** — `docs/{moduleId}/manifest/{targetKey}/` 에 9 파일 생성
2. **5 종 산출물 작성** — 분석리포트 / 기능설계서 / 디자인설계서 / BPMN설계서 / 정합체크서

작성 완료 후 사용자는 **Part 2** 로 이동한다.

---

## Part 2. 보완 정보 제공 — 어디를 보고 무엇을 줄 것인가

산출물 5 종이 만들어지면 사용자는 **딱 2 곳만** 본다.

### 2.1 식별자 미니 사전 (사용자가 *읽을* 식별자)

`Q-NNN` 만 사용자가 *답* 한다. 나머지는 Runner / Agent 가 자동 식별 — *읽기만* 하면 된다. 단 Q-NNN 의 "내용" 칸에 아래 식별자가 등장하므로 의미만 알아두면 답하기 쉽다.

| 식별자 | 한글 | 사용자 시각 (1줄) |
|---|---|---|
| **S-NNN** | 조회조건 | 검색 영역 입력 컨트롤 (드롭다운 / 텍스트박스) |
| **G-NNN** | 메인 그리드 컬럼 | 조회 결과 테이블의 한 컬럼 |
| **GE-NNN** | 확장 그리드 컬럼 | 보조 그리드의 컬럼 |
| **D-NNN** | 상세 필드 | 한 row 선택 시 보이는 필드 |
| **L-NNN** | 라인 필드 | 다중 row 라인 영역 필드 |
| **B-NNN** | 버튼 | toolbar 의 조회 / 저장 / 초기화 등 |
| **GB-NNN** | 그리드 셀 버튼 | 그리드 셀 안의 인라인 버튼 |
| **P-NNN** | 팝업 / 외부 화면 | `OpenForm` 으로 부르는 다른 화면 |
| **ST-NNN** | 상태값 | 진행 / 대기 / 마감 같은 enum 값 |
| **LV-NNN** | 코드 / LoV | 공통 코드 마스터 (회사코드 / 장비구분 등) |
| **V-NNN** | 검증 규칙 | 백엔드 validation 규칙 |
| **Q-NNN** | **확인필요** | **사용자가 결정해서 답 줘야 할 항목** |

> 사용자가 직접 수정·결정하는 것은 **Q-NNN 뿐**. 다른 식별자는 답에 등장하는 *대상* 일 뿐 (예: "G-001 = 장비번호" 처럼 G-NNN 의 한글명을 답).

### 2.2 분석리포트 §13 — 확인필요 / Gap 목록

**위치**: `docs/{moduleId}/design/{screenId}/{screenId}_분석리포트.md` 의 `§13. 확인필요 / Gap 목록`

이 표에 등재된 **`Q-NNN` 항목 = 시스템이 자동으로 결정 못한 것** = 사용자가 답을 줘야 할 항목.

| Q-NNN | 발생 의미 | 사용자가 줄 정보 |
|---|---|---|
| **Q-001** | screenId 미등재 | "screenId = `<이름>` 으로 확정" |
| **Q-002** | moduleGroup 미등재 | "moduleGroup = `<값>`" |
| **Q-003** | To-Be Entity 미확보 | Entity 정의 파일 경로 또는 "미정 — 잠정 직역" |
| **Q-004** | S-NNN 표시명 미확정 (조회조건) | 컨트롤별 한글명 (예: "txtEquidNm = 장비명") |
| **Q-005** | G-NNN 표시명 미확정 (그리드 컬럼) | 컬럼별 한글명 (예: "EQUIP_NO = 장비번호") |
| **Q-006** | 외부 화면명 미확정 (P-NNN) | "PJA001C = 장비등록 화면" |
| **Q-007** | 핸들러 미사용 | "자연 제외 / 살림" 결정 |
| **Q-008+** | 신규 발견 | 항목별 사용자 결정 |

### 2.3 정합체크서 §G — 확인필요 항목 집계

**위치**: `docs/{moduleId}/design/{screenId}/{screenId}_정합체크.md` 의 `§G. 확인필요 항목 집계`

§13 과 동일한 내용이 그대로 인용된다. **모든 Q-NNN 의 상태가 `resolved` 가 되어야 설계 완료** 가능.

### 2.4 보완 prompt (복사 → 붙여넣기)

§13 / §G 의 Q-NNN 을 본 후 사용자가 결정한 정보를 다음과 같이 전달한다:

```
Q-NNN 보완 정보

- Q-001: screenId = equipmentInfo 확정
- Q-002: moduleGroup = master 확정
- Q-005: G-001 = 장비번호 / G-002 = 장비명 / G-003 = 장비구분 / ...
- Q-006: PJA001C = 장비등록 화면 (To-Be 별도 설계)

위 정보로 분석리포트 / 4 설계서 / 정합체크서 갱신 부탁합니다.
```

→ Agent 가 Q-NNN 을 `resolved` 로 갱신하고 산출물 5 종을 재작성한다.

> Q-NNN 이 한 번에 모두 해결 안 되면 추가 정보를 같은 양식으로 반복 전달 가능하다.

## Part 3. 설계 완료 요청 — 마지막 단계

### 3.1 완료 직전 확인 (체크리스트)

다음 3 항목이 모두 ✓ 가 된 것을 확인한다:

- [ ] 분석리포트 `§13` 의 모든 Q-NNN 상태 = `resolved`
- [ ] 정합체크서 `§G` 의 모든 Q-NNN 상태 = `resolved`
- [ ] 정합체크서 최종 판정 표의 모든 절 (§A / §B / §C / §D / §E / §F / §H / §I / §J / §D.4) = ✓

### 3.2 완료 prompt (복사 → 붙여넣기)

```
설계 확정 요청

산출물 5종 검토 완료.
- 분석리포트 §13 Q-NNN : 모두 resolved
- 정합체크서 §G        : 모두 resolved
- 정합체크서 최종 판정  : 모든 절 ✓

설계 완료 처리 부탁합니다.
```

→ Agent 가 산출물 final 처리 후 완료 보고한다.

## 부록 — 자주 마주치는 상황 (간단 응대)

| 상황 | 처리 |
|---|---|
| Agent 가 "Runner ExitCode = 1 / conflict-report 발생" 보고 | `docs/_unresolved/manifest/{targetKey}/conflict-report.json` 의 `candidates` 확인 → 사용자가 한 값 선택 후 prompt 에 명시 → 재호출 |
| 정합체크서 §A.3 (manifest vs 산출물 행수) ✗ | "manifest 인용 강제하여 재작성 부탁합니다" 한 줄로 재호출 |
| 같은 화면을 N번 분석했는데 결과가 조금 다름 | 핵심 enum (S / G / B / P / LV) 동일이면 정상. 부수 enum (ST / V / C1~C6) 차이는 시스템 잔존 한계 — 개발자 영역 |
| Q-NNN 이 점점 늘어남 | 정상 흐름. Q-008+ 는 신규 발견 항목으로 사용자가 결정해 가면서 줄어듦 |

---

> **이 가이드 외에 사용자가 직접 수정할 파일은 없다.** Runner / Agent 가 모든 산출물을 자동 생성·갱신한다. 사용자는 *Q-NNN 응답 + 완료 요청* 만 한다.
