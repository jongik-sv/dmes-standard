## §3. BE 서비스 · BPMN (action별)

> BPMN 매핑 `POST /oasis/{serviceId}/{action}` (또는 화면 확정 컨벤션). 단일 `.bpmn` actionGateway 분기. **OASIS 서비스 `@Transactional` 금지 — cactus TransactionTemplate 사용**(메모리: CGLIB 프록시 `-parameters` 손실). 공통 검증: action별 통합테스트(응답 + 조회 API 로 side effect 재확인, RULE.md §테스트).

- [ ] **ITEM-SVC-01** `.bpmn` 다이어그램 (actionGateway {N}분기) — **반드시 `bpmn-tool create/modify` 로 생성·수정**(직접 XML 작성 금지). DoD: `bpmn-tool validate` = `유효:true` + 파일에 `<bpmndi:BPMNDiagram>` 존재(= Camunda Modeler 렌더 가능) + 7자 일치(serviceId=beanName=camunda:class). ※ 직접 XML 작성 시 DI 누락 → Modeler 빈 화면(BE v2 §9-0, 2026-05-27 사고).
- [ ] **ITEM-SVC-02..N** action별 서비스 — {조회/단건/목록/저장(트랜잭션)/상태변경/삭제 ...} 각각 별도 박스. DoD 에 E-NNN 부수효과·V-NNN 가드·트랜잭션 경계 명시.
- [ ] **ITEM-SVC-LoV** LoV BPMN service 신설 — master/service 코드. mls 등 SqlSession 미등록 모듈은 `apiLovMaster` 금지 → OASIS LoV.
- [ ] **ITEM-SVC-ERR** 에러 처리 매트릭스(BPMN §3) 반영 — 400/409/500 + cactus ErrorCode.
- [ ] **ITEM-SVC-LOCK** 동시 수정 방지 — optimistic lock → 409.
