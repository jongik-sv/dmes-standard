## 1. 공통 화면 구조

<!-- 본 절은 portal PortalShell 의 자동 주입 영역 설명. 화면별 변경 없음 (고정 양식). -->

SIDEBAR / HEADER / TabsBar 는 `portal` 의 `PortalShell` 이 자동 주입한다. 화면 설계 대상은 **`PageLayout` 내부 영역** (title / buttons / SearchArea / ContentBody / ContentPanel) 이다.

### 1.1 포털 공통 영역 (설계 대상 아님 — portal 주입)

```
┌────────────┬──────────────────────────────────────────────┐
│            │ HEADER (portal)                              │
│  SIDEBAR   ├──────────────────────────────────────────────┤
│  (portal)  │ TabsBar (portal)                             │
│            ├──────────────────────────────────────────────┤
│            │  ▼ 아래가 화면 설계 대상 (PageLayout)         │
│            │                                              │
│            │                       page-id-badge (portal) │
└────────────┴──────────────────────────────────────────────┘
```

- **page-id-badge** = 활성 탭의 pageId 를 하단 우측에 표시
- 표시 형식: `{moduleId}:{composedPageName}`
  - **MES 단일 룰** (mls / mqc / mpp 등): `{moduleId}:{pageName}` — pageName = camelCase = screenId (예: `mls:plateSlittingMgmt`, `mpp:workReport`)
  - **APS 예외 (mpn 한정)**: `{moduleId}:{moduleGroup}/{pageName}` — pageName = kebab-case (예: `mpn:operation/order-registration`)
- moduleId 정본: 01 A.1 (업무 페이지는 `portal` 금지)
- 명명 룰 정본: 정합체크서 §B (MES 단일 룰 + APS 예외 분리)

### 1.2 화면 설계 대상 영역 (PageLayout 기반)

```
┌────────────────────────────────────────────────────────────┐
│ PageLayout.title = "{화면명}"   PageLayout.buttons = [...]  │
│  ├─ SearchArea  (A-FILTER)                                  │
│  │    └─ SearchField × N                                    │
│  └─ ContentBody (MAIN)                                      │
│        ├─ ContentPanel  (그리드/폼/2단 상단)                  │
│        └─ ContentPanel  (상세 / 2단 하단 / 분할 우측)          │
└────────────────────────────────────────────────────────────┘
```

| 영역 | 담당 컴포넌트 | 비고 |
|---|---|---|
| SIDEBAR / HEADER / TabsBar | portal PortalShell | 화면별 설계 대상 아님 |
| 페이지 타이틀 / 상단 버튼바 | `PageLayout` `title` / `buttons` | A-TOOLBAR 신설 금지 — `buttons` 배열 |
| A-FILTER (조회조건) | `SearchArea` + `SearchField` × N | `@dk-oasis/shared/layout` |
| MAIN (콘텐츠) | `ContentBody` + `ContentPanel` × N | `@dk-oasis/shared/layout` |
| 그리드 | `AgDataGrid` (+ `useGridDataManager`) | `@dk-oasis/shared/grid` |
| 폼 | `FormGroup` + `ComboBox` / `DatePicker` / `Input` / `Select` | `@dk-oasis/shared/form` |
| 팝업 | `Modal` / `MessageModal` | `@dk-oasis/shared/modal` |

## 7. 빈 상태 / 로딩 / 에러 표시

> 구현 소스: `useApiCall` (로딩·성공/실패) + `useGfnMessage` (사용자 메시지) + `Spinner` (인라인) + `ErrorModal` (치명적). 외부 메시지 라이브러리 / `alert` / `console.error` 금지.

| 상황 | 표시 위치 | 표시 방식 | 구현 |
|---|---|---|---|
| 그리드 데이터 없음 | ContentPanel 중앙 | 아이콘 + "조회 결과가 없습니다" | `AgDataGrid` 기본 empty state |
| 상세 미선택 | 상세 ContentPanel 중앙 | 아이콘 + "목록에서 항목을 선택하세요" | 화면 고유 표시 |
| 그리드 로딩 중 | 해당 ContentPanel | 스피너 오버레이 | `Spinner` 또는 `AgDataGrid` loading prop |
| 저장 중 | 버튼 영역 | 버튼 비활성 + 스피너 | `useApiCall` loading 상태 |
| API 에러 | 토스트 | `useGfnMessage` 토스트 (1회만) | `useApiCall` 자동 처리 |
| 필드 유효성 에러 | 해당 입력 필드 아래 | 에러 메시지 텍스트 | `useFormValidation` FormErrors |
| 치명적 에러 | 전체 | `ErrorModal` | `@dk-oasis/shared/layout: ErrorModal` |
