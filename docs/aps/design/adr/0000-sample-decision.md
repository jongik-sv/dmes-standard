# ADR-0000: 샘플 도메인의 상태 전이 규칙 정의

## 쉬운 설명 (현업용 요약)

샘플 전표는 등록 후 확정·취소를 거친다. 그런데 "취소한 전표를 다시 확정할 수 있는가",
"확정된 전표를 수정할 수 있는가" 가 담당자마다 다르게 이해되어 같은 상황에서 서로 다른
처리가 나왔다. 그래서 전표가 가질 수 있는 상태와 상태 사이에 허용되는 이동 경로를
한 곳에 못 박기로 한다. 확정된 전표는 수정할 수 없고, 취소하면 되돌릴 수 없다.
되돌리려면 새 전표를 만든다.

## Context (배경)

- 샘플 전표 상태값이 화면·서비스마다 개별 판정되어 동일 상태에서 서로 다른 버튼이 노출된다.
- 상태 전이 표가 문서로 존재하지 않아 신규 기능 추가 시 매번 기존 코드를 역추적해야 한다.

## Decision (결정)

- **D1** 상태는 `DRAFT`, `CONFIRMED`, `CANCELED` 세 가지로 한정한다.
- **D2** 허용 전이는 `DRAFT→CONFIRMED`, `DRAFT→CANCELED`, `CONFIRMED→CANCELED` 뿐이다.
- **D3** `CANCELED` 는 종단 상태다. 재사용이 필요하면 신규 전표를 생성한다.
- **D4** 전이 판정은 단일 도메인 서비스가 소유하고, 화면은 판정 결과만 표시한다.

## Consequences (결과)

- 화면 버튼 활성화 로직이 전이 표 한 곳에서 파생되어 화면 간 불일치가 사라진다.
- 취소 후 복구 요구가 들어오면 신규 ADR 로 재논의해야 한다(D3 이 이를 막는다).

## Alternatives Considered (대안)

- **A안: `CANCELED→DRAFT` 복구 허용** — 이력 추적이 끊기고 감사 요건을 만족하지 못해 기각.
- **B안: 상태를 화면별로 자유 정의** — 현행 방식. 불일치 원인이므로 기각.

## Trigger (PROPOSED 인 경우만)

샘플 전표 화면 1건 이상이 실제 구현에 들어가는 시점에 ACCEPTED 로 전이한다.
