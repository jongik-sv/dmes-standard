# 브랜치 3단 전환 설계 (2026-10-19)

> 문체: LLM 작업 메모(`docs/guide/Common/Korean-STE-LLM-Guide.md`). 결정은 2026-10-19 사용자 답변으로 확정했다.

## 목표

- 브랜치를 3단으로 운영한다: 개인 `dev-<이름>` → 개발 통합 `dev` → 운영 `main`.
- 우리 팀은 `dev` 까지만 관리하고 시험한다. `dev → main` 머지는 시스템 담당자가 한다.

## 결정

| ID | 결정 | 근거 |
|---|---|---|
| B1 | 개인 브랜치 이름은 `dev-<이름>`(예 `dev-jji`). 사람마다 하나 | 사용자 지시 |
| B2 | 우리 범위의 최상위 브랜치는 `dev`. `.dflow` 의 `release_branch` 를 `dev` 로 바꾼다 | D'Flow 2단(개발 → 운영) 구조에 그대로 맞는다. `ensure-dev` 가 개인 브랜치를 `origin/dev` 에서 만들고, 스텁 관문이 `dev` 로 가는 승격을 지킨다 |
| B3 | `main` 에는 우리가 push 하지 않는다. `dev → main` 절차·`main` 보호·릴리스 태그는 범위 밖 | 사용자 지시 |
| B4 | 승격(`dev-<이름>` → `dev`)은 스크립트로 직접 push 한다. 순서 = `origin/dev` 합치기 → Flyway 재채번 → 번호·스텁 검사 → 게이트 → fast-forward push | CI 가 없다. 합친 트리를 시험한 뒤 fast-forward 로만 올려야 `dev` 끝 커밋이 늘 시험을 거친 트리다. PR 머지는 서버가 합친 결과를 아무도 시험하지 않는다 |
| B5 | 오류 코드와 결정 `D-NNN` 은 사람별 번호 대역을 쓴다. 등록표 = 리포 최상위 `.number-blocks`(`개인 브랜치=대역`) | 사용자 선택. 순서에 의미가 없는 번호라 대역으로 충돌을 없앨 수 있다 |
| B6 | 대역 k 는 1~8. 결정 = `D-k001`~`D-k999`. 오류 코드 = 숫자 3자리의 백의 자리가 k(예 `MDM1xx`, `E1xx`). 0 = 전환 전 번호, 9 = 예약(`S999` 등) | 지금 결정은 D-157, 오류 코드는 `MDM029`·`E0xx`·`S999` 까지 쓴다. 기존 번호와 겹치지 않는다 |
| B7 | Flyway V 번호는 대역을 쓰지 않는다. 승격할 때 `origin/dev` 의 폴더별 최댓값 + 1 로 다시 매긴다 | 대역을 쓰면 번호 순서와 작성 순서가 어긋나 빈 DB 새 설치가 실패한다(늦게 쓴 낮은 번호가 먼저 실행된다). 운영 DB 에 `outOfOrder=true` 도 필요해진다. 사용자가 재채번을 골랐다 |
| B8 | 강제 진행 스텁은 `dev` 에 들어가지 못한다 | B2 의 결과. 시스템 담당자가 `dev` 를 그대로 `main` 으로 가져간다 |
| B9 | GitHub `dev` 브랜치에 force push·삭제 금지를 건다 | 사용자 승인. 직접 push 승격은 그대로 된다 |
| B10 | 동료의 선행 작업이 `dev` 에 있는데 내 브랜치에 없으면 `promote.mjs --sync-only` 로 받는다. D'Flow 내부 판정(`pred-reflected`)은 바꾸지 않는다 | 판정이 늦어질 뿐 틀린 코드 위에서 작업하지는 않는다. 구현 범위를 줄인다 |

## 범위 밖

- `dev → main` 승격, `main` 보호, 릴리스 태그(B3).
- 조정자 스킬의 기본 `integration_branch` 값 변경. 각자 `.coord.local.json` 에 개인 브랜치를 적는다.
- `scripts/oracle/pdb.mjs template-schema` 코드 변경. Oracle 은 PC 마다 로컬이라 영향이 그 PC 에 그친다. 문서에 "승격 재채번 뒤 `--rebuild`"만 적는다.

## 위험

- 재채번된 V 파일이 이미 적용된 로컬 PDB 는 Flyway 검증이 실패한다. 템플릿을 다시 만들고 PDB 를 다시 복제한다.
- `.dflow-gates` 명령은 macOS 경로(`JAVA_HOME=/opt/homebrew/...`)를 쓴다. 윈도우 PC 는 `.dflow-gates.local`(개인, git 제외)로 대체 대응표를 둔다.
- 버전을 고정한 시험(예: 버전 집합 고정 시험)은 재채번 뒤 게이트에서 실패한다. 승격 스크립트가 옛 파일 이름을 참조하는 파일을 알리고, 사람이 고친 뒤 다시 실행한다.
