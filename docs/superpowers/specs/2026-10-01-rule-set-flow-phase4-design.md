사용자가 정한 것: E4 의 고친 값은 **이번 디버그 실행에만** 남는다. 값 고치기와 **변수 추가·비우기(NULL)** 를 모두 한다. 방식은 **처음부터 다시 실행하며 끼워 넣기(A)** 와 아래 §2.2 의 퍼짐 규칙이다. 작업은 **가능한 만큼 병렬**로 한다.

제외: 반복(loop) 블록, 고친 값을 테스트 케이스로 저장, 그룹 크기로 소속 노드를 바꾸기.

## 1. T1 빈 단계 노드

### 1.1 모양과 의미
- 새 노드 종류 `TASK`(화면 이름 "빈 단계")를 둔다. 룰 ID 가 없고 `label`(제목)만 있다. 흐름 구조에서는 RULE 과 같다(들어오는 선 하나, 나가는 선 하나, 갈래 안·밖 어디든).
- 실행(`evaluateSet`·`traceSet` 모두): 아무것도 읽거나 만들지 않고 지나간다. `PathStep(TASK)` 와 `NodeTrace(kind=TASK, status=OK)` 만 남는다(reads·result 없음).
- 키 검사(`FlowKeys`)는 TASK 를 건너뛴다.
- 검증(`validate`)·저장은 막지 않는다. 빈 단계가 있으면 경고 한 줄 "빈 단계 N개 — 실행 때 그냥 지나간다"를 낸다(기존 경고 목록과 같은 자리).

### 1.2 화면
- 팔레트 [룰] 은 룰 찾기 창을 띄우지 않고 **빈 단계를 바로 놓는다**(누르기 = 고른 선, 없으면 END 앞 선에 끼우기 / 끌어 놓기 = 놓은 자리, 선 위면 끼우기 — 기존 규칙 그대로). 놓은 빈 단계를 고르고 오른쪽 [룰] 탭을 연다(§1.3).
- 노드는 점선 테두리, 제목만 보인다. 제목은 두 번 눌러 고친다(메모 제목과 같은 방식). 기본 제목 "빈 단계".
- **룰 지정**: 빈 단계를 고른 채 오른쪽 룰 목록에서 줄을 두 번 누르거나 [지정] 을 누르면, 또는 룰 줄을 끌어 빈 단계 노드 위에 놓으면 RULE 노드로 바뀐다. 우클릭 [룰 지정…] 은 그 노드를 고르고 [룰] 탭을 연다. 자리·들어오고 나가는 선·경로·라벨은 그대로 둔다(노드 ID 도 유지). 되돌리기 한 번에 돌아간다. 이미 룰이 있는 RULE 노드도 같은 방법으로 룰을 바꾼다(입출력이 다르면 기존 검사 목록이 알린다).
- 룰 찾기 창(`RuleSearchModal`)은 쓰는 곳이 없어지므로 지운다.
- 디버거: 한 단계에 멈추고 지나간다. 변수 패널은 바뀌지 않는다. 중단점도 걸 수 있다.

### 1.3 P1 왼쪽 아이콘 사이드바·오른쪽 룰 목록
사용자 요청: "왼쪽에 컴포넌트들은 사이드바에 아이콘으로 표시/툴팁으로 이름 표시하고 룰 목록은 오른쪽 패널에서 룰 선택할 수 있도록 개선하자."
- **왼쪽**: 편집 모드의 왼쪽 280px 룰 패널을 없애고, 캔버스 칸 왼쪽 가장자리에 폭 44px 세로 아이콘 막대를 둔다(분할 패널이 아니라 캔버스 칸 안의 한 열). 항목은 지금 팔레트와 같다(룰·IF 분기·병렬 분기·메모·그룹). 아이콘만 보이고 이름은 오른쪽으로 뜨는 툴팁이다. 누르기·끌어 놓기·키보드 접근(`aria-label`)은 그대로다. 보기 모드는 막대가 없다. 디버그 모드의 왼쪽 입력 패널은 그대로다.
- **오른쪽**: 보기·편집 모드의 오른쪽 패널 위에 탭 [속성] [룰] 을 둔다. [속성] 은 지금 내용(선택에 따라 속성·세트 패널). [룰] 은 지금 왼쪽에 있던 룰 목록(찾기, 확정 버전만, 끌어 넣기, 두 번 눌러 끼우기)이다.
  - 고른 노드가 빈 단계·RULE 이면 목록 위에 "대상: {노드 제목}" 과 줄마다 [지정] 이 보인다. 그 밖에는 두 번 누르기가 지금처럼 고른 선(없으면 END 앞 선)에 끼운다.
  - 빈 단계를 새로 놓거나 [룰 지정…] 을 누르면 [룰] 탭으로 바뀐다. 사용자가 고른 탭은 세트마다 기억하지 않는다(화면을 열면 [속성]).
  - 보기 모드의 [룰] 탭은 찾기·보기만(끼우기·지정 없음).
- 디버그 모드 오른쪽은 지금처럼 변수 패널이다(탭 없음).

## 2. E4 멈춘 지점에서 값 고쳐 이어 실행

### 2.1 방식
디버거는 지금처럼 서버가 끝까지 돌린 기록을 재생한다. 값을 고치면 **처음부터 다시 실행하되 k 번째 노드를 시작하기 직전에 고친 값을 그 범위의 ctx 에 넣는다**. 실행이 결정적이라(같은 입력·evalTs) k 앞 기록은 같고 뒤만 달라진다. 병렬 갈래 스택을 복원할 필요가 없다.

### 2.2 엔진
- `FlowRun` 이 `List<TraceEdit>` 를 받는다. `TraceEdit(int beforeSeq, String nodeId, Map<String,Object> values)`, beforeSeq 는 1부터(NodeTrace.seq 와 같은 수).
- 노드를 시작할 때(`plain`·`rule`·`task`·`ifSplit`·`parallel`·`merge`) 다음 순번 `nodes.size()+1` 이 beforeSeq 인 edit 를 적용한다. `merge` 는 지금 범위 ctx·made 를 받도록 인자를 더한다.
- **퍼짐 규칙**: 값은 `RecordKeys.putReplacing` 으로 그 범위 ctx 에 넣는다. 같은 이름(대소문자 무시)이 그 범위의 `made` 에 이미 있으면 made 도 바꾼다. 최상위 made 는 `finalValues` 라 최종 결과까지 간다. 병렬 갈래 안에서 입력 변수를 고치면 그 갈래 안에서만 보인다(합류 때 갈래 ctx 는 버린다). 값이 null 이면 비우기, ctx 에 없던 이름이면 추가다.
- 안전장치: 그 자리 노드 ID 가 `edit.nodeId` 와 다르면 새 위반 `EDIT_POINT_MISMATCH`(Stage `INPUT_CHECK`)로 멈춘다. 실행이 오류 없이 끝났는데 쓰이지 않은 edit 가 남으면 같은 코드로 멈춘다(실제 ERROR 노드를 가리지 않도록 정상 완료 때만 본다).
- 실행 중 위반은 노드 시작 뒤에 나므로 ERROR 노드 직전에서 값을 고쳐 오류를 비켜 갈 수 있다.
- `prepare()` 의 입력 키 사전 검사는 바꾸지 않는다. 뒤쪽 키 검사(IF 갈래 진입, 지연 키)는 고친 ctx 로 그대로 한다.
- 입구: `RuleEngine.traceSet(set, record, evalTs, edits)` 겹정의를 더하고 기존 3인자는 빈 목록으로 위임한다. `evaluateSet` 은 edit 를 받지 않는다.

### 2.3 계약·API
- `RunTrace` 에 선택 필드 `edits`(없으면 null) — `[{beforeSeq, nodeId, values: {이름: TypedValue}}]`. 서버가 받은 edit 를 그대로 되돌려 준다.
- `RuleSetSimulateRequest` 에 `editsJson`(문자열) — OASIS params 가 Map 을 받지 못해서(D-111 과 같은 이유). 값은 `recordJson` 과 같은 변환기로 푼다. `runCases` 는 edit 를 무시한다. BPMN `execute` 는 dto 클래스로 바인딩하므로 dto 필드 추가로 전달되는지 확인한다(안 되면 BPMN 입력을 더한다).

### 2.4 화면
- **고칠 수 있는 때**: 기록이 최신이고 커서가 노드 k 실행 전(k < n)일 때. 그 밖에는 변수 표가 지금처럼 읽기 전용이다.
- 변수 표 값 칸을 두 번 눌러 고친다. 원래 타입(NUMBER·STRING·BOOLEAN)에 맞지 않는 값은 칸에서 거절한다. [변수 추가] 로 이름·타입·값, 줄 메뉴 [비우기] 로 NULL. LIST 는 비우기만 한다.
- 고친 줄은 "고침 대기" 로 보이고 [고침 취소] 로 되돌린다.
- 고침 대기가 있을 때 [한 단계]·[계속]·[여기까지 실행] 을 누르면 edit 와 함께 서버를 다시 부르고, 커서 k 에서 그 동작을 한다.
- 누적: 같은 지점에서 다시 고치면 값을 합친다. 앞 지점 j 에서 새로 고치면 beforeSeq > j 인 edit 는 버리고 한 줄 알린다("뒤에서 고친 값 N건을 지웠다").
- [처음부터]·입력 변경·흐름 변경 때 edit 를 모두 지운다. `useSimulation` 의 `needsFresh`·지난 입력 비교는 edit 를 알고 있어야 한다(edit 를 붙여 받은 기록을 낡았다고 보거나, 고침 대기가 새 실행을 일으켜 edit 를 지우지 않게).
- 표시: `frames()` 가 기록의 edits 를 같은 퍼짐 규칙(대소문자 무시)으로 반영한다. 고친 이름은 변수 표에 "고침". 툴바 문구 끝에 "· 고친 값 N건". 고친 지점 노드에 작은 표시(노드 데이터로 `nodes.tsx` 에서만 그린다).
- 고친 값이 있는 기록에서는 [기대값으로] 를 막는다(title "고친 값으로 나온 결과라 기대값으로 쓸 수 없다").

## 3. W1 선분 손잡이(Camunda 식)

### 3.1 손잡이
- 편집 모드에서 선에 마우스를 올리거나(150ms 유예, L1 과 같은 `HoverStore`) 선을 고르면 손잡이가 뜬다. 지금은 고른 선에만 꺾는 점이 뜬다.
- **점 손잡이**: 꺾는 점마다 원. 저장된 경로가 없는 선(자동 꺾은선)은 자동 경로의 꺾임에 뜬다.
- **선분 손잡이**: 가로·세로 선분의 가운데에 선분 방향의 짧은 막대. 커서는 가로 선분 `ns-resize`, 세로 선분 `ew-resize`. 대각선 선분과 화면 28px 보다 짧은 선분에는 없다.
- 선분 가운데가 라벨·[+] 자리에서 화면 24px 안이면 막대를 선분의 1/4 지점(라벨에서 먼 쪽)으로 옮긴다. [+] 비킴(`addSpot`)의 피할 상자에 막대도 넣는다.
- 손잡이는 선과 같은 hover 속성(`hoverProps`)과 `nodrag nopan` 을 단다. 공간 넓히기 미리보기를 따라간다.

### 3.2 동작
- 점 끌기: 지금과 같다(자유 이동). 자동 경로의 점을 끌면 그때 자동 경로를 저장 경로로 바꾼 뒤 옮긴다.
- 선분 끌기: 선분을 수직 방향으로만 옮기고 양 끝 점이 따라간다(이웃 선분은 길이만 변해 직각이 유지된다). 자동 경로면 먼저 저장 경로로 바꾼다.
- 노드에 붙은 첫·끝 선분을 옮기면 노드 쪽 끝은 고정이라, 노드에서 20px 나온 짧은 선분과 꺾임을 끼워 나가는 방향을 지킨다.
- **합치기**: 끄는 동안 옮기는 선분이 이웃과 일직선(화면 6px 안)에 가까워지면 딱 맞춘다. 놓을 때 한 직선 위의 가운데 점과 길이 0 선분을 지운다. 그래서 일직선이 된 선분이 하나로 합쳐진다.
- 놓을 때 `onRouteChange` 를 한 번 부른다(끄는 동안 page 다시 그리기 없음, Local-Rules §16). 되돌리기 한 번.
- 두 번 눌러 점 더하기·고른 점 Delete 는 지금과 같다. 자동 경로의 점(저장 전)은 고를 수 없어 Delete 가 없다.

### 3.3 자동 경로의 점
자동 경로는 React Flow `getSmoothStepPath` 로 그리고, 그 점 계산(`getPoints`)은 공개되지 않았다. `@xyflow/system@0.0.83` 의 `getPoints` 를 `route-path.ts` 로 옮겨(출처·버전 주석, MIT) 손잡이와 저장 경로 바꾸기에만 쓴다. 그리기는 그대로 `getSmoothStepPath` 다. 옮긴 점을 `routePath(점, 8)` 로 그린 꺾임이 `getSmoothStepPath(borderRadius 8)` 의 꺾임과 같음을 네 변 × 네 변 × 상대 위치(위·아래·왼·오른)로 시험한다(`ROUTE_RADIUS` = 8 확인). 그래서 처음 끌 때 선이 튀지 않는다.

## 4. G2 그룹 크기

- `FlowGroup` 에 선택 필드 `pad?: {l, t, r, b}` 를 더한다. 흐름 좌표, 0 이상 2000 이하로 자른다. 그룹 상자 = 소속 노드 경계 + 기본 여백 + pad.
- 여백으로 저장하므로 소속 노드를 옮기면 그룹이 따라가고, 소속 노드보다 작게는 줄지 않는다.
- 편집 모드에서 고른 그룹에 네 모서리·네 변 손잡이를 띄운다. 끄는 동안은 캔버스 안 저장소에만 두고 놓을 때 한 번 편집한다. 되돌리기 한 번.
- 크기를 바꿔도 소속은 바뀌지 않는다(상자 안으로 들어온 노드를 자동으로 넣지 않는다).
- 보기·디버그 모드도 저장된 pad 로 그린다. `sanitizeView`·`clone` 이 pad 를 살린다. 서버는 view 를 그대로 통과시킨다.

## 5. 계약 변경 모음(한 태스크에서 먼저)

- Java `NodeKind` 에 `TASK`, `EngineEvaluationException.Code` 에 `EDIT_POINT_MISMATCH`, `RunTrace` 에 `edits` 와 `TraceEdit` record, 필요하면 `EngineWarning.Code` 에 빈 단계 경고.
- 네 벌을 함께: Java, `engine-contract.schema.json`, 생성 TS(`pnpm --filter @dk-oasis/m-mdm gen:contract`), `RunTraceJson`. 동치 코퍼스와 계약 모양 테스트(`EngineContractSchemaTest`·`ContractTypeShapeTest`·`engine-contract.generated.test.ts`)를 같이 갱신한다.
- `NodeKind` 를 `switch` 하는 곳은 컴파일러·tsc 가 알려 준다. 모두 TASK 를 처리한다.

## 7. 시험
