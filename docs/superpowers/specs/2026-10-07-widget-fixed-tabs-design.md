# 위젯 고정 탭 — 전사·부서 기본 배치를 늘 보이게 (2026-10-07)

정본 지시: `~/.coord/notice-fill2/lanes/widget-fixed-tabs/brief.md`(지시 widget-fixed-tabs-1)와 조정자 보충(같은 날).
이 문서는 [2026-10-02-widget-admin-generic-design.md](2026-10-02-widget-admin-generic-design.md) §4.2·§10.2·§11 과
[docs/widget-2026-10/design-widget-tabs.md](../../widget-2026-10/design-widget-tabs.md) §1·§3·§4 를 개정한다. 겹치면 이 문서가 앞선다.

## 0. 사용자 요구와 원인

- 증상: 위젯관리 「기본 배치」에서 전사 배치를 저장해도 홈에 안 보인다.
- 원인: 기본 배치는 「홈을 저장한 적 없는 사용자」에게만 보이는 시작값이었다(§4.2). 로컬 DB 의 사용자 41000132 는 위젯이 0개인
  `home` 탭 행이 있어(잠금 토글 등으로 탭 행만 저장된 경우) 빈 홈이 보였다.
- 결정(사용자, 2026-10-07): 위젯관리에서 기본 배치로 둔 것은 다 보여야 한다. 전사는 모든 사람에게, 부서 배치는 그 부서 사람에게 무조건.
  방식은 **고정 탭**. 전사·부서 배치는 각각 여러 탭일 수 있다(보충).

```
[홈] [전사 탭들…] [내 부서 탭들…] [상위 부서 탭들…] │ [내 홈] [내 탭1] … [+]
 └──────────────── 고정 탭(관리자 배치, 사용자 잠금) ──────────┘ └─ 개인 탭 ─┘
```

## 1. 고정 탭 집합

사용자의 고정 탭 = 아래 순서의 합집합. 관리자가 배치를 바꾸면 다음 조회(`secWidget/search`)부터 그대로 보인다(사용자 사본 없음).

| 순서 | 탭 | 출처 | 탭 ID | 이름 |
|---|---|---|---|---|
| 1 | 「홈」 | `TB_MCM_WIDGET_DEFAULT_LAYOUT` 키 `*` (없으면 화면 코드 상수 `HOME_DEFAULT_LAYOUT`) | `home` | 홈 |
| 2 | 전사 기본 탭 | `TB_MCM_WIDGET_DEFAULT_TAB` 키 `*`, 관리자 순서 | `def-N` | 관리자 이름 |
| 3 | 부서 대표 탭 | `TB_MCM_WIDGET_DEFAULT_LAYOUT` 키 = 부서 코드(행이 있을 때만) | `dept-{DEPT_CD}` | 부서명(`TB_MCM_DEPT_INFO.DEPT_NM`, 없으면 코드) |
| 4 | 부서 기본 탭 | `TB_MCM_WIDGET_DEFAULT_TAB` 키 = 부서 코드, 관리자 순서 | `def-N` | 관리자 이름 |

- 부서 범위(기본안, 조정자 결정 대기): 사용자 `DEPT_CD` 부터 `UPPER_DEPT_CD` 를 따라 올라간 **모든 부서**(최대 10단, 순환 방지)를 **가까운 순**으로
  3·4 를 반복한다. 하위 부서 사용자도 상위 부서의 탭을 본다. 부서 배치가 하나도 없으면 부서 탭이 없다.
  (다른 선택지: 가장 가까운 부서 하나만 — 부서 사슬 중 배치가 있는 첫 부서의 3·4 만.)
- `def-N` 은 모든 키에서 하나뿐이라(UK) 합쳐도 ID 가 겹치지 않는다. 같은 이름의 탭이 여러 키에 있어도 그대로 보인다(탭 제목 풍선에 출처 표시).
- 서버 응답 `tabSeq` 는 대역으로 나눠 정렬이 섞이지 않게 한다: 홈 0, 전사 기본 탭 `100 + 관리자 순서`, 부서 `200 + 단계×10 + (대표 0 | 기본 탭 관리자 순서)`.
  개인 탭은 그 뒤에 개인 순서대로 보인다(화면 `tabRank`: 고정 → 개인).
- 키당 기본 탭 5개 상한은 그대로 둔다(키마다 대표 + 5 = 6탭). 고정 탭은 개인 탭 한도에 세지 않는다.

## 2. 잠금 — 서버가 강제

- 사용자는 고정 탭의 위치·크기·위젯 추가·삭제·이름·순서·잠금을 바꿀 수 없다. 화면에서는 [배치 편집]이 막히고 탭 메뉴에는 공유·내보내기만 남는다.
- `secWidget/saveTab`·`deleteTab` 은 `home`·`def-*`·`dept-*` 를 거절한다(「관리자가 정한 탭은 바꿀 수 없습니다」).
- `resetHome`·`resetTab` 은 **더 이상 행을 지우지 않는다**(거절). 옛 화면이 이전 전에 불러도 개인 배치가 지워지지 않게 이전 로직과 같은 커밋에서 바꾼다.
- `reorderTabs` 는 고정 탭을 건너뛴다(기존과 같음).
- `shareTab` 원본: `home` 은 전사 배치, `dept-*` 는 그 부서 배치, `def-*` 는 관리자 항목(재정의 행은 쓰지 않는다). 사본은 개인 탭이다(기존과 같음).
- 고정 탭 위젯의 개인 데이터(메모·챗봇 대화)는 지금처럼 `USER_ID + INST_ID` 로 사용자마다 따로다(관리자 저장이 instId 를 유지하는 한 이어진다).

## 3. 개인 탭 한도

- 개인 탭(`tab-N`)만 세어 최대 10개(`MAX_TABS`). 고정 탭 수와 무관하다. `saveTab` 새 탭·`shareTab` 받는 사람·화면 (+)·가져오기에 같은 규칙.
- 이전(§4)은 한도를 보지 않는다(보존 우선). 한도를 넘은 사용자는 새 탭 만들기만 막힌다.

## 4. 개인 배치 이전 (지연 이전, 행 삭제 없음)

- 대상: 사용자 탭 테이블의 옛 행 중 **위젯이 1개 이상인** 것.
  - `home` → 개인 탭 「내 홈」.
  - `def-N` 재정의 행(그 `def-N` 이 지금 사용자의 고정 탭 집합에 있을 때) → 개인 탭 「내 {관리자 탭 이름}」. (조정자 확정 2026-10-07 — 다른 선택지였던 「숨기고 남김」은 쓰지 않는다)
  - 위젯 0개인 옛 행과 집합 밖 `def-*` 재정의 행은 **그대로 두고 숨긴다**(지우지 않는다). 옛 행이 없으면 아무것도 하지 않는다(지워진 행을 되살리지 않는다).
- 시점: `secWidget/search` 가 응답을 만들기 전, 옮길 행이 있을 때만(서버 기동 시 일괄 이전은 하지 않는다 — 다중 인스턴스·기동 시간 부담 없이 사용자별로 한 번).
- 트랜잭션: OASIS 가 서비스 전체를 txBiz 로 감싸므로 `search` 는 그 바깥 트랜잭션을 `NOT_SUPPORTED` 로 내려놓고 돈다(WidgetChatService 와 같은 방식). 이전은 writer 가 자기 트랜잭션으로 커밋하고, 실패하면(DB 잠금 등) 경고만 남기고 옛 행을 숨긴 채 응답한다 — 홈 조회를 막지 않고 다음 조회가 다시 옮긴다.
- 방법: `SecWidgetTabWriter.moveTabs` 한 트랜잭션에서 벌크 `UPDATE … SET TAB_ID=:to, TAB_NM, TAB_SEQ, U_AT, U_USR_ID WHERE USER_ID=:u AND TAB_ID=:from`.
  원래 행이 없으면(동시 요청이 먼저 옮김) 건너뛴다. `INST_ID` 는 그대로라 메모·대화가 이어진다.
  옛 위젯이 관리자 배치에서 복사된 instId(예: `default-kpi`)를 그대로 갖고 있으면 고정 「홈」과 「내 홈」의 같은 위젯이 같은 `USER_ID+INST_ID` 메모·대화를 함께 쓴다 — 예전에도 그 사용자 한 사람의 데이터였으므로 그대로 둔다(instId 를 바꾸면 메모가 끊긴다).
- 새 ID 는 서비스가 `tab-(개인 탭 최대 번호 + 1)` 부터 바라고, writer 가 트랜잭션 안에서 탭 행·위젯 행이 모두 없는 첫 `tab-N` 으로 정한다(동시에 생긴 공유 사본·탭 행 없는 위젯과 겹치지 않게 — 재시도 없음). 이름이 개인·고정 탭 이름과 겹치면 숫자 꼬리(「내 홈 2」), 20자 안. 순서: 「내 홈」 은 개인 탭 맨 앞(0), 나머지는 뒤.
- 멱등: 옮긴 뒤에는 원래 ID 행이 없고, `home`·`def-*` 로 새 행이 생기는 길(saveTab)이 막혀 다시 옮길 것이 없다.
- 새 개인 탭 저장(`saveTab` 새 탭)은 writer `insertTab` 이 같은 빈 번호 규칙으로 넣기만 한다 — 화면이 연 뒤 같은 번호로 옮겨진 「내 홈」을 덮어쓰지 않는다. 응답 `tabId` 가 실제 ID 다.

## 5. 화면

- shared `WidgetTab` 에 선택 칸 `fixed?: boolean`(관리자 고정 탭, 사용자가 풀 수 없음)과 `origin?: string`(출처 풍선 글)을 더한다. 기존 `locked` 는 사용자가 푸는 잠금이라 재사용하지 않는다.
- `WidgetWorkspace` 에 `fixedHome?: boolean`(기본 false — 기존 사용처 그대로). true 면 「홈」은 늘 `homeDefault` 로 그리고(서버 `home` 행 무시) 고정이다.
  고정 탭에서는 [배치 편집]이 막히고(「관리자가 정한 탭입니다. 내 탭에서 편집하세요.」), 탭 메뉴는 공유·내보내기만, 잠그기·되돌리기 메뉴는 없다.
  (+)·가져오기 한도는 고정 탭을 뺀 탭 수로 센다. 탭 비교 함수(`sameTab`)에 새 칸을 넣는다.
- 관리자(`mode="admin"`)는 그대로 편집한다. 새 prop `homeTabName?: string` 으로 부서 키의 「홈」 탭 이름을 부서명(대표 탭)으로 보인다.
- m-mcm 홈(`page.tsx`·`widget-store.ts`): `fixedHome` 을 켜고, store 가 `fixedYn`·`origin` 을 옮긴다. `homeDefault` 는 `widgetDef/list` 의 전사 배치 → 없으면 코드 상수.
- `widgetDef/list` 의 `homeDefault` 는 **전사(`*`) 배치만** 돌려준다(부서 대표 배치는 `dept-*` 탭으로 따로 보이므로). `homeDefaultKey` 는 `*` 또는 null.
- 위젯관리 「기본 배치」: 안내 문구를 「전사 배치(홈·탭)는 모든 사용자에게, 부서 배치는 그 부서와 하위 부서 사용자에게 고정 탭으로 보입니다.
  사용자는 고칠 수 없고, 저장하면 다음 조회부터 바로 반영됩니다.」로 바꾼다. 부서 키의 「홈」 탭은 「{부서명}」 대표 탭으로 부르고,
  [부서 추가]의 시작 배치는 위 부서·전사를 복사하지 않고 **빈 배치**로 시작한다(복사하면 전사 탭과 위젯이 겹쳐 보인다). 상속 안내 띠는 없앤다.

구현하며 위와 달라지거나 보태진 점(2026-10-07):

- 고정 탭 store(`widget-store.ts`)는 서버 줄의 `lockYn=Y` 를 `locked` 로 싣지 않는다. 고정 탭의 `lockYn=Y` 는 사용자 잠금이 아니라 서버가 강제하는 잠금이고, 화면은 `fixed` 로 막는다. `fixedYn` 이 없는 옛 응답은 `defaultYn`·`customYn` 으로 읽는다. `resetTab` 은 서버가 거절하므로 store 에 두지 않는다.
- `WidgetBoard` 에 선택 prop `emptyText?` 를 더했다. 위젯이 없고 편집할 수 없을 때의 안내이며, 고정 탭은 「관리자가 아직 위젯을 놓지 않은 탭입니다.」를 넘긴다(기본 문구는 [배치 편집]을 안내하므로 고정 탭에는 맞지 않는다).
- 홈(`fixedHome`)의 탭 풍선 출처는 「전사 기본 배치」다. 서버가 주는 전사·부서 탭의 출처는 `origin` 글을 그대로 쓴다.
- shared 는 개인 탭 한도에 세는 탭 수 함수 `countedTabCount(tabs)` 를 내보낸다(`fixed` 탭을 뺀다). `isFixedTab`·`orderTabs` 도 `fixed` 를 고정 탭으로 본다.
- 관리자 `loadLayout` 은 전사·부서 모두 `effective=N` 으로 돌려준다(물려받은 배치를 보여 주지 않으므로 상속 안내가 없다). 부서 대표 탭의 시작 배치는 빈 배열이다.

## 6. 바뀌는 서비스 계약 요약

| 서비스/action | 바뀐 점 |
|---|---|
| `secWidget/search` | 옛 행 지연 이전 뒤 응답. `tabs[]` = 전사 기본 탭·부서 대표·부서 기본 탭(고정, `fixedYn=Y`·`defaultYn=Y`·`lockYn=Y`·`origin`) + 개인 탭. `home` 은 돌려주지 않는다(화면이 `homeDefault` 로 그린다). 고정 탭 위젯은 관리자 항목 |
| `secWidget/saveTab`·`deleteTab` | 고정 탭 ID 거절. 새 개인 탭 한도는 개인 탭 수만 |
| `secWidget/resetHome`·`resetTab` | 거절(행 삭제 없음) |
| `secWidget/shareTab` | 원본은 관리자 배치. 받는 사람 한도는 개인 탭 수만 |
| `widgetDef/list` | `homeDefault` = 전사 배치만 |
| `commWidgetMng/*` | 변경 없음(화면만 [부서 추가] 시작 배치를 빈 배치로) |

## 7. 시험

- 백엔드: 고정 탭 합집합 순서(전사 + 부서 사슬, 하위 부서 사용자에게 상위 부서 탭), 부서 대표 탭 유무, 이전(home·def 재정의 → 개인 탭, 멱등 두 번, 이름 충돌 꼬리, 한도 넘은 상태, instId 유지, 빈 옛 행 그대로), resetHome·resetTab 이 행을 지우지 않음, 고정 ID saveTab·deleteTab 거절, shareTab 원본, 개인 탭 한도, widgetDef/list 전사만.
- 화면: 고정 탭 편집 막힘·메뉴, `fixedHome` 이 서버 home 을 무시, 한도 계산, store 매핑, 관리자 부서 대표 이름·빈 시작 배치.
