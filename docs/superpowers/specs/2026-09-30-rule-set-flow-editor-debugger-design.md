- 작성: 2026-09-30
- 상태: 사용자 범위 결정 완료(2026-09-30), 세부 설계는 사용자 위임("나머지는 진행해")
- 앞선 스펙: `docs/superpowers/specs/2026-09-29-rule-set-flow-design.md`(1·2단계). 이 문서는 그 §7(캔버스 편집기)·§8(디버거)을 넓힌다. 흐름 모델·실행 의미·엔진 계약(§3·§4)은 바꾸지 않는다.

## 2. 전역 제약

- 엔진(`kr.dongkuk.maru.mdm.engine`) main 코드와 공개 계약(스키마·`engine-contract.generated.ts`)을 바꾸지 않는다.
- 저장 형식(`FLOW_JSON`, 서버 `RuleSetFlowJson` 정규 JSON)을 바꾸지 않는다. 서버가 view 를 엄격하게 읽으므로 새 UI 상태(블록 접힘·중단점·조사식)는 저장하지 않는다.
- DB 검증은 SQLite 만 한다. 도커를 쓰지 않는다.
- 화면은 `mantine-aggrid-ui` 스킬과 `docs/guide/FrontEnd/Local-Rules.md` 를 따른다. 표 모양은 AG Grid 를 쓴다.
- 새 CSS 는 2단계 방식(`rsf-styles.ts` TS 문자열, React 19 `<style href precedence>`)으로 넣는다. 로컬 `.css` import 를 쓰지 않는다(Local-Rules §17).
- 브라우저 저장소(localStorage)는 개인 편의(중단점·조사식·최근 입력·패널 크기)에만 쓴다. 읽기·쓰기는 try/catch 로 감싸고 없어도 화면이 동작해야 한다.
- 단축키는 캔버스 영역에 초점이 있을 때만 받고 그때만 `preventDefault` 한다. 입력 칸(input·textarea·contenteditable)에 초점이 있으면 무시한다. 포털 전역 단축키와 겹치지 않게 한다.
- 단축키는 보조 수단이다. 모든 동작은 툴바·메뉴 버튼으로 할 수 있어야 한다. F5(새로 고침)·Cmd+F(브라우저 찾기)·Cmd+D(북마크)는 캔버스 초점 밖에서는 브라우저 동작이 그대로 일어나고, Mac 에서 F9·F10 은 fn 을 함께 눌러야 한다. 저장하지 않은 편집이 있으면 `beforeunload` 로 떠나기 전에 확인한다.

## 3. 편집기

### 3.1 끌어 놓기 (A)

- **A1 넣을 선 강조**: 팔레트·룰 목록 항목을 끄는 동안 커서에서 가장 가까운 선(화면 기준 80px 안. 2단계 `nearestEdge` 의 `max` 는 흐름 좌표이므로 `80 / zoom` 으로 넘긴다)을 굵은 파란 선으로 강조하고 선 가운데에 "여기에 넣기" 표지를 띄운다. 선 위에 놓으면 그 선에 끼운다. 빈 곳에 놓으면 넣지 않고 "선 위에 놓아야 한다" 알림을 띄운다. 2단계의 "가까운 선이 없으면 선택된 선에 넣기"는 없앤다(보이지 않는 동작이라 혼란을 준다).
- **A2 놓인 노드 옮기기**
  - 룰 노드나 분기(IF·병렬)를 끌어 다른 선 가까이 가면 A1 과 같이 강조한다. 놓으면 흐름에서 떼어 그 선에 끼운다. 떠난 자리는 앞뒤를 다시 잇는다(`removeNode` 와 같은 규칙).
  - 분기를 끌면 짝 합류와 안쪽 노드까지 블록 전체가 옮겨진다. 화면 위치도 블록 전체가 같은 만큼 움직인다.
  - 자기 자신에 붙은 선, 자기 블록 안쪽 선은 대상에서 뺀다(순환·자기 삽입 방지).
  - 선에서 먼 곳에 놓으면 지금처럼 위치만 바뀐다.
  - 새 연산: `moveNode(f, nodeId, edgeId): EditResult`. 룰 노드와 분기 블록을 모두 받는다.
- **A3 선 위 [+]**: 편집 모드에서 선 가운데에 작은 [+] 버튼을 둔다(사용자 정의 선 + `EdgeLabelRenderer`). 누르면 메뉴: 룰(검색 팝업), IF 분기, 병렬 분기, 붙여넣기(B9 클립보드가 있을 때). 조건 라벨이 있는 선은 라벨 옆에 둔다.
- **A4 룰 목록 패널**: 왼쪽 세로 팔레트를 넓혀 위에 팔레트 버튼, 아래에 룰 목록(검색창 + 목록)을 둔다. 목록은 2단계 룰 검색 팝업과 같은 조건(RELEASED 버전이 있는 룰)과 같은 서버 조회를 쓴다. 줄마다 룰 ID·이름·종류를 보이고, 줄을 끌어 선에 놓으면 넣는다(드래그 MIME `application/x-rsf-rule`). 줄을 두 번 누르면 선택된 선에 넣는다. 패널은 접을 수 있다. 보기·디버그 모드에서는 목록만 보이고 끌기는 꺼진다.

### 3.2 편집 기본기 (B)

- **B5 되돌리기·다시 하기**
  - `useRuleSetEdit` 훅에 흐름 사본 이력을 둔다. 상한 100개. 세트를 새로 불러오면 비운다. 저장해도 비우지 않는다.
  - 끌기는 놓을 때 한 번 기록한다. 조건식·이름 입력은 같은 칸을 1초 안에 연달아 고치면 한 번으로 합친다.
  - 툴바 버튼 [되돌리기][다시 하기]와 Ctrl+Z / Ctrl+Shift+Z(또는 Ctrl+Y). Mac 은 Cmd.
  - dirty 판정은 지금처럼 저장된 정규 JSON 과 비교하므로 되돌려서 저장본과 같아지면 dirty 가 풀린다.
- **B6 단축키**(편집 모드, 캔버스 초점): Delete·Backspace 선택 삭제(노드·선·메모·그룹), Esc 선택 해제·메뉴 닫기, Ctrl+C / Ctrl+V / Ctrl+D(B9), Ctrl+F(D15). 툴바에 [?] 단축키 도움말 팝오버를 둔다.
- **B7 우클릭 메뉴**
  - 룰 노드: 룰 바꾸기, 복사, 복제, 삭제, 룰 편집 열기, 중단점(디버그 모드)
  - 분기: IF↔병렬 바꾸기, 분기 풀기, 갈래 더하기, 블록 복사, 블록 삭제, 접기·펼치기
  - 선: 룰·IF·병렬 넣기, 붙여넣기, 조건 편집(IF 갈래), 선 삭제
  - 빈 곳: 메모 더하기, 붙여넣기(선택된 선이 있을 때), 자동 정렬, 화면 맞춤
  - 보기 모드에서는 편집 항목을 숨기고 보기 항목(룰 편집 열기, 접기)만 남긴다.
- **B8 룰 바꾸기**: 노드 자리·선은 그대로 두고 `ruleId` 만 바꾼다. 룰 검색 팝업으로 고른다. 새 연산 `replaceRule(f, nodeId, ruleId)`. 같은 세트에 같은 룰이 이미 있어도 막지 않는다(검사가 판단한다).
- **B9 복사·붙여넣기·복제**
  - 복사 단위: 룰 노드 하나 또는 분기 블록 하나(안쪽 전체). 여러 노드 선택 복사는 하지 않는다.
  - 클립보드는 화면 메모리(세트를 바꿔도 유지, 새로 고침하면 사라짐). 시스템 클립보드는 쓰지 않는다.
  - 붙여넣기: 선택된 선(또는 [+] 메뉴·선 우클릭의 선)에 끼운다. 노드·선 ID 는 새로 발급한다. 조건식·라벨은 복사한다.
  - 복제(Ctrl+D): 복사한 뒤 원본 바로 뒤 선에 붙여 넣는다.
  - 새 연산 `copyFragment(f, nodeId): Fragment | string`, `pasteFragment(f, edgeId, frag): EditResult`.
  - 붙여 넣은 결과가 노드 상한(200)을 넘으면 거부한다.
- **B10 조건식 즉석 편집**: IF 갈래 선의 조건 라벨을 두 번 누르면 그 자리에서 입력 칸이 열린다. Enter 확정, Esc 취소. 속성 패널 편집과 같은 `updateEdge` 를 쓴다.

### 3.3 분기 편집 (C)

- **C11 IF↔병렬 바꾸기**: 새 연산 `changeSplitKind(f, splitId, kind)`. 근거: 엔진 `FlowParser` 는 IF 에 "그 외" 갈래가 정확히 1개, 나머지 갈래에 조건식을 요구하고, 병렬 갈래에는 조건·그 외를 금지한다.
  - IF→병렬: 갈래 조건식·"그 외" 표시를 지우고, 갈래 순서를 1..n 으로 다시 매긴다(그 외 갈래는 마지막).
  - 병렬→IF: 마지막 갈래를 "그 외"로 두고, 나머지 갈래 조건식은 비워 둔다. 빈 조건식은 검사 오류로 드러나므로 사용자가 채운다.
  - 노드 ID 는 유지한다. 라벨이 기본 라벨("조건"·"병렬")이면 새 기본 라벨로 바꾼다.
- **C12 분기 풀기**: 새 연산 `dissolveSplit(f, splitId, keepEdgeId)`. 고른 갈래의 안쪽 노드만 남겨 분기 앞 선과 합류 뒤 선 사이에 잇고, 분기·합류·다른 갈래 노드는 지운다. 빈 갈래를 고르면 분기 앞뒤를 바로 잇는다. 우클릭 메뉴에서 고를 갈래를 하위 메뉴로 보인다.
- **C13 갈래 순서 끌기**: 속성 패널의 갈래 목록에 끌기 손잡이를 둔다. 놓은 자리에 맞게 기존 `moveBranch` 를 거듭 부르거나 `reorderBranches(f, splitId, edgeIds)` 로 한 번에 바꾼다. IF 의 "그 외"는 늘 마지막에 고정한다.

### 3.4 보기 (D)

- **D14 확대 막대·미니맵**: React Flow `Controls`(확대·축소·화면 맞춤·잠금)와 `MiniMap` 을 캔버스 오른쪽 아래에 둔다. 미니맵은 툴바 토글로 숨길 수 있다(localStorage 기억).
- **D15 노드 찾기**: 툴바 검색 칸(Ctrl+F). 룰 ID·룰 이름·노드 라벨로 찾는다. Enter 로 다음 결과로 옮기며 캔버스를 그 노드로 이동하고 깜빡인다(2단계 `focusSeq`). 결과 수 "2/5" 를 보인다. 접힌 블록 안의 노드면 블록을 펼친다.
- **D16 블록 접기**: 분기 블록을 노드 하나("IF 조건 · 노드 6개")로 접는다. 접힌 블록은 분기 앞 선과 합류 뒤 선을 이어 받는다. 접힘 상태는 저장하지 않는다(화면 상태). 디버거 겹침은 접힌 블록에 "안쪽 실행 k개" 배지와 안쪽 오류가 있으면 빨간 테두리로 보인다. 편집 연산이 접힌 블록 안 노드를 대상으로 하면 먼저 펼친다.

## 4. 디버거와 화면 배치

### 4.1 모드와 배치 (B4)

툴바의 모드를 [보기][편집][디버그] 셋으로 늘린다. 시뮬레이션은 아래 패널 탭에서 빼 디버그 모드로 옮긴다. 2단계의 난잡함(좁은 아래 패널에 입력 폼과 값 표를 나란히 넣음, 실행 중에도 오른쪽에 세트 속성이 남음)을 없애는 것이 목적이다.

디버그 모드 배치:

```
┌ 툴바: 세트 · [보기][편집][디버그] ─ [▶ 계속 F5][⤼ 한 단계 F10][⇥ 여기까지][⟲ 처음부터][■ 끝내기] · 3/7 r2 실행 전 ┐
├ 왼쪽: 입력 ───────┬ 가운데: 캔버스 ───────────────┬ 오른쪽: 변수 ─────────┤
│ 평가 시각          │ 실행한 노드: 초록·순번         │ 조사식(고정 변수)      │
│ 입력 변수 폼       │ 지금 노드: 굵은 테두리         │ 지금 단계 변수 전체    │
│ (타입별 칸)        │ 다음 노드: 점선                │  (바뀐 값 강조)        │
│ [JSON 붙여넣기]▾   │ 아직 안 탄 노드: 회색          │ 노드 상세(선택 노드)   │
│ 최근 입력 ▾        │ 중단점: 노드 왼쪽 빨간 점      │ 식 평가                │
│ 테스트 케이스 목록  │                               │                        │
│ [모두 실행] 결과    │                               │                        │
├──────────────────┴───────────────────────────────┴────────────────────────┤
│ 아래 패널 탭: [값 표(변수×단계)] [실행 비교] [검사 결과]                          │
└──────────────────────────────────────────────────────────────────────────┘
```

- 디버그 모드에서는 캔버스를 편집할 수 없다(끌기·[+]·삭제 꺼짐). 흐름을 고치려면 편집 모드로 돌아간다. 입력값·중단점·조사식은 모드를 오가도 유지한다.
- 편집 모드에서 흐름을 고치면(2단계 `flowVersion`) 실행 결과를 "지난 흐름 기준"으로 표시하고, 다음 [한 단계]·[계속] 때 새로 실행한다.
- 편집·보기 모드의 아래 패널은 [검사 결과] 하나만 남는다.
- 권한: 디버그 모드는 누구나 들어갈 수 있다. 실행 버튼은 2단계와 같이 `execute` 권한(EDIT)이 없으면 꺼지고 title 로 이유를 알린다.

### 4.2 단계 실행 (E1)

- [한 단계](F10): 실행 결과가 없거나 지난 흐름 기준이면 `simulate` 를 한 번 불러 기록을 받고 커서를 0(시작)에 둔다. 이후 누를 때마다 커서를 한 칸 옮긴다. 기록이 있는 동안 서버를 다시 부르지 않는다.
- 실행이 결정적이므로 "미리 끝까지 돌리고 한 칸씩 보여 주기"는 진짜 단계 실행과 결과가 같다. 화면은 커서 이후를 모르는 것처럼 그린다:
  - 커서 이전 실행 노드: 초록 테두리·순번·결과 칩
  - 커서 노드: 굵은 강조 테두리
  - 다음 노드(기록의 커서+1): 점선 테두리
  - 아직 안 탄 노드: 회색. 끝까지 가기 전에는 "안 탄 갈래"와 "아직 안 간 노드"를 구분하지 않는다. 끝에 닿으면 2단계와 같이 안 탄 갈래를 흐리게 한다.
- [처음부터]: 커서를 0 으로. [끝내기]: 커서를 끝으로 옮기고 결과 요약을 보인다. [이전](Shift+F10)은 커서를 한 칸 되돌린다.
- 캔버스는 커서 노드로 이동한다(2단계 `focusSeq`). 이동은 노드가 화면 밖일 때만 한다(화면이 매번 흔들리지 않게).

### 4.3 중단점 (E2)

- 노드 왼쪽 가장자리의 점을 누르거나, 우클릭 메뉴, 선택 노드에서 F9 로 켜고 끈다. 룰·분기·합류 노드에 걸 수 있다.
- [계속](F5): 커서 뒤 기록에서 중단점 노드가 처음 나오는 칸으로 옮긴다. 없으면 끝으로 간다. 기록이 없으면 먼저 실행한다.
- [여기까지 실행]: 우클릭한(또는 선택한) 노드가 커서 뒤 기록에 처음 나오는 칸으로 옮긴다. 기록에 없으면 "이 입력으로는 이 노드를 지나지 않는다" 알림.
- 중단점은 세트별로 localStorage 에 기억한다(`rsf:bp:<setId>`). 흐름에서 사라진 노드의 중단점은 불러올 때 버린다.

### 4.4 변수 패널·조사식 (E3)

- 오른쪽 변수 패널은 커서 시점의 ctx 전체를 이름 순으로 보인다. 직전 단계에서 바뀐 값은 노란 배경, 새로 생긴 값은 "새" 배지.
- 조사식: 변수 이름 옆 핀으로 위쪽 "조사식" 칸에 고정한다. 흐름 입력·결과 변수가 아닌 이름(오타)은 "없는 변수"로 보인다. 세트별 localStorage 기억.
- 선 위 변수 칩에 마우스를 올리면 커서 시점의 그 변수 값을 툴팁으로 보인다(아직 만들어지지 않았으면 "아직 없음").
- 노드 상세(2단계 `TraceDetail`)는 변수 패널 아래에 둔다. 노드를 누르면 그 노드의 기록(커서 이전에 실행됐으면)을 보인다.

### 4.5 식 즉석 평가 (E5)

- 변수 패널 맨 아래 입력 칸에 식을 적고 Enter 를 누르면 커서 시점 ctx 로 평가해 참/거짓/값/NULL/오류를 보인다. 최근 식 5개를 기억한다.
- 평가는 브라우저에서 한다. `src/evalex` 의 TS 평가기(Java 와 코퍼스로 동등성이 묶임)를 쓰고, 변수 값은 세트가 선언한 타입으로 바꿔 넣는다(서버 `BranchCondition` 의 `ValueConverter.toDeclared` 와 같은 규칙, `values.ts` 의 변환 함수). 평가 시각은 입력 폼의 평가 시각을 쓴다.
- 평가기가 폴백 신호를 내는 식(화면에서 재현하지 못하는 함수)이면 "화면에서 계산할 수 없는 식이다" 를 보인다. 서버를 부르지 않는다.
- 결과는 참고용이다. 문구로 "실행 판정은 서버가 한다"를 작게 보인다.

### 4.6 테스트 케이스 (E6)

- **목적**: 흐름을 고칠 때마다 저장해 둔 입력들로 결과가 그대로인지 한 번에 확인한다.
- **DB**: Flyway `V15__create_mdm_rule_set_test_case.sql`, 테이블 `TB_MDM_RULE_SET_TEST_CASE`. 룰 테스트 케이스(`TB_MDM_RULE_TEST_CASE`, V8)와 같은 모양으로 만든다.
  - `MARU_RULE_SET_ID`(FK → `TB_MDM_RULE_SET`) + `CASE_ID` 복합 PK, `CASE_NAME`, `INPUT_JSON`(NOT NULL, json_valid), `EVAL_TS`(없으면 실행 시각), `EXPECTED_JSON`(json_valid), `DESCRIPTION`, `ROW_VERSION`, 감사 칼럼(V8 과 같은 순서).
  - `CASE_ID` 발급: 룰은 `TB_MDM_RULE.LAST_CASE_ID` 카운터(`MdmRuleIdIssuer`, `MdmRuleIdKind.CASE`)를 쓰지만 세트 테이블에는 카운터가 없다. 세트 케이스는 같은 세트 안 최대 번호 + 1 로 발급하고, PK 충돌이면 동시 저장 충돌 문구로 거부한다(세트 테이블 칼럼 추가는 칼럼 순서 불변식 때문에 피한다).
- **서버**: `ruleSetEdit` 서비스에 케이스 저장·삭제, 케이스 조회, 일괄 실행을 더한다. 새 action 동사를 만들지 않는다(ADR-0003 D5 16단어·권한 표). 룰 편집 화면과 같이 저장·삭제는 `save` 의 part 분기(`part=CASE`, 삭제는 `caseDeleted`), 조회는 `view` 결과에 케이스 목록을 넣고, 일괄 실행은 `execute` 에 `runCases`·`caseIds` 칸을 더한다.
  - OASIS 파라미터는 Map·List DTO 칸을 묶지 못한다(2단계 실측 `S999 Generic type`). 케이스 ID 목록은 룰 편집 `RuleTestRequest.caseIds` 와 같이 콤마로 이은 문자열, 입력·기대값은 JSON 문자열(`inputJson`·`expectedJson`)로 받는다.
  - 일괄 실행은 화면이 보낸 현재 흐름(저장 전 흐름 포함, `flowJson` 문자열)과 케이스 ID 목록을 받아 케이스마다 `runner.trace` 를 돌리고 케이스별 통과/실패·실제 결과·차이를 돌려준다. 케이스 수 상한 50.
  - 판정: `EXPECTED_JSON` 에 적힌 키만 `RunTrace.finalValues` 와 비교한다(적지 않은 키는 보지 않는다). 값 비교는 TypedValue 계약 문자열 비교. 룰용 `RuleCaseJudge` 를 넓히거나 같은 규칙의 세트용 판정기를 둔다. 실행이 오류로 끝나면 실패이고 오류 코드를 보인다.
  - 권한: 저장은 세트 저장과 같은 EDIT, 실행은 `execute` 와 같은 EDIT.
  - 세트를 폐기해도 케이스는 남긴다. 되살리면 다시 보인다.
- **화면**(디버그 모드 왼쪽 아래)
  - 케이스 목록(AG Grid): 이름, 마지막 결과(통과·실패·안 돌림), [불러오기]
  - [현재 입력을 케이스로 저장]: 입력 폼 값·평가 시각을 저장. 기대값은 현재 실행 결과의 최종 변수로 채운 뒤 편집 팝업에서 고친다.
  - [모두 실행]: 결과 배지와 "8/10 통과". 실패한 케이스를 누르면 기대·실제 차이 표를 보이고, [디버그로 열기]로 그 입력을 폼에 넣어 단계 실행을 시작한다.
  - 케이스 편집·삭제는 팝업. 룰 편집 화면 `TestCaseEditModal` 의 모양을 따른다.

### 4.7 실행 비교·입력 기억 (E7)

- **실행 비교**: 새로 실행하면 바로 전 실행 결과를 "이전"으로 보관한다(한 개). 아래 패널 [실행 비교] 탭에서 최종 변수 이전·지금·같음/다름 표와, 두 실행의 노드 경로 차이(한쪽만 지난 노드)를 보인다. 흐름을 고친 뒤 같은 입력으로 다시 돌려 영향을 보는 용도다.
- **입력 기억**: 실행한 입력 묶음(값·평가 시각)을 세트별로 최근 10개 localStorage 에 기억한다. 입력 칸 위 [최근 입력 ▾]에서 고르면 폼에 채운다. 같은 입력은 한 번만 기억한다.

## 6. 테스트

- 편집 연산마다 순수 함수 단위 테스트: 정상, 거부 사유, 입력 불변, 결과 흐름이 `parseFlow`·검사를 통과하는지(구조 규칙 유지). 특히 moveNode 의 자기 블록 안 이동 거부, dissolveSplit 의 빈 갈래, changeSplitKind 왕복.
- 되돌리기: 연산 n 번 뒤 n 번 되돌리면 처음 흐름과 정규 JSON 이 같다. 입력 합치기(1초) 가짜 타이머 테스트.
- 캔버스: 끌기 중 강조 상태, 빈 곳 놓기 알림, 우클릭 메뉴 항목(모드별), 단축키가 입력 칸 초점에서 무시되는지.
- 디버거: 커서 이동·중단점 계속·여기까지 실행(지나지 않는 노드 알림)·흐름 변경 뒤 재실행, 변수 패널 바뀐 값 표시, 식 평가(참·거짓·폴백).
- 서버: V15 마이그레이션 SQLite 테스트(칼럼 순서 불변식 `MdmBusinessRuleMigrationTest` 방식), 케이스 저장 낙관적 잠금, 일괄 실행 판정(적은 키만 비교·오류=실패·상한 50), OASIS HTTP 테스트에 새 action·권한(READ 403).
- 브라우저 확인(ego-browser): 끌어 넣기·옮기기, [+], 우클릭, 되돌리기, 디버그 모드 단계 실행·중단점, 테스트 케이스 저장·모두 실행.
