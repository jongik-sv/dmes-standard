# 룰 세트 흐름도 — 룰 노드 외관 옵션(색·크기·표시 항목·아이콘·모양)

- 날짜: 2026-10-01
- 앞 문서: `2026-10-01-rule-set-flow-phase4-design.md`(4단계 — 빈 단계 T1, 그룹 크기 G2, 오른쪽 섹션 패널 P1)
- 화면: `src/frontend/m-mdm/pages/dme/ruleSetEdit/`, 기능설계서 `docs/mdm/screens/ruleSetEdit/ruleSetEdit_기능설계서.md`

## 0. 범위와 사용자 요청

| ID | 기능 | 사용자 요청(원문) |
|---|---|---|
| S1 | 룰·빈 단계 노드마다 외관 옵션 | "각 룰에 대해 외관 옵션도 있으면 좋겠다." |

사용자가 고른 것(질문 3개에 답함):
- 옵션 종류: **색(채움·테두리), 노드 크기, 표시 항목 선택, 아이콘·모양** 네 가지 모두.
- 적용 대상: **룰·빈 단계(RULE·TASK)만**. 시작·끝·분기·합류·메모·그룹은 지금 모양 그대로다.
- 크기 방식: **모서리 끌기**(Camunda 식).
- 아이콘·모양: **정해진 목록에서 고르기**.

그 밖의 세부는 사용자가 "질문할 내용이 있으면 알아서 최적, 최선의 선택을 하고 결정 결과를 남겨줘"라고 맡겼다. 아래 §6 결정 표에 모두 남긴다.

제외: 분기·메모·그룹의 외관, 여러 노드에 한 번에 외관 적용, 외관 복사·붙여넣기 단독 기능, 사용자 정의 색(색상 선택기), 아이콘 검색.

## 1. 저장 형식

- 흐름 JSON `view.styles` 에 노드 ID 별로 둔다. 백엔드는 `view` 를 받은 그대로 저장하므로(`RuleSetFlowJson` — "view 는 화면 전용이라 읽지 않고") 계약·엔진·서비스는 바뀌지 않는다.

```ts
/** 룰·빈 단계 노드 외관(S1). 모든 칸은 선택이다. 기본값과 같은 칸은 두지 않는다. */
export interface NodeStyle {
  color?: NodeColor;   // 팔레트 키(§2.1). 없으면 기본.
  w?: number;          // 너비(흐름 좌표, 정수, 232~640). 없으면 232.
  h?: number;          // 높이(정수, 68~320). 없으면 68.
  hide?: NodePart[];   // 숨길 표시 항목(§2.3). 없으면 모두 보임.
  icon?: NodeIcon;     // 아이콘 키(§2.4). 없으면 아이콘 없음.
  shape?: NodeShape;   // "square" | "pill". 없으면 둥근 모서리(지금 모양).
}
view.styles?: Record<string, NodeStyle>
```

- 읽기(`sanitizeView`): 객체가 아니면 버린다. 칸마다 모르는 값은 버린다(색·아이콘·모양은 목록에 있는 키만, 숫자는 유한한 값만 정수로 반올림 뒤 범위로 자름, `hide` 는 아는 항목만 중복 없이 정해진 순서로). 남은 칸이 없으면 그 노드 키를 두지 않는다. 흐름에 없는 노드 ID·RULE/TASK 가 아닌 노드의 키는 버린다.
- 쓰기(`flowJsonOf`): `styles` 가 비면 키를 쓰지 않는다 — 외관을 쓰지 않은 세트의 저장 글자와 dirty 기준이 예전과 같다(G2 의 `pad` 와 같은 원칙). 칸 순서는 `color, w, h, hide, icon, shape`, 노드 키 순서는 흐름 노드 배열 순서.
- 노드 연산: 정리는 정규화 한 곳에서 한다 — `routesFor`·`labelsFor` 와 같이 `stylesFor(nodes, styles)` 를 정규화 경로(`toEditFlow`·`sanitizeView`·노드 연산 뒤 정리)에 넣어, 분기 블록 삭제처럼 여러 노드가 한꺼번에 지워져도 빠짐없이 정리한다.
  - 노드를 지우면 그 스타일도 지운다.
  - 빈 단계에 룰을 지정해 RULE 이 되어도(같은 노드 ID) 스타일을 유지한다. 반대(룰 지정 해제가 있다면)도 같다.
  - 복사·붙여넣기는 새 노드 ID 로 스타일을 함께 옮긴다 — 복사 쪽 `Fragment` 타입도 스타일을 담는다.
  - 자동 정렬은 스타일을 지우지 않는다(크기는 배치에 쓰인다).

## 2. 옵션

### 2.1 색

- 팔레트 7가지: `default`(지금 색), `blue`, `green`, `yellow`, `orange`, `red`, `purple`. Camunda Modeler 의 요소 색 팔레트(기본·파랑·주황·초록·빨강·보라)에 노랑을 더했다.
- 색마다 채움·테두리 두 토큰을 `styles/` 의 `:root` 에 두고 어두운 화면 값도 둔다(`--rsf-c-blue-bg`, `--rsf-c-blue-border` 등). 글자색은 그대로라 대비가 유지되도록 채움은 옅은 색이다.
- 디버그 겹침 상태(current 굵은 테두리·next 점선·pending 회색·error 빨강)와 선택 테두리는 색보다 우선한다 — 상태 클래스가 테두리를 덮는다. pending 의 흐림도 그대로다.

### 2.2 크기

- 범위: 너비 232~640, 높이 68~320(흐름 좌표, 정수). 최소는 지금 크기라 줄이면 지금 모양으로 돌아간다.
- 캔버스: 편집 모드에서 하나만 고른 RULE·TASK 노드에 오른쪽 변(`e`)·아래 변(`s`)·오른쪽 아래 모서리(`se`) 손잡이 3개를 보인다. 왼쪽 위 자리는 고정이다. 끄는 동안은 캔버스 안 저장소에만 두고(그룹 크기 G2 와 같은 방식) 놓을 때 한 번 저장한다(되돌리기 한 칸). 손잡이는 `nodrag nopan` 이다.
- 오른쪽 패널: 너비·높이 숫자 칸과 [기본 크기] 단추.
- 노드별 크기를 모든 계산에 쓴다 — 종류별 `NODE_SIZE[kind]` 를 쓰던 곳(자동 배치 dagre·갈래 순서 `orderBranches`, 겹침 풀기, 맞춤·간격·화살표, 스냅, 그룹 틀, 선 끼우기 대상·선 중점, 룰 목록 놓기 대상, 메모 놓기 자리, 공간 넓히기, 노드 그리기)을 노드별 크기 함수로 바꾼다. 함수는 반복문 안에서 흐름을 다시 찾지 않도록 `nodeSize(kind, style, folded)` 처럼 노드 종류·스타일·접힘을 받는다. 접힌 분기 블록은 지금처럼 룰 기본 크기다.
- 스타일만 바뀐 흐름에도 자동 배치가 다시 돈다(배치 memo 가 스타일을 의존값으로 가진다).
- 크기를 바꾸면(손잡이·패널 모두) 그때 그린 위치 전부를 저장 위치로 적는다(공간 넓히기 `shiftSpace` 와 같은 방식). 크기 하나 바꿨다고 자동 배치가 다른 노드를 밀어 그림이 바뀌지 않는다. 커져서 이웃과 겹치면 겹친 채 둔다(Camunda 와 같다) — 사용자가 옮기거나 [자동 정렬]을 누른다.
- 높이를 키운 노드는 제목이 여러 줄로 보인다 — 기본 높이에서는 지금처럼 한 줄 말줄임, 높이가 기본보다 크면 제목이 줄바꿈되고 남는 높이만큼 줄 수를 늘려 넘치면 말줄임한다(line-clamp). 너비를 키우면 한 줄에 더 많이 보인다.

### 2.3 표시 항목

- 숨길 수 있는 항목 3개: `sub`(룰: 종류·적중 정책 줄 / 빈 단계: 안내 줄), `id`(룰 ID 또는 룰명 작은 줄 — 룰만), `open`(룰 편집 열기 단추 — 룰만). 제목·검사 표시(mark)·중단점·디버그 배지는 늘 보인다.
- 빈 단계에서 `id`·`open` 은 해당 없음이라 패널에 보이지 않는다(저장돼 있으면 RULE 이 되었을 때 적용된다).

### 2.4 아이콘·모양

- 아이콘 12개(화면이 이미 쓰는 Tabler 아이콘): `calc`(IconCalculator), `check`(IconChecks), `filter`(IconFilter), `calendar`(IconCalendar), `money`(IconCoin), `alert`(IconAlertTriangle), `database`(IconDatabase), `ruler`(IconRuler2), `scale`(IconScale), `truck`(IconTruck), `settings`(IconSettings), `flag`(IconFlag). 제목 왼쪽에 16px 로 그린다.
- 모양: 기본(둥근 모서리, 지금 값), `square`(모서리 0), `pill`(모서리 = 높이의 절반). 빈 단계의 점선 테두리는 모양과 함께 유지된다.

## 3. 화면 — 오른쪽 패널 "외관" 섹션

- RULE·TASK 노드를 하나 고르면 오른쪽 패널에 접는 섹션 "외관"(`Section id="node-style"`)을 더한다. 편집 모드에서만 고칠 수 있고, 보기·디버그 모드에서는 섹션을 감춘다(외관은 편집 일이다).
- 구성: 색 견본 7개(누름 단추, `aria-pressed`, 툴팁 이름), 아이콘 13칸(없음 + 12, 누름 단추), 모양 3가지(SegmentedControl), 표시 항목 체크(제목은 늘 보임), 너비·높이 숫자 칸 + [기본 크기], 맨 아래 [외관 초기화](스타일 키를 지움).
- 각 조작은 편집 한 번(되돌리기 한 칸)이다. 숫자 칸은 Enter·칸 밖 누르기에 저장한다.
- 패널 색 견본은 캔버스와 같은 토큰을 쓴다.

## 4. 시험

- 모델: `NodeStyle` 읽기·쓰기 왕복, 모르는 값·범위 밖 값 자르기, 빈 스타일 키 생략, 외관 없는 흐름의 저장 글자 불변, 노드 지우기·룰 지정·붙여넣기 때 스타일 처리.
- 크기: `nodeSizeOf` 기본·저장값, 자동 배치가 큰 노드를 겹치지 않게 놓음, 그룹 틀·스냅·선 끼우기 대상이 노드별 크기를 씀.
- 캔버스: 색·아이콘·모양·표시 항목이 DOM 에 반영(클래스·data 속성), 크기 손잡이는 편집 모드에서 하나만 고른 RULE·TASK 에만, 끄는 동안 콜백 없음·놓을 때 한 번, 최소·최대 자르기.
- 패널: 섹션이 RULE·TASK 에서만, 편집 모드에서만 보임, 각 조작이 편집 한 번, [외관 초기화].
- memo(Local-Rules §19): 스타일만 바뀐 흐름에도 노드가 다시 그려진다.

## 5. 알려진 한계

- 외관은 노드 하나씩만 바꾼다(여럿 고르고 한 번에 바꾸기 없음).
- 크기 손잡이는 오른쪽·아래 쪽만이라 왼쪽·위로 키우려면 크기를 키운 뒤 노드를 옮긴다.
- 색은 팔레트 7가지뿐이다.

## 6. 결정(사용자가 맡김 — decisions.md D-130 으로 옮긴다)

| # | 결정 | 이유 |
|---|---|---|
| S-D1 | 저장은 `view.styles[nodeId]`, 빈 값이면 키 생략 | 백엔드가 view 를 통과시키므로 계약 변경 없음. 외관 없는 세트의 dirty 기준 불변(G2 pad 와 같음) |
| S-D2 | 색은 고정 팔레트 7가지(채움·테두리 한 쌍) | Camunda 와 같은 방식. 어두운 화면 대비를 토큰으로 보장. 사용자 정의 색은 대비가 깨질 수 있다 |
| S-D3 | 상태 표시(디버그·선택·검사)가 색보다 우선 | 디버그·검사 정보가 외관에 묻히지 않게 |

| S-D5 | 모든 크기 계산을 `nodeSizeOf` 로 통일, 접힌 블록은 기본 크기 | 배치·스냅·그룹·선이 그린 크기와 어긋나지 않게 |
| S-D6 | 크기를 바꾸면 그린 위치 전부를 저장 위치로 적고, 커져서 겹치면 겹친 채 둔다 | 저장 위치가 없는 노드는 자동 배치가 다시 놓으므로 한 노드만 고정하면 이웃이 밀린다. `shiftSpace` 와 같은 방식이고 Camunda 와 같다 |
| S-D11 | 높이가 기본보다 크면 제목을 여러 줄(line-clamp)로 보인다 | 제목이 한 줄 말줄임이라 높이만 키우면 보이는 글자가 늘지 않는다 |
| S-D12 | 스타일 정리는 정규화 한 곳(`stylesFor`) | 여러 노드를 한꺼번에 지우는 연산에서도 빠짐없이 정리 |
| S-D7 | 숨길 항목은 sub·id·open 3개, 제목·상태 표시는 늘 보임 | 노드를 알아보는 최소 정보 보장 |
| S-D8 | 아이콘 12개(Tabler), 모양 3가지 | 사용자 답(정해진 목록). 업무(계산·검사·날짜·금액·치수·물류 등)에 맞춘 고른 목록 |
| S-D9 | 외관 편집 UI 는 오른쪽 패널 "외관" 섹션(편집 모드만), 크기만 캔버스 손잡이도 | 4단계 P1 의 섹션 패널 방식과 일치 |
| S-D10 | 빈 단계→룰 지정·붙여넣기 때 외관 유지·복사 | "그림 먼저 그리고 채운다"는 빈 단계 목적에 맞게 |
