## 신규 기능

- 메뉴 등록, 오브젝트도 관리가 너무 어렵다.
- 역할 관리, 역할 그룹관리, 사용자 관리 너무 어렵고 복잡
- Permission 관리 어렵다. 오브젝트 전용 권한 처리 힘듦
  - 오브젝트에 신규컬럼(버튼 권한, 팝업 권한, 데이터 권한) 추가
  - 퍼미션은 오브젝트에 정의된 권한 안에서 부여가능(오브젝트가 제한한 권한 안에서 부여)
    - 예) 오브젝트 버튼 권한 (search, save, delete, import, export, confirm, cancel)
    - 예) 퍼미션 버튼 권한 (search, export)
  - 값의 콤마로 연결된 값을 사용
  - 현재 데이터 권한은 아직 정해지지 않아서 DB항목과 화면만 표현
  - 테이블 관계
    - ROLE - PERMISSION - OBJECT 모두 1:N:N 퍼미션은 ROLE, OBJECT 식별자를 PK이면서 FK로 가짐
      - ROLE안에 오브젝트 10개가 있다면 퍼미션도 10개 존재
    - 예를 들어 MDM 조회 롤에 코드 등록이라는 오브젝트(사용 가능 권한은 search, save, delete)를 연결하면 퍼미션이 만들어짐
    - 위의 예에서 해당 퍼미션은 PK(롤ID, 오브젝트ID)를 가지며 권한은 셋중에 search만 선택할 수 있는 구조
    - D 에서 역할과 사람사이에 역할 그룹을 하나 더 넣으면 좋겠다. 그리고 역할을 선택하면 메뉴에 있는 오브젝트를 바로 추가하고 바로 퍼미션까지 추가하면 좋겠어.

### MDM 관련

- MES의 가동 MDM과 원장이 되는 MDM이 동일한 화면(다만 DB 시스템, 유저가 다름)을 사용하고 2개의 시스템으로 분리되어야 함
  - MES 시스템에서 실제 적용되어서 사용해야 하는 MDM과
  - 원장이 되는 MDM 이 따로 존재해야 함
  - 이 시스템간 배포/적용 되어서 실제 MDM이 동작함
  - 될 수 있으면 DB 시스템 자체가 다르면 좋겠음(실제 환경과 유사, 테스트 가능)

### 버그·기술 부채

- 로그인 잠금과 계정 삭제가 둘 다 `USE_TP='N'` 이라 구분되지 않는다. 잠긴 계정 로그인 응답도 ACCOUNT_LOCKED 가 아니라 ACCOUNT_DISABLED 로 나가고, 잠금을 푸는 길은 비밀번호까지 초기화하는 '계정 재생성'뿐이다(관리자 비밀번호 초기화는 잠금·실패 횟수를 풀지 않고, `unlockUser` 는 부르는 곳이 없다). 잠금 전용 표시 칸과 비밀번호를 건드리지 않는 잠금 해제 경로(화면·API)를 설계하자(2026-10-03 로그인 잠금 롤백 수정 중 발견).
