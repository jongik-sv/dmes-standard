## 신규 기능

### 위젯 기능

- 홈화면에 위젯 배치기능
- 위젯관리 화면
- 위젯의 표준화
  - 위젯을 데이터 산출 : 쿼리, 웹검색, 프로그램, 일반 데이터, 고정 md / html 
  - 위젯의 출력 방법 : 다양한 모양의 테이블, 차트, 텍스트
  - 특별 위젯 : AI 챗봇
  - 전산인력의 위젯 개발 기능
- 위젯 편집 프로그램
  - 표준화 항목에 대한 편집
  - 위젯 내 화면 링크
  - 위젯 내 외부 링크
- 사용자 전용 위젯 화면 
  - 사용자가 직접 위젯들을 배치해서 개인의 위젯 화면을 만든다.
  - 위젯 배치 기능, 잠금 기능
  - 위젯의 크기 조절 기능

- 위젯 자체는 하나의 독립적인 화면 또는 프로그램으로 인정 받는다.

- 담당자 알림기능
  - 프로그램에서 발생한 기능
  - 메일과 연관 기능
  - 알림의 중요도 고려
  - 메시지 발송 그룹 관리 기능
  - 사용자 관리에서 사용되는 부서코드를 MDM의 마스터코드로 변경 (TB_MCM_DEPT_INFO와 마스터코드 선택가능하도록)
  - 비밀번호도 도메인으로 관리 하자.
  - 시스템의 이름을 정할 수 있는 기능(MDM, MES, ...)

### 기타 수정

- RULE이 상속관계를 가지도록 수정
- 룰도  major, minor 버전으로 처리 되도록 변경하자.
- 같은 화면 중복으로 열기 (서로 다른 내용을 보기 위해)



### MDM 관련 

- 현재 MDM 내용을 실제 내용으로 넣기
- MDM 내용에 대한 캐시관리 (제일 먼저 처리 되어야함)
  - 캐시 등록
  - 캐시 삭제 / 재등록
- 캡션/라벨을 MDM에서 자동으로 가져옴
- 룰 엔진 실행 검증
  - 화면 값 자동 검증
  - BE 에서 값 검증 및 체크
  - 특정 화면의 자체 컬럼에 대한 룰엔진(예를 들어 이 화면에서는 이 값이 NOT NULL)
  - 화면에만 있는 비즈니스 룰 자체에 대한 AST 생성/캐시 기능
  - 일자별 환율 받을 방법은?
- MES의 가동 MDM과 원장이 되는 MDM이 동일한 화면(다만 DB 시스템, 유저가 다름)을 사용하고 2개의 시스템으로 분리되어야 함
  - MES 시스템에서 실제 적용되어서 사용해야 하는 MDM과
  - 원장이 되는 MDM 이 따로 존재해야 함
  - 이 시스템간 배포/적용 되어서 실제 MDM이 동작함
  - 될 수 있으면 DB 시스템 자체가 다르면 좋겠음(실제 환경과 유사, 테스트 가능)

### MDM 화면

- 새버전, 확정이동, 삭제, 확정취소, 해제, ... 넘기기 --&gt; 새 버전(major), 새 버전(minor), 삭제, 확정(이동이라는 말 삭제), 확정취소, 삭제, 해제, ...넘기기 모양을 통일하자.
- 룰 세트도 버전 관리 기능이 있어야 겠다. 
- 컬럼 ID로 컬럼명과 컬럼 설명 등을 자세하게 보여주는 툴팁 (거의 팝업 수준으로 크게 열려야 함, 나중에 각 컬럼에 대한 설명을 HTML로 넣어서 그것도 띄우게 할 수 있음)
- 도메인은 종류와 개수가 많아 질 것으로 예상 된다. 검색에 도메인은 콤보로 만들면 안된다. 
- 중요 !!!! 컬럼 사전에 도메인이 필수 인가? 지금은 필수가 아니다.
- 룰 화면에서 경계값 테스트 케이스 자동 생성 기능
- 룰 세트에서 에러가 나면 Exception으로 받지 않는다면 에러 보고를 해야 한다.
