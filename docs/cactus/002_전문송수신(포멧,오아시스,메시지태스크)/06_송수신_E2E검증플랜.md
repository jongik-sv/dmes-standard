## 0. 확인된 전체 토폴로지 (근거 기반)

```
[송신 leg]  MES(mcm:8080) 업무 BPMN
  → createMsg(HTTP)  DefaultDmomMessageService:46  + MessageSerializer(Map→pipe)
  → 버퍼 → 커밋 → afterCommit  DmomDispatchSynchronization:40
  → DmomHttpSender → DefaultSeraiIntegrationClient  (헤더 X-Client-Key)
  → POST /seraiApi/v1/send (Serai:8200)  HttpIntegrationController:54
  → KafkaMessageProducer.send(topic=INTERFACE_ID)
        ↓
   [Kafka broker  localKafka:9092]
        ↓
[수신 leg]  Serai consumer (OUTBOUND config for topic)
  → OutboundRouter:55 → HttpOutboundHandler  (HTTP_HEADERS 고정키 ← 2026-06-02 작업)
  → POST /dmomApi/v1/receive (mcm:8080)
  → ClientKeyFilter 인증 → DmomReceiveController
  → DmomReceiveDispatcher → serviceStarter.start(TC)   ← OASIS(cactus-core)
  → 수신 BPMN: dmomParseMessageTask.parse(pipe→Map) → 후속 업무 → 커밋 → 200
```

| 런타임 | 앱(main class) | 포트 |
|---|---|---|
| Kafka 브로커 | `LocalKafkaApplication` | 9092 (controller 9093) |
| Serai (송수신 게이트웨이) | `SeraiApplication` | 8200 |
| MES 수신/송신 호스트 | `McmApplication` (`mcm/lib/build.gradle`: `api 'com.dongkuk.dmes:cactus-core'`) | 8080 |

수신 호스트 = **mcm** 확정. cactus-core api 의존 → OASIS `ServiceStarter` + `DmomReceiveController` 자동등록.

## 1. 테스트 피라미드 — 기존 자산 vs 신규 필요

| 레벨 | 범위 | 상태 |
|---|---|---|
| **L0 단위** | serializer/parser, parseHeaders/resolveEnv, dispatcher, controller, handlers | ✅ 완료 (cactus 194 / serai 102 / kmc 31, JDK21) |
| **L1 컴포넌트통합** | 송신 와이어(`DmomHttpPilotE2ETest`, gated skip), 수신 헤더 와이어(`HttpOutboundHandlerTest$WireTransmission` ✅ 2026-06-02) | 🟡 송신=skip / 수신헤더=완료 |
| **L2 계약(왕복)** | `MessageSerializer` ↔ `MessageParser` round-trip 동등성 (DATA_TP 1~5) | ⚠️ **신규 권장** |
| **L3 2-앱 통합(Kafka 無)** | 수신 leg: Serai-style JSON 직접 POST→mcm `/dmomApi` (인증·디스패치·BPMN) | ❌ 신규 |
| **L4 풀 E2E(전 인프라)** | 송신→Kafka→수신 라운드트립 + 업무효과 검증 | ❌ 신규 (핵심 목표) |

기존 송신 E2E `DmomHttpPilotE2ETest`: `@EnabledIf("seraiReachable")` 로 localhost:8200 소켓 도달 시에만 실행(미가동 시 auto-skip). 수신 E2E도 동일 게이팅 패턴 채택.

## 3. 단계별 실행 플랜

### Phase A — 계약/단위 보강 (인프라 0, 즉시)
- **A-1** L2 round-trip 테스트 신규: `Map → MessageSerializer → pipe → MessageParser → Map` 동등성 (DATA_TP 1~5, E/G/GE 그룹). 패딩/정밀도 손실 케이스 명시. → cactus-core test.
- **A-2** (선택) 수신 역변환과 송신 직렬화의 비대칭(Number zero-pad 등) 경계값 고정.
- **Pass**: 신규 테스트 그린, cactus-core 전체 그린 유지.

### Phase B — 수신 leg 단독 통합 (Kafka 無, mcm만)
- **B-1** `@SpringBootTest`+MockMvc 또는 stub `ServiceStarter` 로 `/dmomApi/v1/receive` 검증: 정상 200 / 검증실패 400 / 디스패처 예외 5xx.
- **B-2** **ClientKeyFilter 인증 매트릭스**: 키+`X-Authenticated-User` 有→통과 / 키만→403 / 무헤더→403. (먼저 mcm 보안체인 확인 — 리스크 R1)
- **B-3** mcm 기동 후 **수동 contract 테스트**: Serai가 보낼 JSON을 `curl`로 mcm:8080 `/dmomApi/v1/receive`에 헤더 실어 POST → 200 + (P1 BPMN 있으면) parseData 처리 로그 확인.
- **Pass**: 인증 3케이스 + 디스패치 200/4xx/5xx 일치.

### Phase C — 수신 BPMN 파일럿 작성
- **C-1** P1 수신 BPMN 작성 (`bpmn-skill`/`oasis-project-support` 활용), P2 FORMAT/Interface 시드 — **구체 시드·시나리오는 §7 참조**. 후속 태스크 = **역파싱 데이터 로그 태스크**(§7-3).
- **C-2** mcm 단독 기동 → B-3 재실행하여 **`dmomParseMessageTask`가 BPMN 런타임에서 실제 호출**되고 parseData(Map)가 후속 태스크로 전달되는지 확인 (설계 §11.4 미해결 항목 해소).
- **C-3** `RECEIVE_ACTION("nonui")` ↔ BPMN actionGateway 정합 확인 (§11.6).
- **Pass**: POST→serviceStarter.start(TC)→parse→후속 업무 효과(임시 row/로그) 관측, 200 반환.

### Phase D — 송신 leg 단독 활성 (Serai+Kafka)
- **D-1** localKafka(9092) + serai(8200) 기동 (mssql 프로파일).
- **D-2** 기존 `DmomHttpPilotE2ETest` 활성화(현재 skip) → createMsg(HTTP)→Serai→Kafka 토픽 적재 확인 (Serai 로그 "HTTP 전송 완료"/Kafka offset 증가).
- **Pass**: 1 skip → 1 pass, Kafka에 메시지 도착.

### Phase E — 풀 라운드트립 (전 인프라) — 최종 목표
- **E-1** localKafka + serai + mcm 3종 기동, P3/P4/P5 시드·env 적용.
- **E-2** 송신 트리거: mcm 업무(또는 테스트 훅)로 `createMsg(HTTP, IF=PILOT_RT01, TC=dmomPilotReceive, data=...)`.
- **E-3** **자동 흐름 관측**: Serai INBOUND publish → Kafka → Serai OUTBOUND consume → HttpOutboundHandler가 **HTTP_HEADERS 고정키 실어** mcm `/dmomApi` POST → 인증통과 → BPMN parse → 후속 업무.
- **E-4** **단대단 어서션**:
  - 송신 직렬화 pipe == 수신 parse 입력 (KAFKA_KEYDATA 추적)
  - **수신 BPMN 로그 태스크가 역파싱 Map 출력** → 로그의 ITEM_ID:값 == 송신 data Map (§7-4 기대값과 일치)
  - 양측 TC_ERROR('S'/'R') 미적재
  - 실패 주입 시: mcm 5xx → Serai `failRetryable` 재시도 동작
- **Pass**: 송신 1건 → 수신 1건 처리 + 멱등(중복 재시도 시 KAFKA_KEYDATA로 식별, 선택).
- **게이팅**: 기존 패턴(`@EnabledIf(socket reachable)`)과 동일하게 인프라 미가동 시 auto-skip.

## 4. 검증 매트릭스 (단대단 관측 지점)

| 관측 지점 | 도구 | 성공 신호 |

## 5. 리스크 / 선결 확인

- **R1 mcm 보안체인**: mcm이 cactus default(`.anyRequest().authenticated()` + ClientKeyFilter)인지 portal식 자체 SecurityConfig인지 미확정 → Phase B 전 확인 필요. (다르면 인증 통과 방식 재검토)
- **R2 토픽 consumer 등록**: Serai OUTBOUND 소비는 `TB_MCM_MOM_KAFKA_TOPICS.USE_TP='Y'` + GROUP_ID 필요 → P3 누락 시 consume 안 됨.
- **R3 caravan NEXTVAL**: serai `DataInitializer` 주석의 Tibero `SQ_MCM_MOM_TC_ERROR.NEXTVAL` 잔여 이슈 → 에러적재 경로 테스트 시 벤더 분기 확인.
- **R4 FORMAT_LAYOUT 정합**: 송신 직렬화 포맷 == 수신 파싱 포맷 동일 (TC,IF) 행 — 불일치 시 parse 깨짐.
- **R5 멱등성 미구현**: 재시도 시 중복 처리 가능 (KAFKA_KEYDATA 멱등은 후속/선택).

## 6. 권장 진행 순서

**A → B → C → D → E** (인프라 의존도 오름차순). A/B/C는 인프라 거의 없이 빠르게 그린 만들고, D에서 송신 실측, E에서 라운드트립 마감. R1(mcm 보안체인) 확인은 어느 단계든 먼저 빠르게 수행 권장.

### 빌드/실행 환경 메모
- Gradle 9(serai 등)은 **JVM 17+ 필요**. 시스템 `JAVA_HOME`이 JDK 8을 가리키므로 빌드 시 `JAVA_HOME=C:\Program Files\Java\jdk-21.0.6`(또는 jdk-17) 지정.

## 7. 파일럿 데이터 등록 → 송신 → 역파싱 로그 시나리오 (구체)

> 목적: **DB에 FORMAT/Interface를 실제 등록**하고, 그 포맷대로 한 건을 송신한 뒤, 수신측 BPMN이 **역파싱한 Map을 로그로 출력**하여 라운드트립을 눈으로 확인한다.

### 7-1. FORMAT 조회 모델 (실 스키마, 근거: `DmomMapper.xml:15-31`)

```
TB_MCM_MOM_TC_LIST   (TRANSACTION_CODE → FORMAT_ID, 활성기간)
   └ TB_MCM_MOM_FORMAT_LIST   (FORMAT_ID, FORMAT_VER, 활성기간; TOP1 최신 활성 ver)
        └ TB_MCM_MOM_FORMAT_LAYOUT (FORMAT_ID, FORMAT_VER, ITEM_SEQ, ITEM_TP, ITEM_ID, ITEM_NM, DATA_TP, DATA_LEN, DATA_DECIMAL_PREC)
TB_MCM_MOM_INTERFACES (INTERFACE_ID, TRANSACTION_CODE → SEND_TABLE_ID; DB 송신 경로용)
```
- `DmomFormatRepository.getActiveLayout(TC, IF)` → `getFormatLayout(TC)` 가 위 JOIN 으로 활성 레이아웃 1세트 반환. **송신·수신이 동일 쿼리 재사용** → 포맷 정합 보장.
- ITEM_TP: `E`(단일) / `G`(반복그룹 헤더, DATA_LEN=반복수) / `GE`(그룹 내 항목). DATA_TP: `1`String/`2`Number/`3`Date/`4`String2/`5`Number2.

### 7-2. 파일럿 시드 SQL (MCMAPUSER) — FORMAT/Interface 등록

```sql
-- 파일럿 식별자: TC=dmomPilotReceive, FORMAT=PILOT_FMT01 v1, IF(topic)=PILOT_RT01
-- (1) TC → FORMAT 매핑
INSERT INTO MCMAPUSER.TB_MCM_MOM_TC_LIST (TRANSACTION_CODE, FORMAT_ID, START_ACTIVE_DATE, END_ACTIVE_DATE)
VALUES ('dmomPilotReceive', 'PILOT_FMT01', NULL, NULL);

-- (2) FORMAT 버전(활성)
INSERT INTO MCMAPUSER.TB_MCM_MOM_FORMAT_LIST (FORMAT_ID, FORMAT_VER, START_ACTIVE_DATE, END_ACTIVE_DATE)
VALUES ('PILOT_FMT01', 1, NULL, NULL);

-- (3) FORMAT 레이아웃 — E 항목 3개 (String / Number / Date 혼합)
INSERT INTO MCMAPUSER.TB_MCM_MOM_FORMAT_LAYOUT
  (FORMAT_ID, FORMAT_VER, ITEM_SEQ, ITEM_TP, ITEM_ID, ITEM_NM, DATA_TP, DATA_LEN, DATA_DECIMAL_PREC) VALUES
  ('PILOT_FMT01', 1, 1, 'E', 'PLANT_CD', '공장코드',  '1', 5,  0),
  ('PILOT_FMT01', 1, 2, 'E', 'QTY',      '수량',      '2', 10, 2),
  ('PILOT_FMT01', 1, 3, 'E', 'WORK_DT',  '작업일',    '3', 8,  0);

-- (4) Interface 등록 (DB 송신 경로/검증용; HTTP 송신만 쓸 경우에도 일관성 위해 등록 권장)
INSERT INTO MCMAPUSER.TB_MCM_MOM_INTERFACES (INTERFACE_ID, TRANSACTION_CODE, SEND_TABLE_ID)
VALUES ('PILOT_RT01', 'dmomPilotReceive', 'IF_PILOT_RT01');
```
> ⚠️ 실제 컬럼 전체 명세(NOT NULL/audit/USE 플래그 등)는 시드 전 `INFORMATION_SCHEMA.COLUMNS` 로 재확인. 위 INSERT는 조회에 사용되는 핵심 컬럼 기준. 활성기간 NULL = 무기한 활성(쿼리의 `IS NULL OR ...` 조건 충족).

### 7-3. 수신 BPMN + 역파싱 로그 태스크

- **BPMN**(`mcm/api/.../services/dmom/dmomPilotReceive.bpmn`):
  ```
  Start
   → [Task 1] dmomParseMessageTask.parse(transactionCode, interfaceId, interfaceMsg)  output=parseData
   → [Task 2] dmomPilotLogTask.log(parseData)        ← 역파싱 Map 로그 출력
   → End
  ```
- **로그 태스크 빈**(신규, `dmomParseMessageTask` 와 동일한 빈+method 패턴 — OASIS Wow DI 불가):
  ```java
  // cactus-core(or mcm) : @Bean("dmomPilotLogTask")
  public class DmomPilotLogTask {
      private static final Logger log = LoggerFactory.getLogger(DmomPilotLogTask.class);
      public void log(Map<String, Object> parseData) {
          log.info("[DMOM 파일럿 수신] 역파싱 결과 {}건: {}", parseData.size(), parseData);
      }
  }
  ```
  - BPMN: `camunda:class="dmomPilotLogTask"` `method=log`, 인자 `parseData` 는 Task1 output(context key)에서 바인딩.
  - 파일럿 한정 빈이므로 mcm api 측 `@Configuration` 에 등록(또는 cactus-core 에 `@ConditionalOnProperty` 가드).

### 7-4. 기대 라운드트립 (송신 data → pipe → 역파싱 Map)

| 단계 | 값(예시) |
|---|---|
| 송신 호출 | `createMsg(HTTP, IF=PILOT_RT01, TC=dmomPilotReceive, data={PLANT_CD:"5A", QTY:"123.45", WORK_DT:"20260602"})` |
| 직렬화 pipe(`MessageSerializer`) | `5A\|<QTY 인코딩>\|20260602\|` — Number(DATA_TP 2)는 정수·소수부 zero-pad(소수점 없음) 규칙 적용 → **정확 바이트는 A-1 round-trip 테스트로 고정** |
| 수신 역파싱(`MessageParser`) | `{PLANT_CD=5A, QTY=123.45, WORK_DT=20260602}` (DATA_TP 2: prec>0·소수점없음 → `÷10^2`, DATA_TP 3: 날짜추출) |
| 로그 출력 | `[DMOM 파일럿 수신] 역파싱 결과 3건: {PLANT_CD=5A, QTY=123.45, WORK_DT=20260602}` |

- **검증 포인트**: 로그에 찍힌 `ITEM_ID:값` 이 송신 data Map 과 동등(Number 정밀도/Date 포맷 규칙 반영). 불일치 시 R4(FORMAT 정합) 또는 직렬화/역직렬화 비대칭 의심.
- **사전 게이트**: 7-2 시드 + §2 P3/P4/P5(토픽·OUTBOUND config·env) 적용 후 Phase E 흐름으로 자동 도달.
