## 4. 핵심 컴포넌트 상세

### 4.1 `DmomReceiveController`
```java
@ResponseBody
@RequestMapping("/dmomApi/v1")
public class DmomReceiveController {
    private final DmomReceiveDispatcher dispatcher;
    public DmomReceiveController(DmomReceiveDispatcher dispatcher) { this.dispatcher = dispatcher; }

    @PostMapping("/receive")
    public DmomReceiveResponse receive(@RequestBody DmomReceiveRequest req) {
        validate(req);                 // TC/IF/MSG 필수 — 누락 시 400
        dispatcher.dispatch(req);      // 실패 시 예외 → 5xx (Serai 재시도)
        return DmomReceiveResponse.success(req);   // 성공 → 200
    }
}
```
- ✅ **실패 → HTTP 5xx (확인 완료, 별도 처리 불요)**: `DmomException`(RuntimeException) 전파 시 `GlobalExceptionHandler`(@RestControllerAdvice) 의 `@ExceptionHandler(Exception.class)` → **HTTP 500** + 에러 body. → Serai 가 non-2xx 로 재시도(`failRetryable`). (당초 "200 으로 감쌀 수 있다" 우려는 소스 확인 결과 사실 아님 — 200 wrapping 안 함.)
- `@Controller` 안 붙임(cactus 컨벤션). autoconfig `@Bean` 등록(§7).

### 4.2 `DmomReceiveDispatcher` (백엔드 OASIS 기동, R4/R5)
```java
public class DmomReceiveDispatcher {
    private static final String RECEIVE_ACTION = "nonui";   // 레거시 DEFAULT_GROUP_NONUI 대응
    private final ServiceStarter serviceStarter;
    private final ApplicationContext springApplicationContext;

    public void dispatch(DmomReceiveRequest req) {
        String serviceId = req.transactionCode();           // R4: serviceId = TC
        Map<String, TypedObject> inputs = new HashMap<>();
        inputs.put("action", new TypedObject(RECEIVE_ACTION));
        inputs.put("transactionCode", new TypedObject(req.transactionCode()));
        inputs.put("interfaceId", new TypedObject(req.interfaceId()));
        inputs.put("interfaceMsg", new TypedObject(req.interfaceMsg()));   // raw (파싱은 BPMN 첫 태스크)
        if (req.kafkaKeyData() != null) inputs.put("kafkaKeyData", new TypedObject(req.kafkaKeyData()));

        CactusAudit audit = new CactusAudit("SYSTEM", "DMOM_RECV", serviceId);   // 시스템 audit (R5)
        AuditHolder.setAudit(audit);
        try {
            com.dongkuk.oasis.context.ApplicationContext oasisCtx =
                    new CactusUnwrappingApplicationContext(springApplicationContext);
            DefaultServiceContext sc = new DefaultServiceContext(oasisCtx, inputs);
            sc.setAudit(audit);
            ServiceResult result = serviceStarter.start(serviceId, sc);    // 웹 미경유 직접 기동
            // ★ ServiceResult 는 record 스타일 접근자(get 없음): serviceResultCode()/serviceResultMessage()
            if (result.serviceResultCode() != ServiceResultCode.SUCCESS) {
                throw new DmomException("수신 서비스 실패 TC=" + serviceId
                        + " code=" + result.serviceResultCode()
                        + " msg=" + result.serviceResultMessage());
            }
        } finally {
            AuditHolder.remove();
        }
    }
}
```
- 트랜잭션: `serviceStarter.start` 가 OASIS Spring tx(`transactional:true`) 안에서 실행 → 커밋/롤백 자동. 수신 BPMN 이 `createMsg` 호출 시 송신 버퍼/afterCommit 동일 적용(송수신 대칭).
- `OasisServiceExecutor` 와 동일 패턴(웹 진입만 다름). 향후 공통 추출 가능.

### 4.3 `DmomParseMessageTask` (BPMN 첫 태스크, 빈+method — R6)
```java
public class DmomParseMessageTask {
    private final DmomFormatRepository formatRepository;
    private final MessageParser parser;

    /** BPMN method-style 진입점. inputs(TC/IF/raw)로 역파싱 → Map(ITEM_ID 키). task output 으로 적재됨. */
    public Map<String, Object> parse(String transactionCode, String interfaceId, String interfaceMsg) {
        FormatLayout layout = formatRepository.getActiveLayout(transactionCode, interfaceId);
        if (layout.isEmpty()) {
            throw new DmomException("FORMAT_LAYOUT 없음: TC=" + transactionCode + ", IF=" + interfaceId);
        }
        return parser.parse(layout, interfaceMsg);
    }
}
```
- 빈명 `dmomParseMessageTask`. BPMN: `camunda:class="dmomParseMessageTask"` + `method=parse` + `output=parseData`(컨텍스트 키). 메서드 인자(transactionCode/interfaceId/interfaceMsg)는 서비스 context inputs 에서 바인딩(StrictMethodInvoker, `-parameters`).
- **Wow 아님**(OASIS `newInstance` → DI 불가; 송신 `DmomMessageTask` 와 동일 패턴). AS-IS `DMomParseMessageTask`(Wow, `MOM_PARSE_DATA` 출력)와 위치 동일.

### 4.4 `MessageParser` (pipe→Map, `MessageSerializer` 의 역)
```java
public class MessageParser {
    private static final String SEP = "\\|";
    public Map<String, Object> parse(FormatLayout layout, String interfaceMsg) {
        String[] tokens = (interfaceMsg == null ? "" : interfaceMsg).split(SEP, -1);  // 빈 토큰 보존
        Map<String, Object> result = new LinkedHashMap<>();
        int ti = 0;                          // 토큰 인덱스
        List<FormatItem> items = layout.items();
        int i = 0;
        while (i < items.size()) {
            FormatItem it = items.get(i);
            switch (it.itemTp()) {
                case "E"  -> { result.put(it.itemId(), convert(it, token(tokens, ti))); ti++; i++; }
                case "G"  -> { int[] r = parseGroup(result, items, i, tokens, ti); i = r[0]; ti = r[1]; }
                case "GE" -> { ti++; i++; }   // orphan (정상 포맷 미발생)
                default   -> i++;
            }
        }
        return result;
    }
    // parseGroup: G.dataLen=반복수, 후속 GE 묶음을 반복수만큼 토큰 소비 → List<Map>(ITEM_ID 키) → result.put(groupId, list)
    // token(tokens, ti): 범위 밖이면 "" (전문이 짧을 때)
    // convert: getMsgFromRecvFormat 역변환 (아래 §5)
}
```
- E/G/GE 매핑·그룹 반복 = `DMomParseMessage.msgParsing` 이식(단 TC/IF 추출 불요 — 인자로 받음).

## 5. 역변환 규칙 (`getMsgFromRecvFormat` 이식 — 송신 직렬화의 역)

| DATA_TP | 송신(직렬화) | **수신(역변환)** |
|---|---|---|
| 1 String | 값 그대로 | `trim()` |
| 2 Number | 정수부+소수부 zero-pad(소수점없음) | `trim` 후: `prec>0 && '.'없음` → `new BigDecimal(token).divide(10^prec, prec, ROUND_UP).toString()` / 그 외 비어있지 않으면 `new BigDecimal(token).toString()`(앞 0 제거) |
| 3 Date | 숫자추출+0패딩+절단 | `"1900" < token < "9999"`(문자열비교)면 `-,/,:,공백,.` 제거 후 `substring(0,DataLen)`, 아니면 `""` |
| 4 String2 | trim | ※ 레거시 미구현(빈값) → **신규는 `trim()` 보강** |
| 5 Number2 | 값 그대로 | `trim` 후 비어있지 않으면 `new BigDecimal(token).toString()` |
- null/공백 토큰 처리·정확한 라운딩은 레거시 `getMsgFromRecvFormat` 와 동등성 단위테스트로 고정(§10).
- 송신 `MessageSerializer` ↔ 수신 `MessageParser` **왕복(round-trip) 테스트** 권장(serialize→parse 후 값 보존 확인, 단 Number 패딩/정밀도 손실 케이스 주의).

## 8. 응답·트랜잭션·에러·기타
- **성공**: 수신 서비스 커밋 성공 → HTTP **200** `{resultCode:SUCCESS}`.
- **실패**: `ServiceResult` 에러/예외 → OASIS rollback → `DmomException` 전파 → `GlobalExceptionHandler` → **HTTP 500**(`Exception`) + `DmomErrorLogger.log(..., 'R')`(TC_ERROR) → Serai 재시도. (`BusinessException` 은 `errorCode.getHttpStatus()` — 4xx 가능)
  - ⚠️ 참고: Serai 는 **모든 non-2xx 를 재시도**. 영구성 업무거절(4xx)도 재시도됨 → 무한 재시도 회피가 필요하면 "비재시도 업무오류 → TC_ERROR 적재 후 2xx" 정책을 후속 검토(기본은 모든 실패 non-2xx).
- **TC_SKIP**(선택): 디스패치 전 `getTcSkipLevel(TC)` —
  - `'Y'`(SKIP1): 서비스 미실행 + 200. `'T'`(SKIP2): 200 + 서비스 실행.
- **멱등성**: `KAFKA_KEYDATA` 로 중복 수신(재시도) 식별 가능 → 처리이력 테이블/유니크 검사로 멱등(후속, 선택).
- 🔐 **인증/보안 (확정: 고정키 = cactus BFF 신뢰 채널 재사용)**:
  - **배경 제약**: cactus 기본 `SecurityFilterChain`(`CactusWebSecurityAutoConfiguration`)은 `/auth/**`·`/actuator/health` 만 permitAll, 나머지는 **`.anyRequest().authenticated()`**. → `/dmomApi/v1/receive` 도 인증 필요. Serai 가 인증 헤더 없이 POST 하면 **401/403 → non-2xx 무한 재시도**.
  - **확정 방식 = permitAll 구멍을 내지 않고**, Serai 가 **Next.js BFF 와 동일한 고정키 헤더**를 실어 보내 `ClientKeyFilter` 로 통과 → 보안 체인 **무변경**:
    - `X-Client-Key`: 공유 시크릿. BE 는 `BACKEND_CLIENT_KEY` env(1순위) > `cactus.security.client-key`(yml) 로 검증(`ClientKeyFilter`).
    - `X-Authenticated-User`: **필수**. `ClientKeyFilter` 는 키만 맞아선 통과시키지 않고, 이 헤더가 있어야 SecurityContext 사전 인증을 set 함(`ClientKeyFilter.java:130-136`). 없으면 익명 → `.anyRequest().authenticated()` 에서 **403**. 값 예: `SERAI`.
    - `X-Authenticated-Role`(선택): 후속 RBAC 필요 시. 예: `SYSTEM`.
  - `/dmomApi` 는 `ClientKeyFilter` 기본 skip 경로(`/auth/`,`/api/auth/`,`/actuator/`)에 없으므로 키 검증을 정상 수신. **cactus·모듈은 `BACKEND_CLIENT_KEY`(또는 `cactus.security.client-key`) 설정만** 하면 됨(보안 체인/스킵경로 변경 불요).
  - ⚙️ **Serai 측 전제 변경 (별도 모듈 — 본 설계에서 요건만 명시, 구현은 Serai 작업)**: 현재 `HttpOutboundHandler.sendHttpRequest`(`L106-160`)는 `Content-Type`/`Accept` 만 하드코딩, OUTBOUND config 의 헤더를 안 읽음 → **목적지별 옵셔널 헤더** 전송 기능 추가 필요:
    1. **DDL**: `ALTER TABLE TB_MCM_MOM_KAFKA_SERAI_CONFIG ADD HTTP_HEADERS NVARCHAR(MAX) NULL` — JSON object. **NULL 이면 현재 동작(헤더 0개)** → 비-cactus 외부시스템 행은 비워둠 ⇒ 완전 옵셔널·목적지별.
    2. **Mapper**: `SeraiConfigMapper.xml` 의 `selectOutboundConfig` SELECT 목록에 `HTTP_HEADERS` 추가.
    3. **Handler**: `HttpOutboundHandler` 가 `config.get("HTTP_HEADERS")` 가 non-blank 면 JSON→`Map<String,String>` 파싱 후 `connection.setRequestProperty(k, resolveEnv(v))`. `resolveEnv` 가 `${ENV}` 를 `System.getenv` 로 치환 → **실 시크릿은 DB 가 아니라 Serai 환경변수**에 보관.
    - cactus 대상 행 예시 값:
      ```json
      {"X-Client-Key":"${BACKEND_CLIENT_KEY}","X-Authenticated-User":"SERAI","X-Authenticated-Role":"SYSTEM"}
      ```
    - 이 헤더 기능은 dmom 전용이 아니라 **모든 cactus 대상에 재사용되는 범용 기능**. `DataInitializer` 시드 행이 있으면 신규 컬럼 반영 필요.
  - **대안(채택 안 함)**: ⓐ 수신경로 permitAll + 네트워크 격리만(보안 약함, cactus 보안설정 변경 필요), ⓑ `serai.outbound.http.client-key` 전역 + 행별 `AUTH_ENABLED` 플래그(단일 키 강제, 유연성 ↓). → **행단위 `HTTP_HEADERS` + env 치환** 채택.
- **감사**: 수신 서비스의 DB 쓰기는 시스템 audit(SYSTEM) 로 C_*/U_* 채움(디스패처가 AuditHolder 세팅).

## 9. 시퀀스 상세
```
Serai consume → OUTBOUND HTTP config → POST {JSON}
  (헤더: Content-Type=json + X-Client-Key, X-Authenticated-User[, X-Authenticated-Role]  ← config HTTP_HEADERS)
  → [Security] ClientKeyFilter 키검증+pre-auth set → JwtFilter 스킵 → authenticated 통과
  → DmomReceiveController.receive(req)
      → (TC_SKIP 체크 — 선택)
      → DmomReceiveDispatcher.dispatch(req)
          inputs{action=nonui, TC, IF, interfaceMsg(raw), KAFKA_KEYDATA} + 시스템 audit
          → serviceStarter.start(TC, DefaultServiceContext)
              → [BPMN TC] 첫 태스크 dmomParseMessageTask.parse(TC,IF,raw)
                    → DmomFormatRepository.getActiveLayout + MessageParser.parse → Map → output=parseData
              → 후속 태스크: parseData(ITEM_ID Map)로 업무 처리 (+필요시 createMsg 송신)
          → 커밋
      → ServiceResult SUCCESS → 200 / 에러 → 5xx + TC_ERROR('R')
```

## 11. 미해결 / 구현 전 확인
1. ✅ **실패 시 5xx — 확인 완료**: `GlobalExceptionHandler` 는 `Exception→500`, `BusinessException→errorCode.getHttpStatus()` 반환(200 wrapping 안 함). `DmomException`(RuntimeException)→500 → Serai 재시도 정상. **별도 핸들러 불요.** (잔여: 영구 업무오류의 무한 재시도 회피 정책만 후속 — §8 참고)

3. **OUTBOUND HTTP config** — 수신 토픽에 `DIRECTION=OUTBOUND, INTEGRATION_TYPE=HTTP, HTTP_URL=<MES>/dmomApi/v1/receive` 행 추가(파일럿). **+ `HTTP_HEADERS` 에 고정키 헤더 JSON**(§8: `X-Client-Key=${BACKEND_CLIENT_KEY}`, `X-Authenticated-User=SERAI`[, `X-Authenticated-Role=SYSTEM`]).
4. `dmomParseMessageTask` 의 BPMN 인자 바인딩(메서드 파라미터 ↔ context inputs) 실 BPMN 검증(파일럿).

6. RECEIVE_ACTION("nonui") 이 수신 BPMN actionGateway 와 정합하는지(또는 게이트 없음).
