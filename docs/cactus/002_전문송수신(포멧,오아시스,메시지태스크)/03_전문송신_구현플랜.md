## 0. 확정 입력 (사용자 결정)

| 항목 | 값 |
|---|---|
| GRANT | **MCMAPUSER → EAIUSER 테이블 INSERT 부여 완료** |
| 파일럿 인터페이스 | **`MMQCMMCMTT01`** (`EAIUSER.IF_MMQCMMCMTT01` 생성됨) |
| 파일럿 | 신규 개발 (구현 완료 후), 샘플 포맷 마스터데이터도 그때 1건 |
| OASIS 모듈 | **MCM, MPP, MLS, MQC** |
| KEY_DATA1/2/3 | 미사용 / IF_SEQ=DB채번 / IF_DATE·IF_TIME=Serai |

## 0-1. 검증으로 확정된 사실 (재확인 불요)

- DB 방식 = **`createMsg` 즉시 in-tx INSERT** (beforeCommit 동기화 아님). HTTP = 버퍼+`afterCommit`.
- mcm `cactus.oasis.transactional: true` + `primary-alias: biz` + `tx.default-manager: txBiz`(=biz=MCMAPUSER). 기본 서비스 업무tx = `sqlSessionTemplateBiz` DataSource 일치 → **DB 즉시 INSERT 원자성 성립** (pilotDefaultTx 문서 근거).
- 매퍼 경로 = `persistence/dmom/DmomMapper.xml` (mapper-locations 기본 `classpath*:persistence/**/*.xml`).
- `getFormatLayout` 은 **MSSQL JOIN + `TOP 1 ORDER BY FORMAT_VER DESC`** (Oracle tuple 비교 미지원 → 수정 완료).
- `IF_MMQCMMCMTT01` INSERT 컬럼: `TRANSACTION_CODE/INTERFACE_ID/INTERFACE_MSG/IF_FLAG('N')/audit/VER(0)`. (KEY_DATA·IF_SEQ·IF_DATE·IF_TIME 제외)
- AuditHolder 는 `CoreServiceStarter` 가 `execute()`(commitAll 포함) 전체를 감싸 set/remove → 커밋/afterCommit 시점 유효.

## 0-2. 한계 (설계상 인지 — 파일럿 영향 없음)

- DB transport 는 업무 tx 가 **biz(txBiz 기본)** 일 때만 원자적. biz 외 tx 전용 서비스는 비대상.
- **병렬 실행 태스크에서 createMsg 금지**(활성 tx 없음 → fail-fast).
- 멀티 tx 부분커밋 시 HTTP afterCommit 누락/중간커밋 엣지케이스(문서화). 파일럿=단일 biz tx.

## Phase 3 — createMsg 통합 + AutoConfiguration

- `DefaultDmomMessageService.createMsg`: 활성tx검증(`isActualTransactionActive`)→포맷조회→직렬화→**switch(DB:즉시INSERT / HTTP:버퍼+sync등록)**→String 반환
- `DmomAutoConfiguration`: 빈 등록, `biz-template`/`error-tx-manager` 프로퍼티 해석, `@ConditionalOnBean(SeraiIntegrationClient)`(HTTP), `AutoConfiguration.imports`
- **테스트(비-OASIS)**: `@Transactional` 서비스 → createMsg → 커밋 → HTTP send / DB insert E2E. 활성tx 없을 때 fail-fast. 롤백 시 DB INSERT·HTTP 미전송.

**Exit**: ✅ **완료** — `message/{DmomMessageService,DefaultDmomMessageService}` + `DmomAutoConfiguration`(+ AutoConfiguration.imports 등록). `DefaultDmomMessageServiceTest`(5)가 **실제 트랜잭션 동기화**(StubTxManager) 로 커밋 후 afterCommit 발동·DB 즉시 in-tx INSERT·롤백 시 미전송·활성tx 없으면 fail-fast 검증. `DmomAutoConfigurationTest`(3) 빈 와이어링+Serai 조건. 누적 dmom **47 PASS**. (남은 갭: 실DB SQL=Phase5, OASIS 멀티tx=Phase4)

## Phase 4 — OASIS 연동

- `DmomCreateMessageTask`(`Wow`) — 선언적 재사용 태스크(`camunda:class="dmomCreateMessageTask"` + properties: transactionCode/interfaceId/transport/paramKey)
- 업무 서비스 빈 직접 주입 방식도 지원(권장)
- MCM/MPP/MLS/MQC `cactus.oasis.transactional: true` 확인
- **테스트(OASIS)**: transactional BPMN(단일 biz tx) → createMsg → 커밋 후 HTTP 송신 / DB 원자 INSERT, 감사 컬럼 채움.

**Exit**: ✅ **완료** — `task/DmomMessageTask`(Spring 빈+method, DmomMessageService 주입) + DmomAutoConfiguration 빈 등록("dmomMessageTask"). **정정**: 초기 설계의 `Wow` 방식은 OASIS가 `newInstance()`로 생성해 DI 불가 → 빈+method 스타일로 변경(검증). `DmomMessageTaskTest`(4) PASS. 누적 dmom **51 PASS**. 권장 1순위는 업무 서비스 빈 직접 주입(§9.2). 실제 BPMN 바인딩은 Phase 5 검증.

## Phase 5 — 파일럿 (`MMQCMMCMTT01`) + 샘플 데이터 + 시나리오

- **선행**: 파일럿 업무 tx USER 가 MCMAPUSER(=biz)인지 확인 (GRANT 정합). **mcm 호스팅 권장**.
- 샘플 포맷 마스터데이터 INSERT: `TB_MCM_MOM_TC_LIST` / `FORMAT_LIST` / `FORMAT_LAYOUT` / `INTERFACES` (MMQCMMCMTT01용 1건)
- 파일럿 BPMN 서비스(+필요 시 화면) 신규 개발 — HTTP·DB 양 채널
- **테스트 시나리오** 작성·실행 → HTTP: Serai `/seraiApi/v1/send`→Kafka 도달 / DB: `IF_MMQCMMCMTT01` 적재→Serai 폴러→Kafka. 후속 태스크 실패 시 DB INSERT 롤백(원자성) 확인.

**Exit**: 실DB 파일럿 양 채널 송신·원자성·에러로그 검증.

### Phase 5 진행 현황
> **정정(2026-05-30)**: 로컬 Serai 는 **MSSQL 에 연결**돼 있음(SQLite 아님 — `application-local.yml` 만 보고 오판했던 것). 설정 테이블 `SERAIUSER.TB_MCM_MOM_KAFKA_SERAI_CONFIG` 가 MSSQL 에 있고, DB-inbound 로 `EAIUSER.IF_*` 폴링(1초). 단 **`MMQCMMCMTT01` 은 inbound 미설정** — 설정된 인터페이스는 `MMQCMMLSPP01`/`MMPPMMLSPP01`/`MMQCMMPNTT01` 등.

- ✅ **HTTP 채널 E2E (실 dmom 코드)**: `DmomHttpPilotE2ETest`(@EnabledIf Serai 도달 시) — `createMsg(HTTP)`→afterCommit→실 `DefaultSeraiIntegrationClient`→`localhost:8200/seraiApi/v1/send`→Serai→Kafka. 직렬화 `hello|42|` 전송·SUCCESS 확인(실 HTTP 3.87s). format 조회 mock 격리.
- ✅ **DB 채널 (실 MSSQL + Serai 폴러 → Kafka)**: `insertIfOutbound` 매퍼와 **동일 컬럼 셋**을 실 `EAIUSER.IF_MMQCMMLSPP01` 에 INSERT(IF_FLAG='N') → 6초 후 Serai 폴러 처리(`IF_FLAG=Y`, `IF_DATE`, `U_SVC_ID=serai`) → Kafka 발행 확인. **매퍼 SQL ↔ 실 테이블 정합 + DB-channel E2E 실증**(설정 인터페이스 MMQCMMLSPP01 사용). sqlcmd 직접 실행(cactus-core 테스트엔 mssql 드라이버 없음).
- ⏳ 미실행: `DmomDbOutboundWriter` Java 객체를 실 MSSQL 템플릿으로 호출하는 JDBC 통합테스트(SQL 은 위에서 실증됨, Java 로직은 mock 단위테스트로 검증 — 한계적 가치), 샘플 포맷 마스터데이터로 `createMsg(DB)` 풀패스(getFormatLayout 포함), 신규 BPMN(camunda:class 바인딩), 후속태스크 실패 롤백 원자성.
