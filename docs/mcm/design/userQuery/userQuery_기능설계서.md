# userQuery 기능설계서 (맞춤 레포트 조회)

- 날짜: 2026-10-10
- 작성 방식: 구현 후 사후 작성(스펙 D1 면제 후속)
- 스펙: `docs/superpowers/specs/2026-10-10-user-query-program-design.md`

## 1. 화면 식별

| 항목 | 값 |
|---|---|
| screenId = objId = serviceId | `userQuery` |
| componentPath | `cmq/userQuery` |
| 메뉴 | 공통관리 > 맞춤 레포트 > 맞춤 레포트 조회(폴더 `cmq`, FULL_SEQ 1070100) |
| 화면 제목 | 맞춤 레포트 조회 |
| 권한 세트 | `PERM_USRQ_USE`, PERMISSION_ACTION `myList,getDef,run` |
| 기본 권한 | SYSADMIN × PERM_ALL. 일반 역할은 운영자가 매핑한다 |

## 2. 버튼

| id | 라벨 | action | 동작 | 비활성 조건 |
|---|---|---|---|---|
| `btn_search` | 조회(F8) | `run` | 필수 값을 확인하고 `run` 을 호출한다 | 정의 로딩 중, 실행 중, 쿼리 미선택 |

- 엑셀은 상단 버튼이 없다. 결과 그리드 설정 메뉴의 「엑셀 출력」을 쓴다. 이 메뉴에는 「칸별 필터 보기」와 「엑셀 출력」만 있다(개인화와 열 초기화는 끈다). 받은 행과 보이는 열을 그대로 내보낸다.
- 파일 이름은 `{쿼리 이름}_{yyyyMMdd}.xlsx` 이다. 이름이 없으면 「쿼리」를 쓴다. 잘렸으면 같은 안내를 note 로 넣는다.

## 3. 영역

| 영역 | 내용 |
|---|---|
| 왼쪽 | 폭 20%, 경계를 끌어 조절(`split-sizing` 이 사용자별로 기억). 조회조건과 목록을 세로로 쌓는다 |
| 왼쪽 조회조건(N3 Form) | `SearchArea`. 분류 select(`USRQ_CTG`, 「전체」 포함), 이름 text(쿼리 이름 또는 쿼리 ID 부분 일치, 대소문자와 앞뒤 공백 무시, 설명은 보지 않는다), [조회]·Enter. 서버 조건은 없다 |
| 왼쪽 목록(N3 Grid) | `GridPanel` 「쿼리 목록」 + `AgDataGrid`. 열은 이름·분류·쿼리 ID. 분류는 이름으로 보인다(없으면 「미분류」, 이름을 모르는 코드는 코드 그대로). 행을 누르면 그 쿼리를 고른다 |
| 오른쪽 조건 | `getDef` 의 `params` 마다 칸 하나(text, number, date, select). 입력 정의가 없으면 조건 영역을 그리지 않는다 |
| 오른쪽 설명 | 쿼리 설명이 있으면 한 줄로 보인다 |
| 오른쪽 결과(N4·N5) | 그리드. 제목은 쿼리 이름, 건수 표시. 설정 메뉴는 「칸별 필터 보기」와 「엑셀 출력」뿐 |

## 4. 상태와 문구

| 상태 | 조건 | 표시 |
|---|---|---|
| 목록 빔 | `myList` 0건 | 「할당된 쿼리가 없습니다. 관리자에게 요청하세요」 |
| 목록 로딩 | 진입 직후, [조회] 중 | 목록 그리드 loading |
| 거르기 결과 없음 | 거르기 후 0건 | 그리드 기본 빈 문구 |
| 미선택 | queryId 없음 | 「왼쪽에서 쿼리를 고르세요」 |
| 정의 로딩 | `getDef` 진행 | 「불러오는 중입니다」 |
| 정의 오류 | `getDef` 실패 | 서버 문구를 본문과 오류 창에 보인다 |
| 조회 대기 | 정의 도착, 결과 없음 | 출력 열이 있으면 0행 빈 그리드에 빈 문구 「조건을 확인하고 조회하세요」. 출력 열이 없으면 본문 안내로 같은 문구 |
| 필수 값 누락 | 필수 값이 빔 | 「조건을 입력하고 조회하세요」(빈 그리드 문구 또는 본문 안내). 서버를 부르지 않는다 |
| 실행 중 | `run` 진행 | 그리드 loading, 대기 중에는 「조회 중입니다」 |
| 결과 | 행 있음 | 그리드. 잘렸으면 「상위 N행만 표시합니다」 |
| 결과 없음 | 0건 | 「표시할 데이터가 없습니다」 |

## 5. 동작 규칙

- 진입하면 `SearchArea autoSearch` 가 `myList` 를 한 번 부른다. 오른쪽 결과는 자동 조회하지 않는다.
- 왼쪽 [조회]·Enter 는 `myList` 를 다시 받아, 지금 입력한 분류·이름으로 화면 안에서 거른다(client-side). 같은 목록이면 state 를 바꾸지 않는다.
- 조건을 입력하는 동안에는 목록 그리드와 오른쪽 화면을 다시 그리지 않는다(조건 state 는 조회조건 컴포넌트 안에만 둔다).
- 고른 쿼리가 거르기에서 빠져도 선택은 그대로 둔다. 오른쪽 화면이 초기화되지 않는다.
- 쿼리를 고르면 `getDef` 를 부르고, 조건을 기본값(`initialValues`)으로 되돌리고, 이전 결과 행을 비운다.
- `getDef.columns`(출력 열)가 있으면 정의가 도착하는 즉시 그 열로 0행 빈 그리드를 그린다. 조회하면 같은 열 정의 그대로 행만 채운다(그리드를 다시 마운트하지 않는다).
- 출력 열이 없는 쿼리는 열을 알 수 없으므로 조회 뒤 결과 열로 그린다. 조회 전에는 본문 안내 문구를 보인다.
- 마지막으로 고른 queryId 가 목록에 아직 있으면 진입 때 그것을 고른다. 없으면 고르지 않는다.
- 늦게 온 응답이 다른 쿼리 화면을 덮지 않게 epoch 번호로 버린다.
- 조건 기본값 저장은 끈다(`SearchArea defaults={false}`). 쿼리마다 칸이 달라 값이 엉뚱한 칸에 들어가기 때문이다.

## 6. 검증과 오류 문구

| 구분 | 내용 |
|---|---|
| 필수 값 | 화면이 `planRun` 으로 확인한다. 비면 호출하지 않고 위 문구를 보인다 |
| 값 해석 | 서버가 선언된 입력 정의로 형별 해석한다. 화면은 글자만 보낸다 |
| 미할당, 사용 중지, 정의 없음 | 「쿼리를 찾을 수 없습니다」(같은 문구) |
| SQL, 정의 오류 | 「쿼리 정의에 오류가 있습니다. 관리자에게 문의하세요」 |
| DB 오류, 시간 초과 | 「조회하지 못했습니다. 관리자에게 문의하세요」 |
| 호출 빈도 초과 | 「잠시 후 다시 조회하세요」(사용자당 1분 20회) |
| 표시 방식 | 서버 문구를 그대로 오류 창(`showMessage`, error)에 보인다. 실행 실패 때는 그리드를 두고 행만 비운다 |

## 7. 부수 효과

| 대상 | 내용 |
|---|---|
| localStorage `mcm.cmq.userQuery.lastQueryId` | 쿼리를 고를 때 저장. try/catch 로 감싸 실패해도 동작한다 |
| localStorage `split-sizing`(storageKey `mcm.cmq.userQuery`) | 목록 폭 |
| DB | 쓰기 없음. 실행 기록용 표도 없다 |
| 서버 로그(N6) | `run` 이 성공하면 `UserQueryService` 가 INFO 로 두 줄을 남긴다. 첫 줄은 요약 「맞춤 레포트 실행 queryId= userId= rows= truncated= ms= params=」. 둘째 줄은 같은 logger 의 SQL 본문이고 줄바꿈을 그대로 둔다. 로그 뷰어에서 본다 |
| 실패 로그 | 실패는 지금처럼 WARN 이다. 응답과 예외 문구는 바뀌지 않는다 |

## 8. 보안 점검

| 점검 | 구현 |
|---|---|
| 사용자 ID | 보내지 않는다. 서버가 인증 컨텍스트에서 얻는다 |
| SQL | 받지도 보내지도 않는다. 요청은 queryId 와 `paramsJson` 만 싣는다 |
| 응답 | `getDef` 에 SQL 이 없다 |
| 권한 | 메뉴 OBJECT 권한으로 판정한다. AUTH_ONLY 에 넣지 않는다 |
