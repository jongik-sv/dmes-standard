# 세션 완수 정책 (단일 진실 원천)

> 본 문서는 산출물 생성 스킬(`generate-bpa`, `generate-process-group`, `define-process-groups`, `analyze-service`)이 한 세션 안에서 약속된 산출물을 완수하도록 강제하는 공통 정책이다.
> 변경 시 본 문서만 수정하고 각 스킬은 본 문서를 참조하도록 유지한다.

---

## 0. 배경

Claude Opus 4.7 부터 **입력 컨텍스트 1M** 으로 확장되었다. 한 세션(대화) 안에서 모든 화면 분석본·SP·테이블·트리거 DDL·이전 BPA 를 동시에 메모리에 유지한 채 turn 을 여러 번 돌릴 수 있다. 이전 32k/200k 컨텍스트 시대의 "분량 부족 → 다음 세션으로 미루기" 휴리스틱은 **더 이상 정당화되지 않는다**.

다만 **단일 응답(turn)의 출력 토큰 한도** 는 컨텍스트 확장과 무관하게 ~32k 로 고정이다. 한 응답에 다 못 담는다고 해서 "다음 세션" 으로 미루는 것이 아니라, **같은 세션 내에서 turn 을 추가로 사용** 해 이어 쓴다.

---

## 1. 절대 금지

다음 패턴은 산출물 본문/메타 어디에도 등장해서는 안 된다.

| 금지 패턴 | 이유 | 대체 행동 |
|---|---|---|
| "다음 세션 심화 예정" / "다음 세션 산출" / "다음 세션 분석" | 1M 컨텍스트에선 같은 세션에서 완수 가능 | 같은 세션 내 추가 turn 으로 즉시 작성 |
| "약식 분석본" / "약식 BPA" / 일부 §만 채움 | 약식은 BPA + Legacy 와 사실상 같아 통합 시각 가치 0 | 모든 § 와 §A Appendix 까지 완전 채움 |
| "BPMN 다음 세션 산출 예정" | 스킬 명세상 MD 와 BPMN 은 항상 세트 | 같은 세션 내 BPMN 도 동시 산출 |
| "(schema 분석 다음 세션 — `DBMS/tables/...md`)" 형태의 미래 약속 | 미작성 산출물은 약속이 아닌 누락 | (a) 같은 세션에서 `/analyze-table-schema` 등 명시 호출로 작성 또는 (b) "본 화면 범위 외 — 후속 확장 필요" 로 정직하게 명시 |

> **예외**: 본 화면/PG 의 책임 범위를 명백히 벗어난 항목 (다른 모듈 화면, 다른 PG 의 BPMN, 본 분석 범위 외 SP) 은 "본 분석 범위 외 — 후속 확장 가능" 으로 명시할 수 있다. 이때도 "다음 세션" 이라는 시간 약속은 쓰지 않는다.

---

## 2. 한 응답 토큰 한도 초과 시 행동

산출물이 한 응답에 다 안 들어가면:

1. **turn 을 분할해서 같은 세션 안에서 이어 쓴다.** 사용자에게 "다음 응답에서 §A1~A5 이어 작성한다" 정도만 짧게 고지하고 계속 진행. 사용자 추가 입력을 기다리지 않는다.
2. **분할 단위는 §(섹션) 또는 파일 경계** 를 권장. 한 § 중간에서 자르지 말 것.
3. **파일은 turn 마다 1개씩** 완전히 마무리 (Write/Edit 1회 = 1 파일 완성). 여러 turn 에 걸쳐 같은 파일을 부분 작성하지 말 것 (Edit 누적은 비효율).
4. **모든 파일이 완성된 후** 사용자에게 "산출 완료: N 파일" 보고.

> 사용자가 별도로 "이번엔 일부만 해" 라고 명시한 경우에만 부분 산출. 기본은 항상 완수.

---

## 3. 산출물 완수 검증 체크리스트

스킬 종료 직전 self-check:

- [ ] `다음 세션`, `약식`, `심화 예정`, `산출 예정` 문자열이 산출 파일 본문에 0건
- [ ] 각 `screens/{S}.md` 의 §1~§11 + §A 모두 채워짐 (빈 § 또는 "(추후)" 자리 표시자 없음)
- [ ] 각 `groups/PG-XX_*.md` 의 §1~§8 모두 채워짐
- [ ] 모든 MD 파일에 대응하는 `.bpmn` 동시 산출 (단, 단일 화면 PG 가 BPA 와 중복되어 명시 스킵된 경우 제외)
- [ ] 본 분석 범위 외 항목은 "본 분석 범위 외" 로 명시 (시간 약속 없이)

검증 실패 시 즉시 추가 turn 으로 채워 넣고 재검증.

---

## 4. 적용 스킬

| 스킬 | 적용 범위 |
|---|---|
| `generate-bpa` | screens/{S}.md + screens/{S}.bpmn 의 §1~11 + §A 완수 |
| `generate-process-group` | groups/PG-XX_*.md + groups/PG-XX_*.bpmn 의 §1~8 완수 |
| `define-process-groups` | {MODULE-ID}_PROCESS_INDEX.md 의 PG 분류 + 정당화 + 관계도 완수 |
| `analyze-service` | Phase 1~4 JSON 산출. JSON 은 §·BPMN 개념이 없으므로 본 정책의 §1 "다음 세션" 금지만 적용 |

---

## 5. DBMS 분석 (`/analyze-table-schema`, `/analyze-plsql`, `/analyze-trigger`) 와의 관계

- DBMS 분석은 **별도 스킬의 명시 호출** 로만 산출된다. 본 정책은 화면/PG 산출 스킬에 DBMS 분석까지 자동 트리거하라고 요구하지 않는다.
- 다만 화면/PG 산출물 본문에서 DBMS 자산을 **"다음 세션에 분석"** 으로 약속하는 것은 금지. 대신 "DBMS 자산 인덱스 — 분석 미수행. 필요 시 `/analyze-plsql {NAME}` 명시 호출" 로 표기.
