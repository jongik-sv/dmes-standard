# 메시지 형식과 지시 템플릿

## 0. 역할

- **조정자(나)**: 대화형 Claude Code 세션 1개
  - 하는 일: 분해·할당, 머지 허가, 측정 창, 감시 틱, 세션·Pane 생성·정리, 사용량 띠 판정, compact, 통합 확인, SUMMARY·마감 보고
  - 안 하는 일: 제품 코드·시험 수정, 개발 커밋(몇 줄도 레인에 맡김, 2026-10-06), 레인 소유 파일 수정
- **레인 세션**: 브랜치·워크트리 하나를 가진 Claude Code 세션
  - 하는 일: 레인 일을 Workflow 로 진행, 진행 보고, 머지 요청·머지·정리, 정본 메모 유지
  - 안 하는 일: 허가 없는 dev 머지, 메인 저장소 서버 재기동, 남의 소유 파일 수정
- **임시 워커**: 새 탭의 Claude Code(GLM 포함)·opencode·agy
  - 하는 일: 짧은 단일 과제(교차 리뷰, 조사, 측정 실행, 문서 대조)
  - 안 하는 일: 머지, 다른 워커 관리
- **서브에이전트**: 세션 안 Agent·Workflow 하위 에이전트
  - 조정자와 직접 통신 금지(세션이 대신 보고)

설계 절: §2.2(메시지 형식), §3.i-4(instr_id), §3.k-1(착수 템플릿), §3.l-4·§3.m(예방 문구).

## 1. 규칙

- 모든 메시지 첫 줄 = `[보내는쪽→받는쪽] <종류>: …` (조정자는 `<종류>` 로 분기)
- 조정자 지시는 본문 첫 줄에 `instr_id` 기재: `[조정→a8] 다음 일 (지시 a8-17): …`
  - 발급: `node scripts/coord-state.mjs instr <레인> <kind>` (출력 `<레인>-<n>`, `last_instr_at`·`instrs[]` 동시 기록)
  - 착수 신호 전 예고 지시 → 번호 없음(발급 순간부터 `UNACKED` 이므로 착수 신호 때 발급)
- 레인은 다음 보고 첫 줄에 `instr_id` 기재
  - 받으면 `node scripts/coord-state.mjs ack <instr-id>` (레인 이름을 앞에 붙이면 사용법 오류)
- 지시 전송 = SendMessage (대화 기록에 남고 사용자가 레인 화면에서 봄)
  - 터미널 입력이 필요한 경우(슬래시 명령, opencode 워커)만 `node scripts/term-send-safe.mjs`
- 지시문에 `!` 금지. opencode 지시에는 `/`·`@` 도 금지
- 실행 중인 Workflow 하위 에이전트에는 전송 금지. Workflow 가 도는 레인에는 지시 금지(`monitor.md` 거부 규칙)
- 같은 레인에 같은 종류 지시를 `idle.cooldown_min`(기본 15분) 안에 반복 금지
  - ack 없으면 `<instr_id> 받았는지 한 줄 답` 만 전송(최대 2회)
  - 2회 뒤 → 화면을 읽어 원인 확인, 사용자에게 알림
- 지시 원문을 `lanes/<레인>/brief.md` 에 기록(착수 지시는 필수, 나머지는 요약)
- 상대 세션의 이름과 주소(`uds:/tmp/cc-socks/<pid>.sock`)를 함께 기록(이름이 바뀔 수 있음)

## 2. 메시지 형식 표

| 종류 | 방향 | 형식 |
|---|---|---|
| 착수 지시 | 조정자→레인 | `착수 지시: 레인 / 브랜치 / 워크트리 / 할 일 목록(번호) / 소유 파일 / 금지 파일 / 의존(기다릴 것) / 무거운 작업 칸 / Workflow 단계별 model·effort / 보고 방식` |
| 진행 보고 | 레인→조정자 | `진행 보고: 항목 번호 / 커밋 / 시험 결과(명령과 통과·실패 수) / 진도율 N%(끝난 항목/전체, 가중치면 그렇게) / 다음 항목` |
| 질문·승인 요청 | 레인→조정자 | `질문: 배경 / 선택지 / 기본안` (기본안으로 계속할지 그 단계만 멈출지 함께) |
| 머지 요청 | 레인→조정자 | `머지 요청: 세션 이름 / 원본 브랜치 / 대상 dev / 커밋 수·변경 요약 / 겹칠 수 있는 파일·모듈 / 머지 전 시험 결과(명령과 통과·실패 수) / 머지할 SHA(브랜치에 다음 항목 커밋이 이미 쌓여 있을 때만, 7~12자)` |
| 머지 허가·대기 | 조정자→레인 | `머지 허가: 예상 트리 <hash> / [머지할 SHA] / 조건(재기동·시험) / [건드리지 말 파일] / 머지 뒤 다음 일` 또는 `대기: 사유 / 그동안 할 일` |
| 머지 완료 | 레인→조정자 | `머지 완료: 머지 커밋 / 트리 / 머지 뒤 빌드·시험 결과(충돌·실패도 그대로)` |
| 정리 완료 | 레인→조정자 | `정리 완료: 지운 워크트리·브랜치 / 남긴 것과 이유` |
| 측정 시작·끝 | 조정자→측정 레인 | `측정 시작: 항목 / 창 끝 예정 시각 / 쓸 칸(--exclusive)` · `측정 끝 확인` |
| 무거운 작업 금지·재개 | 조정자→나머지 레인 | `무거운 작업 금지: 사유(측정·이동 등) / 예상 끝 / 그동안 할 수 있는 가벼운 일` · `무거운 작업 재개` |
| 사용량 띠 변경 | 조정자→전 레인 | `사용량 조정: 띠 / 동시 agent 상한 / opencode·agy 로 옮길 일의 범위 / 새 Workflow 금지 여부` |
| 정본 갱신 요청·완료 | 조정자↔레인 | `정본 갱신 요청: compact 예정` → `정본 갱신 완료: 경로 / 남은 일 3줄` |
| compact 뒤 확인 | 조정자↔레인 | `재개 확인: 남은 일 3줄로 답해 달라` → 답 |
| 자기 신원 | 레인→조정자 | 착수 때 한 번: `신원: 이름 / 세션ID / Orca 핸들 / pid / 워크트리` |

`머지 허가` 에는 항상 「머지 뒤 다음 일」 첨부.

## 3. 지시 템플릿 원문

`{…}` = 조정자가 채우는 자리. 괄호 안 설명은 옮기지 않음.

### 3.1 착수 지시

본문 = `templates/brief.md` 를 채운 것. 필수: 레인·브랜치·워크트리, 번호 붙은 할 일, 소유·금지 파일, 의존, 무거운 작업 칸(`heavy_env`), `workflow.md` Workflow 블록 전체, 공통 규칙 문서 링크, 신원 보고 요청.

```text
[조정→{레인}] 착수 지시 (지시 {instr_id}): 아래가 이 레인의 할 일·소유 파일·금지 파일의 정본이다.
공통 규칙은 {rules_doc} 를 읽는다.
(나머지는 templates/brief.md 형식)
착수하면 먼저 신원을 보낸다: echo $ORCA_TERMINAL_HANDLE $CLAUDE_CODE_SESSION_ID $CLAUDE_PID 결과를 "[{레인}→조정] 신원: 이름 / 세션ID / Orca 핸들 / pid / 워크트리" 로 보낸다.
```

- 조정자가 띄운 세션 → 신원 요청 줄 생략 가능(handle 기록 완료). pid·세션ID 가 비면 요청

### 3.2 다음 일

```text
[조정→{레인}] 다음 일 (지시 {instr_id}): {항목 id} {제목}
- 범위: {소유 파일 안 범위}
- 의존: {이미 dev 에 들어간 선행 항목 또는 없음}
- 끝 기준: {시험 명령과 기대 결과}
{workflow.md 의 Workflow 블록}
끝나면 첫 줄에 {instr_id} 를 적어 진행 보고를 보낸다.
```

### 3.3 대기 작업(idle 레인에 backlog 에서 배정)

```text
[조정→{레인}] 대기 작업 (지시 {instr_id}): {backlog 항목 desc}
- 종류: {교차 리뷰 | 기록 문서와 커밋 대조 | 통합 확인 체크리스트 | 범위 안 기존 결함 정리(동작 변경 없음) | SUMMARY 초안 | dev 선합류·컴파일 확인 | 병목 해소 뒤 단계 준비 | 문서·후속 목록 정리 | 병목 레인 읽기 조사·교차 리뷰}
- 범위: 읽기 위주. 뒤 네 종류(병목 대기 일)는 레인 소유 범위 안에서 쓸 수 있다. 소유 밖 파일은 어느 종류든 고치지 않는다(읽기만).
- 병목: {병목 대기 일일 때만. 무엇을 기다리는지}
- 끝 기준: {산출물 위치와 형식}
정본 메모에 남은 일을 갱신해 두고, 끝나면 첫 줄에 {instr_id} 를 적어 보고한다.
```

범위 밖 수정 일 → 자동 배정 금지.

### 3.4 맡길 일 없음

```text
[조정→{레인}] 쉬어라 (지시 {instr_id}): 지금 맡길 일이 없다. 정본 메모를 갱신하고 쉬어라. 새 일이 생기면 보낸다.
```

- 한 번만 전송 후 `node scripts/coord-state.mjs hold <레인> no-work` 실행
- 조건: queue·backlog 가 비고 `monitor.md` 「병목 대기 레인」 (a)~(e) 도 모두 빔(병목 대기 레인이 아니어도 같음)
  - 사유(어느 항목이 왜 비었는지)를 이벤트에 기록
- (a)~(e) 중 하나라도 있으면 → 이 메시지 대신 3.2·3.3 에 「병목: <무엇을 기다리는지>」 한 줄 추가

### 3.5 측정 시작·끝

```text
[조정→{측정 레인}] 측정 시작 (지시 {instr_id}): {항목 id 목록}
- 창 끝 예정: {ISO 시각}
- 쓸 칸: {heavy_env 또는 --exclusive 사용 여부}
- 회차마다 값과 load(`coord-status.mjs` PC 줄의 `load1`, 윈도우는 `-` = 관측 불가)를 남기고, 기준과 변경은 번갈아 잰다. 다른 무거운 명령은 이 창에서 돌리지 않는다.
끝나면 "측정 끝" 으로 보고한다.
```

```text
[조정→{측정 레인}] 측정 끝 확인 (지시 {instr_id}): 창을 닫는다. 수치와 load 기록을 보고 문서에 남겼는지 확인해 달라.
```

### 3.6 무거운 작업 금지·재개

```text
[조정→{레인}] 무거운 작업 금지 (지시 {instr_id}): 사유 {측정 | 이동 | 부하}
- 예상 끝: {ISO 시각 또는 미정}
- 그동안 할 수 있는 가벼운 일: {조사·문서·리뷰·코드 읽기 등}
gradle·vitest·tsc·tsup·playwright 같은 무거운 명령을 시작하지 않는다. 이미 도는 것은 이번 단계에서 끝낸다.
```

```text
[조정→{레인}] 무거운 작업 재개 (지시 {instr_id}): 금지를 푼다.
```

### 3.7 사용량 조정

```text
[조정→전 레인] 사용량 조정 (지시 {instr_id}): 띠 {G|Y|O|R}
- 동시 agent 상한: {workflow.agents_by_band 값}
- Claude 몫 이동: {G: 없음 | Y: 조사·문서 정리·쉬운 반복 구현을 opencode·agy 로 | O: Y 에 더해 일반 구현도 opencode 워커 우선, Claude 는 판정·리뷰·어려운 구현 | R: Claude 세션은 머지·정리만, 남은 일은 opencode·agy 워커로 (usage.md §2)}
- 새 Workflow: {허용(agent 마다 model·effort 명시) | 금지(R, 진행 중인 것은 끝까지)}
- 추가 행동: {R: 지금 단계 끝에서 멈추고 정본 갱신 | 그 밖의 띠: 없음(쉬라는 지시를 하지 않는다)}
이미 도는 Workflow 는 건드리지 않고 다음 Workflow 부터 적용한다.
```

## 4. 예방 문구 두 가지

모든 착수·다음 일 지시의 Workflow 블록(`workflow.md`)에 아래 두 문구를 넣음.

- 확인 창 예방: 「셸 명령은 짧게 나눈다. heredoc·`sh -c`·변수·`$(…)` 를 섞은 복합 명령을 피하고, 파일 수정은 Edit·Write 도구로 한다. 확인 창이 뜨면 Workflow 가 멈춘다.」
- 정지 예방: 「무거운 단계마다 시간 상한(모듈당 15분, 전체 빌드 40분 등)을 두고, 로그가 5분 넘게 늘지 않으면서 CPU 0% 이면 자기 트리만 TERM 으로 끝내고 blocked 로 보고한다. 긴 gradle 실행에는 `--info` 를 쓰지 않고 출력을 파일로 보낸다.」
