# {업무 이름} 레인 공통 규칙

{작성 날짜} {업무 설명 한두 문장}. 세션 {N}개에 레인으로 나눠 진행.
조정 세션 = **{조정 세션 이름}**. 질문·승인 요청·머지 요청은 모두 이 세션에 SendMessage (사용자 화면에 묻지 않음).

| 세션 | 레인 | 브랜치 |
|---|---|---|
| {세션 이름} | {레인 설명} | `{브랜치}` |

레인의 할 일·소유 파일·금지 파일 정본 = 조정 세션의 지시 메시지.

## 1. 작업 방식: Workflow 필수, 단계별 모델 지정

- 레인 작업 = **Workflow 도구**. 먼저 `workflow-authoring` 스킬 읽기
- 모든 `agent()` 에 `model`·`effort` 명시

| 단계 | model | effort |
|---|---|---|
| {설정 workflow.model_table 의 stage} | {model} | {effort} |

(표 = 조정 설정 `workflow.model_table` 로 채움. 기본 행: 조사·위치 찾기·문서 갱신·기계적 치환 sonnet/medium, 특성 테스트·구현·수정 opus/high, 리뷰·정합성 결함 수정 opus/high, 보안·트랜잭션 정합성 판정 opus/xhigh, 시험 실행·결과 확인 sonnet/medium)

- 항목마다 「구현 → 리뷰 → 지적 수정」. 리뷰가 clean 이 아니면 다음 항목으로 넘어가지 않음
- 레인 안에서 파일이 겹치지 않는 항목 = 병렬 가능. 겹치면 순서대로
- 동시 agent 수 = 조정 세션 지시문이 정함(기본 = 현재 띠 상한 G 4·Y 3·O 2)
- 셸 명령 = 짧게 나눔
  - heredoc·`sh -c`·변수·`$(…)` 섞은 복합 명령 금지(확인 창이 Workflow 를 멈춤)
  - 파일 수정 = Edit·Write 도구
- 무거운 단계에 시간 상한(모듈당 15분, 전체 빌드 40분 등)
  - 로그가 5분 넘게 늘지 않고 CPU 0% → 자기 트리만 종료하고 blocked 보고

## 2. 작업 공간

- 레인마다 워크트리 분리. 기준 = `{integration_branch}` 최신 커밋. 브랜치 이름 = 위 표
- {프로젝트 규칙: 이 리포 CLAUDE.md 와 RULE.md 의 작업 규칙을 따른다. PC별 실행 파일·경로는 각 PC 의 CLAUDE.md 와 `.coord.local.json` 이 정한다}
- {시험 규칙: 사용할 DB·도커 사용 여부 등}
- 메인 저장소에서 실행 중인 로컬 서버·FE 의 종료·재기동 금지
  - 브라우저 확인이 필요하면 조정 세션에 요청
  - 직접 연 브라우저 작업 공간 = 보고 전에 닫음
- 무거운 명령(gradle·전체 시험·빌드·E2E) = 레인당 한 번에 하나
  - 조정 세션의 `무거운 작업 금지` 통지 수신 → 풀릴 때까지 시작 금지

## 3. 규율

- {업무 원칙: 예) 동작 보존이 원칙. 바꾸기 전에 특성 테스트를 먼저 깔고, 바꾼 뒤 같은 테스트가 통과해야 함}
- 결함 수정(동작이 바뀌는 것) = 다른 커밋과 섞지 않고 `fix(...)` 커밋으로 분리
- **자기 레인의 소유 파일만 수정.** 금지 파일을 고쳐야 하면 먼저 조정 세션에 질문
- {소유 레인이 하나뿐인 공용 파일 목록과 소유 레인}
- **삭제 금지.** 쓰지 않는 파일 = archive 로 이동(`git mv`, 빌드·시험 대상에서 빠지게 설정)
- {사용자 승인이 필요한 변경: 예) shared 의 기존 공개 API·props·동작 변경은 조정 세션에 승인 요청 후 대기. 새 export 추가는 승인 없이 진행}
- 커밋 = 저장소 관례(Conventional Commits), 작은 단위
- 영역 규칙이 걸리면 리포의 무조건 적용 스킬을 따름

## 4. 머지 절차

1. **준비된 레인부터 머지.** 남는 의존:
   - {A 레인 항목은 B 레인이 들어간 뒤 머지. 의존 그래프를 그대로 옮김}
   - 머지 요청 직전 `{integration_branch}` 최신을 자기 브랜치에 합치고 빌드·시험 재실행
2. 머지 직전 조정 세션에 전송:
   `머지 요청: 세션 이름 / 원본 브랜치 / 대상 {integration_branch} / 커밋 수·변경 요약 / 겹칠 수 있는 파일·모듈 / 머지 전 시험 결과(명령과 통과·실패 수)`
3. 「머지 허가」 수신 뒤에만 머지
   - 「대기: 병목 사유」(다른 레인 머지·측정 창 등) → 그 머지만 기다리고 놀지 않음
   - 「대기」 가 수정·첨부 요청 → 그 일부터 수행
   - 병목으로 기다리게 되면(다른 레인 머지·의존물·Oracle·heavy 슬롯·사용자 결정) 스스로 찾아 진행하고 보고:
     - (a) 범위 안 의존 없는 다음 항목
     - (b) dev 미리 합치고 컴파일까지 확인
     - (c) 병목이 풀린 뒤 할 단계 준비(리허설·스크립트·런북·머지 요청 초안)
     - (d) 문서·후속 목록 정리
   - 넷 다 없을 때만 대기 보고
   - 머지 요청을 낸 뒤 요청 SHA 를 바꾸는 합류 금지
   - 병목 레인을 돕는 일 = 조정자가 배정
   - 머지 방법: {메인 저장소에서 `--no-ff`. git 실행 파일은 PC 설정을 따른다}
4. 머지 뒤 `머지 완료: 머지 커밋 해시 / 트리 / 머지 뒤 빌드·시험 결과` 전송(충돌·실패도 그대로)
5. 이어 워크트리 정리(`git worktree remove`, `git branch -d`. `--force`·`-D` 금지) → `정리 완료: 지운 워크트리·브랜치 / 남긴 것과 이유` 전송
6. 레인 일이 많으면 중간 단위로 여러 번 머지 가능. 매번 같은 절차
7. 레인은 push 금지. dev push·릴리스 반영·반영 빌드 = 머지 뒤 조정자 몫

## 5. 보고

- 항목 하나가 끝날 때마다 조정 세션에 한 줄: `진행 보고: 항목 번호 / 커밋 / 시험 결과(명령과 통과·실패 수) / 진도율 N%(끝난 항목/전체) / 다음 항목`
- 조정 세션 지시마다 번호(`instr_id`) 부여. 다음 보고 첫 줄에 그 번호 기재
- 착수 때 1회 신원 전송: `신원: 이름 / 세션ID / Orca 핸들 / pid / 워크트리`
- 정본 메모 하나 유지: 지금 상태·남은 순서·결정·조정 세션 이름·다음 단계
  - 「정본 갱신 요청」 수신 → 갱신 후 `정본 갱신 완료: 경로 / 남은 일 3줄` 답장
  - compact 뒤 = 정본을 읽고 「재개 확인」 에 남은 일 3줄 답장
- 측정 가능한 성능 항목 = 전후 수치 기록
  - 이 PC 는 측정 편차가 큼 → 반복 측정 없이 결론 금지

## 6. 기록 문서

{필요한 경우만. 사용자가 전후를 직접 비교하려는 업무일 때.}
- 레인마다 아래 문서를 **자기 브랜치에서** 작성, 머지에 함께 포함
- 레인별 파일 분리 = 머지 충돌 방지

| 문서 | 경로 |
|---|---|
| 구조 변경 기록 | `docs/{업무}/structure-{레인}.md` |
| 성능 비교 기록 | `docs/{업무}/perf-{레인}.md` |

- 머지 요청 시점에 해당 머지에 든 항목이 문서에 있어야 함
- 모든 머지 종료 뒤 조정 세션이 두 문서를 모아 `SUMMARY.md` 작성

### 6.1 구조 변경 기록

- 대상: 클래스·모듈 분리와 통합, 패키지 이동, 공개 API·진입점 변경, 호출 경로·계층 변경, 설정 조립 방식 변경, 의존성 변경, archive 이동
- 제외: 이름 정리·서식·시험만 추가한 커밋

```markdown
## S<번호>. <제목>
- 커밋: <해시들>
- 바뀌기 전: <구조>
- 바뀐 뒤: <구조>
- 바꾼 이유: <문제와 기대 효과>
- 동작 보존 근거: <특성 시험 이름·결과>
- 영향 범위: <호출부·설정·다른 레인·화면>
- 되돌리는 방법: <revert 대상 커밋, 주의점>
```

### 6.2 성능 비교 기록

- 대상: 성능을 기대하고 바꾼 항목 전부
- 기준(before) = {기준 태그} 에서 별도 워크트리로 측정
- 측정 시점 = 조정 세션의 「측정 시작」 통지 뒤(다른 레인이 조용할 때 단독 측정)
- 기준·변경 번갈아(A·B·A·B…) 각 3회 이상. 회차마다 값과 load(`coord-status.mjs` PC 줄의 `load1`, 윈도우 `-` = 관측 불가) 기록. 결론 = 중앙값
- 편차 없는 지표 = 1회로 충분

```markdown
## P<번호>. <항목>
- 관련 구조 변경: S<번호> (있으면)
- 지표(단위): <예: 콜드 빌드 시간(초)>
- 측정 절차: <명령·데이터·화면 조작을 그대로 따라 할 수 있게>
- 기준 커밋: {기준 태그} / 변경 커밋: <해시>
- 측정 환경: <단독 여부, 전원 연결, 측정 일시>

| 회차 | 기준 | 변경 | load(1분) |
|---|---|---|---|
| 1 | | | |

- 중앙값: 기준 <값> → 변경 <값> (<증감 %>)
- 판정: <개선·차이 없음·악화, 그 근거>
```
