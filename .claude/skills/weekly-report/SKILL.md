# 주간 업무 보고서 생성

git 커밋 이력을 바탕으로, 지정한 **모듈**과 **기간**의 작업을 상급자용으로 요약한 보고서를 만든다.
상급자가 읽기 때문에 **기술 용어를 최대한 줄이고 업무적 의미 중심**으로 작성한다.

---

## 입력

```
/weekly-report [모듈...] [기간]
```

- **모듈** (선택): 보고 대상 모듈. 여러 개 지정 가능 (예: `aps-core mpn`). **미지정 시 사용자에게 질문**한다.
- **기간** (선택): `YYYY-MM-DD~YYYY-MM-DD` 형식. **미지정 시 기본값**(전주 목요일 ~ 금주 수요일)을 자동 계산한다.

---

## 절차

### 1. 모듈 확정

인자에 모듈이 있으면 그대로 사용한다. **없으면 `AskUserQuestion`으로 묻는다.**
- 옵션은 아래 §모듈 매핑의 주요 모듈로 제시하고, `multiSelect: true`로 여러 모듈 동시 선택을 허용한다 (상급자 보고는 여러 모듈을 묶는 경우가 흔하다).
- 매핑에 없는 모듈을 직접 입력하면, `src/backend/<모듈>` · `src/frontend/m-<모듈>` 경로와 커밋 scope `<모듈>`로 해석한다.

### 2. 기간 확정

인자에 기간이 있으면 그대로 사용한다. 없으면 아래를 실행해 **전주 목요일 ~ 금주 수요일**(보고 주기 목→수)을 계산한다.

```bash
today_dow=$(date +%u)                       # 1=월 … 7=일, 수=3
back=$(( (today_dow - 3 + 7) % 7 ))         # 오늘 포함 가장 가까운 과거 수요일까지의 일수
if date -v-1d +%Y-%m-%d >/dev/null 2>&1; then   # BSD date(macOS)
  start=$(date -v-${back}d -v-6d +%Y-%m-%d)     # 시작: 그 전주 목요일
  end=$(date -v-${back}d +%Y-%m-%d)             # 종료: 금주 수요일
else                                            # GNU date(Git Bash·Linux)
  start=$(date -d "-$((back + 6)) days" +%Y-%m-%d)
  end=$(date -d "-${back} days" +%Y-%m-%d)
fi
echo "보고기간: $start (목) ~ $end (수)"
```

> BSD date(macOS)와 GNU date(Git Bash·Linux)를 모두 처리한다. 윈도우에서는 Git Bash 로 실행한다.
> 계산된 기간은 보고서 머리말에 **명시**한다 (예: `2026-06-11(목) ~ 2026-06-17(수)`).

### 3. 커밋 추출

기간 내 **머지를 제외한** 전체 커밋 제목을 뽑는다. 제목의 `type(scope):` 컨벤션이 잘 지켜져 있어 제목만으로 대부분 분류된다.

```bash
git log --no-merges \
  --since="$start 00:00" --until="$end 23:59:59" \
  --date=short --pretty=format:'%h|%ad|%s'
```

- `--no-merges` 필수: `Merge ADR-...`, `Merge remote-tracking branch ...` 등은 노이즈다. 머지가 묶은 실제 작업은 feat/fix/docs 커밋에 이미 들어 있다.
- **지정 모듈 분류**: 제목의 scope로 1차 분류한다 (§모듈 매핑 참조). scope가 모호하거나 경로 확인이 필요하면 `git show --stat <hash>`로 변경 경로를 본다.
- **경로 교차 주의**: 경로 필터(`git log -- <path>`)만으로는 한 커밋이 여러 모듈에 걸칠 수 있다 (예: `feat(mpn)` 용접 커밋이 `aps-core` 코드도 수정). 이런 커밋은 **주된 업무 맥락**에 따라 한 곳에 배치하고 중복 보고하지 않는다.
- 지정한 모듈과 무관한 커밋(다른 모듈, 머지)은 제외한다.

### 4. 코드 외 추가 작업 입력 요청

3번까지로 **요약 초안**을 만든 뒤, 사용자에게 다음과 같이 묻고 **응답을 기다린다**:

> "위 내용은 커밋 이력 기반입니다. 코드 외에 보고할 작업(회의·설계 협의·분석·문서 검토·외부 대응 등)이 있으면 알려주세요. 없으면 이대로 확정하겠습니다."

- 사용자가 입력하면 보고서에 **별도 항목**으로 자연스럽게 녹여 넣는다 (커밋 기반 항목과 같은 형식: 제목 + 불릿).
- "없음" 또는 빈 응답이면 초안을 그대로 확정한다.

### 5. 요약 작성

§작성 원칙과 §출력 형식에 따라 최종 보고서를 작성한다.

### 6. 출력

기본은 **대화 출력**(복사해서 바로 쓸 수 있는 마크다운). 사용자가 파일 저장을 원하면 `docs/reports/weekly/<start>_<end>_<모듈>.md` 등으로 저장한다.

## 모듈 매핑

| 모듈 | 커밋 scope (제목 괄호 안) | 주요 경로 |
|---|---|---|
| `aps-core` / `aps` | `aps`, `aps-core`, `aps-planning`, `aps-master` | `src/backend/aps-core`, (화면) `src/frontend/m-mpn` |
| `mpn` | `mpn`, `mpn-master`, `mpn-*` | `src/backend/mpn` |
| `m-mpn` | `m-mpn` (APS·MPN 공용 프론트) | `src/frontend/m-mpn` |
| `mcm` | `mcm`, `mcm-core`, `mcm-ui`, `mcm-auth`, `mcm-csa`, `portal` | `src/backend/mcm*`, `src/frontend/m-mcm` |
| `mls` | `mls` | `src/backend/mls`, `src/frontend/m-mls` |
| `mpp` | `mpp` | `src/backend/mpp`, `src/frontend/m-mpp` |
| `mqc` | `mqc` | `src/backend/mqc`, `src/frontend/m-mqc` |
| `analog` | `analog` | `src/backend/analog`, `src/frontend/m-analog` |

> 주의: APS 화면은 `m-mpn` 프론트에 들어간다(`m-aps` 아님). `aps-planning`·`aps-master` scope 커밋은 대개 `m-mpn` 화면 작업이다. `aps`와 `mpn`을 함께 보고하면 경로 공유 문제가 사라진다.
> 매핑에 없는 모듈은 모듈명을 scope·경로에서 추론한다. 디렉토리 목록은 `ls src/backend src/frontend`로 확인한다.

## 작성 원칙 (상급자 대상)

- **기술 용어 최소화**: ADR 번호, 클래스·함수·테이블·컬럼명, 커밋 해시, 마이그레이션 버전(V44 등)은 **본문에서 제외**한다. "무엇을, 왜" 중심으로 업무 언어로 푼다.
  - (나쁨) "ADR-0023 revertFirm + unfirmCascade 가드 추가"
  - (좋음) "확정한 계획주문을 다시 취소·되돌릴 수 있는 경로 신설"
- **건별 묶음**: 관련 커밋 여러 개를 **하나의 업무 단위**로 묶는다 (커밋 1:1 나열 금지). 한 주에 보통 8~12건 이내로 압축한다.
- **제목 20자 이내**, 한 건당 **불릿 2~3개**.
- **불릿 내용**: 한 줄은 "한 일", 다른 한 줄은 "효과/배경"을 적으면 읽기 좋다. 미완·후속 이연은 괄호로 짧게 표기 (예: "(1차: 적재·조회 / 전송은 후속)").
- **대분류 섹션**으로 묶으면 가독성이 올라간다. 모듈·성격에 맞게 정한다. 예: `신규 기능` / `정책·업무규칙 반영` / `사용성 개선` / `안정화·성능`.
- **문서·테스트 전용 커밋**: 단독 보고 가치가 낮으면 관련 기능 건에 "설계 정리"·"검증 보강" 한 줄로 흡수하거나 생략한다. 한 주 작업이 문서 위주면 "설계·정책 문서화" 한 건으로 묶는다.
- 모든 출력은 **한국어**.

## 출력 형식 (예시)

```markdown
## 주간 업무 보고 — APS(aps-core)·MPN
**기간**: 2026-06-11(목) ~ 2026-06-17(수)

### 신규 기능
**1. 계획주문 확정취소 기능**
- 확정한 계획주문을 다시 취소·되돌릴 수 있는 경로 신설
- 오확정 시 복구 불가하던 문제 해소

**2. 계획주문 → 구매요청 연계**
- 구매 대상 계획주문 확정 시 ERP 구매요청 자동 생성·조회
- (1차: 적재·조회까지 / ERP 전송은 후속 단계)

### 안정화·성능
**3. 플래닝 처리 성능 개선**
- 계획수립 단계 병목 해소(약 50초 → 대폭 단축)

### 기타 (코드 외 — 사용자 입력)
**4. 차주 일정 협의**
- ERP 연동 범위 관련 현업 회의 진행
```

---

## 주의

- git·ls 등 **읽기 전용 명령만** 사용한다. 보고서 작성을 위해 코드를 수정하지 않는다.
- 커밋이 0건이면 "해당 기간·모듈에 커밋 작업 없음"을 알리고, 코드 외 작업만 입력받아 보고할지 사용자에게 확인한다.
- 기간·모듈은 보고서 머리말에 항상 명시해 추적 가능하게 한다.
