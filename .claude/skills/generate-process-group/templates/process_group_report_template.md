## 2. End-to-End 프로세스 흐름

<!-- 작성 지침:
- 개별 서비스 단위가 아닌 **업무 단계(Step)** 중심으로 기술
- 각 단계에서 어떤 데이터가 입력되고 어떤 결과가 산출되는지 명시
- 분기 조건 (정상/에러/예외) 포함
- Mermaid flowchart TD로 시각화 (LR 금지)
- 노드 줄바꿈은 <br/> 사용 (\n 금지)
- 한글 노드는 ["텍스트"] 형식
- **색상 필수**: classDef로 역할별 색상 정의 후 class로 각 노드에 할당
- 다이어그램 뒤에 반드시 **범례** 추가
-->

### 프로세스 흐름 요약

`시작 이벤트 → 단계1 → 단계2 → ... → 종료 이벤트`

### 프로세스 흐름도

```mermaid
flowchart TD
    %% 노드 정의
    %% ...

    %% 색상 정의 (역할별)
    classDef external fill:#808080,color:#fff
    classDef trigger fill:#4169E1,color:#fff
    classDef process fill:#4169E1,color:#fff
    classDef decision fill:#408040,color:#fff
    classDef sync fill:#408080,color:#fff
    classDef manual fill:#005080,color:#fff
    classDef quality fill:#408040,color:#fff
    classDef query fill:#808000,color:#fff
    classDef error fill:#C04040,color:#fff

    %% 노드에 색상 할당
    %% class NODE_ID classDef_name
```

**범례**
- 회색 (`external`): 외부 시스템
- 파란색 (`process`/`trigger`): 핵심 처리 / 시작 트리거
- 짙은초록 (`decision`/`quality`): 분기·판별 / 검수·품질
- 청록색 (`sync`): 동기화 처리
- 남색 (`manual`): 수동·보완 처리
- 올리브 (`query`): 조회 서비스
- 빨간색 (`error`): 오류·예외 처리

### 단계별 상세

<!-- 각 업무 단계에 대해:
- **단계명**: 무엇을 하는가

- **처리**: 핵심 업무 로직 (코드 레벨 상세 제거)
- **출력**: 어떤 결과가 산출되는가
