# 이슈사항 정리 (dmes-standard 전 모듈)

> 문체: 산출 문서 → `../_shared/style/Korean-STE-Writing-Guide.md`.

협의·결정이 없어서 다음 단계로 못 가는 사항을 **현업·PM 이 그대로 읽고 결정할 수 있는 형태**로
정리한다. ADR 이 "정해진 것"을 남기는 장치라면, 이 양식은 **"아직 못 정한 것"** 을 남기는 장치다.

## 0. 불변 원칙

**파일을 만들지 않는다.** 요청받은 이슈를 대화에 텍스트로만 출력한다. 사용자가 명시적으로
"파일로 저장해"라고 하기 전에는 `Write`/`Edit` 를 쓰지 않는다. 사용자가 그 텍스트를 회의 자료·
협의 문서로 직접 옮긴다.

**업무 언어로 쓴다.** 엔티티명·컬럼명·클래스명·API 경로를 본문에 쓰지 않는다. 읽는 사람은
현업·PM 이다. "PeggingRecord.isFixed 가 false 면 삭제된다" 가 아니라 "계획을 다시 돌리면
연결이 풀린다" 로 쓴다.

**결정할 수 있게 쓴다.** 정보를 나열하는 게 아니라, 읽은 사람이 A/B/C 중 하나를 고를 수 있어야
한다. 선택지가 안 떠오르면 그건 아직 이슈로 정리할 단계가 아니라 조사할 단계다.

## 1. 양식

```
**{이슈 제목} ⭐신규**

- {확인이 필요한 사항 — 무엇이 미정인지, 왜 지금 필요한지}
- {확인이 필요한 사항 2}
- 결정에 따른 개발 방향
  - {선택안 이름}: {그 안을 택하면 개발이 어떻게 되는지}
  - {선택안 이름}: {...}
  - {선택안 이름}: {...}
```

### 각 부분 작성 규칙

| 부분 | 규칙 |
|---|---|
| 제목 | 명사구. **무엇을 정해야 하는지**가 드러나야 한다. "세척 유형별 캐파·사이클 산정 기준" (O) / "세척 관련" (X) |
| `⭐신규` | 이번에 처음 올리는 이슈에만 붙인다. 기존 이슈를 다시 꺼내거나 갱신하는 경우 붙이지 않는다 |
| 확인 필요 bullet | `~인지 확인 필요` 로 끝낸다. 1~3개. 각 bullet 은 하나의 질문만 담는다 |
| 결정에 따른 개발 방향 | 선택지별로 **개발이 실제로 갈리는 지점만** 쓴다. 갈리지 않으면 그건 선택지가 아니다 |

### 생략 규칙

- 선택지가 하나뿐이거나 개발 영향이 동일하면 `결정에 따른 개발 방향` 절을 통째로 생략한다
- 개발 영향이 "추가 개발 없음"인 선택안도 그대로 쓴다 (현행 유지가 선택지임을 보여야 한다)

## 2. 예시

**세척 유형별 캐파·사이클 산정 기준 ⭐신규**

- 세척 유형(부동태·산세척·불산 등)별로 처리시간(사이클타임)·배치 용량·운영방식이 다른지, 유효 캐파를 유형별로 따로 산정해야 하는지 확인 필요
- 배치 용량 산정에 ERP 라우팅의 기존 계산 배치수량(외경·내경·길이 기반)을 입력원으로 쓸 수 있는지, 현장 실제값과 대조 검증이 필요한지 확인 필요
- 결정에 따른 개발 방향
  - 유형 무관 단일 파라미터: 기존 배치 크기·시간 설정 활용
  - 유형별 상이: 세척 유형별 캐파·사이클 파라미터 마스터 분리
  - ERP 계산값 활용: 라우팅 배치수량 수신 + 현장값 보정

**세척조·건조기 최대 투입량 산정 기준**

- 설비별 CAPA 단위 확정 필요
- 선택 대상: EA, 바스켓 수, 중량, 부피, 제품 크기별 점수
- 결정에 따른 개발 방향
  - 고정 EA 기준: 기존 배치 크기 설정 활용
  - 중량·부피·크기 기준: 품목별 설비 점유량 및 적재량 계산 기능 개발
  - 복수 기준 동시 적용: 다중 CAPA 제약 기능 개발

## 3. 작성 절차

1. **보류 사유를 확인한다.** "우리가 못 정한다"인지 "아직 안 알아봤다"인지 가른다.
   후자면 이슈로 올리지 말고 먼저 조사한다
2. **현행 동작을 코드로 실측한다.** 이슈 본문에 코드 근거를 쓰지는 않지만, 선택지 중 하나는
   보통 "현행 유지"이므로 현행이 실제로 무엇인지 확인하지 않으면 선택지가 틀린다
3. **선택지를 뽑는다.** 각 선택지가 개발을 어떻게 가르는지 한 줄로 말할 수 없으면 선택지가 아니다
4. **양식대로 출력한다.** 파일에 쓰지 않는다

## 4. 인접 장치와의 관계

| 상황 | 쓸 것 |
|---|---|
| 결정이 끝나 되돌리기 어려운 설계를 확정 | `adr-write` 스킬 → `docs/{module}/design/adr/` |
| 아직 못 정해 협의로 넘김 | **본 스킬** (텍스트 출력) |
| mls 모듈의 기존 미결 큐 | `docs/mls/screens/MLS_미해소_확인필요_목록.md` (표 형식, 기존 규약 유지) |
| mpp 모듈의 기존 미결 큐 | `docs/mpp/design/OPEN-ACTION-ITEMS.md` (OPEN-n 채번, 기존 규약 유지) |

mls·mpp 의 기존 문서는 각자의 규약을 그대로 둔다. 본 양식으로 개작하지 않는다.
