# ── 2) 루트 buildEnvironment(classpath) — build-logic 항목 ──
# Gradle 9.3.1(_meta.txt 의 gradle 줄) 의 included build 플러그인 해석은 마커 모듈이 아니라 프로젝트 의존을 classpath 에 넣는다:
#   gradle-composite-builds-9.3.1.jar CompositeBuildPluginResolverContributor$LocalPluginResolution.accept
#   → DefaultProjectDependencyFactory.create(<생산 프로젝트 경로>) → visitor.visitDependency (javap 로 확인, 2026-10-04).
# 그래서 실제 줄은 '+--- project :build-logic' 꼴로 예상한다(실측 덤프 없음 — 형식 미검증). 마커 좌표 꼴
# ('dmes.<id>:dmes.<id>.gradle.plugin[:버전] -> project :build-logic')도 같은 패턴의 대안으로 받는다. 어느 쪽이든 해석 대상은
# project :build-logic 으로 고정이다. build-logic 은 외부 의존이 없어(gradleApi·localGroovy 는 파일 의존이라 보고에 안 나옴) 자식 줄이 없다.
# 최상위 줄만 받는다('+---'/'\---' 로 시작). 끝의 ' (*)' 는 같은 노드 반복 표시라 허용한다.
#
# 2-a) test-conventions 만 쓰는 9개 모듈 — 기대: A 0 / B 9.
@^(aps-core|caravan-core|caravan-hub|caravan-console|mcm-core|cactus-core|maru-mdm-engine|mdm|localKafka)/buildEnvironment/_root\.txt$ ^[+\\]--- (project :build-logic|dmes\.test-conventions:dmes\.test-conventions\.gradle\.plugin(:[^ ]+)? -> project :build-logic)( \(\*\))?$

@^(mpn|mpp|mqc|mls|mcm)/buildEnvironment/_root\.txt$ ^[+\\]--- (project :build-logic|dmes\.test-conventions:dmes\.test-conventions\.gradle\.plugin(:[^ ]+)? -> project :build-logic|dmes\.business-module:dmes\.business-module\.gradle\.plugin(:[^ ]+)? -> project :build-logic)( \(\*\))?$
